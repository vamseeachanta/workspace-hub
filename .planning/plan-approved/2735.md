## Scope sharpening from parent #2733 clarification (2026-05-17)

The canonical-memory-IN-GITHUB directive sharpens the API design:

- **Write API must commit to repo** — semantics include git-add + git-commit (or equivalent direct-write) when memory is updated
- **Read API must pull from repo** — semantics include git-pull or equivalent freshness check
- **Schema must support git-friendly formats** — markdown / yaml / json; not opaque binary
- **Per-write granularity decision required** — one file per memory? per-day rollup? per-session rollup? affects merge-conflict frequency
- **Conflict resolution = git merge semantics** — design must specify how concurrent writes from different providers / sessions / machines reconcile

Reference implementation (per epic): Claude Code is natural starter given session-arc context, but the API must accommodate Codex + Gemini equivalence from day one.
