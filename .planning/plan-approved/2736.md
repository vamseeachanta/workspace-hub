Two sharpening directives expand and tighten migration scope:

1. **Historical-memory consolidation is in scope** — not just future writes; the existing accumulated history from each provider migrates into Hermes with provenance preservation. Migration must:

   - Preserve cross-machine context: user works across multiple machines; migration must consolidate without conflict-resolution loss

2. **Canonical memory goes WITH the repo ecosystem (in GitHub)** — migration target is a SPECIFIC repo (or repo-set for public/private layering):
   - **Naming decision required**: workspace-hub? hermes (separate repo)? new dedicated repo (e.g., `vamseeachanta/hermes-memory`)? per-domain repos?
   - **Public-vs-private layering**: governance for what goes in public vs private repos mirrors existing per-repo data-routing rules (see `feedback_offrepo_intel_routing` and the same boundary that just required Phase B redaction in llm-wiki Wave 2 corpus manifest [commit `f30e0e86`](https://github.com/vamseeachanta/llm-wiki/commit/f30e0e86))
