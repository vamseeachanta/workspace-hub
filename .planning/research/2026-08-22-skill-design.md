# Research: skill-design — 2026-08-22

## Key Findings

1. **Skill authoring meta-pattern: Control Tuning, not just conciseness — five specificity-control patterns exist (Template Scaffold, In-Skill Examples, Known Gotchas, Explain-the-Why, and Control Tuning as the meta-rule).** Prior research (2026-08-15) surfaced "routing rules (imperative)" as guidance; this clarification shows it's one instance of a larger five-pattern control spectrum. The spectrum lets authors dial freedom up/down: high-freedom skills enable agent exploration (risky), low-freedom skills constrain output tightly (safe but brittle). **Directly relevant:** workspace-hub's 50+ skills need categorization into this spectrum — some (`coordination/issue-planning-mode`) are high-control (step-by-step procedure), others (`research/llm-wiki-search`) are high-freedom (exploratory). Explicit taxonomy prevents accidental brittleness or unsafe freedom. → [Skill Authoring Best Practices — Claude Docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) | [Skill Authoring Patterns from Anthropic's Best Practices](https://generativeprogrammer.com/p/skill-authoring-patterns-from-anthropics)

2. **SkillsBench: first public benchmark measuring whether a skill actually changes agent *behavior* (not just technical correctness).** Prior research mentioned "Anthropic Evaluations framework (20–50 tasks)"; SkillsBench is the missing operational implementation — it pairs skills with hand-authored tasks + unit-test grading to verify behavior change. Only 52% of teams run offline evals before deployment (2026 LangChain survey); SkillsBench closes this gap with a standardized, repeatable method. **Directly relevant:** Phase 7's smoke tests currently verify artifact generation + CI gates; SkillsBench-style behavior verification (does solver-lock skill actually check lock status?) would strengthen constraint validation beyond code coverage. → [Evaluating Autonomous AI Agents for Performance, Oversight, and Business Value — Weights & Biases](https://wandb.ai/site/articles/evaluating-autonomous-ai-agents/) | [Agent Skill Evaluation and Evolution: Frameworks and Benchmarks](https://arxiv.org/html/2606.11435v1)

3. **LDP protocol (2025) formalizes multi-agent delegation with identity cards (model family, quality metrics, trust domains, payload negotiation).** Prior research (2026-08-15) identified A2A + self-claiming-quality-signal risk; LDP is the remediation — agents declare capability identity + supporting metrics upfront, negotiating delegation contract explicitly. **Directly relevant:** workspace-hub's model-routing (Fable vs. Opus vs. Codex) currently uses implicit assumptions ("Opus for execution, Fable for planning"). LDP + Agent Cards would formalize this as verifiable declarations, reducing routing mismatches in multi-provider cross-review. Not blocking v1.1, but relevant for Phase 999.4 (autoresearch multi-cycle routing). → [The Provenance Paradox in Multi-Agent LLM Routing: Delegation Contracts and Attested Identity in LDP](https://arxiv.org/html/2603.18043) | [Safe Bilevel Delegation (SBD): A Formal Framework for Runtime Delegation Safety in Multi-Agent Systems](https://arxiv.org/pdf/2604.27358)

4. **Hierarchical delegation consistently outperforms flat coordination on complex tasks, but introduces single-point-of-failure and bottleneck risks requiring deliberate mitigation.** Enterprise adoption is moving toward hierarchical patterns (72% of multi-agent projects, up from 23% in 2024). **Directly relevant:** workspace-hub's T3 cross-review pattern (Claude r1 → Codex r2 → Agy r3) is hierarchical with Claude orchestrating; Phase 999.4's autoresearch multi-cycle would also be hierarchical (researcher → evaluator → merger). The finding validates the choice but flags the mitigation requirement — document single-point-of-failure scenarios (e.g., Claude r1 unavailable → no r2/r3 dispatch) and failover strategy. → [Best Multi-agent Orchestration Frameworks in 2026 — TrueFoundry](https://www.truefoundry.com/blog/multi-agent-orchestration-frameworks) | [AI Agent Delegation and Team Coordination Patterns — Zylos Research](https://zylos.ai/research/2026-03-08-ai-agent-delegation-team-coordination-patterns/)

5. **Iterative skill development via Claude A (expert refiner) + Claude B (real-work tester) + domain expert (you) creates a three-party feedback loop that outperforms top-down design.** Prior research mentioned "documentation-only" skills improvements; this pattern makes refinement concrete and repeatable — Claude A iterates the skill, you validate domain assumptions, Claude B tests in real usage, then repeat. **Directly relevant:** workspace-hub's skill refresh for v1.1 (routing-rule descriptions, control-tuning categorization) should use this pattern: have an expert Claude session refine 3–5 exemplar skills, test them in real cross-review/research work, then batch the learnings into v1.1's skill-authoring guidelines. → [Skill Authoring Best Practices — Claude Docs](https://docs.claude.com/en/docs/agents-and-tools/agent-skills/best-practices) | [Skill Authoring Patterns from Anthropic's Best Practices](https://generativeprogrammer.com/p/skill-authoring-patterns-from-anthropics)

`★ Insight ─────────────────────────────────────`

**The prior research (2026-08-15) was thorough on the strategic level — it identified three emerging frontiers (routing rules, Evaluations framework, A2A delegation integrity).** This week's research operationalizes two of them with concrete techniques:

1. **Routing rules + Control Tuning = a spectrum, not a binary choice.** You identified "passive vs. active descriptions" in 08-15; this confirms it's part of a larger five-pattern spectrum (Template Scaffold, In-Skill Examples, Known Gotchas, Explain-the-Why, Control Tuning). Categorizing your 50+ skills against this spectrum is a 3–4 hour audit that clarifies which skills can be safely exploratory (research/) and which must be procedural (coordination/).

2. **Evaluations framework + SkillsBench = behavior change is now measurable.** Phase 7's smoke tests currently verify that the solver runs; SkillsBench-style evaluation verifies that the solver-skill actually *changed agent behavior* (e.g., the lock-check happens, not just that code compiles). Two-layer validation (code + behavior) is now the industry standard for 2026 agent deployment.

3. **LDP + hierarchical delegation risks are the remaining open decisions for Phase 999.4.** The research validates hierarchical architecture (your T3 pattern outperforms flat) but surfaces the mitigation burden (single-point-of-failure, bottleneck). LDP formalizes routing away from implicit assumptions. Both are design decisions, not blocking v1.1, but decisions worth making explicitly.

**The highest-impact immediate action: implement the Claude A/B/expert iterative loop for skill refinement on 5 exemplars during v1.1.** This transforms a passive "audit descriptions" task into an active improvement loop. You get refined skills, Claude learns domain constraints, and the feedback becomes v1.1's skill-authoring guidelines for everyone else. It's the difference between a documentation pass and a capability uplift.
