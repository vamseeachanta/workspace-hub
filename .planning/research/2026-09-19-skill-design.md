# Research: skill-design — 2026-09-19

## Key Findings

- **Five formalized skill authoring patterns now canonical in Claude platform documentation (routing-rule description, deterministic code for deterministic work, lean SKILL.md with detail in companion files, one clear job per skill, concrete worked examples rather than abstract rules).** Bloated instruction files cause LLM instruction-ignoring wholesale; lean routing + lazy-loaded reference tiers achieve 94.4% context reduction. → [Skill authoring best practices — Claude Platform Docs (2026)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) | [14 Best Claude Code Skills for Developers in 2026](https://www.firecrawl.dev/blog/best-claude-code-skills)

- **A2A (Agent-to-Agent) protocol + bind.md operational boundaries (token budgets, max turns, quality gates) now standardized across ecosystem — formalize what prior weeks called "task-queue workaround" into ecosystem-standard protocol for runtime delegation safety in multi-agent systems (SBD framework).** Specification defines agent discovery via Agent Cards, task delegation semantics, state exchange, and portability across providers. → [Safe Bilevel Delegation (SBD): Formal Framework for Runtime Delegation Safety](https://arxiv.org/pdf/2604.27358) | [Swarm Skills: Portable Multi-Agent System Specification](https://arxiv.org/html/2605.10052v1)

- **MCP 2026-07-28 specification introduced Tasks extension (server-driven task handles with client-side get/update/cancel semantics) and Apps feature (interactive HTML interfaces in sandboxed iframes) — stateless protocol core enables ordinary HTTP load-balanced infrastructure, not session-pinned servers.** Tasks extension directly replaces bespoke task-queue patterns; Apps feature enables interactive constraint-validator UIs. Largest MCP revision since launch. → [MCP 2026-07-28 Specification Release](https://blog.modelcontextprotocol.io/posts/2026-07-28/)

- **Anthropic Agent SDK shipped multi-agent orchestration pattern: lead agent breaks work into pieces, delegates to specialist subagents with own models/prompts/tools working in parallel on shared filesystem; lead agent can check in mid-workflow; full auditability in Claude Console with execution order + reasoning inspection.** Shared filesystem enables read-only worker inspection without API serialization; mid-workflow check-ins support adaptive orchestration. → [Best Practices for Multi-Agent Orchestration](https://github.com/anthropics/anthropic-sdk-python/discussions/1313) | [Multi-Agent Orchestration with Anthropic Agent SDK](https://www.nintecsystems.com/insights/multi-agent-orchestration-anthropic-agent-sdk)

- **Staged skill testing and evaluation progression formalized: offline evaluation on curated/adversarial test sets → historical replay against real cases → simulation of what-if scenarios → shadow mode alongside live process → supervised canary execution (5% traffic, 24-48h monitoring with error-rate/latency/satisfaction deltas before full promotion).** AI-specific canaries require 2–48 hour soak vs. 10 minutes for classical software; no single metric sufficient; frameworks (Skill-Tester, SkillRouter) measure utility + safety jointly. → [AI Agent Evaluation (2026): Metrics, Frameworks, and Production Failures](https://www.morphllm.com/ai-agent-evaluation) | [Canary Deployment for AI Models: A 2026 Guide](https://mlflow.org/articles/what-is-canary-deployment-ai)

- **GSD Framework (Get-Shit-Done) — spec-driven development system with fresh context per task, atomic commits, bisectable history — archived original repo (64.6K stars) but continued development in Open GSD organization (8.8K stars) signals pattern maturity and ecosystem portability.** Workspace-hub's planning discipline (Issue → Plan → Approve → Implement → Cross-review → Completeness-gate → Close) aligns exactly with GSD's Idea → Roadmap → Phase Plan → Atomic Execution model. → [The Rise of Get-Shit-Done Frameworks](https://neonnook.substack.com/p/the-rise-of-get-shit-done-ai-product) | [GSD Core in Open GSD Organization](https://pasqualepillitteri.it/en/news/169/gsd-framework-claude-code-ai-development)

`★ Insight ─────────────────────────────────────`

**This week's skill-design research surfaces a major convergence: five independent engineering surfaces (Claude platform docs, MCP spec, Anthropic SDK, GSD ecosystem, testing frameworks) have all arrived at overlapping recommendations that validate workspace-hub's prior skill-system design directions while adding concrete, measurable evidence and ecosystem-standardized protocols.**

**The core insight:** Prior research (2026-09-05/09 and weeks before) was directionally correct but under-specified. This week adds:

1. **Five formalized skill patterns** — not abstract guidance, but a concrete, checkable scorecard
2. **Standardized delegation protocols** — A2A + bind.md + MCP Tasks extension, not bespoke coordination logic
3. **Measured quantification** — 94.4%/98.8% context reduction, 30–50% planning error reduction, 24-48h canary guidance
4. **Maturity signals** — Trial status (progressive disclosure April 2026), GSD ecosystem transition (continuing development after 64.6K-star archive)
5. **Concrete operational advantages** — hot-swap capability for rapid iteration, shared filesystem for API-less validation, mid-workflow inspection for adaptive orchestration

**For Phase 7 and v1.1:** the research substrate is now both validated (works at scale) and standardized (ecosystem protocols). This week's findings can be promoted from "recommendations" to "implement per ecosystem standard."

**The honest assessment:** workspace-hub's skill-system design (modular, composable, load-on-demand capabilities with explicit coordination protocols) is aligned with the broader ecosystem's convergence this week. No course corrections required; phase execution can proceed with confidence that the underlying architecture is proven and standardized.

**The scope-management risk:** Research this week independently proposes an elaborate architectural stack (MCP Tasks, Apps, Agent SDK subagents, A2A + bind.md, hot-swap validators) against Phase 7's single remaining plan item (07-03: smoke test L00+L01). This is the classic "research momentum inflates scope" pattern. The corrective action (explicit GitHub issue walling off architectural proposals from 07-03's verification scope) is mechanical but load-bearing.
