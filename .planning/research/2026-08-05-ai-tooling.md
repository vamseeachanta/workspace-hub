# Research: ai-tooling — 2026-08-05

## Key Findings

1. **MCP 2026-07-28 Specification: Stateless architecture lands.** The July 28, 2026 MCP spec release is a **breaking architectural shift** — MCP transforms from bidirectional stateful (sticky sessions, shared state stores) to request/response stateless (HTTP-scalable, plain round-robin load balancers). Long-running work now routes through the Tasks extension, and server-rendered UIs ship via MCP Apps. Ecosystem now indexes 19,831+ servers with backing from Anthropic, OpenAI, Google, Microsoft. **Directly affects workspace-hub's MCP tool scope** — `claude_ai_Gmail`, `claude_ai_Google_Calendar`, `claude_ai_Google_Drive` tooling may need audits for stateless compatibility. → [MCP 2026-07-28 Spec Release](https://blog.modelcontextprotocol.io/posts/2026-07-28/) | [The Register coverage](https://www.theregister.com/devops/2026/07/23/model-context-protocol-prepares-to-break-with-its-stateful-past/5276722)

2. **Claude Code v2.1.221 (August 2026): Focus view declutters; OpenTelemetry logging hardens observability.** Focus view collapses tool activity into compact summaries (noise reduction). OpenTelemetry logging now includes `message.uuid`, `client_request_id`, `tool_source` for message-level correlation and tool provenance — audit trail for multi-agent/subagent sessions. Session renaming fixes completed (Desktop↔CLI sync). **Relevance:** The logging enhancements directly support workspace-hub's multi-provider cross-review gates and subagent dispatch observability (per `model-routing.md`). → [Claude Code Changelog August 2026](https://www.gradually.ai/en/changelogs/claude-code/)

3. **Anthropic Agent SDK multi-agent orchestration (May 6, 2026, public beta). Specialist agents + parallel execution + event persistence.** Lead agent delegates to specialists (each with own model/prompt/tools) that execute in parallel on shared filesystem. Events are persistent — agents remember prior work and can be queried mid-workflow. Self-hosted sandboxes + MCP tunnels shipped May 19 (enterprise on-prem execution). Separate monthly Agent SDK credits pooling (June 15, 2026). **DIRECT IMPACT:** workspace-hub's current multi-provider dispatch (Claude+Codex+Agy per `feedback_cross_provider_review_polarity`) now has a first-class Anthropic orchestration primitive. Phase 7 solver-verification gate and Phase 999.4 autoresearch could benefit from structured orchestration instead of manual `Agent` tool calls. → [Anthropic May 6 Launch: Dreaming, Outcomes, Multi-Agent](https://www.mindstudio.ai/blog/code-with-claude-2026-new-agent-features) | [Claude Managed Agents Orchestration Explained](https://www.developersdigest.tech/blog/claude-managed-agents-dreaming-outcomes-multi-agent)

4. **Codex CLI v0.143.0–v0.144.0 (July 2026): Remote plugins enabled by default, app-approval mode, MCP interactive auth.** Remote workflows support daemon-managed codex remote-control. Usage-limit reset credits now tracked with type/expiration. Indexed web-search mode (live searches, restrict direct page access). **Relevance:** workspace-hub's Codex review lane (`feedback_delegate_token_heavy_to_codex`) gains daemon-managed workflow capability — useful for sustained T2/T3 cross-reviews or long-running implementation marathons. → [Codex Changelog — OpenAI — releases.sh](https://releases.sh/openai/openai-codex-changelog) | [Codex June 2026 Digest](https://www.developersdigest.tech/blog/codex-changelog-june-2026)

5. **⚠️ CRITICAL: GSD Framework archived June 26, 2026 — repo now read-only. Last active v1.40.0 (May 3).** GSD shifted to Open GSD repository; original gsd-build repo is archived. Last shipped feature: v1.40.0 (May 3, 2026) with 94% prompt-overhead reduction (12K → 700 tokens via Minimal Install Profile) and structured JSON error mode. **BREAKS workspace-hub workflow.** The GSD invocations referenced in SHARED_SOUL.md (`/gsd:transition`, `/gsd:complete-milestone`) and `docs/plans/` template references assume active upstream. Workspace-hub must either (a) migrate to Open GSD, (b) vendor the last stable v1.40.0 release, or (c) migrate to an actively maintained alternative (e.g., LangGraph multi-step orchestration). → [GSD Original Repo — ARCHIVED](https://github.com/gsd-build/get-shit-done) | [Open GSD Continuation](https://github.com/open-gsd/get-shit-done)

`★ Insight ─────────────────────────────────────`

**The GSD archival is your biggest signal here.** workspace-hub's entire phase/milestone tracking model (ROADMAP.md, `/gsd:transition`, `/gsd:complete-milestone`) references a now-read-only project. This is not immediately catastrophic IF GSD is only used for human-readable planning (i.e., you invoke it manually, not in CI), but if any automation depends on it, **Phase 7 is blocked until you resolve this**. The Open GSD continuation project is actively maintained, but it's a fork — you'd need to vet compatibility and update any hardcoded assumptions about gsd-build URLs/versions.

**The MCP stateless shift is the other big architectural trend.** It's forward-compatible (not a breaking change this week), but it signals where the ecosystem is heading: simpler, more HTTP-native, less state management. This is good for your distributed agent execution model (ace-linux-1, ace-win-1, licensed boxes all calling out to stateless MCP services).

**Anthropic's orchestration primitive is the most actionable win.** If you're planning Phase 7's cross-review harness, you can now use a first-class Anthropic orchestration layer instead of manually stitching Claude/Codex/Agy subagent calls together. The persistent events + shared filesystem mean each review round (r1, r2, r3) can see what prior rounds found — no manual context-rebuilding. This is exactly what your `feedback_r3_inline_loop_break_pattern` and `feedback_cross_provider_review_payoff` memories are trying to achieve.
