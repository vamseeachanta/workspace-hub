# Research: skill-design — 2026-09-12

## Key Findings

- **Claude skill authoring now has five formalized patterns: routing-rule description (specific enough to trigger at the right moment), deterministic code for deterministic work (scripts > LLM for parsing/validation), lean SKILL.md with detail in companion files (loaded on demand), one clear job per skill (not multi-workflow), and concrete worked examples rather than abstract rules.** Bloated instruction files cause LLM instruction-ignoring wholesale rather than selective filtering. Research confirms that workspace-hub's current skill governance framework (Explanatory Output Style, must-fire rules in SHARED_SOUL.md) aligns with this pattern. → [Skill authoring best practices — Claude Platform Docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) | [14 Best Claude Code Skills for Developers in 2026](https://www.firecrawl.dev/blog/best-claude-code-skills)

- **Agent Skills specification has standardized the SKILL.md format as a cross-platform protocol, with A2A agent-agent discovery/delegation/state-exchange protocol and bind.md operational boundaries (token budgets, max turns, quality gates) as load-bearing conventions (not suggestions).** The A2A specification defines how agents discover capabilities via Agent Cards, negotiate task delegation, stream progress, and return results. Standardized coordination enables ecosystem portability. → [Safe Bilevel Delegation (SBD): A Formal Framework for Runtime Delegation Safety in Multi-Agent Systems](https://arxiv.org/pdf/2604.27358) | [Swarm Skills: A Portable, Self-Evolving Multi-Agent System Specification for Coordination Engineering](https://arxiv.org/html/2605.10052v1) | [How to Build Multi-Agent Systems: Complete 2026 Guide - DEV Community](https://dev.to/eira-wexford/how-to-build-multi-agent-systems-complete-2026-guide-1io6)

- **Progressive disclosure reached Trial status (April 2026) with measured context reduction: 94.4% vs. loading all instructions, 98.8% vs. instructions + scripts.** Implementation loads lightweight discovery phase, determines relevant domain, retrieves specific instructions on-demand (RAG pattern). Skill tools load SKILL.md only when skill becomes relevant, load companion files only as needed. → [Progressive context disclosure | Thoughtworks Technology Radar](https://www.thoughtworks.com/radar/techniques/progressive-context-disclosure) | [Is Progressive Disclosure All You Need for Long-Context Agents?](https://arxiv.org/html/2607.17598v1) | [Progressive Disclosure in AI Agents — MindStudio](https://www.mindstudio.ai/blog/progressive-disclosure-ai-agents-context-management)

- **Skill testing and evaluation now follow a formalized staging progression: offline evaluation on curated/adversarial test sets → historical replay against real past cases → simulation of what-if scenarios → shadow mode alongside live process → supervised canary execution (5% traffic, 24-48 hour monitoring with error rate/latency/satisfaction/tool-usage deltas before full promotion).** Frameworks (Skill-Tester, SkillRouter) jointly measure utility and safety. No single metric sufficient; select per domain. AI-specific canaries require 2–48 hours soak vs. 10 minutes for classical software. → [AI Agent Evaluation (2026): Metrics, Frameworks, and Production Failures](https://www.morphllm.com/ai-agent-evaluation) | [Canary Deployment for AI Models: A 2026 Guide](https://mlflow.org/articles/what-is-canary-deployment-ai) | [How to Build an Agent Evaluation Framework With Metrics, Rubrics, and Benchmarks](https://galileo.ai/blog/agent-evaluation-framework-metrics-rubrics-benchmarks)

- **Skill composition patterns in production (serial, parallel, conditional, recursive) combined with registry pattern (embedded in Skill tool description, visible without consuming context) and hot-swap capability (SKILL.md updates take effect on next invocation, no restart) deliver measured gains: 30–50% reduction in planning errors, 16+ percentage point improvement in task completion, 3–8x context budget efficiency.** The combination of progressive disclosure + modular composition + SKILL.md open standard is the dominant production pattern for 2026. → [Generative Skill Composition for LLM Agents](https://arxiv.org/pdf/2606.32025) | [9 MCP Production Patterns That Actually Scale Multi-Agent Systems (2026)](https://dev.to/dohkoai/9-mcp-production-patterns-that-actually-scale-multi-agent-systems-2026-3o5j) | [Agent Skill Composition: The Architecture of Modular AI Capabilities](https://zylos.ai/research/2026-05-12-agent-skill-composition-modular-capability-architecture/) | [Introducing Agent Skills Registry in TrueFoundry](https://www.truefoundry.com/blog/introducing-skills-registry-reusable-agent-skills-for-production-ai-systems)

`★ Insight ─────────────────────────────────────`

**This week's skill-design research surfaces a convergence: five independent research/engineering surfaces (Claude docs, A2A protocol, progressive disclosure, skill testing/eval, composition patterns) have all arrived at overlapping recommendations that validate workspace-hub's prior design directions while adding concrete, measurable evidence and ecosystem-standardized protocols.**

**The core insight:** Prior research (2026-09-05) was directionally correct but under-specified. This week adds:

1. **Five formalized patterns** — not abstract guidance, but a checkable scorecard
2. **Standardized protocols** — A2A + bind.md, not bespoke coordination logic
3. **Measured quantification** — 94.4%/98.8% context reduction, 30–50% planning error reduction, not just "this works"
4. **Maturity signals** — Trial status (progressive disclosure April 2026), widespread production adoption (hot-swap, composition patterns)
5. **Concrete operational advantages** — hot-swap capability, staged testing progression, canary guidance

**For Phase 7, v1.1, and Phase 999.4:** the research substrate is now both validated (works at scale) and standardized (ecosystem protocols emerge). This week's findings can be promoted from "recommendations" to "implement per ecosystem standard" — which is a different confidence level.

**The decision-relevant finding:** The five-pattern skill audit (v1.1) should replace prior constraint-repetition audit. Patterns are higher-fidelity and more actionable. Similarly, Phase 7 should adopt A2A + bind.md explicitly (not as a "pattern we discovered"), because standardization enables future portability and cross-provider interoperability.

**The honest assessment:** workspace-hub's design trajectory (skills as modular, composable, load-on-demand capability packages with explicit coordination protocols) is aligned with the broader ecosystem's convergence this week. No course corrections required; phase execution can proceed with confidence that the underlying architecture is proven and standardized.
