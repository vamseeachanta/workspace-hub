# Research: skill-design — 2026-08-08

## Key Findings

1. **Agent Skills ecosystem now indexes 280,000+ publicly available skills (Feb 2026), but composition/coordination remains the critical bottleneck.** The challenge is not building individual skills but orchestrating them—without explicit skill-to-skill coordination and composition primitives, most skills remain underused and the ecosystem fails to deliver multi-skill workflows. **Directly relevant:** workspace-hub's 50+ skill families are similarly siloed; a formal composition/handoff mechanism (e.g., skills that explicitly delegate to downstream skills, shared state surfaces) would unlock multi-skill chains beyond single-skill activation. → [Organizing, Orchestrating, and Benchmarking Agent Skills at Ecosystem Scale](https://arxiv.org/pdf/2603.02176) | [The Orchestration Era: Why the AI Agent Workspace is the Definitive Business Pivot of 2026](https://worldbusinessoutlook.com/the-orchestration-era-why-the-ai-agent-workspace-is-the-definitive-business-pivot-of-2026/)

2. **Three-layer AGENTS.md/SKILL.md/DESIGN.md hierarchy is now industry-standard (not workspace-hub-specific pattern).** The 2026 convergence on explicit three-layer split (orchestration ↔ skill instances ↔ design system) validates workspace-hub's SHARED_SOUL.md → SOUL.runtime.md → .claude/skills/ topology. Progressive disclosure is now formalized: load lightweight metadata (name/description) at startup; load full instructions only on skill activation; load companion resources on-demand. **Directly relevant:** workspace-hub's Skill loader already implements this, but the pattern description in `.claude/skills/coordination/issue-planning-mode/SKILL.md` and others could explicitly name the three-tier discipline to make composition/handoff surface visible to agent authors. → [CLAUDE.md vs AGENTS.md vs SKILL.md (2026): Which Agent Context File Owns What](https://medium.com/data-science-collective/claude-md-vs-agents-md-vs-skill-md-which-file-owns-what-in-2026-13859378f56a) | [AGENTS.md, SKILL.md, DESIGN.md: How AI Instructions Split into Three Layers](https://dev.to/aws-builders/agentsmd-skillmd-designmd-how-ai-instructions-split-into-three-layers-d0g)

3. **Skill Coverage metric (2026) measures which constraints from skill documents actually become observable in agent execution, distinguishing not-covered from Pass vs. Fail.** This closes an evaluation gap: current benchmarks are binary (skill works or doesn't), but skill-coverage tracks **which documented behaviors the agent actually follows** (or breaks). Useful for finding skills that are implemented but not invoked, or invoked but not fully respected. **Directly relevant:** workspace-hub's cross-review gates (APPROVE/MINOR/MAJOR verdicts) already capture defect verdicts, but no systematic measurement of whether executed skills matched their own documented constraints. Phase 7 solver-verification gate + Phase 999.4 autoresearch (both in ROADMAP.md) would benefit from skill-coverage evaluation to measure whether solver/autoresearch skills are actually respecting their boundaries. → [Agent Skill Evaluation and Evolution: Frameworks and Benchmarks](https://arxiv.org/pdf/2606.11435) | [Skill Coverage: A Test Adequacy Metric for Agent Skills](https://arxiv.org/pdf/2606.20659)

4. **Anthropic's official skill authoring now emphasizes: write descriptions as "pushy" routing rules (when to use, not how), single responsibility, behavioral evaluation over deterministic testing, and software-engineering principles (low coupling, separation of interface/implementation).** Claude under-triggers skills by default; descriptions must include both **what** the skill does and **when** Claude should activate it. This mirrors workspace-hub's existing `.claude/skills/*/SKILL.md` structure but formalizes the anti-pattern: skills overloaded with multiple responsibilities, or described passively ("this skill handles X") rather than actively ("use this skill when Y condition is true"). **Directly relevant:** audit a sample of workspace-hub's 50+ skills for routing-rule clarity; if many lack explicit "when to use" triggers, a skill-description refresh (grouped by domain, e.g., coordination vs. research vs. infrastructure) would improve agent selection accuracy. → [Authoring Agent Skills: A Software-Engineering Approach](https://arxiv.org/html/2607.25032v1) | [Skill authoring best practices — Claude Docs](https://www.beri.net/learning/claude-docs-skill-authoring-best-practices)

5. **Multi-agent orchestration shifted from "tool" to "workspace" as the atomic unit (2026).** The industry pivot is from individual agents using individual tools to **coordinated teams of specialized agents (each with own model/prompt/tools) executing in parallel on shared workspace state**. Anthropic's Agent SDK (May 2026) shipped this primitive. **Directly relevant:** workspace-hub's current multi-provider cross-review pattern (Claude r1 → Codex r2 → Agy r3, per `model-routing.md`) is this specialized-agent composition model, but it's stitched together manually via subagent tooling. The formalization as "orchestration workspace" (shared filesystem, persistent event log, role-based agent delegation) directly applies to Phase 7's solver-verification gate and Phase 999.4's autoresearch multi-cycle iteration. → [The Code Agent Orchestra - what makes multi-agent coding work](https://addyosmani.com/blog/code-agent-orchestra/) | [Multi-Agent AI Orchestration Guide & 2026 Updates](https://www.codebridge.tech/articles/mastering-multi-agent-orchestration-coordination-is-the-new-scale-frontier)

`★ Insight ─────────────────────────────────────`

**Workspace-hub is architecturally ahead of the 2026 consensus on skill design.** Three-layer topology, progressive disclosure, behavioral evaluation — you already have these. The gap is not architecture but **observability and composition.** You have 50+ working skills but no systematic way to measure whether they're being triggered correctly (skill coverage) or whether they coordinate across domain boundaries (composition protocol).

**The orchestration-workspace shift is your biggest signal.** The industry consensus (Anthropic's May 2026 SDK, Addy Osmani's analysis, Kimi's platform survey) is that multi-agent coordination is the frontier, not single-agent capability. Workspace-hub's existing multi-provider cross-review (Claude r1 → Codex r2 → Agy r3) **is this pattern**. Phase 7's design should lean into orchestration primitives instead of stitching subagents manually — this buys formal event tracking, role-based dispatch, and audit trails that make the "who did what" trail visible for compliance/verification.

**Skill coverage is the under-recognized evaluation metric.** You gate on code coverage (test ratio) and verdict verdicts (APPROVE/MAJOR), but not on whether executing agents actually **respect their own skill constraints**. Example: if a skill says "never mutate main without approval," does the agent actually check? Skill-coverage eval would catch violations. For Phase 7's solver-verification gate, this becomes load-bearing: a solver skill that *claims* to verify lock status is worthless if the agent doesn't actually invoke that check.
