# Research: skill-design — 2026-08-29

## Key Findings

1. **Claude skill authoring meta-pattern formalizes repetition of quality expectations (2026 Claude Docs update) — success pattern requires stating output constraints at multiple points in instructions, not once, combined with context-aware lazy loading (SKILL.md metadata pre-loaded, full content on-demand).** This is a formalization of the Claude A/B/expert pattern from prior research with a specific implementation detail: system-prompt engineering treats repetition as intentional (combats tendency to "good enough" output), and Claude tooling itself loads instructions lazily to preserve context budget. **Directly relevant:** workspace-hub's 50+ skills should audit whether critical constraints (solver-lock verification, state validation) are repeated at multiple decision points rather than stated once. → [Skill Authoring Best Practices — Claude Platform Docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)

2. **Four new skill evaluation frameworks emerged post-SkillsBench (Aug 2026): Skill-Tester (utility + safety joint measure), SKILLCRAFT (tool composition reuse across tasks), SKILLLEARN-BENCH (20 skill-dependent tasks, 15 sub-domains), and trace-based eval spans (tool calls, retrieval, reasoning, planner outputs, sub-agent handoffs).** Prior research (08-22) identified SkillsBench as the only public behavior-validation benchmark; August research surfaces four complementary frameworks addressing specific gaps (safety, reuse, multi-domain, traceability). Trace-based evals are particularly relevant for Phase 7 (connects failed quality scores to exact execution step). **Directly relevant:** Phase 7 smoke tests should adopt trace-based evaluation to map failures to specific agent-execution phases (plan → dream → validate → execute → reflect), not just binary pass/fail. → [Agent Skill Evaluation and Evolution: Frameworks and Benchmarks](https://arxiv.org/html/2606.11435v1) | [A Framework for Evaluating Agentic Skills at Scale](https://arxiv.org/html/2606.17819v1)

3. **Six standardized multi-agent skill routing protocols now documented in peer-reviewed literature (Aug 2026): SkillRouter (~80K-skill pool scale), TCAndon-Router (natural-language reasoning chains before prediction), MCP (Anthropic's standardization), A2A (Google 2025), ANP (Chang 2024), Agora (Marro 2025) plus FIPA-ACL/KQML linguistic standards.** Prior research (08-22) flagged implicit routing assumptions (Fable for planning, Opus for execution); August research surfaces explicit formal protocols with proven skill-pool scales (80K tested). **Directly relevant:** workspace-hub's model-routing.md (currently implicit assumptions) should incorporate SkillRouter protocol for T3 cross-review and Phase 999.4 autoresearch delegation. SkillRouter's reranking approach (vs. simple deterministic routing) maps directly to prior feedback about reducing routing mismatches in multi-provider scenarios. → [SkillRouter: Skill Routing for LLM Agents at Scale](https://arxiv.org/html/2603.22455) | [Multi-Agent AI Orchestration Guide & 2026 Updates](https://www.codebridge.tech/articles/mastering-multi-agent-orchestration-coordination-is-the-new-scale-frontier)

4. **AI agent skill governance layer emerged as mandatory (post-Feb 2026): Singapore IMDA Model AI Governance Framework for Agentic AI (Jan 2026) requires verifiable digital identity + audit trail per agent; NIST AI Agent Standards Initiative (Feb 2026) addresses agents-as-service-accounts identity gap; Berkeley CLTC Risk-Management Standards Profile (Feb 2026) is the first comprehensive agentic-AI risk taxonomy. NIST AI Agent Interoperability Profile targeted for Q4 2026.** This governance layer did NOT exist in prior research scope. workspace-hub's SHARED_SOUL.md + agent routing rules are currently governance-by-convention (Hard Gates, Must-Fire Rules); formal governance frameworks now exist and Q4 2026 deadline is approaching. **Directly relevant:** v1.1 skill governance should adopt IMDA identity cards (model family + quality metrics) and Berkeley risk taxonomy for new skill deployment decisions. Phase 7 should document audit trails for solver-verification agent decisions (which model ran, why, with what constraints). → [Agentic AI Governance Frameworks 2026: Risks, Oversight, and Emerging Standards](https://hackernoon.com/agentic-ai-governance-frameworks-2026-risks-oversight-and-emerging-standards) | [Toward Pre-Deployment Assurance for Enterprise AI Agents: Ontology-Grounded Simulation and Trust Certification](https://arxiv.org/pdf/2606.04037) | [Deontic Policies for Runtime Governance of Agentic AI Systems](https://arxiv.org/pdf/2606.19464)

5. **Progressive disclosure concrete implementation pattern (Pydantic AI 2.0, Aug 2026) formalizes conditional tool registration + two-tier API knowledge (Tier 1 activation/syntax, Tier 2 reference/detail), achieving 98.7% context-budget reduction (150K → 2K tokens) in real agents.** Prior research (08-22) flagged progressive disclosure as an area of interest; August research surfaces specific implementation (Pydantic AI conditional tool loading) and concrete ROI (98.7% efficiency gain). This is not theoretical — it's production-deployed and measurable. **Directly relevant:** workspace-hub skills (especially research/, infrastructure/) should adopt two-tier knowledge structure: SKILL.md (Tier 1 activation) for CLI syntax and decision trees, `SKILL-reference/` folder (Tier 2) for detailed tooling docs. Phase 999.4's autoresearch skill should test this pattern (researcher skill with Tier 1 routing + Tier 2 model-selection reference). → [Progressive Disclosure in AI Agents: How to Load Context Without Killing Output Quality](https://www.mindstudio.ai/blog/progressive-disclosure-ai-agents-context-management) | [Progressive tool loading is the new MCP context pattern](https://usewire.io/blog/progressive-tool-loading-mcp-context-pattern/)

`★ Insight ─────────────────────────────────────`

**This week's skill-design research surfaces four major findings that collectively represent a governance + implementation maturation wave across the AI agent ecosystem.**

The 2026-08-22 research (7 days ago) captured the strategic landscape (Control Tuning patterns, SkillsBench, LDP, hierarchical delegation). This week's research operationalizes it:

1. **Governance governance emerged as a distinct, mandatory layer** — IMDA identity cards, Berkeley risk taxonomy, NIST standards. workspace-hub's current governance (SHARED_SOUL.md rules) is policy-by-convention, which works at small scale but doesn't map to formal identity/audit-trail/risk frameworks that regulators now expect. This is not optional post-Q4 2026 when NIST publishes its interoperability spec.

2. **Evaluation frameworks moved from theoretical (SkillsBench) to operational (four new frameworks + trace-based spans).** Phase 7's smoke tests can now use trace-based evaluation to map failures to exact execution steps, not just "pass" or "fail." This is a material upgrade to diagnostic capability.

3. **Routing protocols formalized (SkillRouter) with proven scale (80K-skill pool).** The implicit assumptions in model-routing.md (Fable for planning, Opus for execution) are fine for 3 models; formalizing with SkillRouter's reranking + NL reasoning makes it defensible at scale and auditable.

4. **Progressive disclosure moved from interesting idea to production pattern (98.7% efficiency gain).** This is the operational lever to keep Phase 999.4's autoresearch skill complexity from spiraling (lazy-load model-selection reference, conditional tool registration).

**The honest assessment:** workspace-hub's skill governance is currently sound for v1.1 (Hard Gates, Must-Fire Rules work), but will need formalization by v1.2 to survive regulatory/enterprise scrutiny (IMDA cards, Berkeley taxonomy, NIST interop). The window to plan this is Q1–Q2 2027; the decision to adopt should be made by Q4 2026 (when NIST drops its profile). Not blocking v1.1, but it's now a hard dependency for Phase v1.2+.
