Category D (structural/semantic, blocking):
  - missing or extra top-level OrcaFlex sections

### Spec→modular coverage (r2, Finding #6)

Spec→modular is **explicitly out of scope for this plan**. Rationale:
- spec→single exercises the entire forward-generation stack (spec parsing, intermediate model, OrcaFlex-native emission) in a single deterministic output file that is the easiest to diff.
- spec→modular is a consumer of the same intermediate model (SpecToModularConverter uses the same pipeline). Proving fidelity at spec→single therefore validates the intermediate stages; the modular emission is a presentational variant.
- A follow-on plan will add `test_a05_spec_to_modular_fidelity` using the existing `test_round_trip.py` pattern.
- Acceptance criterion (below) is narrowed to spec→single only to avoid scope creep and keep the fixture-coverage claim honest.
