Compliance alert interpretation

Summary

A zero compliance rate requires the reviewable count to be interpreted. An empty review population is NOT_EVALUATED for alert purposes. A population containing unreviewed commits can produce a critical alert. The alert wrapper validates the dashboard JSON before applying the thresholds.

Inputs and method

The inputs are the top-level dashboard fields total_commits, skipped, reviewable, reviewed, unreviewed, compliance_rate, threshold and verdict, plus the dashboard exit status. Counts shall be nonnegative integers; booleans, missing counts and duplicate JSON keys are rejected.

The count identities are total = skipped + reviewable and reviewable = reviewed + unreviewed. For a positive reviewable count, the integer percentage is floor(100 × reviewed / reviewable). These definitions are taken from scripts/enforcement/compliance-dashboard.sh, function main. The dashboard retains a numerical zero and PASS when the denominator is empty; the wrapper explicitly records NOT_EVALUATED and issues no alert.

A malformed report, inconsistent count or verdict, or unexpected exit status produces a nonzero wrapper exit and an ERROR log entry. It does not produce a compliance alert. The scheduling system must surface the execution failure; an execution error is not evidence of a compliant population.

Worked examples

The examples are synthetic hand calculations based on the alert population reported in issue 3830 and the formula above. They are not historical review evidence.

Empty review population7700 Reviewable = 7 − 7 = 0; division is undefined; NOT_EVALUATED; no alert.
Missing reviews7007 Reviewable = 7; floor(100 × 0 / 7) = 0%; critical alert.
Pass boundary5041 Reviewable = 5; floor(100 × 4 / 5) = 80%; no alert.
Table 2. Independent arithmetic distinguishes zero from an empty denominator.

The alert thresholds are those published in issue 3830, “Thresholds”, dated 2026-09-07: below 30% critical; 30% to below 50% high; 50% to below 80% medium; 80% or higher no alert. They are repository policy, not engineering acceptance limits. A configured dashboard threshold still governs its own PASS/FAIL verdict; alert severity uses the published alert thresholds.

Operation and tests

DRY_RUN=true bash scripts/enforcement/compliance-cron.sh generates local logs and an alert preview, when applicable, without any GitHub calls. Without dry-run mode, the existing publication behavior remains enabled. The existing weekly issue deduplication is unchanged.

tests/enforcement/test_compliance_cron.py exercises the empty population, positive denominators, severity boundaries, nested drift verdicts, inconsistent and malformed reports, and exit status disagreement. Fixtures use disposable roots and stub external commands. Tests also execute the shipped dashboard for empty and all-skipped histories.

Limits and next evidence

Issue 3830 reports seven total commits, zero reviewed and zero unreviewed, with PASS. It omits the reviewable and skipped fields. The original daily JSON and commit window are required to establish the historical population. This change does not establish that historical reviews were completed or that bypasses did not occur. Commit classification and the dashboard's review-evidence heuristics are unchanged. Weekly report aggregation remains a separate consumer and is not changed by this correction.
