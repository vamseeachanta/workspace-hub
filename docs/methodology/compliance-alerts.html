Compliance alert interpretation

Summary

The daily alert consumes validated top-level dashboard JSON. An empty reviewable set is unevaluated; it does not establish failed review compliance. Invalid reports produce an error exit and no compliance issue. A valid measured shortfall retains the existing alert thresholds.

Inputs and method

The report requires nonnegative integer counts for total_commits, skipped, reviewable, reviewed, and unreviewed. Counts shall satisfy both identities:

total_commits = skipped + reviewable
reviewable = reviewed + unreviewed

For a positive denominator, the dashboard rate is floor(100 * reviewed / reviewable). The percentage scale and rate basis follow the repository's Compliance Dashboard Guide, How Compliance is Calculated; integer truncation follows scripts/enforcement/compliance-dashboard.sh, Calculate rates. The reported threshold shall be an integer between zero and one hundred.

The top-level verdict shall agree with that rate and threshold. The dashboard exit status shall be zero for PASS and one for FAIL. Other execution statuses, missing JSON, duplicate keys, inconsistent counts and invalid numeric types stop alert evaluation with an error. Human-readable rate lines and nested event verdicts are excluded from metric extraction.

Worked example

Inputs are synthetic counts chosen to reproduce the alert's empty-denominator condition; they are not a reconstruction of historical commit evidence.

{
  "total_commits": 7,
  "skipped": 7,
  "reviewable": 0,
  "reviewed": 0,
  "unreviewed": 0,
  "compliance_rate": 0,
  "threshold": 80,
  "verdict": "PASS"
}

Both count identities hold: 7 = 7 + 0 and 0 = 0 + 0. The denominator is zero, so the rate cannot be calculated. The legacy dashboard's numeric zero is retained for compatibility; the alert interprets it as NO_REVIEWABLE, logs that compliance is not evaluated, and creates no issue. This disposition does not assert that any commit has qualified review evidence.

The thresholds remain unchanged: below 30% critical, from 30% to below 50% high, from 50% to below 80% medium, and at least 80% no alert. These are repository workflow criteria from that issue, not engineering acceptance limits from a standard.

Verification

tests/enforcement/test_compliance_cron.py exercises the parser and wrapper in disposable repositories, with synthetic dashboard output and a GitHub sentinel. A real-dashboard empty-repository case checks producer compatibility. Dry runs return before any GitHub call, and malformed inputs cannot publish alerts.

Known limits and way forward

Commit classification and review-evidence heuristics are unchanged. Historical compliance, including the later unreviewed commit recorded in issue 3813, is not established by these regressions. Historical review artifacts shall be checked before resolving that issue. Weekly aggregation retains its existing zero-denominator presentation; this change addresses daily alerts only. A report-validation failure requires investigation of the local daily log rather than a misleading compliance percentage.
