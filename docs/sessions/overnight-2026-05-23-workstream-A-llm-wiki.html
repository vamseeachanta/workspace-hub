4. Pipeline / process notes

What worked

  • 3 parallel write-only subagents per batch at the documented cap-3 concurrency. Each subagent self-contained, primed with: PDF text path, output path, frontmatter template, body-section template, hard rules (no fabrication, verbatim section IDs, no PDF copying). Total: 9 subagent dispatches, all succeeded first try, all writes verified landed via ls per feedback_subagent_write_phantom.
  • Pathspec-form commits (git commit -- <file>) preserved the parallel SIROCCO session's staged b1528 file across 10 commits.
  • OCR fallback chain (pdftotext → PyMuPDF 300 DPI → tesseract --psm 6) recovered 2 image-PDF sources cleanly enough to extract structured content; OCR provenance flagged in ocr_note frontmatter field as defensive measure.
  • PDF→text extraction in 8-way parallel bash completed in ~30 seconds total wall-clock; subsequent subagents read from cheap text files rather than the 7.1 GB raw PDF corpus.

What didn't work — and the fix

  • Chained git add && git commit across multiple files in a single bash call — first instance hung on a stuck git add after 19 min in D state. The remaining commits in the chain were never attempted because && exits on first failure. Fix: atomic per-file bash calls (separated by ; not &&) with explicit error tolerance per step.
  • Background git log and git status kept hanging under heavy parallel-git load. Fix: when needed for verification, read .git/HEAD + .git/refs/heads/main + .git/packed-refs directly (no lock-dependent commands).
