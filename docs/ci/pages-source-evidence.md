# Static Pages source evidence

The Pages builder identifies the exact Markdown input of each wrapped page and
states its limits. Shared skip navigation makes the main content reachable from
the first keyboard control. An isolated output option allows repeatable checks
without generating files in the checkout.

## Scope and method

[The builder](../../scripts/build_pages.py) retains its explicit `PAGES` and
`HTML_PAGES` allowlists. Only Markdown pages rendered through the shared shell
gain the new source panel. Standalone HTML and manifest-enumerated reports are
copied without altering their bytes; their authors retain responsibility for
their source and data-limit disclosures. Unlisted files are not discovered.

For a Markdown source, the builder reads the bytes once, computes
`digest = SHA256(source_bytes).hexdigest()`, decodes the same bytes as UTF-8, and
renders the result. The source path is escaped as text. No timestamp or network
request participates in this method. SHA-256 is specified in
[RFC 6234 (2011), sections 4.1 and 6.2](https://www.rfc-editor.org/rfc/rfc6234#section-6.2).
The checksum identifies the input; it is neither a signature nor a validation of
the claims in that input. It excludes the renderer, stylesheet and linked pages.
Reproducing the whole page also requires the corresponding repository revision.

The shared shell places a skip link before the header and targets a focusable
main landmark. Navigation has an accessible label. The shared
[stylesheet](../assets/brand.css) makes the skip link visible on focus and wraps
long source digests. These markup expectations follow
[W3C WCAG 2.2 Technique G1](https://www.w3.org/WAI/WCAG22/Techniques/general/G1.html).
Structural tests do not establish browser or assistive-technology conformance.

## Worked example

Input: an allowlisted file `guide.md` contains exactly the ASCII text `abc`,
without a newline. Its title is `Guide` and its output slug is `guide`.

Method: read the source bytes once, compute their SHA-256 digest, render the
Markdown, and append its source path, digest and documentation-limit disclosure.

Expected answer: `guide.html` contains a paragraph with `abc`, the source label
`guide.md`, and the following digest:

```text
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

The expected digest is the published `SHA256` / `TEST1` vector in
[RFC 6234 (2011), section 8.5](https://www.rfc-editor.org/rfc/rfc6234#section-8.5).
It is not generated by the code under test. Appending a newline changes the input
and therefore does not match this vector. The rendered page explicitly says that
a static documentation snapshot does not establish deployment status, live
algorithm results or outreach activity.

The executable example is
[test_build_pages_evidence.py](../../tests/test_build_pages_evidence.py).
Its manually enumerated fixture output is `guide.html`, `proof.html`, and
`assets/style.css`. An unlisted Markdown file is excluded. A separate fixture
checks manifest enumeration and exact copying, including line-ending bytes.

## Local verification

Choose a fresh output directory outside the checkout. The destination is not
cleaned, so reusing a directory can retain stale files from a previous build.
The default remains the ignored `public` directory for the existing Pages
workflow. For an isolated build:

```sh
python scripts/build_pages.py --output-dir "$TMPDIR/pages-output"
```

Run the new contract tests and the existing builder and brand tests:

```sh
uv run --no-project --with pytest python -m pytest \
  tests/test_build_pages_evidence.py tests/test_build_pages_a11y.py \
  tests/test_build_pages_brand.py tests/test_build_pages_sessions.py \
  tests/enforcement/test_check_brand_drift.py -q -p no:cacheprovider
uv run --no-project --with ruff ruff check \
  scripts/build_pages.py tests/test_build_pages_evidence.py
```

The enforcement workflow runs the focused tests on pull requests. A local build
and structural assertions do not establish hosted publication or runtime status.
