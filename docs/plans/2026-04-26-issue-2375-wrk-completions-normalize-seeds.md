## Pseudocode

### `normalize_wrk_completions.py`
```
function main():
    repo = git_root()
    jsonl_in  = repo / "knowledge-base/wrk-completions.jsonl"
    yaml_out  = repo / "knowledge/seeds/wrk-completions.yaml"
    report    = repo / "docs/reports/wrk-completions-normalization-report.md"

    records  = load_jsonl(jsonl_in)        # 420 records, three source cohorts
    rules    = load_categorize_rules()     # reuse RULES from categorize_uncategorized.py

    entries  = []
    stats    = {"total": 0, "by_source": Counter(), "fields_filled": Counter(),
                "unrecoverable": []}

    for rec in records:
        stats["total"] += 1
        stats["by_source"][rec["source"]] += 1

        if rec["source"] == "memory-migration":
            entry = normalize_raw_record(rec, rules)   # regex extract title/sha/body
        else:
            entry = normalize_structured_record(rec)   # field-rename pass only

        for k, v in entry.items():
            if v not in (None, "", [], {}):
                stats["fields_filled"][k] += 1

        if not entry["title"] and not entry["mission"]:
            stats["unrecoverable"].append(rec["id"])

        entries.append(entry)

    if not args.dry_run:
        write_yaml_atomic(yaml_out, {"entries": sorted(entries, key=lambda e: e["id"])})
        write_report(report, stats)

function normalize_raw_record(rec, rules):
    raw = rec["raw"]
    m = re.match(r'^- \*\*(WRK-\d+) ARCHIVED\*\*(?: \(([0-9a-f]+)\))?:\s*(.+)$', raw)
    title_part = m.group(3) if m else raw
    title = title_part.split(" — ")[0].strip(" —`")  # title before em-dash
    body  = title_part[len(title):].lstrip(" —`")[:500]
    cat, sub = apply_rules(title.lower(), rules)
    return {
        "id": rec["id"], "type": "wrk",
        "category": cat, "subcategory": sub,
        "title": title, "completed_at": None,         # not recoverable from raw
        "commit": m.group(2) if m else None,
        "source": "memory-migration",
        "context": body,
        "patterns": [], "follow_ons": [],
        "artifacts": [], "tests": None, "documents_read": [], "gh_issue": None,
    }

function normalize_structured_record(rec):
    return {
        "id": rec["id"], "type": "wrk",
        "category": rec.get("category") or "uncategorized",
        "subcategory": rec.get("subcategory") or "",
        "title": rec.get("title", ""),
        "completed_at": rec.get("archived_at"),
        "commit": None,                                # not in JSONL today
        "source": rec.get("source"),
        "context": rec.get("mission", ""),
        "patterns": rec.get("patterns", []),
        "follow_ons": rec.get("follow_ons", []),
        "artifacts": [], "tests": None, "documents_read": [], "gh_issue": None,
    }
```

### `build_wiki_candidates.py`
```
function main():
    repo   = git_root()
    yaml_in   = repo / "knowledge/seeds/wrk-completions.yaml"
    yaml_out  = repo / "knowledge-base/wiki-candidates.yaml"

    seed = load_yaml(yaml_in)
    candidates = []

    for entry in seed["entries"]:
        score, reasons = score_candidate(entry)        # 0..3
        if score >= 2:
            candidates.append({
                "source_wrk": entry["id"],
                "source_path": "knowledge/seeds/wrk-completions.yaml",
                "title": entry["title"],
                "wiki_target_domain": route_domain(entry),  # engineering / marine / naval / personal / process
                "extend_or_create": "extend" if existing_wiki_page_for(entry) else "create",
                "score": score, "reasons": reasons,
                "patterns": entry.get("patterns", []),
                "status": "candidate",                  # candidate|reviewed|promoted|rejected
            })

    write_yaml_atomic(yaml_out, {
        "generated_at": utcnow_iso(),
        "schema_version": "1.0.0",
        "candidates": sorted(candidates, key=lambda c: -c["score"]),
    })

function score_candidate(entry):
    # Mirrors #2370 rubric: reusable methodology, stable decision value, evidence richness
    score, reasons = 0, []
    if entry.get("patterns"):
        score += 1; reasons.append("has-patterns")
    if entry.get("category") in DURABLE_CATEGORIES:    # engineering, ai-orchestration, ci, data, etc.
        score += 1; reasons.append("durable-category")
    if entry.get("artifacts") or entry.get("commit"):
        score += 1; reasons.append("has-evidence")
    return score, reasons

function route_domain(entry):
    cat = entry.get("category", "")
    if cat == "engineering":
        return route_engineering_subdomain(entry.get("subcategory", ""))
    if cat in ("ai-orchestration", "ci", "automation"):
        return "process"
    if cat == "personal":
        return "personal"
    return "general"
```

## Risks and Open Questions

- **Risk — silent data loss on memory-migration cohort:** the regex must tolerate variations in the legacy raw string (em-dash vs hyphen, no-sha records, missing body). Mitigation: explicit fixture covering each variant + an "unrecoverable" report section that surfaces records the regex could not parse, instead of dropping them silently.
- **Risk — JSONL/YAML drift after this lands:** if `capture-wrk-summary.sh` ever runs on a machine where the YAML hook fails silently, the JSONL and YAML diverge. Mitigation: hook is non-blocking but logs to stderr; a follow-up cron `normalize_wrk_completions.py --reconcile` (out of scope for this issue, scoped to a follow-on) compares JSONL ids vs YAML ids and reports drift.
- **Risk — wiki-candidate routing wrong:** initial routing rule is title/category-driven and may misroute engineering-subcategory entries (hydrodynamics vs OrcaFlex vs cathodic-protection). Mitigation: routing emits a single coarse `wiki_target_domain` (engineering / marine / naval / process / personal / general) plus the original `category`/`subcategory`; finer routing is deferred to the human reviewer at promotion time per #2236 workflow.
- **Risk — seed file size:** 420 entries × ~10 fields × YAML overhead = a non-trivial single file. Mitigation: keep as a single file (matches existing `career-learnings.yaml` convention); revisit sharding only if file exceeds 1 MB.
- **Risk — duplication with #2370 / #2374:** if the wiki-candidate schema diverges from those siblings' candidate schemas, downstream consumers must reconcile three formats. Mitigation: this plan adopts a status vocabulary `{candidate, reviewed, promoted, rejected}` identical to #2374's proposal and a rubric (reusable methodology + stable decision value + evidence richness) compatible with #2370. A follow-on issue can merge the three ledgers; this plan does not pre-empt that decision.
- **Risk — append-hook race:** `capture-wrk-summary.sh` already uses `flock` on the JSONL. The YAML write must use the same lock or its own to avoid concurrent appends from racing terminals. Mitigation: reuse the JSONL lock as a coarse outer lock; YAML append happens inside the same critical section.
- **Open:** Does the YAML seed live under `knowledge/seeds/` (entries-schema convention) or under `knowledge-base/` (cache convention)? Plan picks `knowledge/seeds/` matching #894 architecture; flag for user during approval.
- **Open:** Should `gh_issue` cross-references be best-effort backfilled at normalization time (search closed issues for `WRK-NNN` mentions)? Plan defers this to a follow-on; the field exists, it is None at v1.
