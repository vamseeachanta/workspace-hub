## Identity Contract (§3 compliance)

`doc_key` emitted in retrieval candidates MUST be `sha256:<64-hex>` per §3.
- CLI rejects candidates with non-`sha256:` keys and logs them under `logs/planner-retrieval/skipped-non-conforming-YYYY-MM-DD.jsonl`.
- Conformance check verifies each row in the Retrieval Candidates table carries a `sha256:` prefix; rows with other prefixes → check FAIL.

## Threat Model

**Input surfaces:** issue body (from `gh`), CLI arguments, plan file content.
**Trust boundaries:**
- GitHub issue body is **untrusted** input (could contain prompt-injection). Tool treats as opaque text; does not execute or evaluate issue content.
- Plan file content is **trusted** (git-tracked, reviewed by owners).
- CLI args are trusted (local dev).

**Mitigations:**
- Issue-body handling: no shell interpolation; treated as string throughout.
- `gh_view` auth: relies on existing `gh` CLI auth (token managed by `gh auth login` — already required by ecosystem; this plan does not introduce new secrets).
- Conformance check is read-only on plan files; no writes.
- Audit log path is allowlist-fixed (`logs/planner-retrieval/`); no user-supplied path.

**Threat tests:**
- `test_issue_body_with_shell_metacharacters_safe`
- `test_conformance_check_is_read_only`
- `test_audit_log_path_cannot_be_overridden`

## Deliverable

CLI + conformance check that auto-surface top-K retrieval candidates at Resource-Intel time, enforced via pre-push hook, with `sha256:`-only candidate filtering and auditable bypass-flag logging.

## Pseudocode

```
function retrieve(issue_number, top_k=10):
    issue = gh_view(issue_number)  # untrusted text, treated opaquely
    query = issue.title + " " + issue.body[:500]
    candidates = query_embeddings(query, top_k, layer="both")
    filtered = [c for c in candidates if c.doc_key.startswith("sha256:")]
    if len(filtered) < len(candidates):
        log_non_sha256_skips(candidates - filtered)
    emit markdown block with filtered rows; status column blank (human fills)

function conformance_check(plan_file):
    parse plan markdown
    if no "## Retrieval Candidates" section → FAIL
    for each row:
        if doc_key not startswith "sha256:" and not startswith "md5:" → FAIL
        if status blank → FAIL
        if status starts "REJECTED" without colon-reason → FAIL
    return PASS

function bypass(skip_reason):
    if not skip_reason → exit with clear error
    append to logs/planner-retrieval/bypass-YYYY-MM-DD.jsonl
        {ts, issue, reason, user, hostname}
    proceed with conformance PASS
```
