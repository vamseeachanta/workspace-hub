Operation, receipts and concurrency

The CLI will default to a read-only report. It will require explicit source checkout, source revision, profile, target project, provider and planned external transaction-directory arguments. Report mode will emit JSON to stdout only, distinguishing absent, identical, replaceable preimage, collision and invalid-source states. Shell redirection or a separately specified orchestration path will retain the reviewed report outside shared trees. Unknown profile versions/modes, duplicate YAML keys, unsupported digest-normalization values, empty or unexpected activation sets, ambiguous skill names and unsupported providers will fail closed. This first materializer will support the existing Foundation schema and six-payload boundary, not arbitrary expansion.

The reviewed transaction manifest will bind profile bytes, source revision, source/target roots, provider, complete six-path mapping, actual source digest and each destination preimage as absent or a regular-file digest. Re-running report will not grant authority or change any path. Apply will require an explicit manifest plus --apply; it will re-derive destinations from the profile and validated mapping, not trust arbitrary receipt paths. Root will establish a scoped coordination claim on the isolated adapter subtree and implementation paths, check parallel work and preserve existing dirty canonical files. A held or unavailable claim will stop affected writes.

Source digests will follow the existing profile contract: byte-exact by default; only an entry explicitly declaring sha256_normalization: crlf-to-lf will permit that transformation for comparison. Unknown modes will be rejected. Sources for this transaction will already satisfy their pins; destination writes will preserve the source bytes exactly. Preimage and postimage receipts will always hash actual destination bytes. No inferred LF normalization, HEAD-blob substitution for dirty files, machine git-config edit or broad attributes change will mask drift. Tests will cover Windows-shaped CRLF inputs and declared normalization separately.

All source/profile paths will remain within the explicit owning checkout; all target payload paths will remain within the explicit target project and provider skills subtree. Traversal and absolute values in relative payload-mapping fields, hard-link files, symbolic links, NTFS junctions/reparse points and any uninspectable existing ancestor on affected paths will be rejected before mutation. Explicit absolute source/target/transaction root fields will be permitted and rebound to the CLI's validated roots; the relative-payload prohibition will not prohibit these root declarations. The target tree, including _archive and other nested directories, will be inspected without following link/reparse entries. Duplicate occurrences of one selected skill's frontmatter name outside its intended destination will stop apply; unreadable or link-backed candidate subtrees will be reported as incomplete collision coverage and will stop apply rather than be followed. Unrelated skills will remain untouched. A stale intended target will be replaceable only through its exact reviewed preimage; a mismatch will require a fresh report, not force overwrite. Physical overlap between the canonical source skills subtree and destination skills subtree will stop apply. A single project checkout may contain the disjoint .claude/skills source and .agents/skills destination; Claude fixtures will instead use separate standalone roots.

Apply will validate every source and preimage before staging six file payloads. It will create same-volume temporary files, flush and close them, and use per-file atomic replacement. It will recheck destination ancestry and preimage immediately before each replacement, retain prior bytes and absence markers in a transaction journal outside the discovery tree, and verify all postimages. The six-file set will not be described as filesystem-atomic. An interruption will leave a journal identifying exactly which files need reconciliation. Hostile or uncooperative concurrent filesystem mutation will remain outside the safety claim; the coordination claim and immediate rechecks will reduce ordinary races without claiming compare-and-swap guarantees that the OS interface does not provide.

On failure or requested rollback, the transaction will restore only files still matching its own postimage. It will remove only transaction-created files still matching those hashes and only empty transaction-created directories. It will never recurse-delete a tree, follow a link, or overwrite a later writer. Changed files, uncertain ancestry or rollback errors will stop automatic recovery and leave the journal plus explicit unresolved residue. Prior bytes and partial-transaction diagnostics will remain until reviewed closeout.
