Contract and authority boundary

consumer_event.py will expose a pure normalize_event(event, context) function. The event argument will be raw UTF-8 bytes or text, never an already-decoded dict. It will pass through workflow_receipt.load_json(raw, max_bytes=1048576), preserving duplicate-key rejection and existing depth64/node100000 limits. Its decoded envelope will contain exactly schema_version, provider, event_kind, payload and evidence_reference; version will be 1, provider will be Claude or Codex, and reference strings will remain inert and never be opened. Context will contain only existing workflow request fields and will undergo bounded canonical validation; it will carry no filesystem root or additional approval schema. Invalid encoding, duplicate keys, non-finite values, oversized/deep input, wrong argument types and unknown fields will return unsupported, null request and MALFORMED_EVENT. Unknown version/provider/event kind will return unsupported, null request and UNSUPPORTED_EVENT. Expected validation errors will be converted to these deterministic results; resource exhaustion or implementation defects will not be mislabeled as valid assessments.

The result will contain exactly mapping_status (mapped | needs-context | unsupported), request (the existing workflow request or null), and sorted unique reason_codes (MAPPED_EVENT | MALFORMED_EVENT | UNSUPPORTED_EVENT | INCOMPLETE_EFFECTS | PATH_BINDING_MISMATCH | MISSING_CONTEXT). Mapped will mean structurally mapped, never permitted, approved or authenticated. Every fixture record will carry provenance: conjectural | captured; captured records will bind raw capture digest, provider version, event point/name and transformation notes. The evidence manifest will validate those references independently; an input claim of native provenance will not authenticate itself. Mapping results and unchanged six-field assessment results will be stored under distinct adapter_result and assessment_result keys; their reason-code sets will never be unioned. A required regression will protect this separation.

The pure normalizer will reuse normalize_changed_paths and require both rename endpoints. Only owner-relative lexical paths will be supported in this slice. Event-extracted paths and supplied request paths will agree after normalization; mismatch will return needs-context, null request and PATH_BINDING_MISMATCH. Absolute, drive-qualified, traversal or ambiguous-root paths will not be relativized; they will produce the same unmapped result. The pure mapper will make no filesystem-containment claim and will not resolve symlinks or junctions. Separate disposable harness tests will observe roots, symlink/junction escapes and nonexistent destinations; those observations will never grant trust to event-supplied roots. Captured events requiring absolute-path translation will remain unmapped in this prototype, with native mapping coverage recorded as unavailable or unsupported rather than fabricated.

Write/Edit and structured patch payloads will be tested as explicitly conjectural shapes unless their exact event contract is bound to an independently verified capture. Passing conjectural cases will establish synthetic contract behavior only. Shell, exec and PowerShell events will not be parsed with permissive regexes into routine authorization. Unknown or incomplete shell effects will return needs-context or unsupported. Supplied effects will remain unverified and will not erase, downgrade or contradict extracted effects. Indeterminate shell/exec/PowerShell events will return needs-context, null request and INCOMPLETE_EFFECTS regardless of caller-supplied benign paths, effects or authorization references; no assessment call will occur. Effect disagreement will likewise remain unmapped. Bare command names will never establish complete effects. A combined opaque-command plus forged benign context case will be a required negative test.

The harness will pass mapped requests to the existing workflow_decision.assess function. Its six-field response will remain unchanged. Provider identity, marker age, review verdicts, copied handoffs and receipt equality will not change action authority. Bounded routine work will continue to depend on independently established standing authorization at the orchestrator; substantial scope and consequential actions will require matching explicit approval. An unavailable local authorization transport will remain an explicit limitation, not an opportunity to invent a signed claim or owner identity.
