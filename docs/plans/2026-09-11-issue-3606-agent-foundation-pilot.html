Objective and deliverable

The pilot will allow Claude and Codex to locate the same authoritative resource, report the same readiness/access limitations, and close a routine task without redundant approval or duplicate work. The first deliverable will be a reviewed four-skill profile and its source/lookup contract, proven in an isolated environment before installed-runtime migration.

The architecture reconciliation will be treated as T3; the bounded pilot implementation will be scoped to T2 where its actual change set permits. The plan will use existing issues rather than introduce another local task queue.

Execution sequence

  1. Freeze the pilot boundary. The execution plan will retain the approved human decisions and record exact issue ownership, baseline hashes, source/adapter roots and an isolated worktree. It will enumerate the four-skill dependency closure before selecting installation files.
  2. Reconcile authority. The plan will trace absent contracts through authorized upstream locations and relevant history. A recovered artifact will be validated; otherwise the reconstruction will explicitly reconcile requirements and conflicting consumers.
  3. Approve substantial pilot changes. The human architecture preference will resolve direction only. The exact substantial pilot code/policy plan will require user approval before implementation writes in the following stages. Read-only baseline verification and plan refinement will continue under standing authorization.
  4. Write meaningful failing tests. The implementation will add/readjust fixtures for read-side availability, owner routing and native-skill preservation before code changes. Existing ingestion fallback behavior will remain covered.
  5. Implement the bounded lookup and profile. The work will repair live reference closure and authored loader claims, then generate tested adapters in the isolated pilot. The four capabilities will call existing tools where their interfaces fit.
  6. Validate through both clients. The pilot will run equivalent fixture tasks through Claude and Codex after confirming account access and bounded execution cost. Structural lint will supplement, not replace, observed discovery and result parity.
  7. Review the exact migration diff. The result will include before/after behavior, the installed path manifest, rollback and relevant independent provider review. Live hook or installed-adapter changes will remain a concrete approval step.

Risk, rollback and exclusions

  • The pilot will preserve native .system skills, plugins, existing user configuration and all unrelated skill content. It will not replace a user root or perform bulk archive deletion.
  • Rollback will restore only enumerated pilot-owned files from recorded hashes/revisions and regenerate derived outputs from reverted sources. It will not sweep unrelated working-tree changes into a commit.
  • Model identities will not serve as permission or competence proofs. The pilot will use measured task outcomes and required access.
  • The plan will not infer that private repository visibility grants rights to copy licensed standards.
  • The work will inspect tools before invocation: scripts/coordination/git/resolve_repos.sh performs Git mutations and will not be used as a read-only repository locator.
  • Repository-wide legal findings will remain a separate baseline concern; each pilot diff will require scoped scan evidence and transparent reporting of unchanged failures.
