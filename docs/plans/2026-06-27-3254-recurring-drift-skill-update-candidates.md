## Resource Intelligence Summary

Issue #3254 (child of epic #3248) closes **gap #5**: `detect-drift.sh` already logs per-session
rule-violation counts to `.claude/state/drift-summary.yaml`, but **repeats never become
skill-update candidates** — a class that drifts **night after night** is invisible until a human
eyeballs the YAML. The design: detect a drift **CLASS** seen on N **distinct days** within a window
and auto-emit a **parked skill-exception / skill-guide CANDIDATE** for human review, reusing the
`candidates/` dir convention.

This plan recommends a **central recurrence-aggregator script** wired into the existing nightly
learning orchestrator, writing a structured candidate file. It **adds no matrix dimension** (justified
in the Decision section, satisfying epic gap-#6 framing).

## Decision: central aggregator + candidate file — NOT a matrix dimension

**Recommend:** a single new script `scripts/session/aggregate_drift_candidates.py` (pure recurrence
core + thin CLI) wired into the existing **dev-primary nightly** *after* Step 3e
(`comprehensive-learning.sh`, line 158) and *before* Step 10 (`commit-learning-artifacts.sh`, line
162), writing a **parked** structured candidate file
`.claude/state/candidates/drift-skill-candidates.yaml`.

**Why that exact insertion point (round-1 MAJOR fix):** the **CLAUDE** drift record for the day is
appended *inside* `comprehensive-learning.sh:138-153`, which the nightly runs at Step 3e (line 158).
Wiring the aggregator before Step 3e (the round-1 draft's "after Step 3f" position) would read a
`drift-summary.yaml` that does **not yet contain today's Claude drift**. Running it after line 158 and
before line 160 means: (a) all three providers' drift for the day is present (Codex 3d @ line 119,
Hermes 3f @ line 137, Claude inside 3e @ lines 138-153), and (b) the candidate file is staged and
pushed by Step 10 in the same run (no stale-by-one-cycle gap).

**This adds NO new machine-equality-matrix dimension.** Justification (Hard Rule 6 — first assess
whether a dimension is even warranted):

1. **Wrong shape.** A matrix cell answers *"is this box equal to its peers right now?"* Drift
   recurrence is a **temporal-repeat signal aggregated centrally**, not a per-machine equality
   property. `comprehensive-learning.sh:29` enforces a **single-machine (dev-primary OR ace-linux-1)
   guard**: drift scans + this aggregator run only on the one aggregator box, over sessions rsync'd
   from every box. There is no per-machine column to grade.
2. **Existing machinery already fits.** The producer (`detect-drift.sh`) runs in the nightly (Codex
   3d @ line 119, Hermes 3f @ line 137) and inside Step 3e for Claude (`comprehensive-learning.sh:138-153`);
   the output dir (`.claude/state/candidates/`) and the input (`drift-summary.yaml`) are already
   auto-committed by `commit-learning-artifacts.sh` (lines 113 / 125 / 196). The closest precedent —
   `correction-to-skill-candidates.sh` — is itself a candidate-emitting pipeline, **not** a matrix
   cell. Epic #3248's gap-#6 note explicitly flags these four children as automation pipelines that
   may hook the nightly/candidate machinery instead of adding a cell. This is exactly that case.
3. **Cost asymmetry.** A new matrix dimension touches **~11 places** and risks spurious reconcile
   actions if any green verdict string is omitted from the OK-skip list. This pipeline touches
   **2 files** (one new script + one nightly wrapper block) plus one new test file and one new
   auto-committed state file. (The ~11 touchpoints are enumerated in *Rejected Alternatives* to show
   the cost was assessed, not ignored.)

### Defining "recurring" precisely  (round-2 MAJOR — day-grained, not session-grained)

A drift **CLASS** `C` is **recurring** at run time `now` iff, restricted to `drift-summary.yaml`
records whose `scanned_at` is within the rolling window `[now - DRIFT_WINDOW_DAYS, now]`:

> `C` has a **nonzero** count on at least `DRIFT_RECUR_DAYS` **distinct calendar days**, where a
> "day" is the **UTC date portion of `scanned_at`**.

- `DRIFT_WINDOW_DAYS` — default **14**, env-overridable (`DRIFT_WINDOW_DAYS`).
- `DRIFT_RECUR_DAYS` — default **3**, env-overridable (`DRIFT_RECUR_DAYS`).
- **Why distinct days, not distinct `log` paths (the round-2 MAJOR correction).** The live corpus
  shows a **single night** producing 20–150 distinct `log` records (one per Codex `rollout-*.jsonl`;
  verified counts: 150 / 75 / 70 / 48 in single days). A distinct-`log` threshold of 3 would therefore
  fire from **one noisy night** — the exact opposite of the protection a recurrence gate is supposed
  to give. Worse, distinct-`log` counting is **not commensurate across providers**: Codex contributes
  ~20–150 logs/night while Claude contributes ~1 (`session_YYYYMMDD.jsonl`), so "3 distinct logs"
  means "<1 Codex night" but "~3 Claude nights." Counting **distinct calendar days of `scanned_at`**
  fixes both: the nightly runs once per day and stamps every record it writes (across all providers)
  with that run's date, so an entire multi-session night collapses to **one day**. Recurrence then
  genuinely means "drifted on N separate days/nights" = persistence over TIME, matching the issue
  intent. This is provider-commensurate by construction: a class drifting only in Codex on 3 nights =
  3 days; a class drifting only in Claude on 3 nights = 3 days. (`scanned_at` is scan-time, so a batch
  **re-scan** of many old logs also lands on one date → still one day → still cannot trip; see Risks.)
- **Per-distinct-session dedup is retained for the EVIDENCE fields only** (not the threshold): for
  `total_violations` and the per-provider breakdown, each distinct `log` contributes its **max** count
  (a re-scan of the same `log` counts once), so evidence isn't inflated by re-scans. `distinct_sessions`
  is still recorded as a supplemental evidence field; **only `distinct_days` gates recurrence.**
- **Classes considered (the four leaf violation classes only):** `python_runtime`, `file_placement`,
  `git_non_conventional`, `git_missing_wrk_ref`.
  - `git_workflow` is **excluded** — it is a ROLLUP (`= git_non_conventional + git_missing_wrk_ref`);
    counting it would double-count its leaves.
  - `git_exempt_type` is **excluded** — it counts *exempt* commits, which are **not violations**;
    surfacing it as drift would be a false positive (a session that correctly used `chore:`/`merge:`
    is healthy, not drifting).
- **Provider aggregation:** recurrence is computed **per class across all providers** by default
  (skill/rule guidance is cross-provider), with a per-provider session breakdown recorded in the
  candidate for context. Because the threshold is day-grained, cross-provider aggregation no longer
  lets a high-session-volume provider swamp the metric (a class drifting in Codex on day-1 and Claude
  on day-2 and Hermes on day-3 = 3 distinct days = recurring). A future `--per-provider` split is a
  clean follow-on, noted as Open.

Thresholds are **named module constants with env overrides**, tunable in one place — the default is
genuinely conservative: **3 distinct days over 14 days**, so a single multi-session night (even
150 logs) is exactly **one** day and cannot trip a candidate (`test_single_noisy_night_many_sessions_not_recurring`).

### Where candidates are written (and how they stay "parked")

- **File:** `.claude/state/candidates/drift-skill-candidates.yaml` (reuses the candidates dir;
  isomorphic to `correction-promotions.yaml`).
- **Schema:** a provenance header (`generated_at`, `window_days`, `recur_days`,
  `machine`, `schema_version: 1`) + a `candidates:` list keyed by `drift_class`. Each entry:
  ```yaml
  candidates:
    - drift_class: python_runtime
      kind: skill-guide            # or skill-exception
      active: true                 # false == decayed below threshold since last triage (see merge)
      distinct_days: 5             # within window — THE recurrence metric
      distinct_sessions: 7         # supplemental evidence (deduped logs); NOT the threshold
      total_violations: 412        # summed over deduped sessions in window
      providers: {claude: 6, codex: 1}
      window_days: 14
      first_seen: "2026-06-13T07:05:11Z"
      last_seen: "2026-06-27T07:09:38Z"
      target: ".claude/rules/coding-style.md (python-runtime)"
      action: "Propose a skill-guide note or a documented skill-exception for bare python3 usage"
      rationale: "python_runtime drifted on 5 distinct days over 14d — repeated rule miss; capture as guidance or sanctioned exception."
      status: candidate            # PARKED — human review gate (see Hard Rule 1)
  ```
- **Class→target mapping** (module constant `CLASS_TARGETS`):
  | class | target | default kind |
  |---|---|---|
  | `python_runtime` | `.claude/rules/coding-style.md` (Python runtime: `uv run` vs bare `python3`) | skill-guide |
  | `file_placement` | `.claude/rules/coding-style.md` (test/src file placement) | skill-guide |
  | `git_non_conventional` | git-workflow rule / conventional-commit guide | skill-guide |
  | `git_missing_wrk_ref` | git-workflow rule (WRK/issue ref in commit) | skill-guide |
  - `kind` defaults to `skill-guide`; the **human** decides at review whether to convert it to a
    `skill-exception` (a sanctioned deviation). The aggregator never picks the final disposition.
- **Park-for-review safety (load-bearing):** the writer is a **merge, not an overwrite**. On each run
  it reads the existing file and:
  - (a) inserts newly-recurring classes as `status: candidate, active: true`;
  - (b) refreshes evidence fields (`distinct_days`, `distinct_sessions`, `total_violations`,
    `providers`, `last_seen`, `window_days`) on entries still `status: candidate` and re-stamps
    `active: true`;
  - (c) **preserves any human-edited `status`** (anything other than `candidate`, e.g. `promoted` /
    `dismissed` / `wontfix`) and does NOT resurrect it to `candidate` (it only refreshes evidence on
    such a row when it is still recurring, and re-stamps `active: true`);
  - (d) **ages out decayed candidates** — when a `status: candidate` row is **no longer recurring**
    this cycle, it is stamped `active: false` (its `last_seen` is left as-is, now out of window) so
    human triage can tell a live candidate from a decayed one at a glance. It is **never silently
    deleted**.
  Human-set non-`candidate` rows that fall below threshold are left fully intact (status and `active`
  untouched — they are already triaged). This is the precise mechanism that makes the output a backlog
  **for** humans, never an actuator.

## Recommended approach (vs rejected alternatives)

**Recommended:** pure-core recurrence aggregator (day-grained threshold) + thin CLI, nightly-wired
(after Step 3e, before Step 10), parked YAML candidate file.

**Rejected — distinct-`log` (session-count) recurrence threshold.** The original draft gated on
"nonzero in >=3 distinct `log` paths." The live corpus refutes the safety claim: single nights produce
up to 150 distinct logs, so 3-of-them fires from one night, and the metric is incommensurate across
providers (Codex ~20–150 logs/night vs Claude ~1). Replaced with **distinct calendar days** of
`scanned_at` (Decision §"Defining recurring").

**Rejected — new matrix dimension `drift_recurrence`.** A matrix cell would require touching the
**~11 standard matrix touchpoints** (enumerated to prove cost was assessed, per Hard Rule 3):
(1) a verdict family fn in `build-equality-matrix.py`; (2) threshold constants; (3) `verdict_for()`
routing; (4) `BASE_DISPLAY_DIMS`; (5) `DISPLAY_DIMS`; (6) `GROUPS`; (7) `ROLLUP_SEVERITY`;

drift recurrence is central/temporal, not per-machine equality (Decision §1), so the cell would be
identical on every box (no equality signal) and the cost/benefit is inverted.

**Rejected — extend `correction-to-skill-candidates.sh`.** That script parses
`.claude/state/corrections/` (a different corpus with different schema and a different threshold
semantics — frequency of file edits, not temporal recurrence of rule classes). Overloading it would
blur two distinct signals and complicate its tests. A sibling script with a shared *pattern* (not
shared code) is cleaner and matches the `audit`/`detector` split the epic already uses.

**Rejected — append free-text to `skill-candidates.md`.** The `.md` candidate files are append-only
human notes; they have no dedup and grow unbounded. A structured YAML keyed by class is required for
the merge/preserve-human-status/aging safety and for idempotent re-runs.

**Rejected — fire a `notify.sh` alert on recurrence (the #3250 posture).** Drift recurrence is a
**backlog** signal reviewed at human cadence, not an incident. A parked candidate is the right
channel; alerting would be noise. (If later wanted, a `notify.sh pass`-style daily digest is a clean
follow-on, noted as Open.)

import sys
from datetime import datetime, timedelta
from pathlib import Path
import yaml                              # NOT PEP-723; nightly hard-preflights `import yaml`

# --- IMPORT WIRING (round-2 MINOR fix) -----------------------------------------------------------
# scripts/ is not a package and scripts/curation is not on sys.path under the bare
#   `${PYTHON} scripts/session/aggregate_drift_candidates.py`
# nightly invocation; insert it BEFORE importing machine_label or the import ModuleNotFoundErrors and
# the `|| echo WARNING` guard would silently no-op the aggregator every night.
sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "curation"))   # -> repo/scripts/curation
from audit_skill_currency import machine_label    # canonical host->label (audit_skill_currency.py:53)
# (importing that module runs its module-top `import yaml`, already guaranteed by the nightly preflight)

# Module constants (env-overridable in the CLI, not in the pure core):
DEFAULT_WINDOW_DAYS = 14
DEFAULT_RECUR_DAYS  = 3                  # distinct CALENDAR DAYS (round-2 MAJOR), not distinct logs
LEAF_VIOLATION_CLASSES = ("python_runtime", "file_placement",
                          "git_non_conventional", "git_missing_wrk_ref")
# git_workflow (rollup) and git_exempt_type (non-violation) are DELIBERATELY excluded.
CLASS_TARGETS = { class -> (target, default_kind, action, rationale_template) }

# ---- CANONICAL TIME HELPERS (round-trip with producer's `date -u +%Y-%m-%dT%H:%M:%SZ`) ----------
PRODUCER_FMT = "%Y-%m-%dT%H:%M:%S"       # producer appends a literal "Z" after this

def parse_iso(s):
    # producer emits naive-UTC seconds + literal 'Z'. Strip 'Z', parse to NAIVE datetime.
    try:
        return datetime.strptime(str(s).strip().rstrip("Z"), PRODUCER_FMT)
    except (ValueError, AttributeError, TypeError):
        return None                       # malformed/absent -> caller skips (fail-closed)

def iso_z(dt):
    # NAIVE utc datetime -> "....T..:..:..Z"; round-trips with parse_iso and matches the producer.
    return dt.replace(microsecond=0).isoformat() + "Z"

# ---- PURE CORE (no IO, no clock, no subprocess; `now` injected as a NAIVE-UTC datetime) ---------
def evaluate_recurring(entries, *, now, window_days, recur_days) -> list[dict]:
    # entries: parsed drift-summary records [{scanned_at, log, provider, violations:{...}}]
    cutoff = now - timedelta(days=window_days)
    # per class: (a) set of distinct UTC dates with nonzero count (THE threshold metric),
    #            (b) per distinct-session(log) MAX count + provider + ts (EVIDENCE only).
    per_class_days     = defaultdict(set)     # class -> {date}
    per_class_sessions = defaultdict(dict)    # class -> {log: Session(count, provider, scanned_at)}
    for rec in entries:
        ts = parse_iso(rec.get("scanned_at"))    # malformed/absent -> skip (fail-closed, never raise)
        if ts is None or ts < cutoff or ts > now:    # future stamp -> skip (clock-skew guard)
            continue
        day  = ts.date()
        log  = rec.get("log") or ""
        prov = rec.get("provider") or "unknown"
        viol = rec.get("violations") or {}
        for cls in LEAF_VIOLATION_CLASSES:
            c = as_nonneg_int(viol.get(cls))      # non-int/neg -> 0
            if c <= 0:
                continue
            per_class_days[cls].add(day)          # day-grained recurrence
            cur = per_class_sessions[cls].get(log)
            if cur is None or c > cur.count:       # dedup: max count per distinct session (evidence)
                per_class_sessions[cls][log] = Session(count=c, provider=prov, scanned_at=ts)
    out = []
    for cls in LEAF_VIOLATION_CLASSES:
        days     = per_class_days[cls]
        sessions = per_class_sessions[cls]
        if len(days) < recur_days:                 # THE recurrence threshold (distinct days)
            continue
        target, kind, action, rtmpl = CLASS_TARGETS[cls]
        out.append({
            "drift_class": cls, "kind": kind, "target": target, "action": action,
            "distinct_days": len(days),
            "distinct_sessions": len(sessions),    # supplemental evidence
            "total_violations": sum(s.count for s in sessions.values()),
            "providers": count_by_provider(sessions),
            "first_seen": iso_z(min(s.scanned_at for s in sessions.values())),   # canonical Z-format
            "last_seen":  iso_z(max(s.scanned_at for s in sessions.values())),
            "window_days": window_days,
            "rationale": rtmpl.format(d=len(days), w=window_days),
        })
    return out

# ---- MERGE (preserve human statuses; age out decayed candidates) -------------------------------
def merge_candidates(existing_doc, fresh, *, now_iso, machine, window_days, recur_days) -> dict:
    by_class      = { c["drift_class"]: c for c in (existing_doc or {}).get("candidates", []) }
    fresh_classes = { f["drift_class"] for f in fresh }
    EVIDENCE = ("distinct_days","distinct_sessions","total_violations","providers","last_seen","window_days")
    for f in fresh:
        prev = by_class.get(f["drift_class"])
        if prev and prev.get("status") not in (None, "candidate"):
            prev.update({k: f[k] for k in EVIDENCE})   # human-triaged -> refresh evidence ONLY
            prev["active"] = True                      # ...never touch status (park-for-review gate)
        else:
            f["status"]     = "candidate"
            f["active"]     = True
            f["first_seen"] = (prev or {}).get("first_seen", f["first_seen"])   # sticky first_seen
            by_class[f["drift_class"]] = {**(prev or {}), **f}
    # classes NOT recurring this cycle:
    for cls, row in by_class.items():
        if cls in fresh_classes:
            continue
        if row.get("status") in (None, "candidate"):
            row["active"] = False           # decayed below threshold -> mark inactive (last_seen kept)
        # human-set non-candidate rows: left fully intact (status + active untouched)
    return {"generated_at": now_iso, "machine": machine, "window_days": window_days,
            "recur_days": recur_days, "schema_version": 1,
            "candidates": [by_class[k] for k in sorted(by_class)]}

# ---- THIN CLI ----------------------------------------------------------------------------------
def main(argv) -> int:
    args   = parse(argv)   # --window-days, --recur-days, --stdout (dry-run)
    window = int(env("DRIFT_WINDOW_DAYS", args.window_days or DEFAULT_WINDOW_DAYS))
    recur  = int(env("DRIFT_RECUR_DAYS",  args.recur_days  or DEFAULT_RECUR_DAYS))
    now    = datetime.utcnow().replace(microsecond=0)        # NAIVE UTC -> matches parse_iso output
    entries  = load_yaml(SUMMARY_FILE) or []                 # missing/empty/garbled -> [] (no-op, rc 0)
    fresh    = evaluate_recurring(entries, now=now, window_days=window, recur_days=recur)
    existing = load_yaml(CANDIDATES_FILE)                    # may be None on first run
    doc = merge_candidates(existing, fresh, now_iso=iso_z(now),
                           machine=machine_label(), window_days=window, recur_days=recur)
    if args.stdout: print(yaml.safe_dump(doc)); return 0
    atomic_write_yaml(CANDIDATES_FILE, doc)                  # tmp+rename; dir auto-committed by nightly
    return 0                                                  # ALWAYS 0 on success (Hard Rule 4)

## Risks & Hard-Rule Compliance

**Hard Rule 1 — never self-apply `status:plan-approved` / `status:completeness-verified`; owner gate is
human.** RESPECTED. The aggregator emits candidates at `status: candidate` into a *backlog* file and
**never** opens issues, applies labels, edits skills/rules, or promotes anything. Converting a
candidate into actual skill/rule work (and the `status:plan-approved` gate for that work) is a
**separate human step**. The merge logic is explicitly designed to never overwrite a human-set status
(`test_merge_preserves_human_status`); the new `active:false` aging marker is an *evidence* flag, not
a status change, so it never touches the owner gate. The file is an actuator for *humans*, never for
the agent.

**Hard Rule 2 — any session/curation audit must be wired into BOTH `.sh` AND `.ps1` and reuse the
audit→state-JSON→collect→verdict substrate.** RESPECTED BY EXCEPTION. This is **not** a
machine-equality/curation audit and adds **no matrix cell**, so it does not touch the curation
substrate at all. It rides the **single-aggregator nightly** (`comprehensive-learning-nightly.sh`),
which is **Linux/bash only** — there is no Windows `.ps1` counterpart for the nightly learning
orchestrator (the `.ps1` companion exists only for `curate-session-memory`, a per-machine 6h curation
path). Wiring this into `curate-session-memory.{sh,ps1}` would be **wrong**: it would run the central
aggregator on every box every 6h instead of once nightly on the aggregator host, violating the
single-machine-guard invariant (`comprehensive-learning.sh:29`, which whitelists dev-primary OR
ace-linux-1). The aggregator reuses the existing substrate where it genuinely applies: the producer's
`drift-summary.yaml`, the `candidates/` dir, the nightly committer
(`commit-learning-artifacts.sh:113`/`:125`/`:196`), and `machine_label()`
(`audit_skill_currency.py:53`).

**Hard Rule 3 — a new matrix dimension touches ~11 places; every green verdict must be added to
`reconcile-ecosystem.sh`'s OK-skip list.** RESPECTED. **No matrix dimension is added**, so
`reconcile-ecosystem.sh:204` (the OK-skip `case` arm — re-verified at HEAD 37d9a984a; opener at :203)
and the other ~10 matrix touchpoints are **untouched** — zero spurious reconcile risk. The 11
touchpoints are enumerated in *Rejected Alternatives* to evidence that the cost was assessed before
declining.

**Hard Rule 4 — do not overload exit codes; audits signal via state, not exit status.** RESPECTED. The
CLI **always returns 0 on success**, including when it finds and writes recurring-drift candidates —
"found candidates" is signaled by the YAML file content (and the `active` flag), never by a non-zero
code. It returns non-zero only on a genuine internal crash, and the nightly invocation is guarded
`|| echo WARNING` so even that cannot abort the run. (Although this runs in the Linux nightly, not the
Windows `$ErrorActionPreference='Stop'` cron, the exit-0-on-findings discipline is honored
regardless.) Guarded by `test_cli_always_exit_zero_on_candidates` + `test_cli_garbled_summary_failcloses`.

**Hard Rule 5 — cross-machine state-ref publish HANGS; bound with a timeout.** RESPECTED / N/A. This
pipeline performs **no state-ref git push**. Cross-machine visibility is achieved because the output
lives under `.claude/state/candidates/`, which the existing `commit-learning-artifacts.sh` stages
(line 113), commits, and pushes via the nightly's normal `git_safe_push` (line 196) — a standard
branch push, not the hang-prone state-ref publish. No `subprocess`/network call is added beyond the
in-process `machine_label` import. (If a future revision wanted a dedicated `drift-candidate-state` ref
for live fleet aggregation, it MUST wrap the publish in the bounded-`subprocess` `PUBLISH_TIMEOUT_S=90`
pattern — explicitly out of scope here.)

**Hard Rule 6 — first assess whether a new matrix dimension is warranted.** ASSESSED → **NO dimension**
(`addsMatrixDimension=false`). Full justification in the Decision section: drift recurrence is a
central/temporal signal aggregated on the single nightly host, not a per-machine equality property;
the existing nightly + candidate machinery is the correct host; a matrix cell would be identical on
every box (zero equality signal) at ~11-touchpoint cost. This is exactly the automation-pipeline shape
the epic flagged for hooking existing machinery rather than adding a cell. **Single-machine-ness note:**
the existing drift scans 3d/3f run *unguarded* in the nightly wrapper and rely on the cron schedule
(the nightly is scheduled on only one aggregator box). The cited `comprehensive-learning.sh:29` guard
lives *inside* Step 3e and does NOT cover 3d/3f/3g. Because the new 3g additionally **writes+commits**
a candidate file (more churn-sensitive than 3d/3f's append), the 3g block adds its **own explicit
hostname guard** mirroring `:29` (dev-primary OR ace-linux-1) — belt-and-suspenders against
mis-scheduling, so single-machine candidate-file behavior does not depend solely on the cron schedule.

**Additional risks:**
- **Risk — `scanned_at` is scan-time, not session-time.** A batch re-scan of old logs lands many
  records with near-identical recent `scanned_at`. **Doubly mitigated:** (a) the day-grained threshold
  means a whole re-scan storm shares **one** `scanned_at` date = 1 day, so it cannot manufacture
  recurrence on its own (`test_single_noisy_night_many_sessions_not_recurring`); (b) the
  distinct-`log` dedup keeps evidence (`total_violations`) from inflating
  (`test_distinct_session_dedup_max_count`). Genuine recurrence still requires drift on N separate
  days/nights.
- **Risk — timestamp format mismatch.** If `parse_iso` returned tz-aware datetimes, `isoformat()+"Z"`
  would emit malformed `+00:00Z` and break round-trip; and `ts.date()` would be a tz-aware date
  comparison hazard. Mitigated by parsing to **naive UTC** and the canonical `iso_z()` helper that
  round-trips with the producer's `%Y-%m-%dT%H:%M:%SZ` (`test_emitted_timestamps_roundtrip`); `now` is
  injected as naive UTC so all comparisons (and `.date()` extraction) are naive-to-naive.
- **Risk — `machine_label` import fails at runtime.** A naked import would `ModuleNotFoundError` under
  the bare nightly invocation, silently no-op'ing the aggregator. Mitigated by the explicit
  `sys.path.insert(parents[1]/'curation')` before the import, exercised by
  `test_cli_production_import_resolves_machine_label` (real subprocess, not monkeypatched).
- **Risk — decayed candidates masquerading as live.** A class that recurred last cycle but drops below
  threshold this cycle would otherwise persist with stale evidence looking active. Mitigated by the
  `active: false` aging marker (`test_merge_candidate_falls_below_threshold_marked_stale`), keeping the
  out-of-window `last_seen` so triage can distinguish decayed from live.
- **Risk — provider conflation.** Aggregating across providers could mask that drift is concentrated
  in one provider. The day-grained threshold prevents one provider's session volume from swamping the
  metric (`test_cross_provider_days_combine`); the per-provider breakdown is recorded in each
  candidate; a `--per-provider` split is a noted follow-on, not a v1 requirement.
- **Risk — candidate file growth.** Bounded by keying on the **four** leaf classes (max 4 active rows)
  plus human-triaged history; it cannot grow unbounded like the append-only `.md` files.
- **Risk — thresholds mis-calibrated.** 3-distinct-days/14-days is conservative (a single noisy night
  is one day and cannot trip a candidate); all thresholds are env-overridable named constants tunable
  in one place.
- **Risk — `log` path leakage.** Session log paths may contain machine/user path segments; the
  candidate stores `log` only inside in-memory aggregation, and the emitted record carries **counts +
  provider + class + day-grained metrics**, not raw log paths. Verified by the legal scan acceptance
  gate.

## Rollout

1. Land the new script + tests + the single nightly wiring block (after L158/before L160) + README
   index via a feature branch and PR (Issue → Plan → **USER APPROVES** → TDD implement → cross-review
   → close).
2. **First nightly run on the aggregator host** creates
   `.claude/state/candidates/drift-skill-candidates.yaml` after Step 3e; `commit-learning-artifacts.sh`
   (Step 10) auto-commits and pushes it in the same run. No new cron, no scheduler change.
3. **Calibration window:** after the first 1-2 nightly runs, inspect the emitted candidates against
   the live `drift-summary.yaml`; tune `DRIFT_WINDOW_DAYS` / `DRIFT_RECUR_DAYS` via env if the
   signal is too noisy or too quiet (no code change).
4. **Human review cadence:** the parked candidates are triaged by a human, who may set
   `status: promoted` (opens real skill/rule work through the normal plan→approve gate) or
   `status: dismissed`; the aggregator preserves those decisions on every subsequent run, and ages
   untriaged candidates to `active: false` when they stop recurring.
5. **Reversibility:** removing the Step 3g block and the script fully reverts the feature; the
   candidate file is inert data (no consumer depends on it). No matrix/reconcile state to unwind.
6. **Follow-ons (out of scope, noted):** `--per-provider` recurrence split; an optional daily
   `notify.sh` digest of *new* recurring classes; a bounded `drift-candidate-state` ref for live
   cross-fleet aggregation (would require the Hard-Rule-5 90s timeout wrapper).
