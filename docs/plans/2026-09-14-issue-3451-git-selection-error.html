Git-selection errors will invalidate the legal scan

Issue 3451 · Client: N/A · Lane: Codex implementation, independent Claude review · Execution: single-lane · Base: a04c129463332a544b08482097cff1edb3a67b74

Proposed scope and authorization

The repair will return exit 2 when the Git command used by --diff-only fails, including a failure after partial stdout. Git stderr will remain visible; the scanner will add ERROR: LEGAL_SCAN_INCOMPLETE: Git file selection failed on stderr and will not emit a completed PASS or FAIL summary. No partial file list from that failed command will be searched. A successful empty selection will retain exit 0 and its existing stdout; Git warnings on stderr will no longer be suppressed. A non-repository target or unborn HEAD will return exit 2 when Git selection is attempted. A failed directory change will enter the same incomplete-selection branch.

The implementation will wait for explicit approval of this concrete plan because the issue requires it and the change affects a legal-gate failure contract. The user's instruction to proceed will authorize discovery and preparation of the reviewable plan. Approval will cover local implementation and verification of this bounded slice; publication will follow only within separately established destination authority. No owner approval label will be self-applied.

Implementation and TDD

The test will be written first and will fail against the unchanged scanner. The implementation will evaluate if changed_files="$(cd "$scan_dir" && git diff --name-only HEAD)"; then, retain successful output, and otherwise print the incomplete diagnostic and return 2 before filtering or searching. The declaration local changed_files will remain separate from the conditional assignment to preserve its exit status. Explicit status handling will avoid relying on errexit inside functions invoked in conditional contexts. The diagnostic will append the target label after its fixed Git-specific prefix.

  1. Each failure fixture will first demonstrate that successful Git selection through the same shim in pass-through mode reaches real ripgrep and detects the synthetic marker. Nonzero status 73 will be exercised in addition to the real Git error cases; a partial list will name a tracked file containing the forbidden synthetic marker.
  2. Git failures with empty stdout and partial stdout will return 2, retain a fixture stderr marker, emit the incomplete diagnostic, emit no completed summary, and never search the failed partial list. The same instrumented ripgrep wrapper will record a nonzero invocation count on the pass-through positive control in each dispatch/mode before its zero-invocation assertion for the failed target will be accepted. Split-stream capture will be implemented locally in the new test file; lib.sh will remain unchanged. At least one JSON-mode failure will capture stdout and stderr separately: stdout will contain neither the fixture Git stderr marker nor the diagnostic, and stderr will contain both the fixture marker and the full Git-specific diagnostic ERROR: LEGAL_SCAN_INCOMPLETE: Git file selection failed.
  3. Default, named-repository, registered-root and initialized-submodule dispatches will be exercised in normal, quiet and JSON modes. The Git shim will fail only the selected target, delegate all other commands, and prove the failing branch was reached.
  4. A valid clean committed repository will preserve the successful-empty result. A Git shim will also emit a warning on stderr and exit 0 with empty stdout: the result will retain exit 0 and existing PASS stdout, preserve the warning on stderr, and omit the incomplete diagnostic. A matching nonempty selection plus warning and exit 0 will reach real ripgrep and produce the expected marker denial. Tests will judge Git status, not stderr presence. Deleted-only and excluded-only selections will also preserve existing exit 0 behavior. Real unborn-HEAD and non-repository-directory fixtures will each demonstrate exit 2, the Git-specific diagnostic and no completed summary without relying on a shim. The non-repository fixture will prevent ancestor repository discovery and inherited GIT_DIR/GIT_WORK_TREE effects, and its Git discovery failure will be checked directly. The failed-directory-change branch will be inspected rather than simulated with nonportable permissions. Existing diff-only tests will be inventoried for implicit unborn-HEAD assumptions before implementation; any required expansion beyond the three paths will trigger scope reassessment.
  5. A multi-target case will preserve evidence from an earlier successfully scanned target while a later selection error will force exit 2 and suppress a completed global summary.
  6. The focused test and all existing tests/legal/test_*.sh scripts will pass after the fix. Shell syntax checks, whitespace checks and the unchanged full-root legal scan will qualify the three-path candidate. The plan and tests will not introduce real client identifiers.

Risks and deferred requirements

Successful empty selection will still not prove evidence was scanned. Untracked files will remain outside Git diff HEAD; selected content will still come from the working tree, not staged blobs. Line-delimited/quoted Git filenames, empty patterns, duplicate deny-list parsing, submodule discovery errors and incomplete traversal will remain existing limitations. A scan target below a repository root may still misinterpret root-relative Git paths; JSON will still lack a completion record and will require exit-status interpretation. The repair will not claim selection completeness. EMPTY/count semantics and require-nonempty will remain with this issue; staged-blob handling will remain linked to issue 3521. No hooks, machine installation, deny-list changes, merges or issue closure will occur in this slice.
