Sparse worktree authority plan

The implementation will distinguish missing index initialization from valid sparse omission and will make content authority explicit before repository inspection.

Resource intelligence and scope

The work will address issues 3457, 3459 and 3460. Regression coverage will preserve the current policy retirement associated with 3523 and the existing root fix associated with 3179. It will not reinstate marker approval or alter independent hook-path wiring. Discovery changes in pull request 4132 and effective hook installation in pull request 4190 will remain separate. The only installer change will replace its learning payload. Execution will use one serial track, with no external provider invocation.

Reproduction and independent oracles

Tests will create real temporary repositories and linked worktrees using Git plumbing. A fixture will contain two named leaves. An interrupted --no-checkout preparation will have zero index entries and will be rejected. Full, cone, non-cone and sparse-index preparations will retain both leaves and will pass. Tests will compare literal fixture contents and independently enumerated leaf counts, not values computed by the checker.

Artifact map and numbered slices

  1. A shell library and thin enforcement entry point will validate HEAD/index state. The storage checkout helper and shell review entry points will call it before inspection.
  2. Tests will confirm that sparse omission and tracked, untracked or absent markers will not reactivate the retired plan gate.
  3. The absolute-path scanner will define working-tree, index and HEAD modes, use NUL-delimited paths, distinguish sparse omission from missing files and report coverage.
  4. A durable installed learning payload will resolve the current commit and common directory. It will execute regular blobs from that snapshot, retain failure events and return success after commit. Tests will invoke the actual installed event shape.
  5. Testing peers will use structural roots. Real linked-worktree tests will exercise hook-like bindings with and without GIT_WORK_TREE and will preserve existing fixed peers.
  6. An HTML guide will tabulate authority by topology, present a worked example and inventory remaining root candidates with explicit limitations.

Method and acceptance

The preflight will resolve a HEAD tree, count NUL-delimited tree and expanded-index leaves, reject a nonempty-tree/empty-index pair, and in fresh mode reject complete staged deletion. It will never repair or delete worktrees. Scanner tests will exercise staged content different from working bytes, missing targets, unmerged entries and unusual filenames. Learning tests will exercise missing, failing, edited and symlink helpers, legacy payload replacement, independent hook preservation and repeated failure counts.

Targeted tests for every changed module, Ruff, shell syntax and ShellCheck will be attempted. Missing tools and proven baseline defects will be recorded separately. Required fixtures will run one command at a time. The final tree will remain uncommitted for publication by the runner. Independent provider review will remain a merge prerequisite.

Adversarial plan review and risks

The local review will challenge index expansion, hook-environment leakage, mutable helper execution, swallowed child failures, staged-versus-working confusion and unknown coverage. Countermeasures will be tested before acceptance. It will reject automatic repair, broad hook replacement and any reintroduction of retired marker policy. An absent or corrupt HEAD will fail closed rather than being assumed empty. A local review will not be represented as independent provider consensus.

Sources

The method will follow the public Git 2.43 worktree, sparse-checkout, githooks, ls-files and rev-parse manuals. No engineering equation, coefficient or acceptance limit will be introduced.
