Proposed implementation sequence

  1. Freeze the inventory. A manifest will classify every discovered surface as active instruction, archive/vendor, or non-instruction example; bind each checked-out repository's remote, branch, HEAD, dirty/unpushed state, presence, full-depth tracked path, mode, and digest; and mark absent repositories uncovered. The repository owner will classify ambiguity with justification and digest or explicitly defer it.
  2. Prove the global replacement first. Disposable roots will test filesystem transitions without credentials. Only approved Phase B on the currently observed Windows host will run authenticated native trials: a fresh inventory will require the old user file to be the known managed symlink and will stop on any handwritten or unexpected user file. Its exact link identity and target-content digest will be saved before temporarily parking it outside all discovery roots. User files will never be copied into public evidence, and credentials will not be copied or changed. The trial will install a real symlink ~/.claude/rules/workspace-soul.md to the generated Claude runtime. A unique high-entropy token absent from every legacy global, project/ancestor Claude file, and repository AGENTS.md will exist only in the trial rule. Two positive and two negative fresh processes per startup surface will use no prior turns and no tools; all four responses must match their expected condition. Each negative trial will park only the controlled trial link outside discovery roots. Tokens will be absent from the request and other instruction sources. A separate lazy-discovery trial will enforce a tool-layer exact-path allowlist containing only the fixed harmless nested fixture file; all other reads, including the sibling instruction file, parked legacy instructions and trial rule, will be denied. If this restriction cannot be enforced the trial will be BLOCKED. Any denied or additional tool call will invalidate a positive trial. A paired negative trial with the sibling instruction absent must return NOT_LOADED. The harmless fixture will contain no canary, and its sibling instruction file alone will hold the token. This Read-only trial will not be reported as tools-disabled. Conflicting directives will diagnose precedence only; they will not prove load multiplicity. Effective-root enumeration, resolved-link identities, content digests and controlled exclusion of the legacy source will establish that one managed global source remains. Any ambiguity will block retirement. A present global Claude file will be treated as a false-positive source, not as AGENTS suppression. /memory, /context, and hook-event silence will not serve as negative proof.
  3. Inventory suppressors. The control-flow gate ordering will govern execution: before any live trial or mutation, its user-home, drive-root, repository, and nested ancestor chains will be checked for CLAUDE.md and CLAUDE.local.md. A preserved local file that suppresses AGENTS will cause that tree to retain Claude loading until its owner separately approves content migration/removal. Tests will require the AGENTS token to remain absent under this suppressor.
  4. Move the managed global lifecycle through staged states. The authored rule, installer, bootstrap, drift check, status emitter, and paired tests will adopt the verified user-rule path. During rollout, drift/status will recognize and report LEGACY, DUAL_VERIFIED, NATIVE_VERIFIED, or BLOCKED; single-surface enforcement will remain a post-convergence condition. Local apply will be idempotent and re-runnable, with durable prestate and detection for commit-without-apply, apply-without-current-source, and partial rollout. No setting or feature flag will be enabled automatically. Unknown plugin/hook/provider/flag behavior or unavailable real-symlink support will block the host.
  5. Stop recreation without blocking the baseline. The adapter generator will cease writing active CLAUDE.md and will validate/generate shared-contract AGENTS.md; Claude-only directives will remain in the Claude delta/runtime. A manifest-digest gate will report existing baseline surfaces without blocking and reject newly introduced active managed surfaces within the enumerated repository scope. Baseline entries will be removed only as their migrations close; changed baseline content will require classification, never silent exemption. Test fixtures will use per-line or path-restricted test-tree sentinels, never blanket file exemptions.
  6. Pilot one simple sibling only in deferred Phase C. No sibling repository will be mutated under A/B approval; phase-table row C will govern any later pilot. A neutral tier1-pilot-a repository with an existing common contract and thin Claude adapter will receive test-first migration. Root and nested canaries, exact content behavior, generator idempotency, rollback, and unchanged settings/plugins will be verified before the adapter is removed.
  7. Migrate unique nested and privacy policy only in deferred Phase D. If lazy read discovery fails, the policy will remain in its current Claude surface or a later approved scope will hoist it to the startup-root contract. If Claude @import or project trust is unavailable, the surface will remain; no universal import behavior will be assumed for Codex/Agy. The repository owner will own any project-trust approval. The 20-line cap from .claude/rules/coding-style.md will apply to AGENTS harnesses, while the generated user rule will be tested at both beginning and end for truncation. Exact mappings and content will remain private.
  8. Roll out only under deferred Phase E. Each machine will retain legacy behavior until a fresh probe verifies version/channel, effective native feature state, plugins, hooks, provider mode, root/nested startup, lazy read behavior, user rule, suppressors, managed identity, and rollback. Workflows using --add-dir will start Claude from the governed target root or remain blocked. No fleet readiness claim will follow from the Windows canary.

  • Transaction tests will cover a managed symlink, a handwritten regular file, an unexpected target, changed identity during apply, failed canary, interrupted install, and conditional rollback.
  • Generator tests will prove default behavior emits no active CLAUDE.md, preserves archive/vendor/example files, rejects ambiguous surfaces, and stays idempotent.
  • Inventory tests will require every surface in the newly frozen manifest to receive a disposition, deriving its count from that manifest and comparing drift against the prior observation of 35; aggregate counts alone will not establish coverage.

  • Targeted tests, generated-runtime drift checks, selected legal/security scans, and repository-required checks will run before exact artifact review.

Acceptance criteria

  • The local replacement trial will load its unique rule token with no user-level Claude file in a discovery root, achieved by parking only the known managed link and stopping on any other user-level Claude file, and with all project/ancestor sources excluded, and its paired negative control will not emit the token.
  • Installer, bootstrap, drift, status, authored rules, generated runtimes, and tests will implement the four staged states; one native surface will become mandatory only after a separately approved convergence.
  • Recreation prevention will cover only repositories enumerated in the frozen manifest; absent checkouts will remain uncovered. Phase A's managed generator will create no new active CLAUDE.md; baseline surfaces outside A/B will remain explicitly deferred rather than counted as completed or blocked migrations.
  • Before/after generated-runtime diffs will show that Codex and Agy receive no new Claude-only directive and that shared AGENTS content remains provider-neutral.
  • Archive/vendor/example files, private local instructions, unique nested policies, settings, plugins, hooks, credentials, roles, and controls will remain preserved unless a later exact scope explicitly owns them.
  • Each retired surface will have before/after identity, behavioral readback, rollback evidence, and independent exact code/artifact review.
  • Completion of this approved increment will mean only Phase A plus the named Phase B local pilot. Issue-wide/full-fleet completion will remain false until separately approved C–E scopes finish.
  • The increment will require the user-approved plan revision, TDD, legal/security checks, Claude/Codex/Agy review (or documented provider unavailability), issue comment, completeness gate, and verified remote state.

Risks and stop conditions

  • Double load or silent omission: any differing canary, duplicate directive, suppressed rule, or ambiguous precedence will preserve the prior runtime and stop that phase.
  • Ancestor suppressor or lazy-read gap: any preserved ancestor local file or failed lazy-read probe will retain the existing Claude surface and defer that repository.
  • Unique content loss: any unmatched instruction digest or failed import/behavior test will block deletion.
  • Host drift: unsupported version, unexpected path type/owner/target, changed state, or incomplete rollback evidence will leave the host unchanged.
  • Scope drift: new repositories, private mappings, settings/plugin changes, archives/vendor removal, or machine-role changes will require a revised reviewed scope.

Local pilot restore boundary. The trial runtime will use a private disposable target containing the canonical runtime plus probe-only directives; neither canonical generated bytes nor live settings will be edited to insert canaries. After positive/negative trials, the final link will target the unmodified canonical runtime, and a fresh session plus exact target/digest readback will verify that final state. Any trial failure will restore the managed legacy link only if current identities match this transaction. A concurrent mismatch will preserve both captured evidence and current bytes and will report BLOCKED for owner reconciliation. No background agent or running session will be restarted.

Live pilot preservation and recovery receipt

FOUNDATION will capture private pre/post manifests immediately around each live trial, negative parking operation, and final readback. The manifests will cover the user rules, settings, hook configuration, plugin configuration and installed plugin identities, credentials, and all transaction paths: relative path, type, resolved target, mode, size and SHA-256 where readable. Credential contents will never be copied or printed. The initial changed-path expectation will permit only the known managed legacy link, controlled user-rule link and declared private journal/parking paths. Native transcript/cache/log writes will be separately identified as expected provider side effects with exact paths; they will not exempt settings, plugins, hooks or credential changes. An unexplained difference, incomplete manifest or changed protected file will fail the pilot, preserve evidence, and enter conditional rollback without overwriting another writer.

Parking and durable prestate will live in the private machine transaction area outside every repository worktree, instruction-discovery root and enforcement scope. A Phase B invocation finding an unfinished journal will perform read-only reconciliation first and will not start a new apply. FOUNDATION will own recovery and will notify CONTROL through the existing coordination route, recording the BLOCKED start time and the actual instruction-coverage state. New sessions on a host with unverified coverage will not be represented as managed-ready. No automatic retry or forced restoration will occur; the owner will reconcile exact current identities against the saved prestate.
