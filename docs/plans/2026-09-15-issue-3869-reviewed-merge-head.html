Proposed behavior

An optional --expected-head argument will accept exactly a lowercase40hex GitHub commit identity; missing or malformed values will exit5 before gh invocation. The existing single PR query will request state, mergeStateStatus and headRefOid together. When an expected head is provided, a different observed head will exit6 without a merge. Existing MERGED/CLOSED and CLEAN-only behavior will remain. An actual merge will require a valid observed full head and will pass --match-head-commit with the explicit expected head, or the same queried head for legacy callers without the new option. Default watch-only mode will not merge. Existing callers will retain their options and normal status behavior; they will gain server-side race protection for the queried head. A GitHub mismatch/error during merge will terminate without retrying or substituting a new head. Human approval of one PR will not authorize another.
