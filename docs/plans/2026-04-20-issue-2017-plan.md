## Locked Design Decisions (v2)

### D1 — Thread state authority: **local-only JSONL + materialized snapshot**

**Decision:** In v1, thread state lives in the repo, not in Gmail.
- Authoritative state: `scripts/email/queue-state.jsonl` (append-only event log).
- Hot-path reads: `scripts/email/queue-state-snapshot.yaml` (derived; rewritten atomically after each transition).
- Gmail-side labels: **out of scope for v1.** Will be layered on top in a separate follow-on issue once `gmail.modify` scope is obtained or browser automation is stabilized.

**Rationale:**
- Eliminates the Gmail-scope blocker flagged P1 by all 3 reviewers.
- Snapshot addresses Claude's O(n)-scan concern for unbounded thread volume.
- Decouples v1 shippability from re-auth negotiation or browser-reliability engineering.

**Counter-options rejected:**
- Gmail labels as source of truth: blocked by scope (per `reference_gmail_mcp_scope.md`).
- GH-issue-per-thread: heavyweight; creates noise in issue tracker at 15+ threads/day.
- Labels + JSONL dual-write: synchronization failure mode flagged by Gemini (split-brain if one write succeeds and the other fails). Deferred to v2 when we have production data on failure rates.

**Concurrency contract (v3 addressed Claude P2 + Gemini P2; v4 adds composite key and meta-file freshness):**
- Single-writer discipline on `queue-state.jsonl` enforced by `fcntl.LOCK_EX` advisory lock acquired before any append.
- **Primary key** for every entry (v4 — addresses Codex P1 #1): composite `(account_id, thread_id)`, where `account_id` is the Gmail account (e.g., `vamsee.achanta@aceengineer.com`, `achantav@gmail.com`, `skestatesinc@gmail.com`). Gmail thread IDs are account-scoped, so using thread_id alone across the 3-account workflow would corrupt state via collision.
- Each JSONL entry schema: `{account_id, thread_id, from_state, to_state, ts_utc, writer_identity, reason?, linked_extraction?, primary_classification?, secondary_classification?}`. `writer_identity` = `{process_name, pid, hostname, boot_id}` for true uniqueness (addresses Claude v3 P3 PID-recycling concern).
- Snapshot rewrite uses **tmpfile + rename** (atomic on POSIX): write to `queue-state-snapshot.yaml.tmp`, `fsync`, `os.rename` to the final path. No reader ever observes a partial snapshot.
- **Freshness check** (v4 — addresses Claude v3 P3): alongside `queue-state-snapshot.yaml`, a tiny `queue-state-snapshot.meta.yaml` records `{last_log_byte_offset, last_log_sha256, snapshot_sha256, written_at_utc, log_generation}`. Reader does `os.stat(log).st_size` vs meta's `last_log_byte_offset` for O(1) staleness; on mismatch, rebuild from log. **Compaction invalidates byte-offset freshness** (v6 — addresses Claude v5 P2): when log compaction lands (follow-on issue), the compaction step MUST bump `log_generation`, and readers compare `log_generation` before `last_log_byte_offset`. Mismatch on generation forces snapshot rebuild. **Double-checked locking on rebuild (v8 — addresses Gemini v7 P3):** to avoid thundering-herd rebuilds when multiple readers detect staleness simultaneously, the rebuild path uses double-checked locking: (1) detect stale via meta mismatch, (2) acquire log lock, (3) RE-read meta under the lock — if another reader rebuilt while we were waiting, exit without rebuilding; (4) only rebuild if still stale after step 3. Test: `test_snapshot_rebuild_double_checked`.

**Snapshot YAML shape** (v6 — addresses Claude v5 P2 + Codex v5 P2): top-level map keyed by the composite string `"{account_id}::{thread_id}"`, values are the entry record. Example:
```yaml
"vamsee.achanta@aceengineer.com::19dac4e88cd85577":
  account_id: vamsee.achanta@aceengineer.com
  thread_id: 19dac4e88cd85577
  state: extracted
  ...
```
This pins the shape for #2026's implementation so composite-key collision-safety is structural, not merely documented.
- Daily sweep acquires a lockfile at **`<repo_root>/.locks/email-queue-sweep.lock`** (v4 — addresses Gemini P3: `/tmp` is cleared at reboot / shared between users). Sweep fails fast if it can't acquire the lock within 5s.
- **Sweep write discipline (v7 — addresses Gemini v6 P2; v8 tightened — addresses Claude v7 P3):** when sweep appends `purged` transitions to `queue-state.jsonl`, it MUST acquire `fcntl.LOCK_EX` on the log (same as inbound/reply handlers), not just the sweep-specific lockfile. The sweep lockfile prevents overlapping sweep runs; the log lock prevents races against concurrent inbound processing. **Sweep must hold the log-lock ONCE per run and batch all `purged` appends in that single critical section** — it does NOT release/re-acquire per transition (which would let inbound processing interleave and invalidate snapshot consistency). Implementation: sweep collects eligible entries from snapshot, acquires log lock, appends all purged transitions, releases lock. Tests: `test_sweep_respects_log_lock`, `test_sweep_holds_log_lock_once_per_run`.
- **Snapshot + meta atomic group (v7 — addresses Gemini v6 P3):** on reader-side rebuild from stale meta, writer overwrites BOTH `queue-state-snapshot.yaml` AND `queue-state-snapshot.meta.yaml` under the log lock to restore consistency; no partial-recovery state persists.
- **Directory bootstrap (v7):** `scripts/email/queue_state.py` creates `<repo>/.locks/` via `os.makedirs(exist_ok=True)` on first use. `.locks/` is gitignored.
- **Fixture redaction standard (v7 — addresses Claude v6 P2; v8 refined with placeholder allowlist — addresses Claude v7 P3):** a pre-commit hook rejects any file under `tests/fixtures/email/` matching real email addresses (`[\w.]+@[\w.]+\.\w+`) with **placeholder-domain allowlist exemption** for canonical test emails (`example.com`, `example.org`, `example.net`, `test.invalid`, `user.test` — per RFC 2606). Also rejects phone numbers, street addresses with numbers, or the user's known domains (`aceengineer.com`, `achantav@gmail.com`, `skestatesinc@gmail.com`). Redacted tokens: `REDACTED_EMAIL`, `REDACTED_PHONE`, `REDACTED_ADDR`. Hook implemented as `scripts/email/fixture-redaction-check.py` invoked via `.pre-commit-config.yaml` block. Tests: `test_fixtures_no_pii` (real-domain rejection), `test_fixture_redaction_allows_placeholder_domains` (example.com / test.invalid accepted).

**Timestamp pinning (v3):** all `ts_utc`, `completed_at`, and any other time fields in JSONL + snapshot are ISO-8601 UTC with explicit `Z` suffix. Schema rejects non-UTC values. Grace-boundary tests pin time via `freezegun` at UTC to avoid CI-timezone non-determinism.

### D3 — Deletion safety + trash-purge recovery

**Decision:**
- `completed` state carries a `completed_at` timestamp.
- Background sweep (daily) evicts threads where `now - completed_at > 7 days` → moves state to `purged`.
- `purged` means: local JSONL entry retained; Gmail message not touched by this pipeline (user may manually archive/delete); extracted data remains in the target repo.
- **Trash-purge recovery:** if a reply arrives on a thread that was `purged` (whether Gmail Trash still has the body or not):
  - Look up thread_id → linked_extraction_path in JSONL
  - If extraction exists → re-open thread as `extracted` state (state=reactivated sub-classification), link to the original extraction for context
  - If extraction missing → emit structured log event `{thread_id, reason: "extraction_missing_on_reactivation", original_extraction_path, ts_utc}` to `queue-state.jsonl` AND `queue-learning-log.jsonl`, then treat as new `inbound` (rare; surfaces in quarterly learning review — addresses Claude v2 P3 "silent history loss")
- Accepted data-loss boundary: raw email body after Gmail Trash auto-purge (30 days). Extracted data in repo is preserved.

**Rationale:** addresses Claude + Codex P2 (trash-purge ambiguity). Conservative: pipeline never deletes from Gmail; user retains Trash behavior control.

## State Machine (v2 — consistency-fixed)

Declared states: `{ inbound, extracted, awaiting-reply, completed, purged }`.

Classifications (applied during inbound→extracted transition; not states themselves): `actionable, data_extract, drive_doc, unsubscribe, archive, noise, spam`.

Transitions:

```
inbound
  -- classify as spam --> (no #2017 state entry; grandfathered gmail-archive-extract.py routing handles any Gmail-side action per its existing config — #2017 adds no new mutation)
  -- classify as noise/unsubscribe --> (no entry in queue; routing applies DELETE/REVIEW)
  -- classify as actionable|data_extract|drive_doc|archive --> extracted

extracted
  -- data written to target repo + no pending reply --> completed
  -- data written + awaiting other party --> awaiting-reply

awaiting-reply
  -- new inbound reply on same thread --> extracted (reactivated; prior extraction linked)
  -- user marks complete --> completed

completed
  -- grace period (7 days) elapsed --> purged
  -- new inbound reply on same thread --> extracted (reactivated)
  -- user un-completes --> awaiting-reply

purged
  -- new inbound reply on same thread --> extracted (reactivated; see D3 trash-purge recovery)
```

Idempotency (v4 — composite key): all transitions keyed on `(account_id, thread_id, target_state)`. Re-emitting the same transition is a no-op (log deduplication by `(account_id, thread_id, from_state, to_state, ts_utc)`). Using `thread_id` alone would collide across the 3-account workflow.

```
# All state lookups + writes use composite key (account_id, thread_id)

function classify_inbound(account_id, message):
    if spam_rules.match(message):
        # v8: #2017 classifies only; grandfathered gmail-archive-extract.py handles any
        # Gmail-side action per its existing routing config. No #2017 state entry.
        return (state=inbound, action=classify_only, classification=spam)
    routing_action = routing_config.lookup(message.sender_domain)
    if routing_action in {DELETE, REVIEW}: return (state=inbound, action=routing_action, classification=noise)
    schema = lookup_schema(message.sender_domain)
    if schema is None:
        # Unknown-sender fallback: archive with needs_schema flag
        extraction = {classifications: [archive], needs_schema: true, sender: message.sender}
    else:
        extraction = extract_structured_data(message, schema=schema)
    primary, secondary = apply_precedence(extraction.classifications)
    write_extraction_to_target_repo(extraction, path=routing_action)
    return (state=extracted, primary_classification=primary, secondary=secondary, extraction_path=path)

function apply_precedence(classifications):
    # v4 formal definition (addresses Claude v3 P3)
    # Fixed ordering: iterate in plan order, first match wins primary, remaining in same order
    ORDER = [actionable, data_extract, drive_doc, unsubscribe, archive, noise]
    matched = [c for c in ORDER if c in classifications]  # preserves ORDER
    # v8 note (addresses Claude v7 P3 dead-code question): the `not matched` branch is
    # reachable when a schema explicitly provides an empty classifications list (valid YAML).
    # It is NOT reachable via the current unknown-sender fallback path because that path
    # hardcodes `classifications: [archive]`. Keeping the safety default guards future
    # schemas that may legitimately emit an empty list.
    if not matched: return (archive, [])  # safety default
    return (matched[0], matched[1:])

function daily_sweep():
    for entry in queue_state.read_snapshot().filter(state=completed):
        if now_utc() - entry.completed_at > 7 days:
            transition(entry.account_id, entry.thread_id, from=completed, to=purged, reason=grace_elapsed)

function on_inbound_reply(account_id, thread_id, message):
    prior = queue_state.lookup(account_id, thread_id)
    if prior is None: return classify_inbound(account_id, message)  # new thread
    if prior.extraction_path and exists(prior.extraction_path):
        transition(account_id, thread_id, from=prior.state, to=extracted, reason=reactivation, linked_extraction=prior.extraction_path)
    else:
        # v4 fix (addresses Claude v3 P3): emit structured log event BEFORE fallback
        append_to_log(queue_state_log, {
            account_id, thread_id,
            reason: "extraction_missing_on_reactivation",
            original_extraction_path: prior.extraction_path,
            ts_utc: now_utc()
        })
        append_to_log(queue_learning_log, same_event)  # for quarterly review
        classify_inbound(account_id, message)  # then treat as new
```
