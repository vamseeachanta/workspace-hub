## Pseudocode

_This is a design issue; the pseudocode captures the queue state machine that the design doc will document._

```
state machine: EmailThread
  states: { inbound, extracted, awaiting-reply, completed }
  transitions:
    inbound       -- classify --> extracted | noise | actionable
    extracted     -- data written to repo --> awaiting-reply | completed
    awaiting-reply -- new inbound message --> re-activated (back to extracted)
    awaiting-reply -- user marks done --> completed
    completed     -- grace period elapses --> deleted (soft, Gmail Trash)
    deleted       -- new inbound message --> re-activated (restored from Trash)

  labels (Gmail-side implementation):
    `queue/extracted`
    `queue/awaiting-reply`
    `queue/completed`
    `queue/reactivated` (transient)

  state log (local):
    scripts/email/queue-state.jsonl — append-only, one line per transition
    fields: {thread_id, from_state, to_state, ts_utc, extracted_to_path?, reason}
```
