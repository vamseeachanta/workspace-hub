## Deliverable

A deterministic, read-only inventory command that treats `mission-map.yaml` as portfolio membership authority, joins workstation placement and safely redacted observed sibling checkouts, reports profile, sensitivity classification, and contract coverage, and regenerates the repository overview.

## Design and Pseudocode

Authority boundaries:

- `mission-map.yaml`: portfolio identity, tier, mission, lifecycle, and new `profile` and `sensitivity` fields. `unclassified` is a valid transitional emitted value but grades incomplete; missing or unknown enum values are schema errors. #3817 owns later enforcement.
- `config/workstations/registry.yaml`: placement expectations only.
- filesystem probe: observed state only; never becomes authority.
- `repos.conf`: legacy clone-URL compatibility input, reported for mismatch but not promoted as membership authority.

Approved implementation scope does **not** add or remove portfolio members. The 21 existing `mission-map.yaml` entries remain the complete declared set for #3816. Observed undeclared siblings are reported only as one aggregate count; adding them requires a separate owner-approved registry change.

Proposed metadata migration:

|---|---|---|
| `workspace-hub`, `deckhand`, `aceengineer-strategy` | control-product | public for `workspace-hub`/`deckhand`; business-internal for strategy |
| `digitalmodel`, `assetutilities`, `CAD-DEVELOPMENTS`, `worldenergydata` | code | public |

Approval of this plan approves only these assignments. Profile is limited to `code`, `knowledge`, and `control-product`. Sensitivity is a separate enum limited to `public`, `business-internal`, `client-confidential`, `personal-sensitive`, and transitional `unclassified`; `unclassified` is not assigned to the current 21. `mcp_required` is a separate boolean.

Contract coverage fields:

Provider-adapter coverage is identical for `code`, `knowledge`, and `control-product` profiles. Profiles may later differ in non-adapter anatomy checks, but those checks are outside #3816 and cannot reduce adapter requirements.

| Surface | Rule |
|---|---|
| `AGENTS.md` | required for every profile |
| root `CLAUDE.md` | presence reported as anatomy evidence for #3646; `.claude/CLAUDE.md` remains the scored Claude adapter for #3816 |
| `.claude/` and `.claude/CLAUDE.md` | required per control-plane contract |
| `.codex/` | required; may be minimal |
| `.gemini/` | required; may be minimal |
| `.mcp.json` | conditional: present/absent/not-declared; absent fails only when registry metadata declares MCP use |

`mission-map.yaml` gains `mcp_required: true|false` for each declared repository. The initial exact assignments preserve the control-plane contract: `digitalmodel` and `worldenergydata` are `true`; all other current entries are `false`. This metadata, rather than prose parsing, is the inventory check authority.

```text
load_declared_repositories(mission_map):
    validate unique repository names and allowed profiles
    return stable mapping keyed by repository name

observe_work_surface(workspace_root):
    inspect immediate children without following external symlinks
    classify Git checkout, plain directory, missing, or unreadable
    record declared repository names and contract booleans
    aggregate unexpected repositories into a count only
    emit no unexpected names, pseudonyms, adapter fields, or stable fingerprints

join_inventory(declared, placements, observed, clone_config):
    emit named records only for declared repositories
    keep declared-portfolio, configured-for-machine, and observed-local as separate fields
    classify configured-present, configured-missing, observed-unregistered, unexpected, or non-git
    apply the same provider-adapter requirements to every profile
    return records sorted by repository name plus summary counts

render_outputs(inventory):
    write canonical JSON with schema version and no absolute paths
    render the Markdown overview from the same in-memory records
    support --check by comparing generated bytes without writing
```

## Risks and Open Questions

- Adding currently observed wiki repositories to `mission-map.yaml` is explicitly out of scope. The current 21 entries remain authoritative; unknown observed names remain redacted and `observed-unregistered`.
- `mission-map.yaml` is schema version 0.1 and currently mixes business and personal tiers. This issue adds explicit sensitivity metadata for reporting; #3817 owns enforcement and cross-zone access policy.
- Git worktrees and plain data directories must not be mislabeled as unexpected repositories.
- Remote URLs can contain credentials. Reports must never emit remotes. Names are emitted only for repositories already declared in the public mission registry; unexpected repositories contribute only to aggregate counts with no tokens or per-repo fields.
- Mac placement is three-dimensional: portfolio membership, `configured_for_machine`, and `observed_local` are independent fields. None implies either of the others.
- `generated_at` would defeat byte-level drift checks; the canonical JSON will omit volatile timestamps or isolate them outside the compared payload.
