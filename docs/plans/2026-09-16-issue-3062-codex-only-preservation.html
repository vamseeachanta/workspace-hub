Codex-only native preservation

Issue: workspace-hub 3062 · Parent: initiative 3815 · Class: T2 · Date: 2026-09-16.

The propagator will gain an opt-in operation that will verify and preserve one repository's recognized native Codex skill root. This operation will allow a later bounded persistence trial to avoid shared Claude-skill and Gemini-adapter mutations. It will not install skills, change a native root, run a live rollout, or claim provider readiness.

No external dataset or engineering standard will govern this shell-selection change. Runtime host evidence and private persistence captures will remain outside this public plan.

Proposed behavior

  • --codex-only will require exactly one --only <repository-basename>. Missing, empty, option-like, repeated, path-valued, unmatched or multiply matched selections will fail before propagation.
  • --hooks-only will be incompatible in either argument order. --skills-only, --dry-run and --verbose will remain compatible.
  • Repository discovery will retain its current nested-and-sibling enumeration and eligibility rules. The selected operation will require exactly one eligible basename match.
  • The operation will call the existing native classifier. A recognized native root will emit one target-specific preservation message and return success.
  • Missing helpers, failed execution, malformed output, blocked metadata and absent native ownership will fail without creating a legacy Codex bridge.
  • The selected operation will return before hooks, permissions, shared Claude skills, ignore/index updates and Gemini handling. It will bypass the shared _internal template precondition because that template is not an input to this operation.
  • Invocations without --codex-only will retain existing behavior.

The tests will use disposable repositories and copied scripts. Ordinary and dry-run cases will preserve six native payload sentinels, a parked Codex bridge, stale Gemini state, Claude settings, Git index state and an unrelated eligible sibling. Cases will include a parent path containing spaces and a foreign invocation directory. Existing default native, absent-root, Gemini and shared-propagation regressions will run where the platform supports their filesystem fixtures.

Stop conditions and limits

The change will stop for an owning-source mismatch, a new classifier, expanded discovery, a default-behavior regression, a write outside the four paths, or a test fixture that touches a real sibling repository. Legal positive controls, whitespace checks and independent Claude and Codex artifact reviews will be required before publication. Windows inability to construct a Unix dangling-symlink fixture will be reported as a platform limitation rather than counted as a pass.

A passing fixture will establish selector behavior only. Source integration, installation on another machine, actual generator execution, persistence readback, plugin or settings changes, and fleet-readiness claims will remain separately gated.
