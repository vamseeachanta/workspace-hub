Proposed validation contract

  1. Conditional property. ImplicitVariableMaxTimeStep will leave the global always-invalid set. In a General mapping with known implicit integration and explicitly enabled variable stepping before the value, a finite positive numeric value will be recognized. Boolean/nonnumeric/nonfinite/nonpositive values and known wrong section placement will remain errors. Mode/solution-method checks will consider only effective local setters preceding the maximum assignment; an explicitly incompatible preceding state will error. Later setters will never retroactively establish the assignment state. Reversed local order without proven earlier incompatible state will warn rather than definitely fail. Boolean parsing will be explicit for YAML booleans and OrcaFlex Yes/No spellings; arbitrary truthy strings will not enable a mode.
  2. Unresolved context. A standalone fragment or General overlay may inherit settings from prior includes. Missing context will yield a warning that requires parent/native qualification; it will never be inferred from an unrelated nested mapping. An unresolved includefile between a setter and the maximum will invalidate local certainty. Before yaml.safe_load collapses mappings, a bounded YAML-node check will detect repeated General sections or relevant mode/maximum keys and aliases that make local order ambiguous; such inputs will warn as unresolved rather than be evaluated from a last-wins dictionary. Cyclic aliases will terminate safely with an explicit unsupported/ambiguous diagnostic. No full stream/include interpreter will be introduced. This increment will not implement a new include-state resolver or silently assume a default mode. Existing includes will still be checked for existence, and the corpus harness will explicitly visit master and include contents. A preceding locally explicit incompatible solution method will fail; an absent or only later solution-method setter will leave unresolved context.
  3. Section recognition. ExpansionTables, LineContactData, MultibodyGroups, PyModels, RayleighDampingCoefficients and StiffenerTypes will be added as recognized section names based on the triage's primary documentation and existing schema/builder mappings. Recognition will suppress only the obsolete unknown-name warning. Existing nested invalid-property checks will still execute; arbitrary unknown section names and misspellings will still warn. PyModels will be identified as soil p-y models, not Python execution. This change will not certify all contents of these sections or add general schema validation for them.
  4. No output changes. Generator output, active maximum timestep, model dependency ordering and raw-property preservation will remain byte-identical for the six affected cases. Neither warnings nor errors will be cleared by deleting model settings. Unsupported runtime versions or native readback will remain qualification gaps under 718.
