Equality collector isolation

Summary

Checkout provenance and matrix remediation are separated from orchestration. Collector tests replace installation lookup and SDK discovery with controlled fixtures. The existing report schema, verdict rules, measured paths and remediation text are preserved. Native Windows execution remains unverified.

Responsibilities

  • scripts/readiness/lib/collect-provenance.sh reads checkout state using the unchanged measured-path allowlist.
  • scripts/readiness/equality_actions.py owns rollup severity and remediation; the builder re-exports its existing API.
  • tests/readiness/collector_support.py owns subprocess environments, path conversion and synthetic SDK outcomes.
  • Provenance and solver tests are separated from schema and serialization tests.

The installation-root function preserves production defaults. Tests override that function through a fixture-owned Bash startup file and the existing library source guard. No production environment switch is added. Interpreter shims reject SDK imports and forward other calls to the test interpreter. These shims precede every ambient interpreter; synthetic successful-import tests supply an earlier shim through the explicit stub_dirs parameter. Generator environments use the Bash tool directories plus the converted uv directory selected from native PATH entries.

Fixture Git commands clear inherited repository bindings, isolate global configuration and disable automatic line-ending conversion in disposable repositories. Native paths are converted to shell paths before use in Bash; filesystem operations convert shell paths back to native paths. Freshness setup uses the same isolated Git helper and preserves the caller's FETCH_HEAD bytes and remote-ref timestamp. Configuration tests check that global line-ending configuration is unavailable and that the disposable repository explicitly disables conversion. Temporary files are placed in the fixture runtime directory outside its checkout.

Worked example

Inputs: a workspace containing spaces, empty synthetic installation roots, and an interpreter shim that rejects SDK imports.

Method: run the real collector with --stdout --machine fixture. An installation directory is then created for the wave solver before a second collection.

Answer: empty roots produce absent for every solver. After the wave installation directory exists, only that solver produces present, with root evidence. Installation presence never establishes a licence entitlement. The workspace remains empty; temporary files stay outside it.

The executable examples are test_solver_roots_are_fixture_owned, test_installed_sdk_cannot_execute_in_collector_fixture and test_environment_clears_repository_bindings_and_owns_temporary_files in tests/readiness/test_collector_isolation.py. Git examples in test_collect_equality_provenance.py verify clean versus changed tracked bytes, caller metadata preservation and user line-ending configuration isolation.

Sources and criteria

The source of the discovery truth table is the output contract in scripts/readiness/lib/probe-solvers.sh. The source of preserved schema and verdict behavior is the parent implementation of collect-equality.sh and build-equality-matrix.py, with expectations in their existing tests. No engineering coefficient, physical equation or new acceptance threshold is introduced.

Validation and limits

The required collector, matrix, solver, provenance and schema tests are run before publication. The extracted matrix functions are compared with the parent using parsed syntax trees; the provenance extraction is compared byte for byte. Ruff is run on touched Python files and Bash syntax is checked on touched shell files.

Baseline

The existing tree-cleanliness suite expects output-directory seams that are absent in the parent collector and builder. Its failures are retained and reported rather than changing output destinations in this refactor. Existing Ruff findings on unchanged source lines remain.

Hooks that could not run

The hook framework is unavailable in this environment. Direct file checks are used; hooks remain enabled for publication.
