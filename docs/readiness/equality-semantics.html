Equality freshness and publication semantics

Summary

Report age gates matrix conformance and peer voting. Unreadable inputs, stale refs and unsuccessful publication remain visible. Local collection preserves an unchanged canonical payload and publishes changed reports through atomic rename.

Policy inputs

DEFAULT_EVIDENCE_TTL_HOURS = 24.0 is a configurable maintainer policy choice, not an engineering limit. The command accepts --ttl-hours; the freshness function requires an explicit TTL. Values must be positive and finite. The required timestamp is generated_at, with an explicit UTC offset. The inclusive rule is 0 ≤ age ≤ TTL, where age is the comparison clock minus the timestamp. Future timestamps have zero allowed tolerance and grade STALE; offset-free timestamps are ambiguous and also grade stale. An offset-free historical report must be collected again rather than assigned an assumed zone.

Timestamp syntax uses the ISO 8601 profile specified in RFC 3339 (2002), section 5.6. Hours use the section's minute and second ranges. The referenced ISO edition in RFC 3339 is ISO 8601:1988. The ISO 8601-1:2019 catalogue page returned HTTP 403 when consulted; no normative requirement from that edition is asserted.

The lock-directory fallback uses PUBLISH_EQUALITY_LOCK_STALE_SECONDS, default 3600 seconds, as a maintainer policy. The value must be a positive integer with at most nine digits (an implementation safety bound, also policy). Reclamation requires an age strictly greater than the bound and a dead owner PID. Live owners, recent locks, missing ownership, and unverifiable ownership are never reclaimed. A guard directory serializes acquisition and reclamation; an abandoned guard requires manual inspection. All callers reserve the same directory even when their available locking tools differ.

PUBLISH_EQUALITY_LOCK=mkdir explicitly selects the portable implementation. Automatic mode additionally uses flock when found. Status 75 is the configured contention convention, supplied through flock -E. Other lock setup failures return nonzero. The publication lock is scoped to the common Git directory, so linked checkouts share it.

Rendered states

StateMeaning and consequence
FRESHThe timestamp passes policy; dimension checks still determine conformance.
STALEOld, absent, ambiguous, malformed or future timestamp. Every matrix dimension is stale; the report cannot vote in peer comparisons.
UNREADABLEA report cannot be read or parsed. Dimension verdicts are MISSING-EVIDENCE, with no conformance claim.
NOT-FETCHEDAn explicit reconciliation --no-fetch run. Counts use possibly stale refs; the banner and JSON ref status retain that qualification.
fetch-failedA repository's fetch failed. The report is incomplete, returns nonzero and prevents automatic application. Other repository failures remain individually visible.

Roster entries declared unreachable retain that verdict. A fresh timestamp alone cannot override unreachable status, checkout contamination, missing evidence or a failed dimension.

Inputs and publication

Reconciliation resolves uv on PATH, then the documented $HOME/.local/bin location. Missing execution support, failed matrix execution, invalid JSON or a missing verdict map stops before printing a plan. Default reconciliation fetches remote-tracking refs before scanning. Each successful fetch reports its observation time; opt-out runs deliberately make no claim about ref age.

Publication records publish-health.json alongside local equality evidence, after successful publication and worktree cleanup. A dry run records no success. The record uses the existing publication-health schema, separately from fingerprint monitoring. Cron requires a successful publisher exit and a record at least as recent as this invocation. Collection uses the equality receipt when the evidence directory is explicitly configured, otherwise preserving the existing fingerprint-health input.

Canonical comparison excludes observation time, checkout identifier, available resources, context modification time and scheduler job count. Checkout dirtiness, ahead/behind counts, ref age and dimension values remain meaningful. Equality uses canonical bytes directly, so absence of a hashing executable cannot force a rewrite. Unchanged payloads intentionally retain their old collection timestamp; freshness therefore means changed evidence within the TTL, not proof of a collector heartbeat. Periodic heartbeat observation is separate follow-up work.

No engineering equation or licensed source value is used. Tests run offline with synthetic evidence, controlled executables and local bare remotes. Native Windows and macOS execution remains unverified; the directory fallback is exercised on Linux. This change adds no automatic issue creation, remote execution or new publication monitoring service.
