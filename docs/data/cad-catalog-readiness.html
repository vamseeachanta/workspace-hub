CAD catalog evidence summary

The inventory report validates catalog structure and summarizes file counts, supplied byte sizes and GLB references by format. Reader suggestions remain unverified. The synthetic example contains three records totaling 35 bytes; readability, conversion, geometry fidelity and manufacturing acceptance remain NOT_EVALUATED.

Scope and method

This is a bounded contribution to the CAD/CAM manufacturing initiative. The implementation has three slices: strict inventory validation, aggregate evidence reporting and a tested synthetic example. Existing discovery work is reused; no archive is scanned and no geometry or solver software is started.

The input schema and suggested-tool mapping are defined by the existing builder, symbols HEADER and READ. This repository source establishes compatibility and routing hints only; it is not an external capability citation.

For each format, N is the number of rows, B = sum(size) in bytes and L is the number of nonempty GLB-reference cells. These are counting identities; no physical equations, coefficients, acceptance limits or standards-derived values are used. All example numbers are synthetic inputs, not measured engineering data.

Worked example

From the repository root, run the standard-library CLI:

python scripts/data/drive-index/cad/report_cad_readiness.py \
  --inventory examples/cad/readiness-inventory.tsv

The fixture supplies two STEP rows of 10 and 20 bytes and one STL row of 5 bytes. One STEP row supplies a GLB reference. Hand calculation gives STEP: N = 2, B = 10 + 20 = 30, L = 1; STL: N = 1, B = 5, L = 0. Total: N = 3, B = 30 + 5 = 35, L = 1.

Validation and provenance

The exact builder header is required. Wrong column counts, blank or duplicate paths, unrecognized formats and sizes other than nonnegative decimal integers are rejected. Format identifiers are case-sensitive, as emitted by the builder. Quoted TSV cells are supported. Duplicate paths use exact textual comparison; aliases and case variants are not deduplicated. Zero size is retained as zero.

The command reads the inventory once and hashes those same bytes with SHA-256. No source models or referenced GLB files are opened. Output goes to standard output only after the complete inventory validates. Errors return a nonzero exit status without printing raw cells or paths. Reports contain format identifiers, trusted builder tool hints, counts, limitations and the inventory digest; supplied names, paths, descriptions, project labels and readability claims are omitted.

Tests cover the hand counts, input preservation, schema and numeric rejection, duplicate rejection, quoted fields, error disclosure, the shipped fixture and the scanner-to-builder-to-report pipeline. The pipeline uses synthetic text files; it verifies catalog plumbing, not valid STEP geometry.

Limitations and way forward

Catalog metadata does not establish archive completeness, current file size, freshness, installed tools, readability, licensing or conversion success. A GLB reference is not proof of an artifact. Large inventories are held in memory for digest binding and duplicate detection; bounded-memory streaming is future work.

Qualification requires source-byte digests, units, converter and version, source rights, conversion logs and explicit intended-use criteria. Neither dimensional fidelity nor manufacturing acceptance can be calculated from this catalog. Those results remain NOT_EVALUATED until the evidence is available and reviewed. Private strategy, archive qualification, geometry adapters and market demonstrations remain with the initiative's linked work.
