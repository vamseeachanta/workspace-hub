## Curated vs raw inventory

This file is the **curated** routing surface. Two things follow from that:

- It is hand-maintained. It only lists canonical paths that exist today and that a worker can reasonably trust as the right place for new work.
- `docs/CONTENT_INDEX.md` is the **raw** inventory generated by `scripts/search/build_content_index.py`. It catalogs everything in the repository, including archives, environments, and cross-repo overlay. Do not treat it as a routing authority. Per the #2460 contract, raw inventories MUST NOT be used as required canonical authority.

When this index disagrees with `docs/CONTENT_INDEX.md`, this index wins for routing decisions. Update it via PRs that link #2464 or #2460.

## How to extend this index

1. New canonical surface lands in a tier-1 repo → add a row to the matrix above and update [`data/document-index/intelligence-accessibility-registry.yaml`](../data/document-index/intelligence-accessibility-registry.yaml) in the same PR.
2. New issue category → add a row to the issue-type matrix only after the category is in regular use; one-off categories belong in the issue body, not here.
3. Reference the #2460 contract section that authorizes the change in the PR description so reviewers can verify against the contract.
