Test-health history and outcome telemetry

The existing dashboard records each completed observation and displays recent pass-rate changes. Missing execution evidence and skipped-only packages do not receive a passing badge. This bounded change advances initiative 3671 through the test-health telemetry branch; it does not establish initiative completion.

Inputs and source basis

scripts/quality/test-health-dashboard.py consumes the existing digitalmodel/tests/ target beneath its resolved repository root. The input is pytest summary output, process return status and the optional docs/dashboards/test-health-history.json file. No solver is launched by the worked example or its regression tests. A live dashboard run executes the target's tests and requires separate verification of their dependencies.

Source: issue 1666, “Test health dashboard: add historical trend tracking and coverage delta detection”, acceptance criteria 2–4, read on 2026-10-22. Criterion 2 specifies timestamp, total, passed, failed, errors, skipped and pass_rate. Criterion 3 specifies the latest eight observations. Criterion 4 specifies a warning for a drop greater than five percent. This implementation interprets a difference between percentage-valued pass rates as percentage points; the warning states that unit explicitly. There are no standards-derived physical constants or engineering acceptance limits in this calculation.

Method and outputs

Total outcomes equal passed + failed + skipped + errors. Pass rate (%) equals 100 × passed / total, rounded to one decimal place. With no outcomes the stored rate is 0.0%; it does not establish a successful run. A nonzero process exit with no reported failures or errors contributes one diagnostic error; a timeout or launch failure also contributes one diagnostic error. These are execution outcomes; launch and collection diagnostics do not establish individual test cases. Singular and plural pytest error summaries are both recognised.

The history stores all observations in append order. The dashboard shows the latest eight and compares the current stored, rounded pass rate with the previous stored rate. A drop strictly greater than 5.0 percentage points emits a warning; a drop exactly equal to 5.0 does not. Skipped-only packages carry a warning badge. Malformed history, negative or nonintegral counts, contradictory totals, inconsistent rates and timestamps without a timezone are rejected before writing. An unavailable test tree raises an error rather than producing empty success.

A history update is written to a sibling temporary file, flushed and atomically replaced. Earlier bytes remain intact if validation or replacement fails. Timestamps are stored in UTC. A single writer is required; concurrent updates are not merged. Failed replacements can retain a diagnostic partial file.

Known limits and later slices

A pass-rate trend is not source coverage. Changes in collected cases, skipped cases or diagnostic errors change the denominator and may prevent meaningful comparison between runs. Historical identity does not yet pin the source revision, environment or test selection. No comparison of equivalent source coverage is established. The warning is advisory; no merge gate or scheduling policy is changed.

The existing source-package discovery is retained. A source package appearing in the test-directory inventory does not prove test coverage of every module. A missing source inventory cannot establish complete coverage. Runtime history and Markdown output are generated on demand; this change publishes no live-suite results and does not execute a complete target-repository suite.

The dashboard and history are separate files, not one transactional publication. A dashboard write failure after a history update leaves an observation without a matching rendered dashboard. Reruns append observations rather than deduplicating runs. Broader repository anatomy, duplicate consolidation, suite repair, scheduling, source coverage, baseline budgets and gate enforcement remain under the parent initiative and its linked epics.
