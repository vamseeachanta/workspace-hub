Behavioral parity evidence evaluation

Summary

The evaluator compares reported token and clarification counts against explicit, caller-supplied criteria. A missing cohort, insufficient samples, a zero reference token rate or ambiguous tool attribution cannot establish parity. A result of WITHIN_LIMITS applies only to the two measured rates and the supplied limits; it does not establish equivalent output quality or operational readiness.

Basis and scope

The definitions follow the repository's behavioral metric definitions (2026, functions metrics_from_digests and compare_to_baseline), under initiative 3669 and its instrumentation issue 3061. The accepted input shape comes from the existing digest extractor (2026, function digest). These are count identities, not empirical coefficients from a standard. No external numerical acceptance limit is adopted.

The existing aggregator and sentinel retain their behavior. The new evaluator is an explicit CLI/API entry point. Scheduling, provider adapters, task-profile matching, memory portability, quality scoring, pricing, credentials and gateway deployment remain outside this slice.

Method

For each selected model, T = sum(output tokens) / sum(model turns). For single-model sessions, A = sum(AskUserQuestion calls) / session count. These are the same weighted token rate and session mean defined in the repository metric source cited above. A tool absent from a present histogram represents zero calls; an absent histogram is invalid evidence.

The token criterion is T(current) ≤ T(reference) × verbosity_multiplier. The clarification criterion is A(current) ≤ A(reference) + clarification_delta. Both cohorts must meet minimum_sessions. All limits and their nonempty reference are required inputs. The multiplier must be positive, the clarification delta nonnegative and the sample minimum a positive integer. These are mathematical domain constraints, not calibrated policy values. Equality meets the upper limit. Exact fractions drive comparisons; displayed rates are rounded to one decimal place.

Counts must be nonnegative integers, excluding booleans. Each included session must carry token evidence for the selected model. Token counts without model turns are invalid. Tool totals in a session with multiple active models cannot be attributed to a selected model, so clarification remains unevaluated even when tokens can be evaluated. Other models do not add selected-model samples.

Worked example: synthetic counts

The following quantities are deliberately synthetic inputs, not provider measurements. Save each object from the current and reference arrays into its own JSON file in separate cohort folders. Save the criteria object separately, outside both folders. The tests execute these same documented inputs.

Current cohort

[
  {"turns_by_model":{"candidate":4},"out_tokens_by_model":{"candidate":40},"tool_histogram":{"AskUserQuestion":0}},
  {"turns_by_model":{"candidate":6},"out_tokens_by_model":{"candidate":120},"tool_histogram":{"AskUserQuestion":2}}
]

Reference cohort

[
  {"turns_by_model":{"reference":2},"out_tokens_by_model":{"reference":20},"tool_histogram":{"AskUserQuestion":0}},
  {"turns_by_model":{"reference":8},"out_tokens_by_model":{"reference":60},"tool_histogram":{"AskUserQuestion":0}}
]

Explicit example criteria

{
  "reference":"synthetic-example-v1",
  "minimum_sessions":2,
  "verbosity_multiplier":2,
  "clarification_delta":1
}

By independent hand calculation, T(current) = (40 + 120) / (4 + 6) = 16.0 and T(reference) = (20 + 60) / (2 + 8) = 8.0 tokens/turn. The token limit is 8.0 × 2.0 = 16.0 tokens/turn. A(current) = (0 + 2) / 2 = 1.0 and A(reference) = (0 + 0) / 2 = 0.0 calls/session. The clarification limit is 0.0 + 1.0 = 1.0 calls/session. Each cohort has two sessions, meeting the example minimum. Both rates equal their limits; the answer is WITHIN_LIMITS, exit 0.

uv run --no-project python scripts/ai/parity_evaluation.py \
  examples/current examples/reference \
  --model candidate --baseline-model reference \
  --criteria examples/criteria.json

Only immediate *.json files are loaded. Dedicated cohort folders are required: a criteria file or report in a cohort folder is not a digest. Malformed files, duplicate JSON keys and non-finite counts or criteria are rejected, not silently skipped. The JSON report excludes input filenames and transcript text.

Verification and limitations

The focused tests contain independent arithmetic expectations for the worked example, threshold equality, small exceedances, missing samples, mixed-model attribution and invalid input. CLI tests cover all exit dispositions. Existing metric tests are run alongside them.

The result assumes honest, complete, nonduplicated, task-comparable digests. A reported zero can be an extractor artifact; transcript completeness, dataset identity, freshness and sampling bias are not verified here. Session means do not establish causality, statistical significance, task completion or equivalent quality. The legacy extractor is provider-specific. No provider-neutral collection or scheduled deployment is claimed. Source data remains in its authoritative repository; this tool does not collect transcripts, copy memory or authenticate evidence.

Public disclosure covers this code, synthetic tests and this guide only. No live transcript, credential, licensed source or private measurement is included. Second-provider review remains a separate prerequisite before merge.
