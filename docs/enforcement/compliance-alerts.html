Compliance alert interpretation

The daily alert uses the dashboard's validated top-level JSON report. An empty reviewable population produces no alert. Missing or inconsistent evidence exits with an error and does not publish a compliance percentage as an alert.

Inputs and method

The dashboard supplies total, skipped, reviewable, reviewed and unreviewed commit counts, the integer compliance rate, the configured threshold and the verdict. These inputs describe review monitoring; they are not engineering acceptance limits.

reviewable = total - skipped = reviewed + unreviewed
rate = floor(100 × reviewed / reviewable), when reviewable > 0
verdict = FAIL when reviewable > 0 and rate < threshold; otherwise PASS

Source for the count partition, percentage scale, integer rounding, empty-window sentinel rate of zero and verdict equation: compliance-dashboard.sh, Main Analysis, Calculate rates and Determine verdict. The configured dashboard threshold is used; the cron wrapper does not impose a second passing threshold.

The report parser checks integer types, nonnegative counts, count reconciliation, percentage bounds, the calculated rate, the verdict and the dashboard exit status. Nested stage-drift verdicts do not replace the top-level verdict. An empty window retains the dashboard's zero sentinel for compatibility; zero is not a measured compliance failure when the denominator is empty.

Worked example

Inputs: total = 30, skipped = 28, reviewed = 1, unreviewed = 1, threshold = 80%. These counts are synthetic. Independent hand calculation: reviewable = 30 − 28 = 2; rate = floor(100 × 1 / 2) = 50%. The rate is below the threshold, so the verdict is FAIL and the alert severity is medium. The total commit count is not the denominator.

For total = skipped = reviewed = unreviewed = 0, reviewable = 0. Division is not performed, the verdict is PASS and no alert is published. The same disposition applies when all commits are skipped.

Source for the default threshold and severity boundaries: compliance-cron.sh, Configuration and Threshold evaluation; the compliance alert issue's Thresholds table dated 2026-10-12 specifies critical below 30%, high from 30% to below 50%, medium from 50% to below 80%, and pass at or above 80%. These existing policy boundaries are preserved.

Verification and limits

Cron regression tests exercise empty and skipped-only windows, severity boundaries, a configured threshold, nested verdicts, invalid reports, exit-status disagreement and the worked example. GitHub calls are stubbed; no production alert is posted by tests.

Existing commit classification and review-evidence heuristics are unchanged. Historical alerts are not closed or rewritten automatically. Invalid reports require inspection of the daily log; no independent monitoring-error notification is introduced. A no-alert result does not establish that historical commits were reviewed. Weekly aggregation remains outside this correction.
