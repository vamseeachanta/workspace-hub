Review evidence text format

Commit-bound evidence is read with filename boundaries preserved and with either LF or CRLF line endings. This prevents a filename or text-file convention from discarding a valid binding. The existing warn-first migration remains unchanged.

Inputs and method

The gate reads result files under scripts/review/results/, including the existing nested-file depth. Spaces and newlines in filenames remain part of the filename. A terminal carriage return is removed from each evidence record; other whitespace is retained and commit identifiers still require exact validation. Evidence order does not affect the union of valid bindings.

Reviewed-Commit: <full-commit-id>
Reviewed-Range: <oldest-full-commit-id>..<reviewed-full-commit-id>

The range syntax above is inclusive of both named endpoints, as defined by the repository evidence contract; it differs from Git's exclusive-left revision syntax.

Worked example

Consider a linear history M → A → B → E. The remote default branch and remote topic tip both point to M. A and B change source files and have feature subjects. E changes only a review-result file. These are synthetic inputs.

  1. The checked set is the commits reachable from E minus the commits reachable from either remote tip: {A, B, E}. The existing evidence-only rule exempts E, leaving {A, B} requiring review.
  2. A result file containing only Reviewed-Commit: A, with A replaced by its full identifier, covers {A}. Set subtraction leaves {B}: reviewed = 1, unreviewed = 1. Strict evidence mode blocks.
  3. Adding Reviewed-Range: A..B, with both full identifiers, covers {A, B}. Nothing remains: reviewed = 2, unreviewed = 0. Strict evidence mode passes. A CRLF result file gives the same answer as an LF result file.

The expected counts above are calculated directly from the enumerated sets, independently of the implementation. The executable example is case_crlf_evidence in the gate tests. case_evidence_filename_boundaries exercises a filename with a newline.

Sources and limits

The governing range, full-identifier, migration and exemption rules are recorded in Review gate defects, Evidence file format and Evidence mode. The set arithmetic above introduces no engineering constants or external acceptance limits.

The gate checks identifier coverage, not reviewer identity, review quality or authenticity. Result files may be outside the pushed tree under the existing contract. LF and CRLF support does not authorize approximate identifiers, trailing spaces, or reviews of rewritten commits. Filename enumeration errors and legacy mtime portability remain separate limitations. The migration default is not automatically changed by the date. Second-provider review remains required before merge.
