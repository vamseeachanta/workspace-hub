## BLOCKERS

### 1. The age private key is in the session transcript (CRITICAL)
Verified by digest comparison: the transcript holds 3 distinct
`AGE-SECRET-KEY` values and one **matches the current live key**.

Rotation cannot fix this from inside Claude Code: `age-keygen -o` never prints
the secret, but the harness emits a file-change notification quoting the new
file's contents back into the conversation. **Any key generated by the agent
leaks automatically.** The owner must generate it in a terminal outside the tool:

```bash
age-keygen -o ~/.config/age/keys.txt.new    # do NOT cat it
```

Then all six bundles need re-encryption against the new recipient and the
attestations rewritten. Scripts are ready.

### 2. Bundles sit on an unauthenticated writable SMB share
`/etc/samba/smb.conf` `[ace_drive]`: `guest ok = yes`, `public = yes`,
**`force user = vamsee`**. Because guests are mapped to the owner, unix
permissions give **zero** protection — `chmod` here is theatre. Any LAN device
can delete or truncate the bundles, which are the sole copy of their contents.

Fix (needs sudo):
```bash
sudo sh -c 'printf "     veto files = /work-surface-bulk/\n     delete veto files = no\n" >> /etc/samba/smb.conf && testparm -s >/dev/null && systemctl reload smbd'
```

## Incident: voice-dictation relocated out from under a live process

`voiced.py` (PID 3193, up since Jul 18, cwd inside the tree) was a **GNOME
autostart** — not cron, not systemd — so the runtime-reference gate, which only
scanned crontab/systemd/env files, passed it as clean.

On NTFS-FUSE the deletion turned its open files into `.fuse_hidden` tombstones
rather than failing loudly, and the runner's `rm -rf … && echo OK` pattern
reported success anyway. **Two failures compounding: a gate that missed the
dependency, and a runner that swallowed the resulting error.**

No data lost — restored from the verified bundle, venv confirmed importable,
daemon restarted (575 deleted mappings → 6, 90 tombstones → 0).

**Both fixed:** the gate now scans `/proc/*/cwd`, `/proc/*/exe` and `lsof +D`;
the delete is fail-closed and verifies absence explicitly. Regression-tested.

## Lessons worth keeping

1. **Git metadata is not content.** `@{u}` unset means no upstream *configured*;
   `branch -r --contains` asks about a *commit object*. Both produced false
   "unpushed work" alarms today. The reliable tests are content-level:
   `git cherry`, blob-hash comparison, or an empty cherry-pick.
2. **Declared-reference scanning cannot see hand-started processes.** Check
   `/proc`, not just config files.
3. **`force user` defeats unix permissions on a Samba share.** Verify the whole
   share stanza, not the four lines after `path =`.
4. **A monitor that has only seen healthy data is untested.** Build the fixture.
5. **Subagents inherit the gaps in their evidence packet.** Codex missed the
   third stale `PRESERVATION.md` claim because it was never briefed on deletion
   status. The packet is the dispatcher's responsibility.
6. **Pathspec commits and `--chmod=+x` conflict in this repo.** `core.fileMode`
   is `false`, so exec bits never reach the index from the working tree; the
   pathspec commit form re-reads those ignored modes and silently defeats
   `git update-index --chmod=+x`. Two practices both individually correct.
   Fix forward with a second commit rather than force-pushing.
7. **The auto-sync pusher is live and fast.** During PR work it pushed the
   agent's own commit before the agent did, producing a spurious
   non-fast-forward rejection. It also moved the main checkout across three
   branches unprompted. Check the reflog before reacting to a rejected push.
8. **`workspace-hub` is PUBLIC — codename-redact before writing a handoff.**
   This document was blocked by the Client-PII Gate on first push: operational
   accuracy (real directory names) collided with a public repo. The gate
   withholds matched values from CI logs by design, so read the line numbers it
   reports and inspect them locally. Write handoffs codenamed from the start
   rather than redacting after the fact.
