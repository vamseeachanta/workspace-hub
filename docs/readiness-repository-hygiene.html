Repository hygiene and equality reporting

Manifest-driven synchronization advances clean checkouts only when the current commit is an ancestor of the fetched branch. Dirty trees, local-only commits, wrong branches, activity markers and failures remain visible without automatic recovery. Equality evidence carries public aliases, timestamps, flags and counts; private manifests retain checkout locations. Scratch inventory reports residue and does not delete data. This implements the software portion of issue 3499.

Inputs and method

Each installation supplies a private YAML manifest using config/hygiene/manifest.example.yaml. The example's timeout, freshness, size and age numbers are synthetic test inputs, not operational recommendations. All paths are relative to an explicitly supplied root and must resolve inside it. Repository IDs are public aliases; do not encode private names in them. The branch, activity marker, Git timeout, freshness limit and scratch criteria are required inputs. An empty scratch list reports not_evaluated.

  1. Validate the complete manifest before fetching. Acquire a status-file lock and then a common-Git-directory lock for each checkout. Lock contention reports busy.
  2. Check the activity marker, branch and tracked/untracked changes. Fetch the explicit branch from origin. Never switch branches, stash, reset, push or delete.
  3. Require the old HEAD to be an ancestor of the fetched object, recheck local state after the fetch, then merge with --ff-only --no-autostash --no-overwrite-ignore. Local-only and divergent commits report wedged. A Git failure is isolated to that repository so subsequent repositories still report.
  4. Write the completed snapshot through atomic replacement. A failed attempt preserves the last successful timestamp; only a successful update or already-current checkout refreshes it. Old or malformed evidence cannot grade healthy.
  5. Inventory regular scratch files without following symlinks. Sum file sizes; count files older than each configured age. Compare with the supplied size limit. An inaccessible root reports error. No cleanup is performed.

Concurrency requires every process that modifies a managed checkout to acquire repo-hygiene.lock in its common Git directory, and execution routines to create the configured activity marker before starting. A marker is an extra refusal signal, not mutual exclusion. Non-cooperating writers cannot be protected by this service. Do not enroll active development checkouts or running software without that coordination. Git hooks remain enabled.

Equality collection and scheduling

scripts/hygiene/maintain.sh invokes sync, collects equality through the existing collector and attaches the allowlisted status as dimensions.repo_hygiene. It collects even after sync refuses a checkout. A collector failure, including partial YAML followed by failure, preserves the previous equality file and returns failure. The combined YAML uses the existing publisher's input format; raw Git output and manifest paths are never attached.

Configure these variables in a private environment file:

HYGIENE_CHECKOUT=<repository checkout>
HYGIENE_ROOT=<managed root>
HYGIENE_MANIFEST=<private manifest>
HYGIENE_STATE=<external state directory>/repo-hygiene.json
HYGIENE_EQUALITY_OUTPUT=<equality input directory>/equality-<public alias>.yaml
HYGIENE_PUBLIC_ALIAS=<existing public roster alias>
HYGIENE_COLLECT_TIMEOUT_SECONDS=<collection timeout>
WORKSPACE_HUB=<repository checkout>
TMPDIR=<external temporary directory>

Use the same equality input directory as the existing publisher's EQ_STATE_DIR configuration. Maintain the existing weekly and on-change publication routines. Choose freshness limits that cover collection and publication latency; a local collection alone is not evidence of remote publication. The service does not publish, enable itself or change an existing schedule.

For Linux user services, place the supplied service and timer templates in the user service directory. Store the private environment in .config/repo-hygiene/environment beneath the user's directory. After reviewing paths, inputs, producer locks and existing schedules:

systemctl --user daemon-reload
systemctl --user enable --now repo-hygiene.timer
systemctl --user start repo-hygiene.service
systemctl --user status repo-hygiene.service repo-hygiene.timer

The timer's every-minute cadence follows the watchdog design linked from issue 3499; override it for each installation. For cron, source the same environment and invoke bash "$HYGIENE_CHECKOUT/scripts/hygiene/maintain.sh" on the approved schedule. Collection timeouts and repository locks prevent overlapping sync mutations. Both Python with PyYAML and the repository's interpreter resolver must work in the scheduler environment. The Python module also carries inline PyYAML dependency metadata for direct uv run --script use.

The matrix adds a repository hygiene group, with per-repository last-success age, dirty/wedged flags, state and residue totals. Ages are recomputed when the matrix builds. Existing unreachable and stale-source precedence remains in force. Malformed/missing status reports missing evidence; future or expired snapshots report stale. A current dirty, wedged or failed attempt cannot inherit a healthy verdict from an earlier success. Repository aliases and every public field are validated before rendering.

Worked example

Construct a disposable origin with commit A. Clone it, append commit B to origin, and run sync on the clone. The ancestry graph is A → B, so A is an ancestor of B; the expected result is clone HEAD = B, status synced and wedged=false. Run again: HEAD remains B and no extra commit appears. Add local commit C to the clone while origin remains B: C is not an ancestor of B, so status wedged and HEAD remains C. The integration tests construct this graph independently using Git.

For a synthetic snapshot at 2026-01-01T00:00:00Z and an input freshness limit of 60 seconds, a build at 00:01:00Z has age = build time − snapshot time = 60.0 seconds; 60 ≤ 60, so synchronized repositories pass. At 00:01:01Z, age = 61.0 seconds and 61 > 60, so the result is HYGIENE-STALE. A four-byte scratch file exceeds an input limit of three bytes. Its age of ten seconds exceeds an input limit of five seconds, yielding one expired file and attention. The file remains unchanged.

Installation across active nodes, Windows-native locking/scheduling, production publisher verification and a month without manual cleanup remain NOT_EVALUATED. The implementation uses POSIX locks. Scratch pruning requires an independently specified retention and rollup contract; reports do not authorize deletion. Repeated collection does not restart running applications.
