Prepare a bounded analysis

  1. State the engineering question, quantities of interest, intended decisions and applicable model-family limits. Route detailed shell/solid stress to the qualified structural FE adapter; OrcaFlex supplies global marine response and slender-member results.
  2. Resolve source data, geometry, units, axes, sections, material properties, connections, environment and load combinations. Mark values as sourced, derived, assumed or missing; unresolved required inputs block the solve.
  3. Choose the existing typed specification and generator. Record unmapped fields explicitly. Schema validity and a high specification-audit score do not demonstrate physical adequacy.
  4. Bind code revision, solver/API version, complete input dependencies and content hashes to a unique run attempt. Preserve private inputs in project-scoped storage.
  5. Confirm the actual task account, executor capability, current licence availability and authority to use that seat for this project. Licence availability is not evidence of cross-project permission.
  6. Check the current plan and child approvals. The proposed initial ceiling is one worker, one solver thread and one active managed OrcaFlex job. Treat enforcement as planned until its tests and deployment evidence exist; CPU count does not establish licence capacity.

Qualify the engineering result separately

Preserve the existing workflow-pack lifecycle: located → extracted → parameterized → reproducible → engineering-validated → approved-for-reuse. Keep the registry's existing template-readiness meaning; do not silently upgrade it to numerical qualification.

  • Semantic proof: compare engineering-significant data, units and conventions; list unsupported residuals. Reuse the existing claim boundary.
  • Native proof: record loadability and bounded run outcomes with the native proof protocol and its evidence template. Its pass-run classification alone does not mean engineering validation.
  • Numerical verification: define force/moment balance, mesh and time-step sensitivity, comparison references and tolerances for the particular quantities of interest. Avoid universal numerical thresholds without a method basis.
  • Physical applicability: verify loads, restraints, material/element models and geometry against the intended question. Reject unsupported elements or mappings instead of silently omitting them.
  • Global-to-local transfer: preserve coordinate transforms, units and simultaneous force/moment or displacement states. Verify transferred balance; do not assemble a load case from unrelated maxima.
  • Engineering acceptance: cite the applicable standard edition/section and existing Citation sidecar for derived constants. Record human review and permitted reuse limits. Wiki heuristics and solver agreement alone are insufficient.

Advance through the strategy's qualification ladder: beam, plate, suspended line, coupled assembly, detailed joint, then additional nonlinear/shell/fatigue families. A method, input, template or solver-version change requires impact review of affected qualification records.

Recover, upgrade and hand off

  • Cancellation / timeout: use the deployed lane's owned-process cancellation contract; verify the process tree has stopped before releasing its execution guard. Preserve logs and mark the attempt failed or cancelled. Planned containment controls must not be claimed as installed.
  • Retry: classify the error and confirm the input is still authorized. A changed input, revision, target or resource request requires a new bound attempt and the applicable approval; never overwrite the old evidence.
  • Upgrade: inventory active consumers, drain the selected lane and retain prior task/environment/pins privately. Enable new batch contracts only after compatibility and task-context acceptance pass.
  • Rollback: quarantine requests requiring the new contract and keep that workflow disabled. Restoring backup configuration does not authorize reactivation: first prove the owned process tree has stopped and resolve execution-guard ownership. Uncertain ownership or an unkillable process keeps both consumers disabled. Do not assume an old worker understands new safety fields.
  • Handoff: record exact commands, source revisions, input/output hashes, solver/API versions, origin/target contexts, resource limits, results, unresolved findings and next issue checkpoint. Distinguish executed, failed, skipped and untested cases.
