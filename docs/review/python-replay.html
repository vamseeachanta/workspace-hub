Python replay import evidence

The recorder captures separate production and test import observations, bundles observed project sources, and retains commands, output digests and frozen inputs. Verification checks a separately retained receipt digest against the bundle and current checkout. These observations support review of the executed Python paths; they do not qualify numerical results or establish unexecuted-path coverage.

Scope and method

Each command runs sequentially in a fresh Python interpreter. Source-loader and profile observations retain package initializers, function-local imports, dynamic imports and modules removed from sys.modules. The final module table adds imported sources that contain no Python calls. Flat and conventional src layouts are recognized. Project module names observed outside the owning checkout refuse an exact-current observation.

All checkout Python source bytes and declared inputs are frozen before either command. Observed source digests are compared with this snapshot, and all checkout Python files, input bytes and Git HEAD are checked after each command. Observed sources are copied from the frozen snapshot into the bundle. The recorder bypasses project bytecode caches through SourceFileLoader so reviewed source bytes supply standard source imports.

The digest method is raw-byte SHA-256, following the Python standard-library hashlib documentation. Observation interfaces follow sys.setprofile and SourceFileLoader. These public documentation pages were checked on 2026-10-22. No engineering coefficients, equations or numerical acceptance limits are introduced.

Worked synthetic example

Create a disposable checkout with the following literal inputs. The integer is an arbitrary fixture marker; it is not an engineering constant.

sample/__init__.py:  (empty file)
sample/helper.py:    VALUE = 7
sample/main.py:
    def run():
        from .helper import VALUE
        print(VALUE)
    run()
test_run.py:
    def test_value():
        from sample.helper import VALUE
        assert VALUE == 7
input.json:          {"synthetic": true}

From the repository containing the recorder, set CHECKOUT to that disposable checkout and BUNDLE to a new directory outside it. The following shell commands illustrate capture and verification. The receipt digest printed by capture shall be retained separately as PIN for review.

python scripts/review/python_replay.py capture \
  --root "$CHECKOUT" --bundle "$BUNDLE" \
  --production '["-m", "sample.main"]' \
  --tests '["-m", "pytest", "test_run.py", "-q", "-p", "no:cacheprovider"]' \
  --input input.json
python scripts/review/python_replay.py verify \
  --root "$CHECKOUT" --bundle "$BUNDLE" --receipt-sha256 "$PIN"

Bundle contract and review

  • receipt.json contains schema, revision, recorder digest, separate run inventories, exact commands, interpreter/version observations, input/source hashes, output hashes, limitations and errors.
  • sources/ and inputs/ retain original bytes at checkout-relative paths. Each run retains stdout, stderr and its runtime inventory.
  • The externally retained receipt digest authenticates the expected manifest bytes only. A receipt that is edited to omit an imported helper fails this pin.
  • Verification rechecks bundle bytes, current checkout sources, input digests, HEAD and recorder digest. A changed file requires replay and renewed review.
  • The existing scripts/review/build-review-packet.py can inline bundled source text for a reviewer. Review shall include the pinned receipt, source union, inputs and captured evidence; a test count alone is insufficient.

Known limits and disposition

exact_current denotes agreement of the recorded file observations and successful command exits within the stated execution scope. It does not mean that an independent review or engineering acceptance has passed. A null revision means Git revision identity is unavailable; such a bundle cannot substantiate an exact Git-revision claim. Dirty files are identified by their source hashes rather than being inferred from HEAD.

Only trusted, single-process, single-threaded Python source commands are supported. Observed additional threads, child processes and project extension or bytecode-only modules refuse exact-current observations. Native libraries loaded by external dependencies, custom loaders, generated code, startup hooks, environment identity and file reads not declared as inputs are not qualified. External modules are recorded with observed paths and installed distribution versions where a mapping exists, plus the interpreter version; they are not bundled project source. An absent distribution mapping does not establish a dependency version.

The recorder is not a security boundary. A target that tampers with tracing or receipts can invalidate observation. Before/after hashing cannot exclude every transient edit restored between observations. Imports under an unrelated alias cannot reliably establish project ownership. Packaging layouts other than flat or conventional src layouts require separate qualification. Checkout scans exclude Git metadata, standard virtual environments, node_modules and bytecode caches; symlinked Python files outside the checkout are refused.

Commands are not retried automatically. Each attempt requires a new bundle folder, preserving previous evidence. Bundles may contain sensitive paths and raw output; public distribution requires an independent content review. The executable receipts are retained evidence, not substitutes for authorization.
