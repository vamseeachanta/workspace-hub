Publication eligibility across dependency closure

The validator checks reviewed record decisions, transitive dependencies, retained-input metadata and the complete staged JSON file set. An eligible receipt establishes agreement with these declarations; it does not authenticate approval, establish source rights or publish data. This reusable implementation addresses issue 3942.

Implementation plan

The first slice will validate record identity, reviewed decisions and evidence fields. The second slice will compute dependency closure and distinguish retained originals from eligible exports. The third slice will validate the exact staged JSON files and provide an executable example. Tests will precede each implementation increment. Adversarial inspection will target approval replay, retained-input leaks and false empty acceptance.

The staging correction will separate the public record projection from private retention metadata, compare every staged digest with both retained digest kinds and extend the worked example. Regression cases will cover relationship dependencies, inherited parents, missing sources, reversed graph order and closure across files.

Contract and method

The implementation is scripts/governance/publication_eligibility.py. The JSON bundle contains exactly publication, records, decisions, originals and files. Unknown top-level or record fields are rejected. Each record has a unique id, explicit dependencies, original_ids and a payload object. The adapter shall enumerate every source, entity, relationship and parent dependency; no dependency is inferred from prose or arbitrary payload fields.

Each decision supplies decision, basis, reviewer and evidence_ref. Eligible decisions are eligible_factual_derivative and permission_granted; permission also requires permission_ref. Missing, unresolved, prohibited or malformed decisions defer the record. The maintainer shall independently verify the public-source basis and any permission record; a nonempty string is not evidence authentication.

E(initial) = empty set
E(next) = E union {r: decision(r) valid and dependencies(r) subset of E}
D = all records minus E

This least fixed point defers missing dependencies and ungrounded cycles. Its source is issue 3942's transitive-deferral requirement, not a numerical engineering standard. Records representing source evidence are graph nodes too. All eligible records shall appear exactly once in the export; no deferred record may appear. An empty export, including an all-deferred bundle, is blocked.

Each retained original declares id, retention equal to private_retained, raw_sha256, archive_sha256 and an opaque evidence_ref. The raw digest identifies original received bytes; the archive digest identifies archive bytes and never substitutes for a raw digest. The validator checks declarations only. The private retention system shall independently verify the retained bytes, private Git disposition and, for client and other third-party material, source-specific copying rights. Pending retention blocks validation. Licensed standards are outside this adapter's retained-original format. Codes and standards follow the owner's ruling of 28 Oct 2026 (.claude/rules/codes-standards-data-routing.md): no internal gates; outward work quotes with citations and reconstructs charts; only original PDFs and whole sections stay off public surfaces.

The trusted caller supplies an externally authenticated approved SHA-256 digest of the entire bundle. Canonical JSON uses UTF-8, sorted object keys, compact separators, unescaped Unicode and finite numbers. Every payload, original digest, decision, staged hash and publication destination is bound to that approval. The destination argument shall match publication.destination; the audience is public. A digest supplied by the bundle itself does not authenticate human approval.

The stage is an exclusively owned frozen directory. Every file is declared once with path, role equal to eligible_export, ordered record_ids and byte sha256. Each UTF-8 JSON file contains exactly {"records": [...]}, matching the public projection of the pinned records in declared order. A public row contains exactly id, dependencies and payload. The private bundle continues to require original_ids; it is omitted from every public row.

public(r) = {id: r.id, dependencies: r.dependencies, payload: r.payload}
retained = {o.raw_sha256, o.archive_sha256 for each retained original o}
For every staged file f: sha256(f) must not belong to retained.

These rules implement the data handling contract's separation of protected original retention and public publication. Digest equality identifies known retained bytes even when an entry claims an export role. Both digest kinds are checked independently; neither an archive digest nor an export digest establishes the raw-source digest. Symlinks, special files, ambiguous relative paths, undeclared files, duplicate exports, changed bytes, retained-original roles and payload mismatches block acceptance. Raw originals, private manifests and the bundle itself stay outside public staging.

Only authorized public identifiers may appear in exported record IDs and dependency links. Retention identifiers and evidence references remain in the private bundle. The aggregate receipt exposes counts and fixed error codes, never private identifiers, paths, payloads or exception messages. Deferred-record identity accounting remains in the private bundle; public reporting uses deferred counts.

This changes the accepted public row format: producers that previously serialized complete private records shall omit original_ids, regenerate export hashes and obtain approval of the changed bundle. Existing approval digests cannot be reused. Additional private fields in staged rows fail with export_record_mismatch; known retained bytes fail with retained_bytes_in_stage.

Worked example: inputs, method and answer

examples/governance/publication_eligibility_example.py writes synthetic inputs into a new explicitly selected directory and prints the candidate bundle digest. It creates no approval record. The graph is source -> entity -> cost (where each right-hand node depends on its predecessor), plus independent. Source is unresolved; all other decisions are synthetically eligible. Hand evaluation defers source, then entity, then cost, leaving only independent eligible.

The private bundle links each record to synthetic-input and separately declares raw and archive digests. The public file contains only:

  --bundle example/bundle.json --stage example/stage \
  --approved-bundle-sha256 APPROVED_DIGEST --destination public-example

The generator shall be run in external scratch storage. Placeholder APPROVED_DIGEST deliberately blocks validation until replaced with the approved digest. In the synthetic regression only, approval is simulated explicitly.

The expected counts are independent graph cardinalities. No measured values or engineering acceptance limits are asserted. Raw and archive digests are calculated from separately labeled synthetic byte strings; no actual archival retention is claimed.

Known limits and follow-up

This is an opt-in validator, not an installed publication hook. Integration into a producer, authenticated approval transport, access to private retention evidence and source-specific rights decisions for client and other third-party material remain external responsibilities (codes and standards need none, per the owner's ruling of 28 Oct 2026). Complete inventory and lineage are trusted adapter inputs. The validator cannot discover concealed relationships, classify arbitrary payload rights, redact free text or establish that original bytes exist from a declaration. The public projection removes structural retention links; it cannot detect private text embedded in a payload or record ID. Digest exclusion detects exact declared bytes, not rewritten or undeclared originals. A hostile concurrent writer is outside the frozen-stage contract; acceptance shall be bound to the same bytes actually published. No data is moved, deleted or published, and no third-party workflow is changed.
