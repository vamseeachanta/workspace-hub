Runtime deployment surfaces

The deployment check compares supported installed symlinks with the corresponding origin/main runtime bytes. Reference artifacts are reported separately and do not contribute to deployment drift. Existing instructions are preserved when replacement cannot be staged or published.

Method

The gate excludes intentionally undeployed providers before reading source or destination bytes. For deployed providers, absence is ABSENT; a regular file is UNLINKED even when its bytes match; a linked file is CURRENT when its content digest matches the origin blob and STALE otherwise. Claude admission failure is BLOCKED. Any deployed drift returns failure. This does not establish that a provider process has loaded the instructions.

The installer creates a candidate symlink in a temporary directory beside the destination and verifies its transport before touching existing instructions. An existing file or link is copied to a timestamped backup, preserving symlink identity. Only then is the staged link renamed over the destination. A failed link, backup or rename reports NEEDS-ATTENTION and preserves the existing runtime; other providers continue. Directories are preserved and rejected. Backup-name collisions are refused. A failed publish may leave a verified backup.

Known limits

Gemini integration remains deferred to issue 2719 Phase 6; no agy loader is installed. The check continues to require deployed Claude, Codex and Hermes surfaces; a missing provider directory does not prove exemption. Native Windows replacement behavior and actual provider loading are not established by the synthetic tests. The older deployment-rule prose describing refreshed copies is superseded by the symlink criterion in issue 3833 and this implementation.
