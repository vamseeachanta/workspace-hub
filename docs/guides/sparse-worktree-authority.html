Sparse worktree content authority

The index preflight rejects an uninitialized index when HEAD contains tracked leaves. Sparse omission is valid when the index retains its entries. Content checks distinguish working files, the effective index and the committed tree. No engineering constants are used.

Scanner findings use exit 1; a completed scan without new findings uses exit 0. A preflight refusal happens before ordinary scanner or review inspection. The preflight is non-mutating and never repairs indexes, removes locks or deletes worktrees.

Worked example

Basis: two independently enumerated leaves, keep/a.txt and omit/b.txt. Each contains the literal text fixture. A prepared full index represents both leaves. A cone containing only keep omits the second file but retains its index entry with the skip-worktree tag. The Git 2.43 worktree and sparse-checkout manuals define these states.

git init example
cd example
mkdir keep omit
printf 'fixture\n' > keep/a.txt
printf 'fixture\n' > omit/b.txt
git add .
git commit -m fixture
# Run the checker from an existing checkout of this tooling:
git worktree add --detach --no-checkout ../interrupted
bash "$TOOLS/scripts/enforcement/check-worktree-index.sh" ../interrupted
# exit 1: empty index with nonempty HEAD; recreate after ownership checks.
# Use a separate destination; do not repair or delete the interrupted worktree.
git worktree add --detach ../prepared
git -C ../prepared sparse-checkout set --cone keep
bash "$TOOLS/scripts/enforcement/check-worktree-index.sh" ../prepared --fresh
# worktree-index: head=2 index=2 skip-worktree=1 OK
# exit 0

The example requires a configured fixture commit identity and TOOLS pointing at this tooling checkout. The regression fixture uses commit-tree in a disposable repository, avoiding installed commit hooks. Its expected counts follow from the two named leaves, independently of the checker implementation.

Integration and limitations

The checkout helper checks the resulting index after checkout and before size reporting. The shell plan/artifact review entry points check their current repository before argument processing and broad inspection. The standalone checker accepts an explicit root. Other creation paths, including readiness publication and local CI, retain their existing contracts; no coverage of every worktree creator is claimed.

The enforcement installer embeds the learning entry point in the installed post-commit file. Only the learning payload changes here. Effective hooks-path resolution and pre-push event installation remain separate work. Legacy generated learning calls are replaced without removing independent hook steps. No live hooks are installed by the tests.

Learning failures are recorded in the Git common directory as post-commit-learning-failures.log; each failed invocation adds one event. The diagnostic reports the observed event count. Concurrent append order is not a transactional sequence. Helper output is retained in post-commit-learning-output.log. If the common directory cannot be resolved or written, stderr reports the loss and persistence/counting is not established. Optional learning steps absent from the pinned commit retain their existing skip behavior. Learning side effects beyond dispatch are not qualified by these fixtures.

Linux execution is tested. Other platforms are not evaluated. Existing scanner requirements, including Bash associative arrays and the optional realpath-based baseline-key conversion for explicit external files, remain. The report wrapper's line-oriented finding format has not been qualified for newline filenames; the scanner itself enumerates and scans those paths. Independent provider review remains pending.

Root-resolution audit

run-all-tests.sh and run-benchmarks.sh already use structural roots and are preserved. The same resolution is added to run-cross-repo-integration.sh and refresh-fixtures.sh. scripts/lib/tier1-repos.sh already anchors its configuration to its source location. The scanner clears inherited repository bindings for explicit-root Git queries.

The bounded audit of testing entry points and enforcement shell scripts found the following remaining Git-root candidates. Their presence identifies review work, not a proven failure: check-soul-runtime-drift.sh, check-soul-deployment-drift.sh, report-no-abs-paths.sh, install-hooks.sh, upgrade-enforcement.sh, correction-to-skill-candidates.sh, stage-prompt-drift-status.sh, compliance-weekly-report.sh, smoke-test-escalation.sh, compliance-dashboard.sh, check-harness-file-size.sh, compliance-cron.sh, require-tdd-pairing.sh, check-marker-label-parity.sh, require-stage-prompt-drift.sh, require-review-on-push.sh and check-canonical-drive-paths.sh. Additional phase-gate candidates require-plan-review.sh, require-cross-review.sh and require-verify-artifacts.sh are subject to the same preflight while their existing review requirements remain. Migration must not reactivate retired marker approval.
