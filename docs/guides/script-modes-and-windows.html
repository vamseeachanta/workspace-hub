Script modes and Windows portability

Summary

Index modes and physical permissions are independent observations. A script intended for direct execution has a shebang and Git mode 100755. Interpreter invocation tolerates a lost physical execute bit. The read-only audit reports indexed content, including content that differs from the working tree.

Mode policy and audit

Git 2.44.0 git-ls-files, --stage defines mode, object, stage and path output. git-update-index, --chmod defines executable index changes. These sources govern the mode literals and fixture setup below. They were retrieved on 2026-10-22.

python3 scripts/enforcement/audit_script_modes.py --format table
python3 scripts/enforcement/audit_script_modes.py --format json
python3 scripts/enforcement/audit_script_modes.py --check \
  --exemptions config/script-mode-exemptions.json

The default output is JSON. Table output escapes line breaks, tabs, carriage returns and pipes. Symlinks and submodules are excluded. Unmerged entries are an error. The audit reads indexed blobs and never changes files or Git metadata. Shebangs with binary payloads are included.

The guard returns 0 when no unexempted non-executable shebang remains, 1 when one remains, and 2 for invalid input or a Git read error. These are the command's defined interface values. Executable files without shebangs are reported for investigation; they do not block the guard because executable binaries need no shebang.

Exemptions name exact repository-relative paths and explain why execution is intentionally disabled. Wildcards, parent traversal and empty reasons are errors. An existing sourced review library is the initial exemption. Baseline failures are not automatically exempted. Repository-wide guard enrollment will follow review and repair of the existing mode inventory.

Worked three-file fixture

The following commands will be run only inside a disposable repository. Each mode is assigned explicitly, so the expected result is independent of umask and filesystem executable-bit detection.

git init example
cd example
printf '#!/bin/sh\ntrue\n' > 'needs exec.sh'
printf '#!/bin/sh\ntrue\n' > run.sh
printf 'plain text\n' > plain.txt
git add -- 'needs exec.sh' run.sh plain.txt
git update-index --chmod=-x -- 'needs exec.sh'
git update-index --chmod=+x -- run.sh plain.txt
git ls-files --stage

Hand calculation: the non-executable shebang contributes one finding; the executable shebang contributes none; executable plain text contributes one. Thus the audit emits two findings, and the unexempted guard returns 1.

Calling helpers and reading settings

Use bash "$VALIDATOR" for Bash helpers and python3 "$RENDERER" for Python helpers. The review submitters already render through uv run --no-project python, which also avoids execute-bit dependence. A correct Git mode remains useful for direct callers; interpreter invocation does not repair index or physical modes.

The readiness hook check removes carriage returns from extracted jq values before testing paths. Missing paths use Bash printf '%q' escaping, making control characters visible. The regression isolates the production function and supplies CRLF settings and CRLF jq output without probing services.

Known limits

The baseline index contains 1,254 non-executable shebangs and six executable files without shebangs. These counts refer to the inspected index before staging the renderer mode repair. Of the findings, 122 are under paths excluded from this contribution's staging manifest. A repository-wide repair and guard enrollment remain pending. No broad exemption list is introduced to hide this inventory.

Native Windows execution and independent provider review remain unverified.
