Personal operations evidence summary

The local summary tool coordinates travel, media archiving and private workspace readiness without copying personal records into the public repository. It evaluates self-reported evidence; service availability and evidence authenticity are not established. The initiative's live-surface and terminal-state criteria remain unfulfilled until private integrations and their evidence are independently checked.

Scope and sources

Initiative 3609 requires travel programs, media archives and private workspaces to have live-facing surfaces and terminal states. The linked travel comparison epic requires trip parameters, a current cost basis and explicit decisions. Media epic 3589 requires extraction, integrity, off-site copies and an incremental-sync decision. The linked private-workspace epic requires data boundaries, membership restrictions and cross-scope isolation checks. These issue requirements were inspected on 2026-10-22; the summary criteria below do not replace their detailed acceptance criteria.

The existing repository mission portfolio assigns cross-repository coordination to the hub and execution to the owning repositories. The data-handling contract requires explicit freshness and distinguishes evidence claims from permission or proof. No external dataset is ingested or allocated. The existing source catalog and domain index remain authoritative; no parallel personal-data registry is introduced.

Implementation slices

  1. Validate a narrow JSON evidence vocabulary and reject unknown fields.
  2. Evaluate the domain criteria below with explicit missing and terminal states.
  3. Produce local HTML or JSON summaries and exercise the synthetic worked example.

Private service integrations, trip bookings, archive manipulation, messaging-channel creation and decisions on the linked epics remain later work. No network operation, credential lookup, scheduling, deletion or cross-repository mutation is performed.

Input contract

The top-level object may contain only travel, media and workspace. A missing domain produces NOT_EVALUATED. Each present domain has exactly state (active or complete) and checks. Every provided check has exactly result (pass, fail or unknown), reference, checked_at and valid_until.

References are opaque lowercase tokens starting with evidence-, followed by letters and optional hyphen-separated letter groups. Keep the mapping to actual records in the owning private repository. No names, links, personal text or paths belong in these tokens. This vocabulary reduces accidental disclosure; it cannot establish whether a token encodes private information. Real inputs and generated reports require private storage and audience review.

Every complete domain additionally requires a passing terminal check. A pass is a declaration that the criterion was satisfied, never an instruction to execute an operation. Terminal evidence shall identify the actual disposition in the private record; arbitrary closure of a tracking issue does not establish completion.

Method and status meanings

All timestamps require timezones. A supplied observation is current only when checked_at <= as_of < valid_until and checked_at < valid_until. The caller supplies the assessment time and the expiry; no age limit or physical coefficient is assumed. This interval test implements the freshness ordering in the data-handling contract. It is a logical comparison, so engineering equations and numerical standards constants do not apply.

Table: synthetic logical truth table, with no averaging or cross-domain completion inference.

A stale failing observation becomes unknown; its prior failure is not established at the new assessment time. An optional terminal check supplied for an active domain is still validated; a current failure blocks the domain. Malformed input aborts the entire assessment without emitting input content. Duplicate keys and non-finite JSON tokens are rejected.

Worked example: inputs, method and answer

The synthetic input declares travel complete with passing checks, media complete with a failed off-site check, and supplies no workspace record. All supplied observations run from 2030-06-01T11:00:00Z to 2030-06-02T11:00:00Z. The assessment time is 2030-06-01T12:00:00Z. These dates are invented example inputs, not observed records.

Hand calculation: the assessment falls inside each declared interval. Every travel criterion and terminal check passes, yielding COMPLETE. The media off-site check fails, yielding BLOCKED regardless of the passing terminal check. The workspace record is absent, yielding NOT_EVALUATED. No domain result establishes live availability.

python scripts/operations/personal_operations.py examples/operations-evidence.json \
  --as-of 2030-06-01T12:00:00Z --output report.html

Run from the repository root with a supported Python interpreter. The output path shall be a new file in an appropriate private location for real evidence. The command returns the incomplete-result status for this example and creates an HTML report with the assessment time and criteria version. Without --output, fixed summary labels are written as a JSON object to standard output, with the assessment time, criteria version and self-reported basis. Evidence references are omitted from both forms. Existing output files and the input are never overwritten.

Exit codes follow this tool's interface: zero means every domain is COMPLETE; one means a valid assessment includes another state; two means invalid input or an inaccessible file. These are interface identifiers, not numerical acceptance limits.

Verification and limits

The accompanying tests derive expected states from the hand evaluation above and exercise missing criteria, failures, expiry boundaries, timezone offsets, malformed records, duplicate keys, report metadata and file preservation. No private content, service probe or external numerical reference is required. Provider-independent review and verification of actual evidence remain prerequisites for relying on a real summary.

The public example and guide are synthetic. Actual private surfaces, backup status, family membership and travel decisions have not been verified by this change. Reports are static snapshots and shall be regenerated against current evidence; the initiative is not declared complete by this tooling.
