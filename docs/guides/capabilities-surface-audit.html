Capabilities surface audit

Summary

The capabilities hub is the canonical overview. Repository landing pages redirect there; technical reports, dashboards, PDFs and explorers retain their existing URLs. The read-only audit checks explicit source files and navigation inputs without generating pages, fetching data or changing another repository.

Scope and sources

Issue #3494 selects the single-surface design over the earlier alternatives in epic #3485. The redirect implementations already landed in digitalmodel PR #1573 and worldenergydata PR #1001. This audit complements those changes; it does not recreate their pages or introduce another registry or HF client.

The July 2026 merged source stubs supply the exact HTTPS canonical URL, immediate refresh (zero delay), readable fallback link and noindex, follow directive. These are web routing requirements; no engineering equation, coefficient or acceptance limit applies.

Method

  1. Read the two declared landing files from caller-supplied repository roots.
  2. Require exactly one canonical link and immediate refresh in the head, both targeting https://www.aceengineer.com/capabilities/, plus one robots directive containing only noindex, follow. Ambiguous duplicate attributes are rejected with rule markup.
  3. Require a matching text link in the body. Comments, empty anchors, hidden ancestors, inline hiding styles and head links do not satisfy this check.
  4. Reject rich landing content such as tables, headings, images, scripts and embedded reports. Only the redirect prose structure is accepted.
  5. For each explicit --links input, report line numbers for absolute GitHub Pages URLs to the exact repository capabilities root or its index.html. Preserve technical subpage links. Replace reported landing URLs with the canonical hub after checking their context.

JSON entries use PASS, FAIL or NOT_EVALUATED. An unreadable or missing source is NOT_EVALUATED. The command succeeds only when every supplied input passes. Diagnostics show repository-relative source names, rule names, input ordinals and line numbers; they never echo file content or caller paths.

Worked example: inputs, method and answer

From a workspace containing the two source repositories, supply their roots explicitly. The roots below are illustrative relative directories:

uv run --no-project python scripts/content/check_capabilities_surface.py \
  --digitalmodel-root ../digitalmodel \
  --worldenergydata-root ../worldenergydata \
  --links docs/reports/casing-design-worklog.html

Example input for either landing file, using the merged routing contract:

<html><head>
<link rel="canonical" href="https://www.aceengineer.com/capabilities/">
<meta http-equiv="refresh" content="0; url=https://www.aceengineer.com/capabilities/">
<meta name="robots" content="noindex, follow">
</head><body><main><p>Capabilities have moved:
<a href="https://www.aceengineer.com/capabilities/">Capabilities</a>
</p></main></body></html>

Hand inspection finds one canonical link, one matching immediate refresh, the robots directive and readable body link, with no report content. Therefore each repository entry is PASS. After replacing the worklog's landing links with the hub, links-1 is also PASS with an empty lines array; the command succeeds.

Changing the refresh destination produces FAIL with rule refresh. A missing repository source produces NOT_EVALUATED with rule source-unreadable. Both cause a nonzero exit. Technical paths such as /capabilities/insights.html, /capabilities/pdf/brief.pdf and /well/casing-design-explorer.html remain outside the landing replacement rule.

Verification and limits

tests/content/test_check_capabilities_surface.py supplies literal contract mutations and CLI examples. Expected results follow hand inspection of those inputs, rather than output from the checker. The CLI example also verifies byte preservation of all supplied repository files.

This is a structural source audit, not an HTML browser, deployment check, semantic comparison of prose, SEO guarantee, registry validator or HF data qualification. Stylesheet rules can affect visibility beyond the inline cases checked. Arbitrary prose in allowed paragraph tags still requires review. Relative URLs need publishing context and are not classified. Link files must be explicitly enumerated; a passing command does not establish whole-workspace coverage. Missing inputs are never silently treated as passed.

Later work may reconcile figures from qualified registry evidence and check deployed URLs. Neither is required to redirect the landing pages. Serving-page improvements remain in the website repository.
