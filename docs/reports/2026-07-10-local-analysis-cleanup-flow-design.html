Interactive ecosystem cleanup with a public/private evidence boundary

The cleanup will review every top-level folder interactively, preserve explicit user authority for every disposition, and route evidence to the correct repository surface without publishing private project identifiers.

Design approved by user

Outcome

The machine-local root will be reduced only through explicit, folder-level decisions. Local Claude permissions will remain local and untracked. The exact cleanup ledger will live in a private control-plane repository; the public workspace will receive a sanitized transactional record and human-facing report.

Three evidence surfaces

Machine-local

.claude/settings.local.json remains untracked. Exactly two stale one-off worktree-removal rules will be removed; all other permissions will be preserved.

Public control plane

Sanitized counts, classifications, aliases, hashes, decisions, and milestones will flow to workspace-hub issue #3454 and persistent watcher #2572.

Private evidence plane

Exact folder names, paths, relocation destinations, manifests, and verification sidecars will flow to the private ledger tracked by aceengineer-admin issue #37.

Safety and failure handling

  • Deletion requires live origin/dirty/stash checks where Git is involved, residue classification, an explicit user decision, and fresh race checks.
  • Any incomplete check produces defer, not a guessed safe-delete classification.
  • Machine-local permission cleanup will use a red/green assertion: the two stale rules must be demonstrated before mutation, then JSON validity and exact retained permissions must pass afterward.
  • Public artifacts will fail closed on private identifiers, raw private paths, or sensitive manifests.
  • Temporary isolated worktrees will be verified and removed at closeout.
  • The unsafe scheduled-cleanup behavior discovered during reconnaissance is excluded from this implementation and tracked separately in #3453.

Verification plan

  1. Assert the stale local rules exist and make the pre-change test fail.
  2. Remove only those rules; parse the JSON and compare the retained permission set exactly.
  3. Enforce one-to-one parity between the complete private ledger and public aliases/counts.
  4. Scan public artifacts for private identifiers, absolute private paths, secrets, and legal deny-list matches.
  5. Validate HTML structure and links; run the repository legal sanity scan.
  6. For every executed action, verify target state, cleanup-lock absence, and sidecar integrity before recording completion.

Scope boundary

Not included: automatic batch deletion, a generator for root Claude settings, public storage of machine-specific permissions, or repair of the scheduled cleanup script. Implementation remains blocked until the issue plan is adversarially reviewed and the user approves it.
