Registry-Driven Connection Helpers

A hostname-first, fail-closed connection architecture for two Linux workstations, with machine-local verified fallback and one shared execution boundary across Bash and PowerShell.

Public authority

The workstation registry will hold canonical identity, MagicDNS/SSH hostname policy, and an opaque fallback reference—never an observed fallback address.

Local observation

A repository-external overlay will hold the OS-owner assertion, evidence reference, timestamps, machine binding, and connection-policy digest. On POSIX it must be an owner-controlled regular non-symlink with mode no broader than 0600, under a non-group/world-writable parent.

Single execution boundary

The required uv runtime will launch one Python command that validates, resolves, redacts, and starts OpenSSH with an argument vector. Shell wrappers will not parse configuration or build commands.

Explicit fallback only

No DNS, timeout, host-key, or authentication failure will cause a second destination attempt. Fallback will be a distinct operator action.

Windows boundary

Windows will support hostname mode. Address fallback will fail closed with exit 4 until a separately reviewed native ACL validator exists.

Authority and data flow

Registry identity + policy→ Strict Python resolver→ Hostname routeor explicit POSIX owner-asserted overlay→ OpenSSH argv

Credentials, keys, endpoints, operator identities, and raw rejected values will not enter plans, logs, dry-run output, or tracked helper defaults.

Runtime security contract

Overlay integrity

  • Read the registry and selected overlay once into immutable snapshots.
  • Reject duplicate YAML keys, symlinks, wrong owners, non-regular files, broad modes, unsafe parents, stale evidence, legacy digest fields, and policy-digest mismatches.
  • Require verified_at ≤ now < expires_at and a validity interval no longer than policy.
  • Hash every security-relevant field in versioned canonical ASCII JSON; unrelated valid registry edits do not invalidate the selected machine.
  • Keep the overlay outside the repository; it is an owner assertion, not a signed attestation.

Canonical SSH identity

The canonical hostname remains the positional OpenSSH destination. Explicit POSIX fallback adds only fixed HostName and canonical HostKeyAlias options and forces StrictHostKeyChecking=yes. Caller-supplied SSH options are not accepted.

Redaction boundary

Resolver, wrapper, and dry-run diagnostics will reveal neither target, identity, rejected raw value, environment, nor overlay content. Inherited interactive OpenSSH stderr remains an explicit local-terminal boundary.

Checked enforcement

The manifest will classify registry, core, CLI, wrappers, Tabby, endpoint-prohibited docs, and the separately owned VNC surface. Local hooks inspect staged blobs; CI compares exact base and head commit blobs.

Success contract

  • Every governed SSH helper resolves through one validated command.
  • Hostname access is the default; POSIX fallback is explicit, current, owner-asserted, and bound to the canonical per-machine policy.
  • Windows hostname access works natively; unsupported fallback returns exit 4.
  • No SSH failure silently changes destination.
  • Fallback retains canonical host configuration and host-key identity with strict checking.
  • Dry-run executes nothing and reveals no target or identity.
  • Bash and native PowerShell behavior are tested through the required uv runtime.
  • Manifest-backed staged and commit enforcement catches added files, odd filenames, index/worktree races, and adjacent unsentinelled violations.
  • Changed-code coverage explicitly includes the shared launcher under scripts/operations/connection/.
  • Implementation cannot start until multi-provider plan review completes and the user applies status:plan-approved.

Known risks

  • Implementation must prove its base descends from merged #3553 before RED tests begin.
  • Current-tree cleanup will not erase historical endpoint exposure.
  • Projection omission could weaken invalidation; closed-field mutation tests and format versioning will guard it.
  • Gitleaks v8.30.1 will be checksum-pinned and forced to embedded defaults with a runtime positive control before scanning the frozen candidate tree.
  • POSIX fallback depends on restrictive local ownership and permissions; Windows fallback remains unsupported.
  • The existing workstation suite has one unrelated recorded baseline failure.
  • Endpoint enforcement must remain narrow enough not to block its own tests and review evidence while covering every checked manifest entry.
