Registry-Driven Connection Helpers

A hostname-first, fail-closed connection architecture for two Linux workstations, with machine-local verified fallback and one shared execution boundary across Bash and PowerShell.

Current human gate

The design is approved. This implementation plan will require adversarial review and explicit user-applied status:plan-approved before code changes begin. The agent will not self-approve.

Dependency: the reviewed #3548 runbook must land through PR #3553 before implementation starts.

Public authority

The workstation registry will hold canonical identity, MagicDNS/SSH hostname policy, and an opaque fallback reference—never an observed fallback address.

Local observation

A gitignored overlay will hold the verified address, evidence reference, timestamps, machine binding, and registry digest.

Single execution boundary

Python will validate, resolve, redact, and launch OpenSSH with an argument vector. Shell wrappers will not parse configuration or build commands.

Explicit fallback only

No DNS, timeout, host-key, or authentication failure will cause a second destination attempt. Fallback will be a distinct operator action.

Authority and data flow

Registry identity + policy→ Strict Python resolver→ Hostname routeor explicit Verified local overlay→ OpenSSH argv

Credentials, keys, endpoints, operator identities, and raw rejected values will not enter plans, logs, dry-run output, or tracked helper defaults.

Success contract

  • Every governed SSH helper resolves through one validated command.
  • Hostname access is the default; fallback is explicit and attested.
  • No SSH failure silently changes destination.
  • Fallback retains canonical host-key identity.
  • Dry-run executes nothing and reveals no target or identity.
  • Bash and native PowerShell behavior are both tested.
  • Staged enforcement catches added files, odd filenames, index/worktree races, and adjacent unsentinelled violations.

Known risks

  • PR #3553 is not yet on main; this remains a hard dependency.
  • Current-tree cleanup will not erase historical endpoint exposure.
  • A global registry digest will deliberately invalidate fallback after any registry edit.
  • The existing workstation suite has one unrelated recorded baseline failure.
  • Endpoint enforcement must remain narrow enough not to block its own tests and review evidence.
