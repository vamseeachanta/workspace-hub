Python-Native Residue and Bound Finalizer

A fail-closed client-wiki bootstrap design that never deletes a pathname after rendering begins, never allows Git to follow repository-local configuration authority, and retains descriptor authority through the first private push and remote-SHA attestation.

1. Goal and scope

The design will preserve the metadata-only bootstrap outcome from issue 3449 while replacing two invalidated guarantees: identity-conditional pathname cleanup and pathname-based final commit/push. The implementation will remain Python standard-library plus existing Git, GitHub CLI, uv, and yq dependencies. It will introduce no FFI, compiled helper, raw-source reader, client-specific data, or private-registry mutation.

Load-bearing policy change: after the renderer creates its first target object, no automatic cleanup will delete or move any rendered pathname. A failure will preserve bounded residue and report it. Manual cleanup will require a separate operator decision after inspecting identities and repository state.

2. Security invariants

  1. Schema 0.2 will continue to deny every ingestion_enabled: true state.
  2. Legacy numeric 0.1 will remain audit-only, require its historical non-empty source-backed shape, and reject all 0.2 state fields.
  3. Schema, classification, rendering, finalization, and checker execution will never stat, open, resolve, enumerate, or indirectly include a registered raw root.
  4. Git subprocesses will ignore ambient, system, global, and repository-local configuration. Local config will be parsed only from a held no-follow descriptor with include and URL-rewrite authority denied.
  5. Template object reads will ignore replacement refs and will consume exact committed blob object IDs.
  6. Target writes will remain relative to held no-follow directory descriptors and use exclusive creation.
  7. Final attestation will cover absolute binding identities, complete inventory, bytes, sizes, and modes.
  8. The factory will not use pathname-based Git add/commit/push after rendering. A bound finalizer will own those operations.
  9. The first push will name the exact registered HTTPS URL, and the remote main SHA will have to equal the local committed SHA before registry lifecycle update.
  10. No public issue, public stub, or generic template will receive a private client identifier or private repository/path evidence.

3.1 Registry contract

The schema module will centralize exact identity rules. Current entries will retain the exact owner/llm-wiki-<short-name> relationship. Legacy rows will require non-empty historical roots and will reject raw_source_status and ingestion_enabled rather than ignoring them. The contract's validate command will apply protected-root disjointness for every current entry using module-anchored workspace, template, and derived-target paths without touching a raw root.

3.2 Git authority isolation

Every Git subprocess will receive a fresh environment containing GIT_CONFIG=/dev/null, GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=/dev/null, and GIT_NO_REPLACE_OBJECTS=1. No caller-provided GIT_* variable will survive.

The clone's .git/config will be opened as a real no-follow regular file and retained by descriptor. A dedicated parser call will use git config --file /proc/self/fd/N --no-includes --null with that descriptor passed explicitly. The parser will:

  • reject every include.* and includeIf.* key;
  • reject every url.*.insteadOf and url.*.pushInsteadOf key;
  • preserve leading and trailing bytes rather than applying strip();
  • require exactly one fetch URL and zero or one push URL;
  • require each present URL independently to equal an approved exact spelling.

Bound repository commands will use explicit --git-dir=/proc/self/fd/GIT_FD and --work-tree=/proc/self/fd/ROOT_FD while repository-local config remains disabled. They will never use git remote get-url.

3.3 Replacement-free template snapshot

The renderer will replace tar archive consumption with a blob inventory. It will resolve one commit under replacement-disabled Git, enumerate the template subtree recursively with exact modes and blob IDs, and read each blob by object ID. Python will derive directory entries from the validated paths. This removes archive extraction and prevents a replacement ref from changing bytes behind a reported commit.

3.4 Direct render with residue-on-failure

The rehearsal staging directory and all cleanup deletion code will be removed. The renderer will materialize the in-memory blob inventory directly into the bound empty clone. Directories will use exclusive mkdir followed immediately by no-follow descriptor binding. Files will use O_CREAT|O_EXCL|O_NOFOLLOW.

The renderer will maintain a bounded attempted/confirmed path ledger. If any operation fails, it will close descriptors but will not unlink, rmdir, rename, truncate, or overwrite any created pathname. The CLI will emit a structured failure record to stderr containing the pinned template commit, target identity, confirmed created paths, attempted path, and residue_policy: preserved.

Recovery rule: a failed render is never retried into the same non-empty clone. The operator will inspect the residue record and either preserve the clone for forensics or remove the entire disposable clone through a separately authorized cleanup action before starting again.

3.5 Byte-, mode-, and path-complete attestation

The successful render manifest will record root, .git, and config device/inode identities plus every created path's type, normalized mode, byte length, and SHA-256 digest. Final validation will reopen each named member through held parent descriptors, reject symlinks and unexpected members, and compare all recorded facts. Privacy-firewall files will be checked as ordinary manifest members and by required-path policy. Validation will run after every callback and immediately before returning the manifest.

The manifest will also record the derived target path. A later finalizer will have to rebind that path and match all root/.git/config identities. A rename or parent replacement after render can therefore produce residue, but it cannot authorize commit or push.

3.6 Descriptor-bound finalizer

The command will be finalize-scaffold --registry PATH --short-name SLUG --manifest PATH. The manifest path will resolve outside the target and name a mode-0600 regular non-symlink file. The command will re-attest the exact private repository, rebind the target and Git/config identities, and revalidate the complete rendered manifest before mutating Git state.

The finalizer will require CLIENT_WIKI_GIT_AUTHOR_NAME and CLIENT_WIKI_GIT_AUTHOR_EMAIL. Git author configuration will be command-scoped; no global or local author setting will be trusted. Authentication will use a fixed command-scoped gh auth git-credential helper without storing a token.

It will stage only the attested manifest paths, create the fixed signed-off bootstrap commit, and push to https://github.com/<registered-repo>.git rather than the mutable origin name. It will then query that same explicit URL for refs/heads/main, require the remote SHA to equal local HEAD, and re-attest exact GitHub identity, PRIVATE visibility, and unarchived state. Success output will be JSON with exact status, scaffold_sha, remote_sha, and template_commit fields.

3.8 Checker and factory

The checker will delegate registered-clone inspection to the Python contract rather than invoke config-aware shell Git. It will retain exact public-stub and dependency exit semantics. GitHub JSON types will be checked, mixed independently allowed fetch/push spellings will pass, and protected-root overlap will fail before host-availability metadata checks.

The factory will require explicit author environment variables, create and clone the exact private repository with a fixed gh credential helper, render to an external manifest, and call the bound finalizer. It will contain no pathname-based add/commit/push commands. Registry update will remain after remote-SHA and PRIVATE attestation. Project guidance will reference only the authoritative private registry; the public relocation stub will remain exact and empty.

No exception class, including KeyboardInterrupt or SystemExit, will trigger pathname cleanup. Descriptor closure will remain in finally blocks.

5. Test strategy

  • Legacy downgrade tests will reject empty roots and all added 0.2 state fields.
  • Protected workspace, template, canonical checkout, and derived-target roots will fail checker validation.
  • Local include/includeIf and URL rewrite config will be present but will not affect any Git result; the parser will reject the authority without opening the referenced target.
  • Actual replacement refs will be installed in a temporary template repository; rendered bytes and reported commit will remain the unreplaced committed objects.
  • Whitespace-bearing, multiple, mixed-valid, and malformed origin values will exercise exact NUL-record parsing.
  • File creation, fstat, ledger insertion, write, chmod, final validation, KeyboardInterrupt, and SystemExit failures will assert that no cleanup deletion function is called and that residue is reported.
  • In-place byte, size, mode, firewall, directory membership, target, parent, .git, and config substitutions will fail final attestation.
  • Dangling and corrupt symbolic HEAD states will be distinguished from a genuinely unborn branch.
  • Finalizer tests will cover initial success, commit-before-push recovery, idempotent remote success, target/config/origin swaps, wrong remote SHA, missing author identity, and unavailable credentials.
  • A temporary repository with global/system config disabled will create its first commit using only explicit author values.
  • Factory behavior tests will execute the command sequence against fake gh/Git transport boundaries rather than rely on substring order alone.
  • Committed-HEAD mode tests will use git ls-tree HEAD, not the mutable index.

6. Non-goals

  • No automatic residue cleanup or whole-clone deletion.
  • No raw-source ingestion, extraction, enumeration, or content validation.
  • No private registry migration or client-wiki creation under issue 3449 tests.
  • No native syscall wrapper, FFI, container sandbox, or privilege boundary.
  • No claim that a same-UID process cannot rename created paths; the guarantee is that such substitution cannot authorize deletion, commit, or push.
  • No support for arbitrary remote URL spellings beyond the explicitly approved exact set.

7. Acceptance boundary
