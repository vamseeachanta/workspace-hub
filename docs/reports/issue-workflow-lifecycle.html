GitHub issue lifecycle

The canonical method — plan → review → implement → HTML artifact → live link. Timeless reference; authority lives in the planning/engineering workflow skills.

flowchart TD
    A["Issue opened"] --> B["1. Intake & classify
T1 / T2 / T3 · lane · exec mode"]
    B --> C["2. Resource intelligence
existing code · standards · docs · prior plans"]
    C --> D{"3. Runtime claim?
failing test / import / regression"}
    D -- Yes --> E["Reproduce & cite
verbatim output in plan"]
    D -- "No (docs/governance)" --> F["Mark: Reproduction proofs N/A"]
    E --> G["4. Draft plan
docs/plans/YYYY-MM-DD-issue-NNN-slug.md"]
    F --> G
    G --> H["5. Adversarial plan review
Claude + Codex + Gemini"]
    H --> I["Post plan to GH
label status:plan-review"]
    I --> J{"HARD STOP
user approves?"}
    J -- "REVISE" --> G
    J -- "REJECT" --> K["Ask preferred approach"]
    K --> G
    J -- "APPROVE" --> L["label status:plan-approved"]
    L --> M["7. Implement TDD
tests first to FAIL, then code to PASS, full suite"]
    M --> N["8. Cross-review impl
Codex + Gemini · artifact-verification"]
    N --> O{"MAJOR finding?"}
    O -- Yes --> M
    O -- No --> P["9. Completeness gate
score to docs/reports/<date>-<issue>-completeness.html"]
    P --> Q{"status:completeness-verified
≥ threshold?"}
    Q -- No --> M
    Q -- Yes --> R["10. Publish HTML artifact
build_pages.py HTML_PAGES to pages.yml
or wiki reports/ + stable alias"]
    R --> S["Live link
vamseeachanta.github.io/... (public-safe, no PII)"]
    S --> T["11. Close
commit + push + summary"]
    T --> U{"closed without
completeness label?"}
    U -- Yes --> V["completeness-gate.yml
REOPENS issue"]
    V --> P
    U -- No --> W["Done"]

hard stop — user approval automated gate — completeness / server-side reopen publish + live link
Two invariants hold on every path: no code before an approved plan, and TDD always (tests written and observed to fail before implementation).
