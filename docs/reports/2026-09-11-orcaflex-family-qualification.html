Acceptance rule

Every example in the declared corpus will receive an identity, family, dependency manifest and expected behavior. A family will be vetted only when every in-scope positive case passes its required stages and every negative fixture correctly rejects the intended fault. Missing files, unsupported fields, skips, untriaged warnings and unexecuted stages will remain visible as blockers; no reduced denominator will hide them. Reference fragments and duplicate aliases will remain listed with their parent case or canonical content hash rather than be counted as runnable analyses.

This report records discovery and existing-code verification. It will not authorize changes to engineering assumptions, implementation, production queues or scheduled tasks. Generic local checks will continue using the qualified isolated code; the safety repair and remote cutover will keep their separate approval gates.

Per-example evidence matrix

  1. Identity and dependency closure: source commit/hash, original path alias, family, positive/negative/reference role, include/catalog/RAO dependencies and source rights.
  2. Input fidelity: schema validation, units and mandatory fields, assumption ledger, explicit unmapped residuals. Unknown keys will not silently count as preserved.
  3. Generation: generated master/includes/parameters, strict YAML validation, post-validator findings, original-to-generated semantic comparison where an independent reference exists.
  4. Native execution: API/model version, licensed load, statics convergence, intended dynamic completion, finite required results, actual thread count, owned-process cleanup and saved-model/simulation reload.
  5. Outputs: requested engineering histories/profiles/envelopes, summary/report artifacts, case/input/output hashes. Batch execution manifests will not substitute for engineering results.
  6. Engineering qualification: independent/reference agreement, predeclared tolerances, equilibrium/convergence, warning disposition and applicability bounds. Reduced-duration smoke will not count as full analysis qualification.

Each cell will use PASS, FAIL, BLOCKED, NOT RUN or justified NOT APPLICABLE with evidence. A full family PASS will require every applicable cell and every selected example to satisfy its contract. Existing tests that deliberately reject bad inputs will be reported separately from positive simulation cases.
