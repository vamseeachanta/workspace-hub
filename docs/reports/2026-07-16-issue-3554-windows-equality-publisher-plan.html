Make equality publication truthful and Windows-portable

Issue #3554 · 2026-07-16

Observed failure

Git Bash lacks flock. The publisher converts command-not-found into “another publish in flight,” exits zero, and lets cron claim success.

Design

The implementation will remove the host-local gate and strengthen the existing fetch, sparse-worktree, fast-forward push, and bounded retry transaction.

Boundary

Sentinel state, scheduling, dirty-checkout reconciliation, evidence schema, and matrix semantics will remain outside this issue.

Why no lock-directory fallback?

A host-local lock cannot coordinate separate machines pushing the same branch. A fallback would add stale-owner, PID-reuse, TTL, crash-recovery, and cleanup risks while the remote fast-forward transaction already supplies the global arbitration point.

TDD sequence

  1. Prove publication succeeds with no flock.
  2. Race two isolated publishers against one bare remote and require convergence.
  3. Force a first-push race and require a fresh fetch/rebuild retry.
  4. Force retry exhaustion and require nonzero plus failure notification.
  5. Prove cron never emits PASS or OK after publisher failure.

Acceptance checkpoint

A supervised ace-win-2 reconciliation will publish fresh evidence to origin/main without flock. Existing newer-only, allowlist, dirty-checkout independence, dry-run, and cleanup invariants will remain green.

Approval gate

This is a planning artifact. Implementation will remain blocked until adversarial review completes and the user explicitly approves the plan.
