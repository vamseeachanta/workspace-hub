Proposed way forward

  1. Recover one trustworthy baseline. Existing issue and PR evidence will be reconciled; review blockers will be corrected before merge. Cleanup will remove only verified inactive worktrees after preserving unique results, logs and dependencies.
  2. Qualify one representative case per existing solver path. Each case will identify its input revision and digest, assumptions, solver/runtime version, licensed execution context, raw output and digest, independent comparator, governing tolerance and readiness verdict. Exit code zero alone will not constitute acceptance.
  3. Reuse the existing architecture. Project/source records will remain with their authoritative data owner. Digitalmodel will prepare, extract and validate. Deckhand will route deterministic pinned run packets. Evidence reports will consume recorded results and preserve refusal, missing and provisional states.
  4. Resolve routing before unattended scale-out. The existing host-migration issue and licensed production epic will own the routing work. The committed default still names the secondary Windows host; changing an alias alone could direct work to an unqualified executor.
  5. Expand only after acceptance evidence exists. NavCad and further asset templates will receive bounded issue plans after existing secondary-host findings are recovered. Parametric sweeps will follow validated single-case execution, not precede it.

This is a consolidation and proposed sequence, not a newly approved implementation plan. Existing approved issues retain their own scopes and TDD/review gates. The repository merge policy requires an exact reviewed PR target before agent-run merge.
