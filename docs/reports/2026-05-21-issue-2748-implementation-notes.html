Issue #2748 implementation notes

Scope: result/output-layer scaffolding for reports, chatbot answer packs, and evidence packs.

Design decisions

  • Extended the existing report evidence bundle schema instead of introducing a parallel output manifest format.
  • Made source-level provenance explicit with sources[], source_doc_key, confidence/readiness scores, source residency, output residency, and release gates.
  • Kept HTML as the default client-facing format and PDF as a limited derivative requiring an exception reason.
  • Used fail-closed JSON Schema constraints for unscored sources, client-private output clearance, and public output promotion.

Deviations / interpretations

  • The implementation does not build a report generator or chatbot indexer; it establishes the contract those tools must satisfy.
  • No private client data, retrieval indexes, raw traces, or local client paths were added.

Tradeoffs

  • Schema-level gates were chosen over a new Python validator to keep this issue bounded and compatible with the existing architecture test pattern.
  • Report readiness and evidence completeness currently use a conservative minimum of 0.5; later issue work can tighten thresholds once real scoring data exists.

Open questions

  • Whether production report validators should raise the readiness threshold above 0.5 for specific client-facing deliverables.
  • Whether chatbot/query-surface bundles should require additional fields for embedding model, index version, and retrieval freshness.
