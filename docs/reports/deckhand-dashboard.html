Design decisions9 resolved · captured in glossary + governance records

#DecisionWhy it matters
1"named channel" → scopescope (repos+perms) ≠ channel (transport target, channel_directory.py) ≠ delivery group (#2902). Stops one word meaning three things.
2Scope ⟂ routingA command names a scope (repos) and, separately, where output goes. Replies default to origin. Issue body fused them; we split them.
3Explicit allowlist, fail-closedMembership is an enumerable list, not "all as needed". Unknown repo → deny.
4"deletion" = destructive opsrepo/branch/tag/release delete, force-push, reset --hard/clean — not a commit that removes file lines.
5Enforced below the modelcommand hook + per-scope fine-grained PAT; prompt text is guidance only, never the boundary.
6Per-scope operator allowlistOn top of the gateway allowlist; ecosystem gets the tightest list. Fail-closed.
7Origin-bound default scopeResolved from a registered channel→repo binding only (never prose); read+write no-destructive; allowlist-contained.
8Audit every decisionallow+deny, PENDING-before + FINAL-after, redacted; raw private, redacted summary public; feeds #2741 canary.
9Sensitivity clears routingPrivate-scope output fans out only to cleared delivery groups; origin allowed only if DM/cleared.
