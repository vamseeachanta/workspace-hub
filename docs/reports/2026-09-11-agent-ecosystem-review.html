One shared lifecycle; thin provider entrypoints

  1. Intake and reuseResolve objective, owner repo, existing issue, prior decisions and completed work.
  2. Bounded discoveryLoad relevant catalogs, manifests and skill; record source freshness and missing access.
  3. Risk and ownershipApply standing authorization or obtain a concrete consequential-action approval; claim contended resources.
  4. Plan and executeUse a short plan for routine work; a reviewed substantial plan where warranted. Parallelize only independent work.
  5. Verify deltaRun meaningful tests or artifact checks; invalidate evidence when inputs, code, environment or criteria change.
  6. Review and integrateReview proportionally to consequences; serialize shared writes and Git operations.
  7. Close and learnRecord result and reusable evidence; release claims, name residue, update an existing lesson when applicable.

Claude and Codex will follow the same outcomes and authority boundaries. Provider adapters will describe only supported loading paths, tool interfaces and runtime behavior. Evidence reuse rule: retain validation only when its dependency scope is known and the input, code, environment and governing-criteria digests match. Mutable dependencies—remote revisions, source freshness, access, machine availability and authorization scope—require an appropriate expiry or live recheck. Rerun only affected checks after a change; unknown dependencies invalidate reuse.

Coordination rule: claim contended resources, isolate write lanes where needed, and serialize shared integration. A claim is a concurrency control; it is not implementation authorization.

Skill requirement: purpose and trigger, scope, source authority, essential constraints, output contract and verification. Ordered procedures remain where ordering matters. References carry detail; model-family folklore and historical status do not belong in active instructions.

Acceptance criteria for the proposed operating model

  • Each category has one authority and an explicit owner; references resolve from the actual checkout.
  • The same source lookup reaches the same owner and readiness result through both providers.
  • A completed task is recognized and resumed or skipped without duplicating its work.
  • Routine reversible work completes without redundant permission requests; consequential actions stop at a concrete approval boundary.
  • Both providers discover the intended skills and references; archives/templates do not crowd the activation profile.
  • Representative task comparisons record correctness, user interruptions, repeated discovery, unnecessary reruns and cost/time. No claimed model improvement is accepted without those results.
