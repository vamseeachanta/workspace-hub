2 · Verify one host using existing fixtures

Discover actual authorized access to the registry-listed simulation host. Record the checkout revision, Python, CadQuery/OCP, Gmsh and CalculiX versions; verify imports and native executables. Run existing geometry and solver tests and report skipped tests separately from passes.

Exit evidence: logs for the equipment CAD tests, STEP/INP round-trip and a real CalculiX fixture. Preserve current environment isolation; do not treat this as permission for fleet provisioning.

3 · Define one analysis question and the required geometry

For the straight jumper, start with geometric volume and cross-section properties from nominal OD, wall and length. Mass will require an independently supported density and a declared component boundary; pipe-only mass will not be compared with an assembly weight containing hubs or flanges.

Exit evidence: a reviewed pilot plan with source pages, unit conversions, parameters, independent reference, tolerances and exclusions. Pressure, bending and thermal load cases will be added only after material properties, supports, connections and load definitions are established.

4 · Qualify the export and analysis connection

Test invalid dimensions, BRep validity, analytical volume/section properties and STEP re-import. Reuse digitalmodel’s Gmsh/CalculiX components for a defined case. Document mesh quality and refinement evidence, physical boundary conditions and output-specific tolerances. A STEP header or successful solver exit will not be sufficient.

Exit evidence: reproducible source → parameter set → STEP → mesh → solver input → result relationships, with a named analysis reviewer. The existing polyline sweep will not be used to claim real bend stresses without verified bend geometry.

5 · Publish two derivatives from a traceable source

The asset package will link a lightweight viewing mesh and a dimensional CAD/analysis representation to the same asset ID and revision where applicable. Each derivative will state its simplifications. Component names, connection points and assembly hierarchy will let users navigate from a field scene to the underlying evidence.

Exit evidence: a repeatable asset package and a viewer that exposes assumptions and analysis eligibility. Visualization derivatives will never become the hidden authoritative geometry.

6 · Expand only after the first qualified asset works

Proceed to a dimensioned rounded-bend jumper, then manifold/tree layout. Choose one rig or artificial-lift subassembly when its source dimensions and intended use are available. Keep full-rig construction, fleet rollout and the 180-run LLM comparison deferred until they answer a concrete decision.

Tracking: use digitalmodel #1786 for tooling; link assembly evidence to worldenergydata #641. A new analysis qualification deliverable will need an appropriately scoped issue/plan; these comments will not expand existing issue acceptance criteria automatically.

From a useful model to a defensible analysis

Source & reuse rights→Nominal dimensions→Named CAD components→Validated derivative→Specific analysis case

Visual proxy

Will support navigation, training or concept communication. Dimensions may be approximate; limitations will remain visible.

Dimensioned CAD

Will carry units, tolerances, component boundaries, geometry checks and source provenance. It will not automatically authorize every solver use.

Qualified analysis case

Will bind a geometry revision to materials, loads, supports, mesh, solver settings, reference checks and reviewer disposition for one intended use.

Proposed asset record fields

Existing catalog asset ID; owning repository; author/source URL and revision; source page/drawing; use/reproduction rights; measured/specified/assumed dimensions; unit system and coordinate frame; material evidence; component/assembly membership; connection points; omissions; CAD and viewing outputs; digest; geometry checks; eligible and excluded analyses; linked case results and reviewer/date. Extend existing metadata authorities rather than creating a competing registry.

Proposed ownership, subject to the existing data-handling contracts: worldenergydata will remain the existing catalog/field-assembly reference; digitalmodel will own engineering geometry validation and solver workflows. Catalogs and source notes will follow their established metadata owner. Reusable solver outputs will follow the current data-handling contract, including private digitalmodel-data where applicable. Machine working directories will remain execution copies.

What to borrow from PetroMind

The author’s build article describes specialist research, petroleum-engineering review, 3D modeling and independent software review, with bounded handoffs. Apply the useful boundary here: engineering reviewers will qualify source assumptions before geometry is accepted, and software reviewers will test the viewer separately from physical validation.

Our proposed extension is analysis traceability: selecting an asset will show its dimensions, source basis, simplifications and eligible analysis cases. This is an ecosystem recommendation, not a feature verified in PetroMind.
