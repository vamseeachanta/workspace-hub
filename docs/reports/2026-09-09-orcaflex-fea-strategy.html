Extend the existing spec-authoring architecture and output-driven workflow pattern. Existing spec_author.py, inverse_resolver.py, ProjectInputSpec, DiffractionSpec, assumption ledgers and workflow/result contracts are the foundation. Keep solver-specific extensions rather than forcing all physics into one lowest-common-denominator schema.

The contract will include purpose; applicability; geometry/topology; units and axes; materials/sections; connections/supports/contact; loads and combinations; requested analysis; mesh/time-step rules; solver/version; quantities of interest; source/standard citations; uncertainty; and acceptance criteria.

AI will help locate evidence, propose specifications and explain residuals. Deterministic code will validate, generate and execute. Engineering review will own model adequacy and acceptance; a plausible generated input is not engineering approval.

First qualification ladder

  1. Beam/cantilever: compare reactions and deflection with an independent closed-form reference; verify section orientation, boundary conditions and mesh sensitivity.
  2. Plate with a hole: repair the existing CalculiX benchmark; define stress location/measure, geometry range and convergence criteria. Do not treat a singular peak or one fixed mesh as qualification.
  3. Suspended line/riser: verify static equilibrium and shape, then a bounded dynamic response with time-step/segmentation sensitivity.
  4. Mooring or lifting assembly: validate connectivity, vessel/body properties, environment and coupled load paths.
  5. Detailed padeye/joint: use qualified global loads in MAPDL/CalculiX; verify material, contact, restraint and local stress extraction.
  6. Shell, buckling, fatigue and nonlinear contact: add one family at a time with its own method, reference cases and applicability limits.

Use the existing workflow-pack lifecycle: located → extracted → parameterized → reproducible → engineering-validated → approved-for-reuse. Keep separate evidence for loadability, convergence, benchmark agreement and approval. A registry's current “ready” template flag will not be reinterpreted as numerical qualification.

Deckhand will own authenticated submission, execution and result transport. workspace-hub will own portfolio reconciliation and machine readiness. llm-wiki will own cited methods, solver fundamentals and supported workflow knowledge. Private project repositories will retain source models, private geometry/data, run records and project approval.

Reuse the existing solver knowledge-placement issue and private workflow-pack ownership. Library promotion will use sanitized/synthetic regression fixtures where necessary. Large historical corpus size estimates in issues will remain historical claims until a permitted live census verifies counts and source rights.

Standard-derived values will carry edition, section, applicability and the existing Citation sidecar. Wiki heuristics or broad defaults will not become executable acceptance criteria without verification.
