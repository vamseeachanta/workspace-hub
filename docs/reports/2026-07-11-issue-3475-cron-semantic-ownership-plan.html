Planning and review only. Implementation will remain blocked until the user applies status:plan-approved. No live crontab or process action is authorized.

Observed gap

Unsafe destructive authority

Three deletion routes still use substring matching: installed fingerprints, catalog-key fallback, and selected preserved-entry promotion.

Incomplete write verification

The transaction verifies only preserved-line multiplicity. Corrupted managed state can still return applied.

Existing safeguards retained

Physical-local binding, lock, durable backup, pre-write CAS, preservation, daemon guard, and rollback CAS will remain.

Proposed transaction

  1. Deterministically render every selected catalog task for every canonical Linux machine id from config/workstations/registry.yaml, require unique complete cron-line identity, and enforce digest-bound JSON byte parity in CI.
  2. Authorize out-of-block deletion only through complete exact canonical or explicitly allowlisted legacy line bytes—never shell parsing, substring, token fragment, or basename equality.
  3. Remove destructive cmd in line fallback and migrate the three known selected/catalog legacy identities.
  4. Model setup and onboarding wrappers as attested pure delegation edges inheriting the direct-owner contract; forbid copied legacy authority/transaction fields.
  5. After writing planned state B, re-read observed state C and require byte-for-byte C == B.
  6. On mismatch, restore baseline A only when a rollback CAS proves no concurrent change; re-read A before reporting rollback success.
