Compliance alert interpretation

The daily alert consumes the dashboard's top-level JSON report. A window with no reviewable commits is reported as not applicable and creates no alert. Malformed or inconsistent evidence returns an error for diagnosis.

Inputs and method

The report supplies total, skipped, reviewable, reviewed and unreviewed counts, compliance rate, threshold and verdict. All counts are nonnegative integers. The count identities are total = skipped + reviewable and reviewable = reviewed + unreviewed. For a nonzero denominator, rate = floor(100 × reviewed / reviewable), in percent. The producer defines these identities and the integer arithmetic in compliance-dashboard.sh, “Calculate rates” and “Determine verdict” (2026).

The producer retains a numeric zero and PASS for an empty denominator for compatibility. The alert consumer treats that case as not applicable. It checks the top-level verdict against the report threshold and checks the dashboard exit status before considering publication. Nested drift-event verdicts do not replace the compliance verdict.

The alert severity boundaries (30%, 50% and the default pass threshold of 80%) come from issue 3808, “Thresholds” (2026), and the existing cron configuration. The pass threshold now follows the validated dashboard threshold, including an explicit COMPLIANCE_THRESHOLD setting. These are repository workflow criteria, not engineering acceptance limits. No licensed standard or physical coefficient is used.

The tests copy the consumer into disposable directories, supply synthetic reports and replace GitHub access with a recording stub. DRY_RUN=true permits inspection of the generated issue body in the daily log without querying or writing GitHub. Missing JSON, count disagreement, an inconsistent verdict or an unexpected exit status returns a nonzero status.

Limits and next action

The dashboard's existing commit classification and review-evidence heuristics are unchanged. Historical compliance and bypass claims are not established by these examples. The weekly report's empty-denominator display is outside this alert repair. The maintainer can inspect historical logs and arrange review of identified reviewable commits; this change does not retroactively review commits or close historical alerts.
