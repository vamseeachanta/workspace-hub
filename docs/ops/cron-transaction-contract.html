Cron transaction contract

The cutover planner classifies every live body line before replacing a managed block. Any unrecognized executable line blocks the plan. Exact catalog identities provide replacement authority; preservation fingerprints provide retention only. The audit and planner use cron_line_model.classify_line_detail. This contract describes proposed behavior and fixture validation; it does not establish authorization for a live scheduler change.

Malformed or duplicate block delimiters also abort. A substring match against a catalog command does not establish exact ownership. The plan reports line_classes, per-class counts, preserved, uncataloged, replaced and dropped. Replacement lists retain duplicate occurrences. The dropped list is the occurrence subtraction of original body lines from proposed lines; marker delimiters are structural metadata and are excluded. No drop is claimed for an aborted plan.

These lists expose intent; they do not add an acknowledgment flag or authorize application. Canonical lines may be consolidated or reordered by rendering. Environment assignments and preserved commands retain their relative order within the preserved portion, but interleaving with cataloged commands can change. Scheduling equivalence therefore requires inspection of the complete preview.

Worked example

The following synthetic input contains one executable body line and two block delimiters. Independent enumeration gives one uncataloged line and no cataloged or preserved commands. The command chain and redirect are part of the command body under crontab(5), DESCRIPTION.

# >>> workspace-hub managed (role: worker) — generated by setup-cron.sh, do not edit >>>
0 3 * * * first && second >> output.log 2>&1
# <<< workspace-hub managed <<<
{"new_text": null,
 "uncataloged": ["0 3 * * * first && second >> output.log 2>&1"],
 "counts": {"uncataloged": 1},
 "replaced": [], "dropped": [],
 "abort_reason": "uncataloged live cron line(s): ['0 3 * * * first && second >> output.log 2>&1']"}

A corrected fixture replaces that body with the complete selected identity 0 1 * * * echo owned. Its independently enumerated plan has no blockers, one cataloged occurrence and an unchanged rendered command:

{"abort_reason": null, "uncataloged": [],
 "counts": {"cataloged": 1},
 "replaced": ["0 1 * * * echo owned"], "dropped": []}

The regression matrix also places cataloged, external, unknown, comment, environment and blank lines in each section. Expected lists are written directly in the test table. A pair of identical legacy identities becomes one canonical identity; both legacy occurrences appear in the replacement and dropped lists.

Application and rollback

The current transaction library binds the request to the local scheduler target, takes a baseline snapshot and checks it under a lock before writing. The baseline is backed up, the replacement is written, and exact readback is required. A write or verification failure triggers rollback only after a further comparison with the observed candidate. An intervening edit aborts rollback rather than being overwritten. The restored bytes are verified; an unreadable final state is reported as indeterminate. These guarantees are described and tested in cron_apply.py and test_cron_apply_exact_state.py.

Reconciliation through harness-update.sh returns the child status, records cron_reconcile_status, includes failure in its summary, and preserves that status through final reporting. The direct installer's local-target comparison remains unchanged. The timeout duration is operational configuration, using the existing script budget as its default. GNU timeout, Exit status defines the timeout result used by the fake-executable tests.

Declared roots and generator audit

The current base renderer already represents absolute POSIX workspace roots as PurePosixPath, preventing local symlink resolution from changing a remote declaration. The inventory regression remaps the synthetic root through a fake macOS-style realpath and requires an unchanged independently constructed command and digest. No additional production root-rendering fix is required.

The identity inventory is the only build*.py generator in scripts/cron. Its local source-path resolution identifies files to hash; it does not resolve the declared absolute POSIX workspace root. cron_render.py also emits cron lines and shares this lexical branch. Its fallback for relative, tilde or Windows-style roots still uses local path resolution; cross-platform support for those declarations is not established by this POSIX regression.

Limits and remaining migrations

The three legacy marker installers and the dual-backend timer remain outside this implementation. Their existing substring ownership and whole-crontab writes cannot inherit the catalog transaction merely by changing the entry point. A completed migration will require exact legacy identities bound to their target, backup and comparison after backup, post-write readback, and rollback that refuses concurrent changes. Each install, reinstall and uninstall needs fake-executable coverage before replacement of the existing implementation.

The timer additionally requires a transaction covering service and timer bytes, enable and active state, and cron fallback. A proposed order is to snapshot both backends, prepare and verify the destination, then remove the old trigger; failure between these steps will require exact restoration while preserving concurrent edits. Systemd cannot offer atomic cross-backend commit, and a complete rollback protocol and its registry attestation remain unestablished. No live scheduler mutation or daemon signalling is performed by this change.
