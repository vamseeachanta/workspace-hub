Engineering result precision contract

Summary

The optional scripts/reporting/result_precision.py helper retains evidence for native storage, recovery, serialization and accumulation separately. It evaluates inclusive limits using supplied absolute error bounds and exact arithmetic on decimal inputs. Missing evidence produces NOT_EVALUATED; an interval crossing a limit produces INDETERMINATE. Display rounding never changes acceptance. This contract does not establish solver accuracy, mesh convergence, physical validation or continuum error.

Scope and interface

See precision issue 3850. Slice 1 defines the per-quantity records and missing-evidence disposition. Slice 2 propagates conservative error bounds through exact linear combinations, without assuming statistical independence. Slice 3 separates display formatting from acceptance and supplies tested worked examples. The helper is opt-in; existing report generators and external solver adapters do not automatically use it.

Table 2. Required evidence
RecordMeaning and caller responsibility
Quantity identityName, unit, serialized decimal value, source evidence locator, producing release and extraction location or region.
Native storageActual representation and release-specific evidence. Text width or a later double conversion cannot recover lost native information.
RecoveryOperation such as averaging, extrapolation or integration, with its own error bound and evidence. Storage error must already be scaled into the recovered quantity's units.
SerializationFormat and export or parse loss, independently of storage representation. More printed digits do not establish more supported digits.
AccumulationUpstream algorithm and numerical accumulation error. The helper's own rational arithmetic adds no rounding to the supplied decimal values.
CriterionLimit as a decimal string, exact matching unit, inclusive comparator and governing evidence. No engineering limit or tolerance is built in.

Every stage contains a description, evidence locator and nonnegative absolute error bound in the quantity's unit. An explicit zero requires evidence of exactness within the stated model. An unknown bound is None, not zero. Descriptions or evidence that are blank, missing stages or missing identity fields deny acceptance. Negative bounds, non-finite numbers, binary float inputs, incompatible units and unsupported comparators raise an error. Evidence strings are declarations to be independently checked; the helper does not authenticate them or fetch sources. All four contributions must cover distinct additive errors relative to the same target quantity. A contribution already included elsewhere must be documented and accounted for without inventing a zero. Shared or duplicated errors may conservatively be counted more than once.

Method

The bounded-error model assumes a serialized value x and a target value x* such that |x − x*| ≤ B. For each quantity, B = Bnative + Brecovery + Bserialization + Baccumulation. This follows by writing the total discrepancy as the sum of the four stage discrepancies and applying the triangle inequality. For an exact linear combination y = Σ wixi, the bound is By = Σ |wi| Bi: since |Σ wiδi| ≤ Σ |wi| |δi| and |δi| ≤ Bi, this is a conservative enclosure, including correlated errors. These equations are derived here from the stated absolute-bound assumptions; they contain no empirical constants.

Weights must be exact dimensionless inputs, with all terms in identical units. Coefficient uncertainty, nonlinear recovery, conversion of native component errors and spatial recovery validity require separately qualified bounds. The helper does not infer them. Rational accumulation is exact for the supplied decimal strings; it cannot restore information lost before serialization. Statistical standard uncertainty and covariance propagation are different models; NIST TN 1297 (1994), section 5 describes combined standard uncertainty. No probability coverage is claimed by this interval method.

Table 3. Inclusive threshold dispositions, derived by interval containment

INDETERMINATENeither the whole interval meets nor the whole interval fails the limit.
NOT_EVALUATEDA required bound, evidence record or identity field is unavailable.

PASS qualifies only the stated numerical interval and criterion. It does not qualify physical adequacy or overall engineering acceptance. Bounds exclude unprovided solver, discretization, modelling and continuum errors. The returned object retains contributing quantities, criterion, reasons, exact value and endpoints. No file is overwritten.

Display uses decimal nearest-even rounding, as defined by Python 3.11 decimal documentation, ROUND_HALF_EVEN. Exact integer quotient and remainder arithmetic avoids double rounding. The caller explicitly chooses decimal places. rounding_sensitive means the nominal limit decision differs when made on displayed text; it does not describe interval overlap. Display digits remain a presentation choice, never evidence of accuracy.

Sources and applicability

The Ansys 2025 R2 results-translator reference distinguishes default elemental and nodal storage representations. This supports keeping storage and export records separate; its approximate error statement is not used as a bound or acceptance criterion. Installed-release settings and per-quantity applicability require direct evidence. The public page was retrieved successfully; no licensed solver was started or queried.

Numeric fixture inputs and expected values are derived in test docstrings. No standards-derived material constant, safety factor, storage error estimate or acceptance tolerance is supplied by this implementation.

Verification and limitations

tests/test_result_precision.py checks hand-derived intervals, inclusive limits, missing evidence, false precision, nearest-even ties, signed weights, cancellation, unit mismatches, invalid numbers and the executable example. External adapter integration, native evidence authentication, nonlinear propagation, statistical covariance, uncertain weights and physical error qualification remain follow-up work. Independent provider review remains required before merge.
