Compliance alert summary contract

An empty review window does not establish a compliance percentage. The daily alert wrapper suppresses threshold alerts when the validated reviewable count is zero. Missing or inconsistent summaries are errors, rather than passing observations.

Inputs and method

The dashboard emits a top-level JSON object after JSON Report:. Required fields are total_commits, skipped, reviewable, reviewed, unreviewed, compliance_rate, threshold and verdict. Counts and percentages are nonnegative integers; booleans are rejected.

The identities are total = skipped + reviewable and reviewable = reviewed + unreviewed. For a positive denominator, rate = floor(100 × reviewed / reviewable). These equations follow scripts/enforcement/compliance-dashboard.sh, main(), as inspected for this revision. The zero-denominator numeric placeholder remains zero for compatibility, but is not a measured rate. The dashboard verdict is checked against its own reported threshold.

Alert boundaries remain those in issue 4105, Thresholds table, dated 2026-10-19: below 30% critical, from 30% to below 50% high, from 50% to below 80% medium, and at least 80% no alert. The dashboard execution contract is exit zero for PASS and exit one for FAIL; other exits are errors. Nested drift-event verdicts do not replace the summary verdict.

Verification and limits

tests/enforcement/test_compliance_cron.py runs copied scripts with isolated command doubles. GitHub calls are recorded locally and no remote operation is performed. The tests cover empty and excluded-only windows, threshold boundaries, nested verdicts, inconsistent counts, invalid types, missing JSON and execution errors.

The existing dashboard commit classification and review-evidence heuristics are unchanged. This contract validates summary consistency, not the authenticity or completeness of review evidence. Weekly aggregation is unchanged. Existing alert issues are not closed automatically. Independent review and publication remain separate steps.
