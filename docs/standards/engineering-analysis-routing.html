Documentation reach, analysis compliance and reusable response readiness are separate observations. This guide introduces no engineering equations, acceptance limits, solver execution or installed enforcement.

Record routing and compliance in existing records

Attach a structured observation to the existing repository issue or owning analysis record. The worked example is a template, not a new allocation registry. The schema is optional documentation support; it is not connected to runtime gates, hooks or publication. Its validation checks shape only.

ObservationRecording rule
Criteria and workflowRecord both owner-relative locators, document revisions and exact source revisions. Reconcile later source changes in the owning analysis; never silently replace a pinned basis.
RoutingUse DOCUMENTED only with an inspected entry point, its exact revision and an evidence reference. NOT_EVALUATED means not assessed; UNREACHABLE records a failed resolution with its reason. None of these statuses establishes analysis compliance.
ComplianceUse NOT_EVALUATED until an analysis is assessed. PARTIAL and DEMONSTRATED require an exact analysis revision and evidence references. The assigned independent reviewer checks every applicable criterion, approved exception and unresolved finding. Schema validity alone cannot establish either assessment or independence.
DatasetREFERENCED requires the authoritative owner, unchanged dataset identity, explicit revision, owner-relative manifest reference, SHA-256 digest and existing catalog reference. It indicates a reference, not verified bytes, rights or readiness. Uninspected datasets remain NOT_EVALUATED with null identity fields.
Coverage and response qualificationRetain the complete attempted-case ledger, sampling design, invalid/failed/unresolved dispositions and response-specific evidence in the owning analysis. Do not sum documentation records as verified cases or treat a missing check as a physical zero. Refer to criteria AC-06 through AC-08 rather than defining new thresholds here.
Query and maintenanceResolve dataset/method revision, component/model identity, exact parameter keys, units, response definition and intended use. Verify current rights, bytes, review, withdrawal and readiness before use. Record consumers and impact dispositions on correction. The existing criteria AC-09 through AC-13 govern acceptance and non-exact extensions.

Worked example: documented route with no qualified answer

Inputs: the linked JSON observation identifies digitalmodel issue 2117, a lifting connection assessed by hand calculation, the pinned criteria/workflow revisions and the historical direction record. The pinned engineering entry point links the criteria. No current analysis package, independent response verification or dataset was inspected.

Method: inspect the pinned entry point and resolve the criteria/workflow identity. Classify documentation reach separately from analysis and dataset evidence. The schema requires entry-point evidence for DOCUMENTED and refuses PARTIAL or DEMONSTRATED without an analysis revision and assessment evidence. This is a logical evidence classification; no engineering equation, coefficient or numerical acceptance limit is used.
