Claude native instruction recovery

This procedure supports the Windows pilot in issue 1249. It restores the preserved machine loader before a fresh native verification. It does not authorize sibling or fleet deployment.

Admission and evidence lifetime

The native rule links to the persistent canonical Claude runtime. Admission requires the current provider binary/version, source, project configuration, protected policy state, retained evidence digests and original transaction journal to match the successful receipt. Credential content is excluded from admission comparison because OAuth refresh is expected; credential file presence, type and metadata remain checked. Full credential-content hashes are used only for preservation checks during the pilot. No credential content is saved.

A changed rule, hook, setting, provider or canonical source requires renewed verification. A change cannot be classified as unrelated from its filename alone. Failed admission therefore remains blocked until the current baseline is reviewed and observed again. Successful historical evidence remains historical; it is not rewritten into a new acceptance result.

Keep the authoritative pilot output in the durable machine evidence directory under %LOCALAPPDATA%/workspace-hub/evidence/. Keep original journals under %LOCALAPPDATA%/workspace-hub/transactions/. These directories are outside repositories and instruction discovery. The home receipt is a byte-identical reference copy. Deleting either evidence or original journals invalidates admission and can remove automatic recovery inputs.

Explicit operator restore

  1. Acquire the existing scoped coordination claim and check active work before any mutation. Preserve all failed attempts, settings, parked links and archived bytes. Do not run concurrent loader installation.
  2. Read the successful receipt's recovery object. Independently compare its capture/final journal digests against retained reviewed evidence. The source digest shall identify the current reviewed canonical source; do not blindly replace an expected digest after a mismatch.
  3. Use the reviewed helper below with those exact values and a new journal directory on the same volume as the user home. The destination must not exist. The flags below are placeholders for verified values, not an executable deployment record.
python -B scripts/agents/claude_native_restore.py \
  --home USER_HOME --source PERSISTENT_CANONICAL_RUNTIME \
  --capture ORIGINAL_CAPTURE_JSON --capture-sha256 REVIEWED_CAPTURE_SHA256 \
  --final ORIGINAL_FINAL_JSON --final-sha256 REVIEWED_FINAL_SHA256 \
  --source-sha256 CURRENT_REVIEWED_SOURCE_SHA256 \
  --journal NEW_SAME_VOLUME_RECOVERY_DIRECTORY --execute

The helper validates source, parents, journal digests and loader identities before moving anything. It restores the original legacy link first, parks the native link and home receipt in the new journal, and preserves unrelated rules. No files are deleted. LEGACY_RESTORED is the successful terminal state. On an interrupted move, conditional recovery returns NATIVE_RESTORED or BLOCKED; concurrent changes are preserved. A missing terminal record is incomplete evidence even if the loader appears restored. Inspect actual paths and retained prestate before any further action; never retry against an occupied journal.

Re-verification and limits

A credential-content change during the pilot will stop that attempt under the approved plan's full preservation requirement, even if OAuth refresh is suspected. This differs deliberately from later admission. Inspect the retained before/after hashes, provider evidence and rollback result without copying credentials. If rollback is verified and the original legacy loader is restored, a reconciled new attempt can use a unique output name; journal names are derived from that name. The old output and both old journals shall remain in place. No removal, relocation or manual cleanup is needed. A regression covers a mid-trial credential change, exact legacy restoration and a successful freshly named synthetic attempt while preserving failed evidence. If rollback is incomplete or current identities differ, stop for owner reconciliation; the finalized-journal restore helper does not apply to an unfinished transaction.

After a verified legacy restore, review the changed baseline and run the approved native pilot with a new durable output name. Retain both generations of receipts and journals. The pilot must observe project and nested instruction loading, lazy discovery, global positive/negative controls, rollback and final canonical readback. Fixture tests and a successful command exit alone do not qualify native loading.

The scoped installer admission helper and read-only status/drift checks can then be exercised. Running the full multi-provider installer is outside this Windows pilot. Origin/main-based drift may remain STALE while the repair is on an unmerged branch; report that state separately from native loading. Merge and fleet readiness are not established by this recovery procedure.
