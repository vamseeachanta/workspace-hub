Capture snapshot review contract

Repository-path validation shall precede repository commands. Snapshot completeness and satisfaction of the trusted specification shall precede equality qualification. The executable assertions in tests/contract/capture_review_contract.py implement a reusable review test contract; they do not collect records, introduce a persistence schema or establish runtime readiness.

Review gates

  1. Root and bindings: establish the intended physical root, ancestors and permitted Git metadata paths without invoking Git. Reject prohibited links, absent metadata and redirected bindings before reading repository configuration. A legitimate linked worktree requires explicit validation of its pointer and common directory; it shall not be rejected solely because its .git entry is a file.
  2. Completeness: validate identity, intended member sets, every required nested field and exact types against the trusted specification and owning schema. A record's own member list or specification digest cannot supply missing intended membership.
  3. Conditions: independently evaluate each declared absence, content digest, metadata, required ignore-entry and untracked-selection condition against each complete record. Unsupported conditions shall remain explicitly not evaluated and shall not qualify.
  4. Equality: compare only records that pass the preceding gates. Two complete, condition-satisfying records may still differ. Missing, incomplete, failed, different and qualified dispositions shall remain distinguishable.

Review shall hunt for counterexamples rather than assume acceptance: identical empty identities; omitted nodes or repositories; empty nested records; wrong container and scalar types; correctly bound but violated conditions; validation of one argument only; and commands issued before root rejection. A review verdict shall bind the actual adapter, callers, specification, fixture bytes and execution environment. Changed bytes require review of the affected delta and interfaces.

Executable test contract

assert_repository_rejection(capture, root, monkeypatch, rejection) intercepts both subprocess.run and subprocess.Popen. It records attempted launches before raising, and requires an explicit caller-specific rejection with no attempted subprocess. An unrelated crash or silent return fails the test. Run it separately for a linked root, linked ancestor, missing Git binding, linked Git metadata and redirected Git pointer. Supply a positive control for each legitimate repository form in the caller's own tests.

The interception covers standard Python subprocess entry points during the assertion only. Native bindings, previously cached launcher references, direct operating-system execution and external processes require caller-specific spies or isolation. These assertions alone do not establish freedom from filesystem races; descriptor binding and race fixtures remain caller responsibilities. Fixture processes shall clear inherited Git bindings before repository discovery and preserve caller files and Git metadata.

assert_comparison_contract(compare, specification, cases) accepts an adapter returning the test dispositions below. The adapter shall translate existing result enums or explicit validation exceptions, without duplicating validation or converting arbitrary crashes into expected rejection. Fixture authors supply the intended specification independently from the snapshots. Inputs are copied for each invocation and checked for mutation.

The helper requires the complete category inventory and rejects duplicate names, unknown categories and contradictory expected dispositions. Use category:field names to enumerate every required field and type of the actual schema. The minimal category set is not exhaustive schema coverage. Every missing, incomplete or failed fixture is tested identically against itself, against the qualified control, and in both argument orders. The different-record control must contain distinct records, and each must qualify against itself before comparison. A right value of None repeats left; a missing-evidence case uses left=None.

Worked synthetic example

The executable example is tests/contract/test_capture_review_contract.py. All tokens below are synthetic literal evidence, not measured values or real content hashes. The test-only comparator illustrates the assertions; it is not a new production comparator.

Trusted specification:
  identity: fixture
  digest: expected
  ignored: cache
Intended membership:
  nodes: config
  repositories: repo
Complete snapshot:
  identity: fixture
  nodes:
    config: {digest: expected, mode: regular, absent: false}
  repositories:
    repo: {ignored: [cache], untracked: []}

Method and answer: by direct inspection, the complete snapshot has the intended identity and members, every required field and type, a present regular node with the expected digest, the required ignore entry and no selected untracked records. Two copies therefore return qualified. Removing nodes.config.digest leaves a required field unknown; two copies return incomplete. Keeping the record complete but changing the digest to other violates the trusted condition; two copies return failed. Adding a distinct observation to one otherwise qualifying record yields different. Absent records yield missing. Each expected result is written independently in the fixture table and test docstring.

The same procedure changes absence to true, metadata to a link, required ignore membership to empty, and untracked selection to a nonempty list. Each complete counterexample returns failed, even when both records are identical. Tests deliberately substitute equality-only, shallow, condition-skipping, one-sided and mutating implementations and require the assertions to detect them.
