# Public guidance for offshore engineering analysis report structure
Date of research: 2026-10-13; public sources only; issue reference: #3925.

## Scope and questions

1. Classification-society documentation requirements for analysis reports submitted for review: what a report must contain, from freely published rules and guidance.
2. Reporting sections that public recommended practices and guidance call for in riser analysis, lifting and installation analysis, cathodic protection design, and diffraction hydrodynamic analysis.
3. Design-basis contents according to public sources, including data, codes, load cases, acceptance criteria, assumptions and revision control.
4. Presentation of operating limits and conclusions to operations teams, including operability tables, limiting sea states, watch circles, weather windows and summary-first layout.
5. A proposed common section list and rules, compared item by item with the repository draft reporting standard.

## Method

Network access was proven first by opening `https://ww2.eagle.org/en/rules-and-resources/rules-and-guides.html`; the returned page title was "ABS Rule Manager". The issue and comments for #3925, the named merged pull requests, the repository documentation index, and `docs/standards/engineering-reporting-conventions-proposed.html` were then read.

Search terms used: `classification society analysis report documentation requirements offshore rules guidance report submitted for approval`; `DNV offshore standard design basis document load cases acceptance criteria assumptions revision control public`; `riser analysis report contents design basis methodology results public PDF`; `offshore installation analysis report lifting analysis report contents operability limiting sea state public PDF`; `DNV-RP-B401 cathodic protection design report`; `diffraction hydrodynamic analysis report contents offshore WAMIT AQWA public PDF`; `operability table limiting sea state weather window watch circle offshore public PDF`.

Sources opened: 20. Sources cited in findings: 12. Sources not used because access failed, content was too large, or the page was only a search result are listed under Not found.

## What the sources state and what is inferred

Stated:

- Classification guidance states that submitted documentation includes objectives, premises, assumptions, conclusions, design criteria, design basis, analysis and testing documents.
- Riser guidance states that design analysis documentation is self-contained, includes summary, introduction, design basis, input data, formula references, traceability, model graphs, key results and interface loads.
- Cathodic-protection guidance states a named CP detailed design report and lists its calculation and drawing content.
- Hydrodynamic-diffraction tool guidance states that standardized hydrodynamic analysis reports can be generated and that calculation parameters include radiation/diffraction choices, water depth and numerical method selections.
- Marine-operation guidance and examples state limiting sea states, calculated operability, weather-window decisions, watch-circle radius and wave-height/wave-period probability matrices.

Inferred:

- A common offshore analysis-report structure can be formed by grouping the stated content into: summary, scope, design basis, methodology, model, cases, criteria, results, operating limits, verification, conclusions, recommendations, references and appendices. This inference rests on the riser design-analysis list, CP detailed-design report list, CR documentation table and hydrodynamic report parameters above.
- Design-basis sections should include data provenance, governing codes, load cases, acceptance criteria, assumptions, operational philosophy and revision control. This inference rests on the CR design-basis description, the DNVGL-ST-F201 design-basis list and the DNV-RP-N201 lifting input-data and operational-criteria statements.
- Operations-facing conclusions should be table-first and limit-first where the result controls execution. This inference rests on the DNV-RP-H103 operability tables, the ResearchGate weather-window paper page and the NYSERDA probability matrix and watch-circle table.
- Diffraction-analysis report sections need explicit numerical-method and parameter subsections because the WAMIT/SIMA sources define radiation/diffraction problem type, method order, source strength, singularity treatment and solver method as calculation parameters.

## Proposed common section list and rules

The following proposal is derived from the stated source requirements above. Each item is marked as a proposal and compared to `docs/standards/engineering-reporting-conventions-proposed.html`.

| Proposed item | Basis in findings | Relation to repository draft standard |
|---|---|---|
| Proposal: 1 Executive Summary with governing result, criterion, operating limit and next action. | Riser summary and key results; DNV-RP-H103 operability tables; NYSERDA summary-first availability statement. | Agrees with Section 2 Executive Summary and adds an explicit operating-limit cue for operations-facing analyses. |
| Proposal: 2 Scope, configuration and exclusions. | CR documentation objectives/premises; riser introduction and brief system description. | Agrees with Section 2 Introduction and Section 3 register rules; no material difference. |
| Proposal: 3 Design Basis with source data, codes, environmental data, load cases, acceptance criteria, assumptions and revision status. | CR design-basis table; DNVGL-ST-F201 design-basis list; DNV-RP-N201 input-data requirement. | Agrees with Section 3 Design Data and Section 4 Basis; adds a stronger requirement to state revision status inside the design-basis section when the source basis is versioned. |
| Proposal: 4 Methodology and model, including software, numerical method, boundary conditions, mesh/panel model and verification approach. | Riser calculation input and model graphs; WAMIT/SIMA diffraction parameters; Aqwa primary hydrodynamic parameters. | Agrees with Section 4 Analysis Methodology; adds diffraction-specific numerical parameter headings. |
| Proposal: 5 Analysis cases and operational envelope. | Riser load cases and operating modes; lifting operational criteria; marine operability examples. | Adds to the draft: the draft covers operating cases and limits, but a distinct operational-envelope subsection would help operations teams find limits faster. |
| Proposal: 6 Results and checks, with result tables tied to criteria, comparator class and governing case. | Riser key results and limit states; CP calculations; repository draft comparator language. | Agrees with Sections 5 and 6 of the draft standard. |
| Proposal: 7 Operating limits, weather windows and monitoring requirements where the analysis supports field execution. | DNV-RP-H103 limiting sea states; ScienceDirect weather-window decisions; DNV-RP-N201 monitoring parameters. | Adds to the draft: Section 7 Limitations and Section 8 Recommendations cover implications, but an operations-limit table is clearer for marine operations. |
| Proposal: 8 Conclusions, limitations and recommendations, each bound to evidence and missing basis. | CR conclusions; riser result evaluation; repository standard limitation classes. | Agrees with Sections 6, 7 and 8. |
| Proposal: 9 References, source rights, and internal traceability. | CR regulatory basis; riser formula references; WAMIT rights notice. | Agrees with Section 9 References and Section 8 audience/source-rights controls. |
| Proposal: 10 Appendices for calculations, drawings, model evidence, certificates, detailed operability tables and verification records. | Riser drawings and DFI resume; CP detailed calculations; lifting certificates; hydrodynamic report parameters. | Agrees with Appendix A onward; adds explicit certificate and operability-table placement for lifting and marine-operation reports. |

Rules proposed:

- Proposal: every section that reports a conclusion also states its criterion, comparator or design limit, and governing case. This follows the riser key-result requirement and the repository draft; it agrees with the draft.
- Proposal: operating-limit tables are mandatory when the report will be used offshore or by planners. This follows the DNV-RP-H103 and DNV-RP-N201 findings; it adds to the draft.
- Proposal: design-basis tables mark supplied, assumed, derived and pending data, with source revision where available. This follows the CR and riser findings; it agrees with the draft and adds revision visibility.
- Proposal: hydrodynamic diffraction reports state water depth, frequency and heading ranges, radiation/diffraction options, method order, source strength/singularity treatment and output quantities. This follows WAMIT/SIMA/Aqwa findings; it adds discipline-specific detail to the draft.
- Proposal: source-rights status is recorded for standards, manuals and public reports before reuse. This follows the WAMIT restriction notice and the repository public-source boundary; it agrees with the draft audience/source-rights controls.

## Recommendations for the report

- Use the repository draft ten-section sequence as the main report frame; this follows Findings 1 and 2.
- Add a required operating-limit table when the report informs field execution; this follows Findings 2 and 4.
- Keep the design basis as a checkable table of data, codes, assumptions, load cases and criteria; this follows Finding 3.
- For riser reports, include the DNVGL-ST-F201 design-analysis content as a discipline checklist; this follows Finding 2.
- For CP reports, include the CP detailed-design report list as the minimum calculation checklist; this follows Finding 2.
- For lifting reports, include input data, certificates, load-radius basis, operational criteria and monitoring parameters; this follows Findings 2 and 4.
- For diffraction reports, include numerical-method parameters and the selected report outputs; this follows Finding 2.
- Keep rights and access status in the source list when citing standards or software manuals; this follows the source-rights findings.
