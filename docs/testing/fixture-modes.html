Physical and Git modes in test fixtures

A native fixture is ready when its physical permissions and Git index mode match the intended file type, and its owned path has clean Git status. An index-only executable change leaves a nonexecutable working-tree file dirty when core.filemode=true. Windows fixture success alone does not establish native POSIX coverage.

Fixture inventory

The tracked fixture builders that explicitly assign index modes are tests/readiness/test_reconcile_ecosystem.py and tests/skills/test_materialize_profile.py (symbolic-link entries), tests/client_llm_wiki/test_bootstrap_snapshot.py and tests/workstations/test_clone_profile.py (submodule entries). These entries intentionally model nonregular files; physical regular-file modes must not be imposed on them. The tracked inventory contains no executable regular-file fixture using an index-only chmod operation. The new negative regression introduces that operation deliberately.

The native sibling repair fixture now sets physical permissions before staging and checks both modes and clean owned-path status after every fixture commit. Its Git environment excludes inherited repository bindings and global configuration. Production admission checks and portability policy are unchanged.

Worked example

Input: a new control.sh containing #!/bin/sh and exit 0, intended to be executable. The method is exercised by test_prepared_file_has_physical_index_and_clean_status:

path.write_text("#!/bin/sh\nexit 0\n")
prepare_file_mode(path, executable=True)
commit_all(repo)
assert_file_modes(repo, "control.sh", executable=True)

Expected answer: physical permissions 0755, index mode 100755, and empty owned-path status. For a nonexecutable regular file, the corresponding permissions and mode are 0644 and 100644. These values follow the Git 2.44.0 index format, Index entry mode field, rather than an engineering equation or coefficient.

Independent negative derivation: a committed file with physical permissions 0644 retains those permissions after git update-index --chmod=+x -- control.sh, while its index mode becomes 100755. Therefore the executable expectation fails physical readback, the nonexecutable expectation fails index readback, and git diff-files reports the path. The tests assert all three observations independently.

Forward and recovery criteria

A correctly prepared native fixture must reach the complete repair path. An injected exception after the owned file rewrite must restore the original bytes, permissions and link target, with empty owned-path status. A deliberate physical mode change on an owned file must block repair before installation. Content dirt and disabled native mode detection are also rejected by the helper.

Coverage limits

The dedicated POSIX mode regressions explicitly skip on Windows. The portable repair tests still run there, but their success is limited coverage until native POSIX controls pass. A filesystem that does not honor executable bits cannot satisfy the native regression. Tests use disposable repositories and synthetic files; no provider process or live installation is exercised. Second-provider review remains required before merge.
