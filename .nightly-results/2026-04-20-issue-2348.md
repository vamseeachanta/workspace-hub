### Adversarial probes (defect-hunt stance)

1. **Q: Could the override parser produce a false positive if someone puts
   "Owner override:" in a non-source-heading `##` section (e.g. a future
   "Policy questions" section)?**
   A: No. The parser filters headings by `title.lower().startswith("source:")`
   — non-source `##` headings are skipped entirely.

2. **Q: Could the override parser under-match if a section has CRLF line
   endings or a different indentation?**
   A: `re.MULTILINE` anchors match at `\n` boundaries regardless of `\r`;
   `^##\s+` tolerates trailing whitespace. LF-only content in this repo per
   `.gitattributes` discipline. Low risk.

3. **Q: Could the robots.txt check succeed but robots.txt itself be a
   CAPTCHA/HTML page rather than a valid robots file (so can_fetch returns
   True for everything, giving us a false-allow)?**
   A: `urllib.robotparser.RobotFileParser.read()` raises on network-level
   failure but does not validate content. A 200-OK HTML page without valid
   robots directives would cause `can_fetch` to default to True. This is a
   residual risk inherited from stdlib behavior; mitigation is that live
   robots.txt files on indeed.com / linkedin.com / career-page hosts return
   valid Robots Exclusion Protocol content in production per today's run.
   Documented in observational-follow-up V3 from the plan.

4. **Q: Can `--skip-career-pages` smuggle LinkedIn/Indeed past the override
   mechanism?**
   A: No. `safe_request()` runs the robots check unconditionally for every
   URL regardless of the career-page flag; the flag only controls whether
   the career-page loop runs, not the per-request policy.

5. **Q: What if `TOS_REVIEW.md` is deleted in a PR?**
   A: `_parse_owner_overrides_from_tos_review()` returns `set()` when the
   file is absent (`test_override_parser_survives_missing_file`). LinkedIn
   would then silently drop from the run via fail-closed robots — which is
   the safest possible failure mode (no un-authorized scraping). The doc-test
   asserting presence would fail in CI for any PR that deletes the file.
