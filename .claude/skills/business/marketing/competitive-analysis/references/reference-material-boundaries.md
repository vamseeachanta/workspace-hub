# Reference Material Boundaries for Competitor-Derived Assets

Use when a session produces or imports artifacts from competitor-adjacent material, market examples, demos, reports, screenshots, or public competitor workflows.

## Default classification

Treat competitor-adjacent assets as **research/reference material**, not as reusable GTM or project-delivery collateral.

This applies even when the artifact is polished, committed, or visually useful. Commit/push only means it is preserved in the repo ecosystem; it does not imply approval for external use.

## Required boundary statement

When documenting the asset, explicitly state:

- whether the material is internal reference, research note, methodology seed, project collateral, or GTM collateral;
- whether any named organization is a competitor;
- whether downstream reuse requires explicit approval;
- what future work should extract as original methodology versus avoid copying.

## Safe usage

Allowed by default:

1. Internal research and market understanding.
2. Competitive analysis and positioning notes.
3. Extraction of abstract engineering/reporting patterns.
4. Planning original repo-native workflows, schemas, and reports.

Requires explicit user approval:

1. Client/project delivery reuse.
2. GTM/public collateral reuse.
3. Direct use of competitor-derived wording, layout, claims, or visuals.
4. Any external publication or send action.

## Closeout expectation

If the user clarifies that a polished asset is only reference material, add a small README or handoff note at the canonical repo path so future sessions do not promote it into GTM/project collateral by accident.
