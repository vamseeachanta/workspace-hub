# Engineering workflow context retrieval

Use for delegated FEA, calculation or report tasks. Start in the owning project's instructions and existing accepted workflow; the common routes below are a retrieval aid, not a substitute for qualified engineering inputs or current approval.

- Read [FE analyst](../../../../engineering/marine-offshore/fe-analyst/SKILL.md) for the existing analysis sequence and archived method references. Retrieve the project model/input revision, units, materials, load cases/combinations, boundary conditions, solver/version and license route, mesh/convergence basis and design-code/acceptance revision before inferring readiness. Missing qualified inputs belong in the existing assumption/decision ledger, not fabricated model defaults.
- Carry the full applicable sequence through setup, model/mesh checks, solver execution, convergence and result extraction, design checks, report generation and artifact review. Reuse the closest accepted model/report and its tests after checking applicability. A file, submitted run or solver exit alone does not prove an accepted engineering result; distinguish numerical verification, physical validation and acceptance.
- For calculation deliverables, read [calculation report](../../../../data/calculation-report/SKILL.md). For report production read [engineering report generator](../../../../development/engineering-report-generator/SKILL.md), [claim discipline](../../../../../../.claude/skills/development/report-claim-discipline/SKILL.md) and [HTML/report verification](../../../../development/html-report-verify/SKILL.md) as applicable. Existing Engineering register, audience/surface rules and project template remain authoritative. Preserve source/provenance, uncertainty, assumption and design-basis links through the report; generating HTML/PDF is not render/content verification or publication.
- Retrieve the latest task handoff and artifact manifest from the owning repo. The existing [artifact verification reference](../../../../../../.claude/skills/development/html-report-verify/references/engineering-report-artifact-verification.md) explains regeneration, manifest integrity and bounded content proof. Link the model/input revision, run/log and accepted results to the final artifacts and recorded review; qualify any check unavailable on the current host.

Search existing catalogs, project plans and accepted artifact references before requesting paths. If a link is broken, inspect its archive/history and current replacement within permitted context; record that status. Archived examples are historical mechanics, not current standard editions, machine readiness or client commitments. Do not retrieve or transfer another client's sources to fill a project gap.
