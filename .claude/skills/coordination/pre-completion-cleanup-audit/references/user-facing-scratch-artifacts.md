# User-facing scratch artifacts

Use this note when a task intentionally generates files for the user outside a canonical repo, such as recursive inventories, exported reports, downloaded PDFs, screenshots, or media attachments.

## Durable lesson

Do not treat every `/tmp` or `/mnt/local-analysis` artifact as cleanup residue. If the artifact is the requested deliverable and is named, verified, and delivered or linked to the user, classify it as **EXPECTED** residue in the closeout audit.

## Recommended closeout wording

- `EXPECTED residue: /tmp/<artifact> preserved because it is the delivered user-facing output.`
- Include file size/count evidence when available.
- If both a script and generated output are kept, name both explicitly.

## Boundary

This does not authorize broad cleanup or deletion. The audit remains report-first: preserve requested deliverables, surface unrelated scratch separately, and only delete when the user requested cleanup or the governing cleanup skill says it is safe.
