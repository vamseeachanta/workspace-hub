## Mission

Remove the deprecated `scripts/work-queue/next-id.sh` script and ensure all callers use `gh-next-id.sh` instead. The old script allocates WRK IDs from a local counter (`state.yaml last_id`) which produces IDs that don't match GitHub issue numbers, breaking the unified numbering established by WRK-5097. The deprecation warning is insufficient — agents ignore it and create mismatched WRK/GH pairs.

Additionally, resolve the archive collision problem: `gh-next-id.sh` creates GH issues in the ~1300 range, but archived WRK items already occupy those IDs, making the new GH issue numbers unusable as WRK IDs.

## Acceptance Criteria

1. [ ] `scripts/work-queue/next-id.sh` deleted or replaced with a hard error pointing to `gh-next-id.sh`
2. [ ] All references to `next-id.sh` in skills, scripts, and docs updated to `gh-next-id.sh`
3. [ ] Archive collision resolved: `gh-next-id.sh` checks for existing WRK IDs before returning
4. [ ] Hook or guard that blocks WRK creation if GH issue number collides with archived WRK
5. [ ] `state.yaml last_id` field documented as legacy-only (not used for new allocations)
