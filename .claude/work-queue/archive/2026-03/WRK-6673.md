# GH Issues as Single Source of Truth

## Mission
Make GitHub Issues authoritative for work item metadata. Local files become cached views synced from GH. GH is the single source of truth.

## Tasks
- [ ] Design GH issue template with required fields: status, priority, machine, category, subcategory, complexity, route
- [ ] Set up GH project board custom fields (or labels) for machine assignment and execution tracking
- [ ] Write `gh-sync-down.sh` — pull GH issue metadata → update local frontmatter + rebuild index (GH → repo)
- [ ] Refactor `whats-next.sh` to query GH API (with local cache fallback) instead of scanning local markdown
- [ ] Refactor `/work add` to create GH issue first (`gh issue create --template`), then generate local file from GH response
- [ ] Deprecate `rebuild-wrk-index.sh` in favor of GH-sourced index — keep as fallback only
