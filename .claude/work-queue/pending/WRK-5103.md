# WRK-5103: Filter ghost entries from whats-next output

## Problem

When WRK files are deleted from disk (completed/removed) but `wrk-status-index.json`
is not rebuilt, ghost entries appear in `whats-next.sh` output. This wastes time —
users pick up items that are already done (e.g. WRK-1360, WRK-1362 appeared as
high-priority with urgency 46.0).

## Fix (2026-03-23)

Added `file_exists_on_disk(wid)` check in the Python classifier within
`scripts/work-queue/whats-next.sh`. Non-archived entries whose `.md` file is missing
from `pending/`, `working/`, and `blocked/` are silently skipped.

Immediate result: 4 ghost entries removed (107→103 high-ready, 8→6 working).
