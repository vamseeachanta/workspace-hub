# WRK-5126: Session-to-execution flow — integrate intelligence and structure into /work

## Problem

Agents executing `/work run` don't automatically know about:
1. The data intelligence map (`docs/document-intelligence/data-intelligence-map.md`) — where to look before searching
2. File structure conventions for artifacts, work items, assets, specs, code, tests
3. That Chrome extension (claude-in-chrome) is available for browser-based testing
4. How session-start → work-execution flows end-to-end

## Questions to Resolve

- Should `/work run` auto-load the data intelligence map as context, or just reference it?
- Is a single entry-point `.md` file the right pattern for document intelligence (vs. skill trigger)?
- What file structure checks should be enforced at which stage gates?
- How should chrome-extension testing be surfaced — as a stage option, a skill trigger, or a checklist item?
- What other session learnings should be codified into the work execution flow?

## Scope

1. Map the full session-start → `/work run` → execution → completion flow
2. Identify where data intelligence context should be injected
3. Ensure file structure adherence is checked (stage gate or hook?)
4. Add chrome-extension testing as a known capability in the work/test stages
5. Review recent sessions for other patterns worth codifying
