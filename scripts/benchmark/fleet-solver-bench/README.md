# fleet-solver-bench

Measures wall time per workload class on each fleet host and checks that every host
produces the same OrcaFlex answer. The results set which host receives which job class
and how many parallel workers each host takes (`routing-rules.yaml`).

## Workloads

| ID | Script | Workload | Licence |
| --- | --- | --- | --- |
| W0 | both | Host profile: CPU, cores, RAM, disk, Python, OrcaFlex DLL version | none |
| W1 | `bench_cpu.py` | NumPy matmul (1 thread / all), FFT, pure-Python loop | none |
| W2 | `bench_orcaflex.py` | Statics, generated catenary riser, segment 10 / 2 / 0.5 m (S / M / L) | Orcina seat |
| W3 | `bench_orcaflex.py` | Dynamics, same riser, regular wave, 10 s build-up + 200 s | Orcina seat |
| W4 | `bench_orcaflex.py` | 16 M-size dynamic runs across K worker processes, K = 1, 2, 4 … logical cores | Orcina seat |

The riser model is generated by `build_model()`; no client model or data is used.

## Running

Records carry the fleet label (`ace-win-1`, `ace-linux-2`, …) and are refused without
one; physical host names stay in the private label map. Results default to
`~/fleet-bench-results/<label>/` (override with `--out` or `FLEET_BENCH_ROOT`), outside
the repository.

```bash
# W0 + W1, any host, any time (~5 s)
uv run python scripts/benchmark/fleet-solver-bench/bench_cpu.py --label <label>
```

OrcaFlex workloads run **only through the scheduled-task path**; a direct-SSH session
cannot complete the FlexNet checkout (`.claude/rules/licensed-solver-dispatch.md`).
There is one `Flex` seat fleet-wide, so hosts run one at a time.

```bash
ssh <label> "powershell -NoProfile -ExecutionPolicy Bypass \
  -File '<repo>/scripts/windows/dispatch-run.ps1' -Action submit -Shell bash \
  -JobId bench-<label> \
  -Command 'uv run python scripts/benchmark/fleet-solver-bench/bench_orcaflex.py --label <label> --smoke'"
```

Drop `--smoke` for the full W2–W4 run. Set `FLEX_LICENSE_SERVER=27002@<server>` with
`lmutil` on `PATH` so the run checks the seat first and exits 3 when it is in use,
rather than queueing behind it. The W4 sweep stops when free RAM falls below 15 %.

Aggregate on any host once the JSON summaries are gathered:

```bash
python scripts/benchmark/fleet-solver-bench/aggregate.py <dir> [<dir> ...] \
  --reference ace-win-1 --out fleet-bench-report.md
```

## Correctness checks

Tolerances are fixed in the code before any run.

| Check | Comparator class | Tolerance | Where |
| --- | --- | --- | --- |
| Sum of end vertical forces vs. submerged line weight (statics; no seabed contact) | conservation | 0.5 % | `bench_orcaflex.py`, exit 4 on failure |
| Static top tension vs. reference host | cross-host | 1e-6 relative | `aggregate.py`, exit 1 on failure |
| Max dynamic top tension vs. reference host | cross-host | 1e-4 relative | `aggregate.py`, exit 1 on failure |

A host that fails a check is excluded from routing for that class until the cause is
found.

## Status

The OrcFxAPI calls follow `scripts/solver/generate_minimal_sim_fixture.py` and have not
yet run against a licensed DLL. The first `--smoke` run on `ace-win-2` is that test;
property names may need correction there. `tests/benchmark/test_fleet_solver_bench.py`
covers the harness wiring with a fake OrcFxAPI, which establishes nothing about OrcaFlex
results.
