## Findings

### A — MINOR — Manifest-model-pin gap
**Defect:** nothing prevented querying with a different embedding model than the index was built with. Result would be garbage similarity scores with no error.
**Fix applied:** added `test_manifest_model_pin` — runtime asserts `--model` matches `manifest.model` or exits.

### B — MINOR — Incremental refresh behavior ambiguous
**Defect:** pseudocode mentioned "incremental" but didn't specify how unchanged chunks are detected. Reviewer could reasonably assume full rebuild.
**Fix applied:** added explicit `chunk_hash` caching: if unchanged, reuse prior embedding.

### C — MINOR — `.gitignore` row missing from Files to Change
**Defect:** AC requires `embeddings.parquet` be gitignored; Files-to-Change table didn't list `.gitignore` modification. Implementation would likely forget.
**Fix applied:** added `.gitignore` row + `test_parquet_gitignored`.

### D — MINOR — no graceful handling of pre-#2360 state
**Defect:** wikis without `doc_key` frontmatter would crash the builder or emit silent zero-key entries.
**Fix applied:** added `test_missing_doc_key_skipped` — skip + log + skip-count in manifest.

### E — NOTED, NOT FIXED — cost-envelope assumption
**Observation:** issue body cites ~$5/week at `text-embedding-3-large`. That assumes ~50k docs. Current corpus size not verified; actual cost may differ. Spike should measure.
**Action:** left as-is; spike deliverable must empirically calibrate.

### F — verified — operating-model §4 consistency
Embeddings are an L2/L3 derived artifact, not a new layer. Plan does not invent "embedding layer" hybrid. Compliant.
