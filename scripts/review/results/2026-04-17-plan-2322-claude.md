## Findings
- **Correctness — `check-no-abs-paths.sh` allowlist is not expressible in shell.** The plan's pseudocode says "not in_allowlist(file, line_no)" with the allowlist described as "explicit constants, test fixtures, file-path arg parsing". The last category — detecting whether an absolute path appears inside a tool-call parameter vs. hardcoded in script logic — is undecidable by regex and requires AST parsing. Plan commits to functionality it cannot implement.
- **Correctness — `check-queue-git-tracked.sh` schema assumption unverified.** Pseudocode iterates `.claude/work-queue/*.yaml` for fields named `path`/`file`/`target`. Direct `ls` of `.claude/work-queue/` shows `pending/`, `done/`, `INDEX.md`, `scripts/`, `assets/` — no top-level `*.yaml` files. The actual schema was not sampled; the pseudocode is guessing.
- **Correctness — harness-file-size cap will fail on committed `MEMORY.md`.** `~/.claude/projects/.../memory/MEMORY.md` is currently 37 lines and above the 20-line cap, but that is not the file the check targets (plan says repo-root CLAUDE/MEMORY/AGENTS/GEMINI.md). Direct check needed: does any target file currently exceed 20 lines? If so, the check will fail on first commit and block everyone until a separate PR fixes it.
- **Correctness — pre-commit on harness-file-size will fire during transient in-session edits.** Short writes → commit cycles will hit this repeatedly. Memory (`feedback_queue_git_tracked.md`) shows the user values friction-aware tooling; the plan ignores this.
- **Scope — `.bats` dependency introduces setup burden.** Repo precedent is plain `test_*.sh` (verified: `scripts/enforcement/tests/test_require_review_on_push.sh`). Using bats requires installing bats-core, not documented as a repo dependency.
- **Scope — `check-no-abs-paths.sh` targets `.sh` and `.py` but TDD fixtures are all `.sh`.** `TDD Test List` has zero Python fixtures despite the check covering Python.
- **Scope — no rollback if a check false-positives.** A check that blocks commits needs a documented bypass (`SKIP_*=1` env var pattern from precedent in `require-plan-approval.sh`). Plan doesn't include one.
- **Scope — rule-doc citation lacks line-level anchor.** `Files to Change` says "cite new scripts" in `.claude/rules/coding-style.md` and `patterns.md`, but doesn't specify which line(s) get the citation. Low-effort implementer could satisfy with a trailing footnote, which doesn't help rule-readers.
