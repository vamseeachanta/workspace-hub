## Findings
- Tests are listed as `.bats` files, but recon of `scripts/enforcement/tests/` shows existing tests use plain shell (`test_require_review_on_push.sh`). Plan should default to the established pattern unless bats-core is already installed — bats adds a dependency without precedent.
- `check-no-abs-paths.sh` allowlist design ("allowlist: explicit constants, test fixtures, file-path arg parsing") cannot be expressed in a shell regex without codifying the allowlist. The plan should define the allowlist as an explicit file/line patterns list or a comment marker (e.g., `# abs-path-ok`) rather than leave it implicit.
- `check-queue-git-tracked.sh` pseudocode assumes fields `path`, `file`, `target` in YAML entries, but the actual schema under `.claude/work-queue/` was not verified (recon showed `pending/`, `done/`, `INDEX.md`, `scripts/`, `assets/` subdirs only). The plan should read one real queue file and pin the schema before implementation.
- Running harness-file-size check on pre-commit will fire on every commit that touches those files — including transient edits during a planning session. Consider pre-push instead, matching the precedent of `require-review-on-push.sh`.
- The rule-doc updates (`coding-style.md`, `patterns.md` citing the scripts) should specify exact line-level insertion points to avoid ambiguity; today the plan says "cite new scripts" without being specific.
- No tests for the absolute-path check on `.py` files specifically — the implementation targets `.sh` and `.py`, but the TDD list only shows shell fixtures.
