`★ Insight ─────────────────────────────────────`
Adversarial review of plans against a busy issue tracker has a specific failure mode: the planner's Resource Intel section often quotes parent/policy docs that exist but silently fails to enumerate sibling and predecessor *issues* whose scope overlaps. The plan's gap claim ("no contract exists") is locally true against files but globally false against open issues — a defect class that markdown-only retrieval misses.

## Findings

1. **Duplicate-scope blind spot vs. open issue #2119.** Plan §"Files to Change" line 135 creates `docs/architecture/execution-routing-matrix.md`. Open issue [#2119](https://github.com/vamseeachanta/workspace-hub/issues/2119) "feat(operations): define machine dispatch policy and workload routing contract" has identical deliverable scope (workload-to-machine routing, fallback rules, worked examples for licensed solver / AI review / GPU-heavy work). The plan never cites #2119, never explains how the new artifact reconciles, supersedes, or merges with it. Resource Intel §"Documents consulted" (plan lines 32–37) lists only #2728 and #2726. **MAJOR — splits architecture surface without coordination; merge or supersede must be decided in the plan, not after.**

2. **Authoritative machine registry ignored.** `config/workstations/registry.yaml` (222 lines) is the existing single-source-of-truth for machines, listing dev-primary (ace-linux-1), dev-secondary (ace-linux-2), licensed-win-1, licensed-win-2, macbook-portable, and gali-linux-compute-1 with `capabilities.agent_clis`, `tools`, `gpu`, `storage`, `telegram_hermes.dispatch_enabled`, and `sync_policy`. Plan §"Proposed Execution Layer Levels" line 112 lists "ace-linux-1, ace-linux-2, licensed Windows/machines, local worktrees, background jobs, provider agents" as if novel. Plan §"Files to Change" line 137 only says "Update: `config/workstations/registry.yaml` — Cross-link only if needed after approval" — i.e., the canonical registry is demoted to an optional cross-link instead of being declared the canonical input to the routing matrix. **MAJOR — proposes a new routing artifact that ignores the existing canonical registry's schema.**

3. **Resource Intel missed every relevant sibling/predecessor issue.** None of these appear in the plan's Documents-consulted list, yet all directly overlap:
   - [#2731](https://github.com/vamseeachanta/workspace-hub/issues/2731) "inventory and normalize canonical data/repo locations for llm-wiki promotion"
   - [#2732](https://github.com/vamseeachanta/workspace-hub/issues/2732) "canonical first/second-level mount and folder taxonomy" — explicitly lists itself as related to #2728 in its body, asks for `docs/architecture/repo-ecosystem-mount-map.md` and `config/repo_ecosystem_path_contract.yml`, which is the same scope the plan's "E-L1 Input contracts" + "data source_ids" boundary claims.
   - [#1838](https://github.com/vamseeachanta/workspace-hub/issues/1838) "AI credit utilization governance — horses-for-courses routing"
   - [#2089](https://github.com/vamseeachanta/workspace-hub/issues/2089) "weekly Hermes + AI provider settings review"
   The plan's Gap statement (line 18) "No single current architecture contract defines the data → execution → report layer boundaries…" is locally true against files in the repo but globally false against the open issue queue. **MAJOR — violates the discovery-first contract in CLAUDE.md / SHARED_SOUL.md.**

4. **TDD tests are doc-shape grep checks, not behavior tests.** All five tests in §"TDD Test List" (plan lines 145–149) check markdown presence:
   - `test_execution_manifest_required_fields` — "all required fields present" in a schema doc.
   - `test_no_execution_direct_publication` — "direct publish wording absent/blocked" in a contract doc.
   - `test_routing_matrix_has_capability_and_data_access` — "required columns present".
   - `test_validation_evidence_required_for_report_handoff` — "explicit gate present".
   - `test_input_data_boundary_crosswalk` — "source_id/path reference requirement present".
   These verify that the writer copied the required headings into the markdown; they do not verify any execution-time behavior. A markdown rewrite by any agent passes. Plan template `_template-issue-plan.md` line 175 calls for `uv run pytest <repo>/tests/path/to/test_module.py -v` against verifiable behavior. **MAJOR — tests measure obedience, not architecture safety. Plan-text presence tests cannot fail in the way a contract regression would.**

5. **Self-blocking risk in `test_no_execution_direct_publication`.** Plan line 146 says the test confirms "direct publish wording absent/blocked" in the contract. But the contract `docs/architecture/execution-layer-contract.md` (per plan line 133) is *the* file that must declare "direct publish is forbidden." A naive substring check will flag the contract itself for containing "direct publish." This is the **enforcement-script-blocks-its-own-artifact** pattern called out in `SHARED_SOUL.md` (per [#2722](https://github.com/vamseeachanta/workspace-hub/issues/2722) Gemini r2 #1). Plan must specify per-line sentinels or path-restricted whole-file sentinels, not blanket substring presence. **MAJOR.**

6. **`tests/architecture/` directory does not exist; `tests/governance/` does.** Plan §Artifact Map line 97 + §Files to Change line 136 create `tests/architecture/test_execution_layer_contract.py`. `ls tests/architecture` → "No such file or directory." `tests/governance/` exists and is the established home for governance/doc-shape tests. Plan creates a new top-level test namespace without justifying why the existing `tests/governance/` parent is wrong. **MINOR — but easy to fix and points to under-baked Resource Intel.**

7. **Acceptance criterion #3 already satisfied by existing artifact.** Plan line 156: "Routing matrix covers ace-linux-1, ace-linux-2, licensed machines, local worktrees, background jobs, and provider agents at the class level." `config/workstations/registry.yaml` already covers all five named machines (plus a sixth, `gali-linux-compute-1`) with capability, sync, license, and storage fields. The criterion is true *today*, before any implementation. Either the criterion is wrong-as-written or the planned deliverable is duplicative. **MINOR.**

8. **Acceptance criterion #7 is meta-circular template stuffing.** Plan line 160: "Plan receives adversarial review before `status:plan-review`." That is the workflow gate the plan is currently traversing, not a property of the deliverable. Acceptance criteria define the implemented system's success conditions, not the plan's workflow compliance. The template at `_template-issue-plan.md` lines 174–180 shows behavioral acceptance criteria (pytest commands, numerical tolerances). **MINOR.**

9. **"Line excerpts consulted" is paraphrase, not excerpt.** Plan lines 71–76 are a freehand summary block prefaced "Line excerpts consulted" but contain no `sed -n N,Mp` invocation and no verbatim YAML/markdown. Template line 84 (`Line excerpts (sed -n N,Mp path/to/file)`) explicitly requires verbatim excerpts so "reviewers verify line numbers match." Example: the paraphrase "source roots include workspace_hub_local, ace_standards_local, og_standards_local, ace_project_local, research_literature_local, DDE remote roots, api_metadata_virtual, and acma_codes_local" is not a quote from the registry — it's a writer's summary, indistinguishable from training-data hallucination on inspection. **MINOR — but it is a retrieval-discipline violation per `feedback_reviewer_dispatch_refetch_live_body` and CLAUDE.md "verify before citing."**

10. **Internal inconsistency in the registry citation.** Plan line 15 says the registry includes `api://worldenergydata`. Plan line 74 paraphrase says the registry includes `api_metadata_virtual`. Both happen to be partially true (registry source_id is `api_metadata_virtual` with `mount_root: api://worldenergydata` at lines 163–165), but the plan never reconciles the two surfaces or names what is actually canonical (`source_id`). **MINOR.**

11. **Prior review attempt failed silently.** `scripts/review/results/2026-05-17-plan-2728-claude.md` exists (0 bytes per `head -60`) alongside `.err`. The plan's "Status" header (line 5) says "not adversarial-reviewed" — but the artifact name pattern indicates a review WAS attempted and failed. Plan owes a one-line note on what happened. **MINOR — and `feedback_attestation_enables_contradiction_detection` applies: that empty `.md` next to an `.err` is exactly the silent-failure surface to address before re-running.**

12. **T3 complexity is asserted but unsupported.** Plan line 178 justifies T3 by topic surface ("crosses data input contracts, code/tools, machines/providers, licensing, validation, and report handoff governance"). Per AGENTS.md, T3 = 3-provider cross-review. Status (line 5) says review pending. The label is consistent with intent, but the plan does not specify *which 3 providers* will review (Claude + Codex + Gemini per default), nor does it acknowledge that Gemini quota outages or the prior failed attempt above will degrade T3 to T2 per `feedback_codex_sustained_major_loop` / provider-outage convention. **MINOR.**

13. **Gap-statement copied verbatim from parent plan #2726.** Plan line 18 ("No single current architecture contract defines the data → execution → report layer boundaries across `/mnt` data, client project data, all tier-1 repo data, public/private `llm-wiki`, execution machines, and report/chatbot surfaces.") is byte-identical to line 18 of `docs/plans/2026-05-17-issue-2726-layer-boundary-architecture-review.md`. The execution-layer child should surface execution-specific gaps (e.g., "no input/output manifest schema across tier-1 repos," "no documented routing tie-break between #2119's matrix and `config/workstations/registry.yaml`"), not echo the parent. Indicates Resource Intel was templated rather than re-run. **MINOR.**

## Blockers

- Finding #3 — Resource Intel must consult and disposition #2731, #2732, #1838, #2089. Sibling plan #2727 (data layer) and #2729 (report layer) should also be cross-cited so the four-plan wave is coherent.
- Finding #4 — TDD test list must include at least one behavioral test (e.g., a check that runs against a real execution manifest and rejects one missing a `source_id` field), not pure markdown-presence grep.
- Finding #5 — must specify sentinel-based or path-restricted enforcement so `test_no_execution_direct_publication` does not flag the contract that declares the prohibition.
