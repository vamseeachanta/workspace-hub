## Verdict
APPROVE — no MAJOR blockers. The hardening is internally consistent, the new test cases lock the four post-reboot failure modes (empty stdout, stderr-only review, timeout, partial-stderr-then-timeout), and the trap closes the orphan-process gap that triggered this issue. Recommend merge.

## Findings

1. **Conservative-on-failure semantics are correctly enforced.** `normalize_provider_output` only promotes stderr when `rc==0` AND all three section headers are present; the `MOCK_CODEX_STDERR_PARTIAL_THEN_SLEEP` test confirms a partial-stderr verdict cannot leak into the canonical artifact under timeout. This is the safer default given how aggressively `MAJOR` propagates downstream.
2. **Trap placement is race-tolerant.** `pids=()` is declared before `trap cleanup_provider_jobs INT TERM EXIT` is registered, so a signal arriving before any provider spawns iterates an empty (not unset) array — safe under `set -u`. Cleanup is idempotent and silent (`2>/dev/null || true`), so the EXIT-on-success path is harmless.
3. **`local reason="$(... | ...)"` masks substitution failure.** When the unknown-provider arm runs (no `$err` file written), `head -c 400 "$err"` fails but `local` masks the exit code, so the script falls through to the `"no stderr captured"` fallback rather than aborting under `set -e`. Pre-existing behavior, but worth noting it survives the refactor.
4. **Codex argv path is preserved correctly.** `</dev/null` + argv-inlined plan body is retained inside the `timeout` wrapper, and the test now actively asserts `^ARGV: exec -$` does NOT appear — guarding against a regression to the stdin-sentinel hang documented in the codex-cli 0.124.0 issue.
5. **Trust-env coverage is observable.** The gemini mock now logs `GEMINI_CLI_TRUST_WORKSPACE`, and `test_gemini_invocation_inlines_plan_body` asserts the exact value `true` — this directly closes the rc=55 trust-prompt failure mode documented in your auto-memory.

## Residual risk

- **Stderr-prelude noise on promotion (LOW).** The promotion path moves the entire `$err` file to `$out` once the three section headers are detected anywhere in it. If a provider writes log lines before the structured review, those lines land in the canonical artifact verbatim. Downstream parsers tolerate this today, but if section-anchored extraction is added later, tighten to a `sed -n '/^## Verdict/,$p'` slice.
- **PID-reuse in `cleanup_provider_jobs` (VERY LOW).** Stored `$!` values can in principle be reused by an unrelated process if cleanup runs much later than spawn. Bounded in practice by `PLAN_REVIEW_PROVIDER_TIMEOUT_SEC` (default 600s) plus the 5s `-k` grace; not worth additional code.
- **Plans exceeding default 600s timeout (LOW).** Default produces a false UNAVAILABLE for legitimately long reviews. Mitigated by the documented `PLAN_REVIEW_PROVIDER_TIMEOUT_SEC` env knob and test coverage that exercises a 1s override; left as operator-tunable.
- **Successful-review-then-cleanup-stall (LOW).** A provider that writes a complete review to stderr and is then killed by `timeout` during post-review cleanup will be classified UNAVAILABLE and the review discarded. The PR author chose this trade-off explicitly (the partial-stderr test enshrines it). Acceptable; revisit only if observed in the wild.
