## 1. Verdict: MAJOR

## 2. Scope and workflow fit
The plan is directionally aligned with #2129’s owner comments: it keeps the P0 categories bounded to stale artifacts, duplicates, stale premises/repo contradictions, and parent-child drift, and it avoids auto-mutation of GitHub.

However, workflow fit is incomplete in three material ways:
- The plan is not indexed in `docs/plans/README.md` yet.
- “Weekly-review flow can consume this audit” is underspecified; the plan only promises a doc update, not an invocation point, command contract, or artifact handoff.
- The issue currently sits in `status:plan-review` with no local approval marker, and later issue comments already discuss an implementation plus follow-up hardening issues (#2217, #2218). The plan does not reconcile that governance/history drift.

## 3. Strengths
- Good evidence gathering from repo files and live issue anchors.
- Strong false-positive guard for duplicates: structural evidence beyond title similarity.
- Deterministic action vocabulary (`refresh / merge / close / verify`) is the right operator contract.
- TDD list is anchored to real cited examples.
- Risks section correctly identifies over-expansion risk.

## 4. Findings
- `scripts/knowledge/review-open-issues.py` is currently a small label-grouping utility; the plan overloads it with live GH joins, artifact parsing, repo-reality checks, duplicate scoring, output rendering, and workflow integration without specifying internal decomposition.
- Acceptance criterion “surface at least one current-repo example for each required category” is not deterministic.
- Test design is too unit-heavy for the promised deliverable; it lacks an end-to-end CLI test covering mode selection, output generation, and non-regression of existing grouping behavior.
- Weekly-review integration is only documentation-level; the plan needs an explicit command, artifact location contract, and consumption point.
- The plan does not explicitly bound non-goals, especially around label enforcement, GitHub mutation, and heuristic hardening already captured by follow-up issues.
- The draft itself is out of workflow compliance because `docs/plans/README.md` had no row for issue #2129.

## 5. Required changes before approval
- Replace the live-state acceptance criterion with deterministic verification:
  - fixture-backed required tests for all 4 categories
  - optional/manual smoke check for “current repo examples”
- Add explicit implementation decomposition inside `review-open-issues.py` or helper modules/functions:
  - GH snapshot loader
  - artifact scanner/parser
  - repo-reality checker
  - finding classifier
  - report/schema renderer
- Add at least one CLI-level regression test proving:
  - existing grouping output still works
  - new audit mode is opt-in
  - JSON/markdown outputs are stable and written to declared paths
- Specify the weekly-review integration contract concretely:
  - exact command to run
  - expected output paths
  - where the weekly doc or runner consumes those artifacts
- Add explicit v1 non-goals/deferred work, especially around label enforcement, GitHub mutation, and heuristic hardening already captured by follow-up issues.
- Keep the plan in workflow compliance by indexing it in `docs/plans/README.md`.
