### Verdict: MAJOR

### Summary
The #2760 revision is well-structured: it replaces the prior "OCIMF-inspired placeholder" coefficients with a real workbook-interpolated route, adds a fail-closed citation preflight, generates a Word/PDF/Markdown/HTML report bundle, and updates the test suite to lock the new sweep/contract. However, several issues will block reliable execution and may break the test suite as currently written. The hard dependencies on absolute paths under `/mnt/ace/...` and `/mnt/local-analysis/digitalmodel/...` raise the bar for every consumer (CI, standalone pip install, other workspaces) without the graceful-degradation fallback that the mooring_design citation pilot established (per `.claude/rules/calc-citation-contract.md` pilot reference). The updated test `test_ocimf_current_rudder_and_total_components_are_reported_about_cog` references three row keys (`ocimf_first_cut_cx_current/cy_current/cm_current`) that do not appear to be added to the row dict in the diff — verify or the test KeyErrors. There are also a few smaller cleanup items in the JS chart code and dataclass cache hygiene.

### Issues Found
- [P1] tests/naval_architecture/test_b1528_sirocco_current_heading_rudder.py:~395 — test reads `row["ocimf_first_cut_cx_current"]`, `ocimf_first_cut_cy_current`, `ocimf_first_cut_cm_current`, but the visible diff for `_row()` in `b1528_sirocco_current_heading_rudder_report.py` does not add those keys to the returned dict (only `ocimf_current_force_*_N` and `ocimf_current_moment_*` survive). If the keys truly aren't present this is a guaranteed KeyError on first test execution. Verify and either add the coefficient fields to the row dict or correct the test to read from `ocimf_coefficients` directly.
- [P1] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:~267 — `issue_2760_source_preflight()` hard-fails with `FileNotFoundError` if `/mnt/ace/acma-codes/OCIMF/OCIMF Coef.xlsx` or `/mnt/local-analysis/digitalmodel/docs/data/OCIMF_CORPUS_README.md` is missing. Every report run, every test that invokes `run_b1528_current_heading_rudder_report()`, and CI runners without those mounts will fail. The existing `mooring_design.check_mbl_with_safety_factor` pilot referenced in `.claude/rules/calc-citation-contract.md` degrades gracefully outside workspace-hub via `RuntimeWarning`; this new module loses that property and provides no env-var override (e.g., `OCIMF_WORKBOOK_PATH`, `DIGITALMODEL_DOCS_PATH`).
- [P2] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py — two absolute paths are baked into source (`/mnt/ace/acma-codes/...`, `/mnt/local-analysis/digitalmodel/...`). The provenance README path additionally crosses repos (digitalmodel's source referencing a sibling-repo-specific location). At minimum this should be an env var or a workspace-relative discovery (`$REPO_ROOT/docs/data/...`); cf. `.claude/rules/coding-style.md` path-handling guidance.
- [P2] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:`select_ocimf_loaded_tanker_current_basis` — raises `ValueError` for any `wd_over_t <= 6.0`. The current YAML hardcodes 100m / 12.2m draft = 8.197 which is fine, but the function gives no out-of-band escape for legitimate shallower-water reviews. If the intent is "#2760-only" then the function should be named or scoped accordingly; otherwise add the shallower buckets or document the hard scope.
- [P2] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:`_write_docx_report` — `from docx import Document` raises `RuntimeError` on missing dependency, but the new test `test_issue_2760_docx_output_opens_and_contains_required_sections` does an unconditional `from docx import Document` at the top of the test body, so missing python-docx surfaces as an ImportError test failure rather than `pytest.importorskip` skip. Same hazard for `playwright` in `_write_pdf_from_html` cascading through `write_b1528_current_heading_rudder_report` into every test that exercises the writer.
- [P3] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:`updateYawChart` JS — the function computes a `z` heatmap matrix (`rudders.map(...headings.map(...))`) and never plots it; only the single-rudder line trace is rendered. Dead code; drop the matrix build to avoid confusing future readers and unnecessary work on each `updateCharts()`.
- [P3] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:`_load_ocimf_workbook_basis` is `@lru_cache`'d and returns a dict of mutable lists. No caller mutates today, but the contract isn't enforced; consider freezing to tuples or documenting immutability so a future caller doesn't poison the cache.
- [P3] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:`updateSelectedSpeedEnvelope` — label is "Max |X_ship| at selected speed" but value rendered is `maxH.force_x_ship_N/1000` (signed). `absMax` picks the abs-max row, but the displayed number can be negative. Render `Math.abs(...)` or change the label.
- [P3] Several newly created JSON artifacts end with `\ No newline at end of file`. Harmless but inconsistent with most editor configs; add trailing newlines for cleaner diffs going forward.

- Add `OCIMF_WORKBOOK_PATH` / `DIGITALMODEL_DOCS_PATH` env-var overrides in `issue_2760_source_preflight` and degrade to `RuntimeWarning` when the workbook is absent and the caller is in standalone-package mode — matches the existing mooring_design pilot contract.
- If the coefficient values are part of the test contract, persist `ocimf_first_cut_cx_current` / `_cy_current` / `_cm_current` (or rename to match the dict that's already stored) so the row truly carries the coefficients used. Either way, run the test file locally to confirm green before relanding.
- Move the OCIMF workbook ingestion into a tiny adapter module (`digitalmodel/ocimf/loaded_tanker_curves.py`) so the report generator depends on a typed interface rather than `openpyxl` directly; this also gives a clean seam to stub in tests without requiring `/mnt/ace/`.
- Mark the docx and pdf tests with `pytest.importorskip("docx")` / `importorskip("playwright")` so missing optional deps skip instead of fail.
- Drop the dead `z` matrix build in `updateYawChart`; if a heatmap is wanted, re-introduce the chart container; if not, simplify.
- Consider splitting `b1528_sirocco_current_heading_rudder_report.py` (now ~700+ lines after this change) into report-generator, OCIMF-resolver, and docx/html/pdf writers — module is doing four jobs.
