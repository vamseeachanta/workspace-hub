### Verdict: MAJOR

### Summary
V3 is a strong, disciplined revision that correctly resolves both r2 P1 findings (test-order coupling via pytest_sessionfinish; Kendall-tau self-referentiality via rank-vector formula) and is internally consistent on collection arithmetic (12 + 120 = 132). However, the rubric scoring formulas for dimensions 2–5 produce 0.0 when both actual and oracle token sets are empty (because only dimension 1 has an explicit "both empty → 1.0" clause), which will spuriously fail introduction-category topics that legitimately contain no tables/code/images. A couple of smaller specification gaps around fixture scope and AC wording also need tightening before this is ready for execution.

### Issues Found
- [P2] Important: Empty-denominator scoring defect. For dimensions 2 (Link), 3 (Table), 4 (Code), and 5 (Image) the formula is match_count / max(|oracle|, 1). When an oracle legitimately has zero tokens of that type (e.g., an introduction page with no tables) AND the actual output also has zero, the score is 0/1 = 0.0 — below both the 0.70 hard-min and per-dim floor. Dimension 1 explicitly handles this ('if both empty → J = 1.0'); dimensions 2–5 do not. With 4 introduction-category topics quota'd in the sample, this is likely to trip count(topic_scores[table|code|image] < 0.70) > 0 on a perfect conversion, making the gate unreliable.
- [P3] Minor: The session-autouse `_disable_network` fixture lives in `conftest.py` under `scripts/data/llm-wiki/tests/`. pytest `conftest.py` applies to ALL tests collected in that directory, including the existing `test_resolve_wiki_path.py`. No analysis is given that the existing module tolerates socket disabling with `allow_unix_socket=False`. If that module or any fixture it loads touches network/unix sockets, this silently breaks a previously-green sibling test.
- [P3] Minor: AC line 'exits 1 when a synthetic floor-occupancy violation is injected (regression test for the session hook)' and build-sequence step 9 do not specify the injection mechanism — temporary test file? monkeypatch of `check_floor_occupancy`? CLI flag? Without that, this AC is unfalsifiable as written and executors will pick arbitrary mechanisms.
- [P3] Minor: `test_oracle_has_second_reviewer` asserts a non-empty `oracle_second_reviewer` distinct from `oracle_authored_by` for all 20 entries. If this plan is executed by a solo contributor (a realistic scenario given the T3 oracle-authoring load), this AC becomes a hard blocker with no documented escape hatch. Fixture README's conflict-resolution procedure requires two reviewers, but does not address the zero-second-reviewer case.
- [P3] Minor: Unverified claim about `pyproject.toml` scipy declaration. The Attested Evidence section states scipy is declared as a 'general dep but NOT pinned in the test-dev group' — this is a plan-text assertion without an external attestation block appended to the review prompt, so the exact current state at base SHA 8c235f5e is not independently verified in this review payload.

### Suggestions
- Fix the empty-denominator case in dimensions 2–5: add an explicit clause 'if len(oracle_tokens) == 0 and len(actual_tokens) == 0 → score = 1.0'. For the asymmetric case (oracle empty, actual non-empty) decide explicitly whether that is a 0.0 (false-positive content) or 1.0 (no regression against oracle); the current formulas silently handle it as 0/1 = 0, which is plausibly correct but should be stated in the Rubric section.
- Move `_disable_network` to a module-scoped autouse fixture *inside* `test_conversion_quality.py` instead of `conftest.py`, OR explicitly verify the existing `test_resolve_wiki_path.py` module is compatible with `disable_socket(allow_unix_socket=False)` and record that verification as a build-sequence step.
- Specify the synthetic-violation injection mechanism in the AC (e.g., 'a throwaway `tests/test_conversion_quality_violation_injection.py` that patches `check_floor_occupancy` to return a non-empty violations list and asserts `pytest` exits with code 1'). Commit it in the TDD order directly after step 9.
- Add a documented single-reviewer fallback to the fixture README: e.g., allow `oracle_authored_by == oracle_second_reviewer` if the second review is performed ≥72h after initial authorship with both signatures in git log, and mark such entries `single_reviewer_timelag: true` in the manifest for audit.
- Add an Attested-Evidence verify line for the scipy declaration claim: `grep -E '^\s*scipy' pyproject.toml` with the expected current state captured verbatim, so r3 reviewers can diff.
- Consider adding a 'not-applicable' marker semantics: per-topic per-dimension scores that come from a trivially-empty comparison (len(oracle)==0 AND len(actual)==0) could be recorded as `null` in `.artifacts/per-topic/*.json` and excluded from floor-occupancy counting, which is more honest than forcing a 1.0.

### Questions for Author
- How does an introduction-category topic with zero tables (likely for 2–4 of the 20 samples) achieve a passing Table-fidelity score under the formula `matching_cells / max(|G_o|, 1)` when |G_o| = 0? Is the intent 1.0 or 0.0, and should the formula be updated to match?
- How is the synthetic floor-occupancy violation for AC #3 actually injected — a dedicated test file, a monkeypatched `check_floor_occupancy`, a `pytest` CLI flag, or an environment variable? The plan leaves this as executor's choice.
- Does `pytest-socket`'s `disable_socket(allow_unix_socket=False)` affect `uv`'s subprocess IPC during `uv run pytest`? The risks section says a CI probe is in build-sequence step 1, but the session-autouse fixture activates inside an already-running pytest — is there a scenario where pytest-launched subtests or plugins need unix sockets?
- Has the existing `test_resolve_wiki_path.py` module been verified to run cleanly with the session-autouse `_disable_network` fixture active via the shared `conftest.py`? If not, this v3 silently risks breaking a sibling test.
- For a solo contributor, how is `oracle_second_reviewer` meant to be satisfied, or is two-person review a hard execution prerequisite documented elsewhere?
- Is the plan's claim that `scipy` is already a general dep but not pinned in the test-dev group verified at base SHA `8c235f5e`? (The review payload does not contain an external Attested Evidence block attesting this.)
- Will the `pytest_sessionfinish` hook interfere with pytest exit codes under `pytest-xdist` workers, where session-finish fires on each worker plus the master? If it fires on workers, setting `session.exitstatus = 1` on a worker may behave differently than on the master.
