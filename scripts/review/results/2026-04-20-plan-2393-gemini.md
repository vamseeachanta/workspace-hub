### Verdict: MAJOR

### Summary
Plan fails to enforce operating model §3 namespaces, omits testing for performance Acceptance Criteria, and lacks a security threat model for external API dependencies.

### Issues Found
- [P1] blocking: Missing enforcement of `sha256:` namespace for `doc_key`. The plan states 'embeddings keyed on doc_key' but fails to assert or test compliance with the operating model §3 requirement that `doc_key` must use the `sha256:` namespace (Section: Resource Intelligence Summary & Pseudocode).
- [P1] blocking: Missing TDD coverage for performance Acceptance Criterion. The AC requires 'Query latency p95 < 2s on local corpus' but the TDD Test List contains no performance or benchmark tests.
- [P1] blocking: Cache mirroring strategy is undefined. The Artifact Map specifies 'embeddings.parquet → cache mirror at /mnt/ace/.embeddings/' but the pseudocode and files-to-change contain no logic, scripts, or synchronization mechanism for writing to or validating this shared-mount tier (Operating Model §7 violation).
- [P2] non-blocking: Missing threat model and secret management. The spike and pseudocode consider cloud models (text-embedding-3-large, Voyage-3) but fail to specify how external API keys will be securely injected, accessed by the cron job, or tested for failure modes.
- [P2] non-blocking: Scope/Dependency contamination. The plan bundles a model-selection Spike ('separate deliverable') with the implementation, meaning the target model `CHOSEN_MODEL` is undefined at the time of this plan's approval.

### Suggestions
- Add explicit validation and a corresponding test (e.g., `test_doc_key_sha256_namespace_enforced`) to ensure all indexed documents use the `sha256:` prefix.
- Add a benchmark test `test_query_latency_p95` to the TDD list that asserts the 2-second p95 SLA on a generated or fixture corpus.
- Explicitly detail the synchronization logic to `/mnt/ace/.embeddings/` in the pseudocode and add a TDD test `test_cache_mirror_sync` to ensure shared-mount tier rules are respected.
- Define the secret injection mechanism for API keys in the cron wiring and add tests for missing/invalid credential states.
- De-couple the Spike from the implementation plan, or update the plan to hardcode a fallback model if the spike is inconclusive.
