2. **Silent Regression via Default Edition:** Plan §P1 `normalize_edition` warns and defaults to `"2021"` if `edition=None` is passed. Because `DeprecationWarning` is suppressed by default in standard Python execution, legacy callers of the functional package (which currently implements the 2017 standard) will receive no visible warning but will experience a massive, silent numeric shift in CP design (e.g., 5.6x harsher FBE breakdown). This violates the regulatory-hazard mitigation against silent undersizing/oversizing.
3. **Missing `run` Dispatcher:** Plan §P4 pseudocode refactors the router to invoke `digitalmodel.cathodic_protection.run(...)`. However, no such `run` entrypoint exists in the current facade, and neither §P1 nor §P2 implements this function. The refactored router will fail unconditionally with an `AttributeError` at runtime.
4. **Invalid Dataclass Method Invocation:** Plan §P4 pseudocode invokes `**result.dict()` on the return value. However, plan §P1 explicitly defines the result objects (e.g., `AnodeSizingResult`) as standard Python `@dataclass` classes. Standard dataclasses do not possess a `.dict()` method; this will raise an `AttributeError` unless `dataclasses.asdict(result)` is used.
5. **Dangling Duplicate Module and Lost Formula:** Plan AC-P2.2 claims `cp_sacrificial_anode_b401.anode_resistance_flush` uses a unique `ln(2L/r) - 1` formula. Plan §P4 explicitly deletes the deprecation shim `infrastructure/common/cp_sacrificial_anode_b401.py`, but completely omits the actual implementation module `infrastructure/base_solvers/hydrodynamics/cp_sacrificial_anode_b401.py` from the "Files to Change" table. Furthermore, `FLUSH_RESISTANCE_FORMULA` in §P2 only preserves `mccoy` and `dwight` (`ln(4L/r) - 1`), dropping the `ln(2L/r) - 1` formula variant entirely. This fails to preserve the documented numerical divergence.
6. **Splash Zone Type Incompatibility:** Plan §P2 `SPLASH_CURRENT_DENSITY` defines the 2017 splash zone return as `{"coated": 0.0, "bare": 0.0}`. However, plan §P1 `test_baseline_splash_zone_divergence` demonstrates that the existing `marine_structure_cp.py` expects and returns a 3-tuple `(0.0, 0.0, 0.0)` for different tide levels. Replacing the tuple with a scalar dictionary lookup will cause a `TypeError` in existing functional package calculations that expect a tuple.
