## Blockers (MAJORs)

1. **`update`/`delete` subcommands don't exist** — plan promises hooks into `llm_wiki.py` paths that have no callable surface. Either add the subcommands (and scope the work) or re-architect the emitter to backfill-only.
2. **Inflated `index.jsonl` size** (claims 1.03M, actual 649K). Sidecar rationale rests on a wrong number; correct it.
3. **`doc_key` vs `source_doc_key` confusion** — the emitter extracts `frontmatter["doc_key"]` which (per #2360 / parent §8.1) is the page's OWN identity, not the source it cites. The reverse lookup should index by `source_doc_key`. As written, the plan materializes a self-loop, not the L3→L2 back-link the issue asks for.
4. **Quiet scope drop in supersession** — `registry.yaml` was a Wave-1 L2 target in the prior plan. New plan removes it without explicitly flagging the scope reduction. Either reinstate or label the change as a SCOPE CHANGE in line 310-315.
5. **Acceptance criteria are vacuously satisfiable in v1** — every live-data AC depends on #2360 having shipped. Honest v1 ACs need to specify "fixture-only" or stage the live-data ACs explicitly.

## Strengths

1. **Honest framing of the upstream blocker** — the plan correctly identifies #2360 as a hard prerequisite for live-data materialization (lines 41, 45, 312-315). Many plans bury this; this one foregrounds it.
2. **Sidecar-vs-mutate-index decision is well-reasoned** (line 122) — write-isolation from the indexer + cheap rebuilds + line-by-line query is the right call. The number is wrong (see Finding #2) but the architectural decision is defensible.
3. **TDD list is comprehensive for in-scope behavior** (lines 260-279) — 20 tests covering emit, idempotency, deletion, slug-only, namespace separation, CLI exit codes, and backfill bounds. This is above the bar for a T2.

**Recommendation:** MAJOR revisions required before plan-approved. Specifically: (1) resolve `doc_key`-vs-`source_doc_key` semantics with the contract authors before any code lands; (2) either add `update`/`delete` subcommands explicitly or re-scope the emitter; (3) correct the `index.jsonl` row count; (4) explicitly mark the `registry.yaml` scope drop as a SCOPE CHANGE, not a "correction"; (5) restate ACs in fixture-only-v1 terms with staged live-data v2 ACs.
