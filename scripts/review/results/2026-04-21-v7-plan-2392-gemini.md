### Summary
The plan lists four 'Live blocker themes' at the end of the document but fails to actually resolve any of them in the proposed design or pseudocode.

### Issues Found
- The plan acknowledges the blocker 'source deduplication across multiple inventory surfaces is still undefined', but the pseudocode simply iterates `for record in source_records:` without defining any logic or policy for deduplicating source records that share the same `doc_key` across different input registries.
- The plan acknowledges the blocker 'cross-domain coverage semantics (doc_key match in wrong wiki domain) need an explicit policy'. However, the pseudocode uses a global `wiki_index` and blindly matches `if canonical_key in wiki_index:` without validating whether the wiki page's domain matches the source record's domain, leaving the policy undefined.
- The plan acknowledges the blocker 'exit-code contract for clean vs degraded vs fail-closed runs needs to be specified'. While it references `exit_code_for_run_status()`, it never actually defines the specific integer exit codes for these states.
- The plan acknowledges the blocker 'scheduled publication needs clean-worktree / exclusivity safeguards'. Yet, the proposed cron command simply runs `git add ... && git commit`, which lacks any clean-worktree check (like `git status --porcelain`) or locking mechanism to prevent race conditions during publication.

### Suggestions
- Define a specific deduplication policy for source records. If the same `doc_key` appears in `index.jsonl` and a supplemental ledger, which fields win? How is the duplicate resolved before gap analysis?
- Define cross-domain coverage semantics. If a source record expects domain A but the wiki page is found in domain B, explicitly state whether this is a gap, a covered record, or a degraded/warning state.
- Explicitly map `clean`, `degraded`, and fail-closed states to integer exit codes (e.g., 0, 0 or 2, 1) in the 'Deliverable' or 'Scheduled Task Contract' sections.
- Update the scheduled command to enforce a clean worktree before starting or at minimum fail gracefully if `git pull --rebase` or `git status --porcelain` indicates conflicting concurrent states.
