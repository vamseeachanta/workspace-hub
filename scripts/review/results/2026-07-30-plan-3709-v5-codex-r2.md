## Findings

### 1. MAJOR - The parse-only test-integrity conjunct can be bypassed by skipping the preservation tests while leaving the parsed structure present

**Evidence:** v5 makes Layer 3 responsible for closing deletion/neutering of the primary control: `behavioural-test-present-and-pinned` reads `records[b"tests/cron/test_cutover_preservation.py"]` and checks only that named test functions exist, P1 is parametrised over the full scenario list, the invariant helper body is the pinned multiset comparison, and the shape-corpus table has the pinned number of entries (`docs/plans/2026-07-30-issue-3709-managed-block-classification-v5.md:193-209`). The acceptance criterion similarly says deleting or neutering the primary control will fail the enforcement gate through this parse-only conjunct (`docs/plans/2026-07-30-issue-3709-managed-block-classification-v5.md:697-699`). The S1 row only names deletion, removing a named test, and replacing the invariant body with a constant as mutants (`docs/plans/2026-07-30-issue-3709-managed-block-classification-v5.md:641`).

That stated parse contract does not require the tests to be executable by pytest. A module-level `pytestmark = pytest.mark.skip(...)`, a per-test `@pytest.mark.skip` / `@pytest.mark.xfail(..., run=False)` decorator, or a leading `pytest.skip(...)` inside each test body can leave all of the stated AST facts true: the functions still exist, `pytest.mark.parametrize` can still be present with the full scenario list, the invariant helper body can stay byte-for-byte pinned, and the expectation table can retain the same entry count. The CI job would report a non-failing skipped suite, and the parse-only conjunct as specified would still pass.

The current checker architecture can support the intended cross-file parse: `read_index_records` loads every tracked index blob into `records` (`scripts/enforcement/check-scheduler-mutation-surfaces.py:88-116`), `evaluate_attestation` passes that full dict to `evaluate_python` (`scripts/enforcement/check-scheduler-mutation-surfaces.py:183-186`), and `evaluate_python` already delegates Python attestations with the full `records` dict (`scripts/enforcement/scheduler_mutation_attestations.py:253-268`). Keeping `python-postwrite-preservation-multiset-v1` in `ATT_SOURCES` as `cron_transaction.py` also works mechanically (`scripts/enforcement/scheduler_mutation_contract.py:71-80`, `scripts/enforcement/scheduler_mutation_contract.py:127-128`, `scripts/enforcement/scheduler_mutation_contract.py:365-369`). The problem is not dispatch feasibility; it is the missing negative checks for skipped or otherwise disabled tests.

**Failure scenario:** commit 1 adds the preservation suite and Layer 3 conjunct. A later edit, or a malicious/self-protecting implementation commit, adds `pytestmark = pytest.mark.skip("temporarily disabled")` to `tests/cron/test_cutover_preservation.py` while preserving the pinned invariant helper and test names. `uv run pytest tests/cron/test_cutover_preservation.py -q` exits 0 with skipped tests. The parse-only enforcement conjunct still sees the named functions, parametrization, helper body, and table count, so `check-scheduler-mutation-surfaces.py` exits 0. A destructive `plan_cutover` shape can then merge or be locally accepted without the primary behavioural control ever running.

**Required revision:** extend Layer 3 and row S1 before approval. The parse-only conjunct must reject:

- module-level `pytestmark` or any skip/xfail marker that can disable the module or preservation tests;
- decorators other than the required `pytest.mark.parametrize` forms, and any `skip`, `skipif`, `xfail`, `usefixtures`/fixture indirection that can alter execution semantics;
- calls to `pytest.skip`, `pytest.xfail`, `unittest.skip`, `pytest.importorskip`, or equivalent early-return disabling in the preservation tests;
- changed shape-corpus expectation values, not merely a changed entry count, unless the invariant body is pinned strictly enough that this table is no longer part of the integrity claim.

Add named S1 mutants for module-level skip, per-test skip/xfail, body-level skip, and expectation-table value tampering, and require them to make `check-scheduler-mutation-surfaces.py` return non-zero.

### 2. z10 and the multiset fix

Verified. The committed prototype's `z10_new_text_dedupes` renders `new_text` with `dict.fromkeys(new_lines)` while building intent from the full `new_lines` list (`scripts/review/prototypes/3709-v5/cases/z10_new_text_dedupes.py:97-114`). `run.py` accepts it under all 19 predicates, and `behaviour.py --check` reports it as accepted and destructive only under scenario D: `DROPS 1/5 LIVE LINES`.

The multiset invariant is the right fix for this class. It compares `Counter(new_text.split("\n"))` against the raw live-line counter, excluding only the exact managed markers (`scripts/review/prototypes/3709-v5/behaviour.py:192-219`). That catches deduplication, whitespace changes, and any move between managed/after that loses a raw occurrence. I did not defeat the multiset invariant. Ordering changes that preserve multiplicity are outside the stated line-preservation invariant; they may still deserve future semantic tests if ordering becomes operationally meaningful, but they are not a live-line loss.
