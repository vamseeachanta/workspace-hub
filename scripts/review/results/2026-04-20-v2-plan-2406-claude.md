### Issues Found
- [P2] T29 timing sensitivity: the test's premise is "printf has unread buffer when codex exits, producing SIGPIPE" — this is race-sensitive. On fast machines the mock may terminate fast enough that printf has flushed before the reader closes. Mitigation: the fixture is 24 000 bytes; pipe buffer on Linux is 64 KiB; all 24 KB fits in one write. The test may NOT reliably reproduce the SIGPIPE scenario. Better approach: explicitly `kill -PIPE $PRINTF_PID` from the mock before exit, OR use a smaller prompt and expect pipefail to return the mock's intended exit code via `PIPESTATUS[1]` without needing actual SIGPIPE. Plan should specify.
- [P2] T30 probe caching: the plan says "cached in a module-scope flag" — but the test spec doesn't verify the probe is called at most once per script invocation. A future regression could re-probe on every dispatch, which would be slow. Add an assertion: across T26+T27+T28 when all run through the same script invocation, the mock's `--help` branch is invoked ≤ 1 time. Or acknowledge this as an impl-quality concern rather than a correctness test.
- [P3] Minimum codex version still un-pinned: the plan adds a runtime probe to detect `-` stdin support, but doesn't document "we verified this works in codex X.Y or later". A one-line evidence addition (`codex --version` of the currently installed version) would close this loop and give a concrete baseline for the fallback test.
- [P3] Class B findings acknowledged but not logged as follow-up: when #2405 lands, the iter-3 re-review of THIS plan can (and should) drop the "unverified" finding. Worth a one-liner in "Open questions" pointing at #2405 so future readers trace the resolution path.
