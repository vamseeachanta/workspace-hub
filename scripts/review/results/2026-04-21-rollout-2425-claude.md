## Findings

1. **Pilot #1 is misranked against a better candidate on the same umbrella (MAJOR).** #2425 selects #2347 as "smallest scope, cleanest validation of attestation-checker thesis," but #2347 requires updating **four** tracker bodies (#2016, #1669, #117, #191) and cross-referencing ship dates and artifacts — that is not the smallest-scope instance available. `status:plan-approved` #2357 is a literal single-file rewrite (`aceengineer-website/public/sitemap.xml`, apex→www host, <200 lines), has user approval, and is the exact "validate the orchestrator can do deterministic transforms" signal. The umbrella's own reasoning ("Pure contradiction detection") fits #2357 equally; narrative convenience (#2347 touches tracker bodies ≈ "attestation checker") is doing the ranking, not measurable readiness.

2. **Anti-candidate list conflicts with epic #2390 (MAJOR).** `#2390` body: "Wave 0 — external prerequisites / schema authority: #2360 update wiki CLAUDE.md files to require doc_key … #2362 back-populate doc_key on pre-existing standards-transfer-ledger entries." #2425 body: "Anti-candidates (do NOT wrap in Claude-CLI): … #2360–#2362 schema/frontmatter edits." One epic says these unblock a 20+ issue wave program; the other dismisses them as "20-60 line diffs — faster as direct edits." Dismissing Wave-0 prerequisites is a coordination defect — at minimum the umbrella must acknowledge the #2390 sequencing implication.

3. **Pilot #3 (#2413) is not a pilot — it's an existing epic (MAJOR).** `#2413` body reads: "It's a coordination artifact: one durable home for the roadmap, with pointer comments on each of the 14 constituent issues. Nothing new is being built by this epic itself." Putting #2413 in the pilot sequence promotes a coordination-only umbrella to executable status. The umbrella's own hedge — "#2017 v7 in flight; this is framing, not a separate plan" — confirms there is no unit of Claude-CLI work to pilot here. This line item should be removed or replaced with a concrete child of #2413 (#1963, #1968, #1969, etc.).

4. **Parallel-work scan is >10× undercounted (MAJOR).** Umbrella lists 4 parallel items (#2346, #2324, #2017, #2348). `git worktree list` shows 28 worktrees, including 5+ that are on active branches (`issue-2348-nightly-exec`, `feat/ecosystem-sync`, `integration/ecosystem-sync-stage1-stage2-handoff`, `nightly-2026-04-20-batch`, `issue-2281`, `issue-2282`, `issue-2320`, `issue-2322`, `issue-2323`, `issue-2290-v2`, `issue-2248`, `issue-2249`, `issue-2250`, etc.). Several of those intersect the umbrella's own picks — e.g., `issue-2322` (rule promotion) and `issue-2320` (skills audit) overlap bench item #2333; `issue-2323` is a cross-AI fanout directly related to the rollout's cross-provider-review constraint. The umbrella's claim "live state as of 2026-04-21" is false.

5. **Claim "#2347 … 0 plan yet — clean slate" is false (MINOR–MAJOR).** `gh issue view 2347` returns label `status:plan-review`. A plan-review state means a plan exists and is awaiting adversarial review + approval. Running a Claude-CLI pilot on top of an in-flight plan without acknowledging it risks double-write into the same plan slot. The umbrella's table needs correction.

6. **Meta-issue self-exempts from issue-planning-mode (MINOR, governance drift).** #2425 explicitly states: "Does not apply `status:plan-review` or `status:plan-approved` to itself or to any child." Per `CLAUDE.md` project instruction — "Planning Workflow (ALL issues — mandatory)" — every issue must go through plan-review → user-approves. A meta-issue with no labels, no plan, and selection bullets that will drive which pilots run is exactly the governance rot `issue-planning-mode` was designed to prevent. The umbrella either needs a plan under `docs/plans/` and `status:plan-review`, or the project rule needs an explicit meta-exception clause (neither exists today).

7. **Recommendation pressure advances the approval gate the user keeps pushing back on (MINOR).** Umbrella ends: "recommendation: #2347 — smallest scope, cleanest validation." Per `feedback_never_offer_to_self_label_plan_approved.md`: "present links + CLI commands only; user-in-loop at plan-approval is load-bearing, not friction to route around." The rec+rationale combo is not identical to self-labeling, but it functions as soft pre-approval pressure: it prefills the user's choice with a ranked default derived from reasoning only Claude has seen. Safer pattern: show the four pilots + link + one-line fit, no ranking.

8. **No machine-binding specified (MINOR).** `feedback_cross_machine_execution.md` says per-machine tasks go via shared git, not SSH/rsync; umbrella does not name which machine(s) run the pilot loop, where Codex quota sits (`project_hermes_codex_quota.md` — #6551/#6564-6567), or whether the Claude-CLI orchestrator box is the one currently running `issue-2348-exec`/`ecosystem-sync` worktrees. On a 28-worktree host, implicit "all of ace-linux-1" is a real scheduling collision risk.

9. **#2399 is bench-listed but is itself a high-priority epic (MINOR).** `gh issue view 2399` → "feat(ai-orchestration): define next-model-release readiness contract for repo ecosystem" with `priority:high`. Being bench-listed below a medium-priority rollout umbrella inverts the priority signal without justification. Either the umbrella raises priority, or #2399 declines, but the current shape is inconsistent.

10. **Sourceless review citation (MINOR).** The umbrella derives its selections from "the 2026-04-21 ecosystem review." No artifact path (`docs/reports/...`, commit SHA, plan file) is cited. Without a source artifact, the selection criteria are un-auditable — which is precisely the failure mode `feedback_attestation_enables_contradiction_detection.md` tries to prevent.
