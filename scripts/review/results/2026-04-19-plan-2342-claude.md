## New v2 findings

### Defect A — sitemap.xml will list 5 new URLs at the *redirected-from* host
**Severity:** major
**Evidence:**
- `vercel.json` lines 7-18: unconditional 301 redirect from host `aceengineer.com` → `https://www.aceengineer.com/:path`.
- `sitemap.xml` lines 5, 12, 20, … entries use `https://aceengineer.com/` (apex).
- Pseudocode D lines 137-141: plan's new entries also use `https://aceengineer.com/demos/<slug>.html` — **perpetuating the existing mismatch**.
- Result: Googlebot fetching any sitemap entry gets a 301 to `www.`. Google treats the canonical URL as the 301 target; the sitemap's declared URL is not indexed directly. This is usually tolerated but (a) adds a crawl-budget tax, (b) every new entry inherits the same defect, (c) `robots.txt` (line 5) advertises `https://aceengineer.com/sitemap.xml` — same apex-redirect pattern.
- The plan's v2 Resource Intelligence (line 27) explicitly notes "uses `aceengineer.com` host (the redirect source)" but does not treat this as a defect to fix — it copies the pattern.
**Impact:** Sitemap-based indexing for the new demo pages passes through a 301 on every crawl. Canonical URL ambiguity weakens SEO precisely where the GTM campaign wants discovery.
**Recommendation:** Write the 5 new entries with `https://www.aceengineer.com/demos/<slug>.html` (the redirect target). Optionally backfill the existing 20+ apex entries in a follow-up, but at minimum do not add NEW entries at the wrong host.

### Defect B — Jest link-check will not actually run under `npm test`
**Severity:** major (blocker for the v1 "regression guard" fix)
**Evidence:**
- `package.json` lines 10-41 — `jest.projects` array lists six projects, each with a literal `testMatch` glob pointing to a specific file:
  - `<rootDir>/tests/js/build.test.js`
  - `<rootDir>/tests/js/navbar-toggle.test.js`
  - `<rootDir>/tests/js/hse-risk-dashboard.test.js`
  - `<rootDir>/tests/js/npv-calculator.test.js`
  - `<rootDir>/tests/js/obs-calculator.test.js`
  - `<rootDir>/tests/js/wall-thickness.test.js`
- A new file `tests/js/demo-links.test.js` (plan's Files to Change, line 183) matches NONE of those globs. Under `jest.projects` mode, Jest does not discover tests outside the registered projects — the new file is silently skipped.
- Files to Change (lines 172-184) does NOT include `package.json`. The plan line 29 claims "Link-check can be added as a Jest project to inherit CI" but the actual artifact list omits the project registration.
- Plan line 56 says "Link-check script wired into `package.json` as a Jest project so `npm test` fires it" — the Files to Change contradicts this.
- TDD acceptance `gallery_has_5_detail_ctas` (line 201) and `demo2_has_both_ctas` (line 202) both route through this unwired test.
**Impact:** This is the exact same v1 "write-only guard" defect the plan claims to have fixed. The test file will be committed, `npm test` will pass (because Jest never sees the file), and a future gallery edit that breaks an anchor will not be caught.
**Recommendation:** Add `package.json` to Files to Change. Add a new Jest project entry: `{ "displayName": "demo-links", "testEnvironment": "node", "testMatch": ["<rootDir>/tests/js/demo-links.test.js"] }`. Also update the acceptance criterion: explicitly verify `npm test` output lists a `demo-links` project with passing assertions — proves the wiring works, not just the file exists.

### Defect C — rollback plan's "single-commit revert" premise fails for 11-file PR
**Severity:** minor
**Evidence:**
- Plan line 244: "Rollback = `git revert <merge-commit>` → push → Vercel redeploys prior state automatically".
- Artifact Map lists 11 changed files: 4 new content pages + 1 retrofit (jumper) + gallery + sitemap + vercel + vendored Plotly binary + Jest test + plan README.
- Failure modes table (lines 248-252) then describes **per-file partial reverts** ("revert the single `content/demos/<slug>.html` change"). This contradicts the single-commit claim.
- If the PR lands as one squash-merge, a "single-commit revert" pulls all 11 files back — including the jumper-installation.html retrofit, which would regress the already-live Demo 5 detail page from v2 back to the v1 (no GA, old branding) state.
**Impact:** "Revert the merge commit" reverts the jumper retrofit too. If Demos 1-4 break but the jumper retrofit is fine, operators have to choose between (a) leaving the 4 broken pages up, or (b) regressing the live jumper page. Neither is clean.
**Recommendation:** Either (a) split jumper retrofit into its own prior commit/PR so the demos-1-4 commit can revert cleanly, or (b) explicitly document that rollback means losing the jumper retrofit too and plan a re-apply commit. Do not claim "single-commit revert" as a safety property when the blast radius is 11 files.

### Defect D — vendored Plotly claim unverified; 3+ MB binary in git
**Severity:** minor
**Evidence:**
- Plan pseudocode F (lines 153-157): `curl -o assets/js/plotly-2.32.0.min.js https://cdn.plot.ly/plotly-2.32.0.min.js; verify checksum against upstream release`.
- Plotly 2.32.0 minified is ~3.5 MB. Committing it as a binary blob to `aceengineer-website/assets/js/` bloats the repo permanently. Plan line 279 accepts this as "cost-of-trust" but provides no size measurement, no checksum (SHA256) value to verify against, and no mention that Plotly's CDN does not publish per-version checksums on a stable URL.
- "Verify checksum against upstream release" is not a concrete action — upstream release artifacts for Plotly are npm-published (`npm view plotly.js-dist@2.32.0 dist.shasum`), not CDN-hashed. Plan lacks the actual sha256.
- No `.gitattributes` rule to mark it binary or LFS — it will inflate every clone.
**Impact:** Checksum verification is unexecutable as specified. Repo clone time grows by ~3.5 MB forever.
**Recommendation:** Replace "verify checksum against upstream release" with an actual sha256 (obtain via `npm view plotly.js-dist@2.32.0 dist.shasum` or equivalent). Consider `plotly.js-dist-min` from npm with a lockfile entry instead of a binary blob.

### Defect E — jumper-installation.html retrofit introduces behavior change, not just a fix
**Severity:** minor
**Evidence:**
- Current `content/demos/jumper-installation.html` (verified): line 6 `<title>A&CE — Subsea Jumper Installation Analysis Demo</title>`, has inline `<style>` of 15 lines, NO plotly dependency whatsoever, is a static HTML table-based report. No charts to render.
- Plan pseudocode B: "Same head rewrite + Plotly vendor point". This ADDS a 3.5 MB Plotly script reference to a page that doesn't use Plotly.
- Files to Change line 178: "Modify `jumper-installation.html` … swap CDN Plotly → local vendor". There is NO CDN Plotly reference in `jumper-installation.html` today to swap.
**Impact:** The plan as written would add an unnecessary 3.5 MB JS payload to the already-live Demo 5 page — degrading the page's performance for no functional gain, and testing `prod_plotly_loads_locally` (line 212) would actually become true for a page where Plotly should not load at all.
**Recommendation:** Split the jumper retrofit scope: add head-common include (justified — GA/nav gap) but DO NOT add the Plotly script tag. Rewrite pseudocode B to clarify: "head-common include only; no Plotly since the page has no charts." Update test `plotly_is_vendored` to 4/4 on new pages, not 5/5.

### Defect F — Title rewriting will collide with source `<head>` structure
**Severity:** minor
**Evidence:**
- Source `demo_01_freespan_report.html` head (verified, lines 1-10) contains: doctype, html, `<head>`, meta charset, meta viewport, `<title>`, preconnect, Google Fonts stylesheet link, plotly script, then `<style>`.
- Pseudocode A (lines 104-122) shows stripping/rewriting `<head>` wholesale — but also says "original inline styles preserved" and "source body" appended. The `<link href="fonts.googleapis.com/css2?family=Inter...">` is in the source HEAD, not body. Plan does not specify whether Google Fonts link is preserved, dropped, or moved.
- Per `docs/gtm/gtm-plan-30day.md` rationale, the reports' distinctive Inter-font look may be part of the "rich report" promise. Dropping the font link silently changes visual appearance.
**Impact:** Ambiguity — implementer may strip the Google Fonts link, silently changing all 4 pages' typography from the source. Not caught by any automated test in the TDD list.
**Recommendation:** Pseudocode A should enumerate explicitly: preserve `<meta charset/viewport>`, rewrite `<title>`, DROP plotly CDN script in favor of vendored, PRESERVE Google Fonts preconnect+stylesheet, INJECT head-common after title, PRESERVE inline `<style>`. Add a TDD test `pages_preserve_inter_font_link` if the font is load-bearing.

## Claims verified in v2

2. **"head-common GA deferred via `requestIdleCallback`"** — CONFIRMED. `content/partials/head-common.html` lines 11-22: IIFE wraps `gtag` script-tag injection in `requestIdleCallback(loadGtag)` with `window.addEventListener('load', loadGtag)` fallback.

5. **"package.json has jest multi-project config"** — CONFIRMED, but the plan's reliance on implicit pickup is WRONG — see Defect B. Each project uses explicit `testMatch` with a single literal file path; there is no catch-all glob for new test files.

Both defensible, but claiming v1 was "estimated, not measured" (plan line 31) is unfair — raw bytes ARE measured, and more precise than du.

7. **"robots.txt allows /demos/*"** — CONFIRMED. Line 2: `Allow: /`; no `Disallow:` clauses active (admin/private are commented out).

8. **"Source `<title>` reads '<Demo Title> — digitalmodel'"** — CONFIRMED for Demo 1: `<title>DNV Freespan / VIV Screening Analysis — digitalmodel</title>` at line 6 of source.

9. **"Source references cdn.plot.ly/plotly-2.32.0.min.js"** — CONFIRMED. Demo 1 line 9: `<script src="https://cdn.plot.ly/plotly-2.32.0.min.js"></script>`.
