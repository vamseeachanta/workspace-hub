## Verdict

MINOR — proceed after addressing the denormalization / scope / maturity-YAML issues below. Plan is largely well-formed; the gaps are architectural framing and bookkeeping, not implementation logic.

## Retrieval Adequacy

Adequate per #2208. Nine distinct sources cited with concrete file paths, line numbers, and specific findings (diagnosis doc, issue body, three GOTCHA-bearing skill/doc files, maturity YAML, two data artifacts, plus negative finding on wiki/standards). ## Architectural Coherence

Partial concern. Embedding `content_type` and `summary_done` in `index.jsonl` is the right call — both are cheap booleans/enums derivable from cheap sources (`ext` and stat of a summary file). These belong denormalized into the index because every agent query needs them and the current separate-JSON-file layout is the documented GOTCHA.

However, embedding `summary_title` and `summary_discipline` (free-text strings) is a different decision and the plan treats it as a trivial extension. Per the #2205 operating-model pyramid, `index.jsonl` sits in the structural/reachability layer; LLM-extracted semantic fields belong one tier up. Inlining them:

- Couples index size to summary-model output drift (re-runs with a better LLM force index rewrites).
- Creates two sources of truth for title/discipline (summary JSON + index.jsonl) with no sync contract.
- Conflicts with the "index stays thin, agents query summaries on demand" pattern implicit in Phase B/C today.

Recommendation: keep `content_type` + `summary_done` (denormalized pointers/flags). Demote `summary_title` / `summary_discipline` to either an opt-in `--include-semantic` flag or a separate sidecar file (`index-semantic.jsonl`). Do NOT ship them as default inline fields in this PR.

## Scope Boundary

Mostly contained; one over-reach.

- Correct: deferring `conference-index-batch.jsonl` — explicitly flagged as out of scope with a follow-up-issue note. Good.
- Correct: not wiring validate script into pre-commit in this PR (open question surfaced).
- Over-reach: modifying 3 skill/doc files carrying the GOTCHA in the same PR. These files are governance surfaces. Risk: if the enrichment ships but regresses before thresholds stabilize, the GOTCHA is prematurely removed and agents trust broken fields. Split: land enrichment + validation + tests in PR-A; flip GOTCHA wording in PR-B after two clean pipeline runs (or after validate script is wired to pre-commit).
- Minor over-reach: Phase-A `--preserve-metadata` is a behavior change to the canonical indexer. It is the correct long-term fix but merits its own tests beyond the two listed; specifically a test for path-rename collisions and for records whose `content_hash` changed between runs.

## Documentation Debt

The maturity YAML fix is stated but underspecified. Plan says "refresh with index.jsonl-only figures; add scope note." Problems:

1. The 61.9% figure is a published summary used by #2205 dashboards. Changing its denominator without a schema bump will silently move trend lines. Require either (a) a new field `index_only_summary_coverage_percent` alongside the combined figure, or (b) a version bump with a migration note — not an in-place overwrite.
2. Plan does not touch the intelligence accessibility registry (#2136) — but that registry advertises reachability of index fields. New fields `content_type`/`summary_done` should be declared there or the registry drifts stale the moment this ships.
3. Three-file GOTCHA update is duplicative. Consider consolidating to a single canonical GOTCHA location referenced by the other two (separate follow-up issue acceptable, but flag it).

## Backwards Compatibility

Risks the plan does not address:

- **Dashboards/exporters:** any JSON consumer using strict-schema validation (pydantic, jsonschema) will reject the new fields. Plan should enumerate known consumers (at minimum: provider-routing-scorecard, queue-refresh tooling, `build-capability-map.py`) and confirm lenient parsing.
- **Size growth:** plan admits ~65 MB growth from title/discipline. If index.jsonl is read fully by any in-memory tool (e.g., `build-capability-map.py`), check it. Removing title/discipline per the denormalization recommendation above also eliminates this risk.
- **Validate thresholds:** acceptance criterion `≥60% summary_done` is tight against diagnosis projection of 83.7%. Set default threshold lower (e.g., 55%) with a tightening-after-first-run plan.
- **Backup retention:** `index.jsonl.backup-2026-04-16` has no cleanup policy — will accumulate on every run.

## Recommendation

Blocking revisions requested:

1. Drop `summary_title` / `summary_discipline` from the default inline schema; gate behind flag or sidecar.
2. Split skill/GOTCHA edits into a follow-up PR contingent on a clean validation run.
3. Specify maturity-YAML change as additive field, not in-place overwrite; reference #2205 dashboard impact.
4. Add explicit known-consumer compatibility check (grep `index.jsonl` readers) and note in Risks.
5. Add intelligence accessibility registry (#2136) update to Files-to-Change or as a named follow-up.

Non-blocking: add backup-retention policy; lower `summary_done` floor to 55%; add Phase-A tests for `content_hash` churn.
