1. **Unreconciled R12 attempt contradicts the plan's review ledger.** Plan header states "completed failed rounds are preserved at [r1…r11]" and "requires a fresh R12 adversarial review when provider quota is available." On disk, `scripts/review/results/2026-06-11-plan-2026-r12/` already exists (created 2026-06-11 21:51–21:52) containing a **zero-byte** `2026-06-11-plan-2026-claude.md` and a Gemini `TerminalQuotaError` artifact. The plan's own R10 round flagged exactly this defect class ("R10 artifacts needed ledger reconciliation"), and SOUL's cross-review routing requires quota outages be documented as UNAVAILABLE per the results convention. A zero-byte claude.md is worse than an absent one — under the adversarial-review contract an empty review is a failure, but a stray empty file invites later misreading as a completed artifact. The ledger, the README row, and the plan header must reconcile the attempted-and-failed R12 before any label move.

2. **D5 self-contradiction: the cycle-timestamp guard defeats the supplied-`cycle_id` historical dedup path.** D5 prose requires both: (a) "Non-reactivation transitions … must not have `ts_utc` earlier than the current snapshot `cycle_started_at`" and (b) "Historical retry detection must not rely only on the current snapshot cycle. If the caller supplies `cycle_id`, require an exact six-field historical key match." Pseudocode `prepare_event` places the (a) guard (`raise StaleStateError`) **before** the dedup branch that implements (b). Consequence: a replayed earlier-cycle event carrying its original `ts_utc` and an explicit `cycle_id` — the canonical event-log re-ingestion idempotency case — raises `StaleStateError` instead of being recognized as the exact six-field duplicate that (b) mandates. The dedup branch is only reachable for replays that carry a *fresh* timestamp. No TDD test pins the supplied-`cycle_id` cross-cycle replay case (the test list covers no-trigger cross-cycle raises and fresh-ts retries, not same-ts explicit-cycle replays). This is the identical prose-vs-pseudocode-gate defect class that R11 returned MAJOR on.

3. **Sweep-apply safety gate is asymmetric: the raw-snapshot path reintroduces the forgeability hole the precheck object was built to close.** D9 requires sweep apply to receive "the **same** inbox snapshot used for the reactivation check or a non-forgeable `ReactivationPrecheck`," and the precheck is bound to "the same log path, account set, and snapshot hash." But pseudocode `sweep_grace` gates only on `not (inbox_snapshot or valid ReactivationPrecheck…)` — **any** non-empty `inbox_snapshot` list satisfies the gate with no account-coverage, freshness, or sameness validation. A partial snapshot (e.g., `ace`-only while both accounts have eligible completed threads) authorizes purging `personal` threads with zero reply-check, because sweep treats absence-from-snapshot as no-new-reply. No test in the TDD list covers "completed thread absent from a supplied partial snapshot" or "snapshot covering fewer accounts than the sweep set." Within the plan's own threat model (it made the precheck hash-bound in R8 precisely against forgeable proofs), the snapshot arm is the unguarded door.

4. **Gmail credential availability was empirically checkable and is false on the target machine, but Resource Intelligence never checked.** Issue #2026 is `machine:dev-primary`; on this machine `~/.gmail-mcp/oauth-env.json` and `~/.gmail-{ace,personal}/credentials.json` — the exact prior-art layout D4/D11 commit to wrapping (`gmail-digest.py:33,49,54`) — do not exist (verified `ls`). The plan's "Open" question (run label setup in-session vs. operator step) is already answered by the filesystem and should be resolved in the plan, per the SOUL rule "verify coverage assumptions empirically." The Evidence section verified repo files but not the runtime surface the plan depends on.

Setting only `EMAIL_QUEUE_STATE_DIR` relocates state but not config — and `pending_work_report()` calls `load_account_scope()` implicitly when `account_scope` is None, so a hermetic test (or future production override) with a temp state dir silently reads the developer's real `~/.hermes` config once one exists. `test_account_config_defaults_to_aliases_only` says "isolated env" without specifying what isolates the home-path fallback.
