### Suggestions
- Use only human-authored GitHub approval events to establish the authoritative approval timestamp. Keep `.planning/plan-approved/<issue>.md` as corroboration or conflict detection, never as the boundary used for chronology checks.
- Add a second discovery path for implementation evidence that does not depend on `#NNNN` in commit subjects, and report unattributed implementation as an explicit cohort that prevents strong compliance claims.
- Replace the heading-only stale-review heuristic with a normalized plan hash or a broader substantive-diff rule so any policy-relevant plan edit forces re-review.
