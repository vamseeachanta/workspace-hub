## Findings
1. The plan’s own review summary is false against the cited artifacts. In `docs/plans/2026-04-25-issue-2488-reconcile-untracked-active-skill-files-before-loss.md` under `## Adversarial Review Summary`, the table says `Claude | MINOR`, but `scripts/review/results/2026-04-25-plan-2488-claude.md` begins with `## Verdict` = `MAJOR`. The summary line `current Claude/Codex findings are addressed in this revision` is therefore unsupported by the artifact it cites.

2. The required planning hard gate is still missing from the executable contract. `AGENTS.md` hard gate 1 and `docs/plans/README.md` steps 5-7 require: post the plan to the issue, add `status:plan-review`, stop, wait for user approval, then move to `status:plan-approved` before implementation. This plan’s `Acceptance Criteria` only says `Plan review artifacts are posted before implementation begins`, which does not bind the issue-comment/label gate at all.

3. The manual reconcile CLI contradicts the plan’s own `--skills-dir` abstraction. In the `Pseudocode` section, `build_skill_inventory_with_git(...)` says “never hard-code `.claude/skills` when `--skills-dir` points elsewhere,” but the later `manual CLI contract for scripts/skills/reconcile_filesystem_only_skills.py` hard-codes `git ls-files -z -- .claude/skills` in the trust checks. As written, non-default `--skills-dir` is either unsupported or incorrectly specified.

4. The recurring-family integration is incomplete in the plan. The `run_weekly_audit_extension()` pseudocode names `_all_active_findings()` and `_write_markdown_artifact()`, but current `scripts/skills/weekly_skills_audit.py` also hard-codes family participation in `_baseline_finding_sources()` and `run_audit()` `summary_counts`. Without explicitly changing those surfaces, the new `filesystem_only_*` family will not participate correctly in carry-forward detection or totals on subsequent runs.

5. The CLI contract `--strict (default true for manual reconcile)` is not implementable as specified. In the plan’s `manual CLI contract`, `--strict` is presented as a flag while also claiming `default true`. That leaves the disabling shape undefined: omission, `--no-strict`, or value form. This is not a runnable interface contract.

6. The policy-driven Markdown ordering claim is stronger than the plan’s implementation contract. The plan says `_write_markdown_artifact()` will consume `ranking_policy.section_order` for the new `filesystem_only_inventory` section, but current `scripts/skills/weekly_skills_audit.py` hard-codes section order with literal calls and never reads `ranking_policy.section_order`. If that refactor is required, it should be explicit in `Files to Change` and the TDD list rather than implied only in prose.
