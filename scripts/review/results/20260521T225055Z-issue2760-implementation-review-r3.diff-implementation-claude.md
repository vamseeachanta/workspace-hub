### Issues Found
- [P2] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:638-644 — Sign convention for Cyc/Cxyc uses `sign * abs(_interp_curve(...))` keyed off the input heading sign, throwing away whatever sign the OCIMF workbook itself tabulates at `table_angle = 180 - |heading|`. If the licensed workbook already encodes signed Cyc/Cxyc on its 0..180° basis, the `abs()` step could mask or invert a built-in sign and silently misreport sway/yaw direction at port vs starboard headings. The locked test values (-0.0324, +0.03406, +0.00843 at 175°) are regression-locked against the implementation's own output, so they self-confirm without catching this convention defect class.
- [P3] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:632 — `issue_2760_source_preflight()` runs inside `resolve_ocimf_loaded_tanker_current_coefficients`, which is called from `_row` for every one of the 990 rows. The workbook read itself is lru_cached, but the preflight re-instantiates two `Citation` objects and re-runs `validate_citation` twice per row. Minor perf smell, not a correctness issue; consider caching the preflight result the same way the workbook load is cached.
- [P3] tests/naval_architecture/test_b1528_sirocco_current_heading_rudder.py:~258 — `assert "alpha = δ - ψ" in html or "α = δ - ψ" in html` is an OR-disjunction test fence, which is a known cross-review defect class. The diff intentionally migrates to the Unicode α form everywhere except inside the SVG label legend text; the test should pin the post-change form, not both, otherwise it can silently accept regression to the ASCII spelling.
- [P3] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:286-287 — `_repo_root()` hardcodes `Path(__file__).resolve().parents[3]`. Per the existing `feedback_path_parent_infinite_loop` precedent, prefer env-var or sentinel-file detection over hard depth counts so the module survives relocation under `src/digitalmodel/...`. Static, not looping, so not a hang risk — just a brittleness flag.
- [P3] src/digitalmodel/naval_architecture/b1528_sirocco_current_heading_rudder_report.py:583-592 — `points()` hardcodes start_row=3 and the angle/value column indices (23/24, 1/7, 9/15) for the three curves. Acceptable since the basis selection is fixed to the >6 bucket and the workbook layout is the licensed source-of-truth, but worth a sentinel test that fails loudly if the workbook is reissued with a different sheet layout rather than silently regressing to whatever the new cells contain.

### Suggestions
- Add an independent OCIMF sign-convention reference test that pins the expected sign of Cyc/Cxyc for at least one off-centerline heading against the published Annex A figure, not against the implementation's own row output. This is the single highest-leverage test you can add and would directly close the convention defect class flagged in P2.
- Memoize `issue_2760_source_preflight()` (lru_cache with maxsize=1 keyed off `(OCIMF_WORKBOOK_PATH, mtime)`) so the per-row hot path doesn't re-validate citations 990 times per sweep.
- Tighten the alpha/α test to a single canonical form rather than disjunction; if both forms must coexist (SVG vs body), assert each independently against the section it belongs in.
- Per `.claude/rules/calc-citation-contract.md` §4, confirm the cited wiki page `wikis/marine-engineering/wiki/standards/ocimf-meg4.md` carries the `code_id: OCIMF-MEG4`, `publisher`, `revision: "4th edition, 2018"` frontmatter in the private llm-wiki — the diff confirms the ACMA concept page does, but the OCIMF-MEG4 wiki page itself isn't shown in this patch.
- Consider a sentinel workbook-layout test (e.g., assert the cells at the hardcoded indices on the licensed workbook match a known fingerprint) so a reissued workbook fails loudly rather than silently shifting the screening basis.
