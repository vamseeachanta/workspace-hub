## Findings

1. **R1 evidence chain is broken at the source.** Plan line 7 cites `scripts/review/results/2026-05-20-plan-2766-claude.md` and `...-codex.md` as the R1 review artifacts; both are 0 bytes on disk. This is exactly the `feedback_reviewer_dispatch_refetch_live_body` and `feedback_adversarial_review_stance` failure pattern — if R1 ran, its evidence must be persisted; if it did not run, the plan must not claim it returned MAJOR. **Block.**

2. **`data_access_profile.repos` reconciliation is asserted but not in Files-to-Change or AC.** Plan line 153 ("Reconciliation rule: `telegram_hermes.data_access_profile.repos` must include all `required` tier-1 repos") implies updating `config/workstations/registry.yaml:44` to add `llm-wiki`, but: (a) the live value at registry.yaml:44 is `[workspace-hub, digitalmodel, assetutilities, worldenergydata, assethold, OGManufacturing]` — `llm-wiki` is missing; (b) AC §lines 261–271 never names `data_access_profile.repos`; (c) the test at line 230 (`test_data_access_profile_includes_required_repos_and_allows_classified_non_tier1`) will fail against the live registry. The plan either silently changes a load-bearing dispatch list with no AC, or accepts a permanent fixture-vs-live divergence. **Block.**

3. **Legacy `machines.dev-primary.repos` semantics undefined under new schema.** Plan §"Proposed Registry Schema" lines 89–99 expands the `repos:` array to 9 entries by adding `llm-wiki`, `aceengineer-website`, `aceengineer-strategy`. The current registry.yaml:29–35 has 6. AC line 261 only requires the `tier1_baseline` block. The plan never states what `repos:` means once `tier1_baseline.required/optional/non_tier1_machine_access` exist. Two sources of truth + no migration rule = drift waiting to happen. Per `feedback_doc_counter_rule_writetime`, this overlap should be expressed as a write-time recompute rule, not parallel sets.

4. **Disjointness assertion omits `non_tier1_machine_access`.** Pseudocode line 173 asserts pairwise disjointness across `required`, `optional`, `reference_only`, `not_planned` — but `non_tier1_machine_access` is excluded from the assertion. The whole point of the new schema is to detect when `OGManufacturing` (currently in `data_access_profile.repos`) leaks into `required`. Without `non_tier1_machine_access` in the disjointness check, the schema permits the exact silent-overlap class it claims to prevent.

5. **`historically_moved_not_currently_present` is empty in the schema example but must be non-empty to satisfy AC.** AC line 264 requires `OGManufacturing and other affected machine-access repos are explicitly classified outside the tier-1 decision set or as `historically_moved_not_currently_present`; no affected repo from #2766 comments is silently omitted.` Plan line 65 explicitly names nine repos (`acma-projects`, `client_projects`, `doris`, `frontierdeepwater`, `OGManufacturing`, `rock-oil-field`, `saipem`, `sd-work`, `seanation`) as "not present in the latest top-level git inventory" — yet schema line 137 sets `historically_moved_not_currently_present: []`. Either the AC cannot be satisfied by the schema template, or the implementation will diverge from the schema-as-written without warning. No test in the TDD list verifies this bucket gets populated.

6. **`source_issue: 2770` plus self-attached unauthorized enumerations.** Schema line 102 cites `source_issue: 2770` for the whole baseline. But the `non_tier1_machine_access` 18-entry list at schema lines 118–136 is **not** in #2770 — #2770 body deliberately scopes itself to tier-1 placement only ("Tier-1 repos to consider: …" 8-repo list). The plan is laundering an 18-repo machine-access decision through the `source_issue: 2770` field. Either the field needs to be `source_issues: [2770, 2766]` (with #2766 explicitly authorizing the non-tier-1 list), or the non-tier-1 list needs its own decision issue.

7. **Pseudocode dead branch — workspace-hub special case.** Line 188: `missing_required = required - inventory.top_level_names - {workspace-hub if workspace_root is git repo}`. Since `workspace-hub` IS a top-level child of `/mnt/local-analysis`, it will appear in `inventory.top_level_names` whenever `/mnt/local-analysis/workspace-hub/.git` exists; the special-case subtraction is either dead code or papers over a `discover_top_level_git_repos` that mistakenly skips it.
