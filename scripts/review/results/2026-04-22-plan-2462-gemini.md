### New Issues Found (r2)

- **[MINOR] HARD GATE coupling: `status:plan-approved` is weaker than merge-to-main.** Line 8 and line 246 gate implementation on #2460 reaching `status:plan-approved`, not on #2460 being merged to main. `status:plan-approved` means the plan is approved for implementation; it does not guarantee the contract doc (`docs/standards/TIER1_INDEXING_AND_CODE_PLACEMENT_CONTRACT.md`) actually exists on main. Since #2462's registry path and operator-map host location depend on contract text that only comes into existence when #2460 is implemented-and-merged, an over-eager worker could read the current gate as "#2460 plan-approved → green to start" and hit missing-contract-doc failures. Fix: tighten gate wording to "#2460 has reached `status:plan-approved` AND its contract doc has been drafted to the point where the registry path shape and operator-map host location are textually locked (either in the plan or the contract file)." Alternative acceptable wording: "#2460 contract doc exists on main with the registry-path and operator-map-host decisions locked." This is MINOR because the plan's pseudocode and "Open" items already treat these decisions as deferred to #2460, so the risk of drift is already soft-mitigated.

- **[MINOR] Race between main-session plan commit and worker-3 edits.** Line 198's ownership note says "The row is already present (indexed line 280) and will be updated by the main session at merge or by a subsequent pass." This assumes the main session has already committed the canonical #2462 plan filename (`2026-04-22-issue-2462-digitalmodel-repo-wide-routing-surfaces.md`) with its row in `docs/plans/README.md`. Verified: row 280 in `docs/plans/README.md` does reference this canonical filename. But the plan's acceptance criterion #14 (line 241) asserts "`docs/plans/README.md` includes the #2462 row" without specifying *which* row content — if a filename drift happens (e.g., the plan is renamed during review) the row will point at the wrong file and the criterion will pass spuriously. Fix: strengthen acceptance criterion #14 to "includes the #2462 row AND that row's third-column path value matches this plan's actual filename." This is MINOR because the canonical filename is already frozen by the commit at row 280.
