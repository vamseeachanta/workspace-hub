### Verdict: MAJOR

### Summary
Exceptionally thorough plan that has genuinely closed most prior-round findings, but a concrete pseudocode-vs-test contradiction in the publication-state classifier (federal data could pass to generic public_llm_wiki), an un-handled output_residency value, an unmitigated shared-schema regression surface, and a large "MVP" review burden keep it short of approval. None are fatal; all are addressable with targeted edits.

### Issues Found
- [P1] Pseudocode/test contradiction: classify_publication_state's `public_llm_wiki` branch returns public_publishable whenever sources are public-safe. Because `public-federal-data` IS in public_safe_source_classes, a federal-data source with output_residency=public_llm_wiki would be classified public_publishable — directly contradicting `test_public_federal_cannot_route_to_generic_public_llm_wiki` (expected exit 1). The classifier is missing the rule 'if any source is public-federal-data then output_residency must be public_federal_wiki (else blocked)'.
- [P2] Inconsistent output_residency value: `publication_sequence` stage 3 (hse-marine-segregated) declares `allowed_output_residency: domain_private_corpus`, but that value is never added in the schema-extension section (only `public_federal_wiki` is) and is not handled by classify_publication_state (it falls through to `return blocked`). Either the staged config or the classifier/schema is wrong.
- [P2] Scope/reviewability vs 'MVP' framing: the non-cuttable blocking floor is ~52 tests plus the standard, config, two closed-schema edits, seven templates, and full fixtures — all in one issue/PR. The plan's own r4 flagged validator complexity; the helper-module split organizes code but does not reduce the single-PR verification burden. Phase A (standard/config/templates/schema) and Phase B (validator) read as separable deliverables.
- [P2] Shared-schema regression surface not enumerated: the plan edits `execution-manifest.schema.yaml` and `report-evidence-bundle.schema.yaml` (both additionalProperties:false) and only commits to running `test_report_layer_contract.py`. No enumeration of all other consumers/validators of these two schemas to prove the additive enum + 'public-output fail-closed constraints' do not regress existing manifests/bundles elsewhere.
- [P2] `.gitattributes` change is ambiguous and potentially repo-wide: the canonicalization text lists `*.yml`, `*.yaml`, `*.json`, and 'new `*.jsonl text eol=lf`'. If the first three are also being added (not pre-existing), introducing `text eol=lf` for those globs can renormalize unrelated committed files on next checkout/normalize. The Files-to-Change row only mentions `*.jsonl`; the two statements should be reconciled and the blast radius confirmed.
- [P3] Symlink rejection depth unspecified: legal-attestation 'reject symlinks' — unclear whether each path component is lstat-checked (defends against a symlinked parent directory / mid-path TOCTOU) or only the final path element. SOUL rules explicitly call out TOCTOU/symlink hazards.
- [P3] Public identity registry effectively BSEE-only: dataset_slugs for noaa/usgs/mms are empty lists, so any NOAA/USGS/MMS public run fails `test_public_projection_ids_match_public_identity_registry`. 'public-federal-first' staging is in practice BSEE-only for the MVP; this should be stated as intended.
- [P3] run_history.jsonl 'append-only' is not provable from a single static fixture snapshot; the validator cannot enforce true append-only without history/diff. The append-only guarantee should be explicitly scoped to duplicate-identity checks now, with real append-only enforcement named as follow-up.
- [P3] Enum fenced-block parsing scope is ambiguous: it is unclear whether `publication_sequence` and `public_identity` live inside the `ecosystem_wiki_flywheel_enums` root block (parsed by test_standard_enum_table_matches_config) or in separate fenced blocks, and which test owns each comparison.
- [P3] Process note: file-existence and cross-repo issue-state evidence are plan-asserted; the attestation hash is intentionally deferred ('not embedded in this changing draft'). At review time these remain unverified, and the same-repo attester is known to mislabel workspace-hub #450-#453 as closed — reviewers must run the attestation before approval rather than trusting the embedded evidence list.

### Suggestions
- Add the missing classifier guard explicitly: before the public_llm_wiki branch, 'if any source.source_publication_class == public-federal-data: require output_residency == public_federal_wiki else return blocked'. Then re-confirm test_public_federal_cannot_route_to_generic_public_llm_wiki against the corrected pseudocode.
- Reconcile `domain_private_corpus`: either add it to the output_residency enum extension and give classify_publication_state an explicit private-corpus branch, or change stage 3's allowed_output_residency to a value the classifier/schema actually supports.
- Consider splitting #2975 into two stacked PRs/issues — Phase A (standard + config + templates + additive schema enum) and Phase B (validator + 52 tests) — to keep each review tractable while preserving the non-cuttable gate set across both.
- Enumerate every current consumer of execution-manifest.schema.yaml and report-evidence-bundle.schema.yaml (grep for loaders/validators) and add a regression assertion or note for each, not just test_report_layer_contract.py.
- Clarify the .gitattributes edit to state that only `*.jsonl text eol=lf` is newly added (and that yml/yaml/json rules already exist), or run/verify `git add --renormalize` impact and document that no unrelated files change.
- Specify component-wise symlink/lstat checking for legal-attestation path normalization to close mid-path symlink TOCTOU.
- State explicitly that NOAA/USGS/MMS publishing is structurally blocked until dataset_slugs are populated, and that the BSEE valid fixture is the only passing public-federal path in the MVP.
