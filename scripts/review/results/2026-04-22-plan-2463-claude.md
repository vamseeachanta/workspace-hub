### Issues Found

- [P2] Important — **Banner-retire of `DEPLOYMENT_GUIDE.md` leaves 991 lines of GitHub Pages procedure inline.** A reader who jumps past the banner (search hit, TOC click, fragment URL) can still be misrouted. The plan acknowledges this in Risks but accepts it. Either (a) explicitly redirect the file's body to a `See VERCEL_DEPLOY.md` stub (loses history but forecloses misrouting), or (b) add a visible per-section banner inside each `## Step N` header, not just the file-top banner. Current approach is minimal but soft.
- [P2] Important — **`validate_docs_links.py` scope excludes top-level MD files that carry legacy refs.** The plan scans `README.md`, `AGENTS.md`, `docs/**/*.md`. It does NOT scan `VERCEL_DEPLOY.md`, `PHASE_4_AND_6_PLAN.md`, `PHASE_6_EXECUTION_CHECKLIST.md`, `CASE_STUDY_TEMPLATE.md`, `GITHUB_ORG_SETUP.md`, `GOOGLE_ANALYTICS_SETUP.md`. Several of these are referenced from README.md; if they in turn reference `.agent-os/product/*.md`, this plan closes the loop only for one hop of the reference graph. Fix: glob `aceengineer-website/*.md` + `aceengineer-website/docs/**/*.md` + `aceengineer-website/AGENTS.md`.
- [P3] Minor — **`test_no_dot_agent_os_product_references` hardcodes four full paths.** Variants (`.agent-os/product/mission` without `.md`, `.agent-os/product/roadmap.yaml`) pass the test while still being broken. Replace the four literal substrings with a regex like `\.agent-os/product/[a-zA-Z0-9_-]+` and invert the assertion.
- [P3] Minor — **Evidence block declares 7 sources but does not re-cite commit SHA.** Like #2464, the line-excerpt citations are stable only at the HEAD they were observed on. Cheap fix: capture `git rev-parse HEAD` once and include it in the Evidence block header.
- [P3] Minor — **Plan is silent on `docs/plans/README.md` index update.** Write boundaries forbid the edit for this worker; call out explicitly that the orchestrator must add the row before merge.
- [P3] Minor — **`docs/maps/aceengineer-website-operator-map.md` shape not locked.** The pseudocode lists section titles, but nothing asserts the operator map uses the same section ordering as the digitalmodel exemplar (`docs/maps/digitalmodel-orcawave-orcaflex-operator-map.md`). Portfolio consistency matters for #2460 compliance; name the exemplar explicitly and assert the test mirrors its headings.
