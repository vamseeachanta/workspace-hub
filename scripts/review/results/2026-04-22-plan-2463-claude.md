## Findings

- [MINOR] Regression-test location is unresolved. The plan offers `aceengineer-website/tests/docs/test_routing_surfaces.py` **or** a shell equivalent under `aceengineer-website/scripts/`. That flexibility is defensible, but the acceptance criterion "a minimal test or shell check enforces the four conditions above and is runnable locally with no network" does not force the implementation agent to pick either and then actually wire it into a runnable target. Risk: the check lands as an orphaned file with no discoverable entrypoint. Recommendation: tighten acceptance to require the check be registered in an invocable manner (e.g. `pytest -k routing_surfaces` if Python, or an explicit reference from `aceengineer-website/AGENTS.md` if shell).

- [MINOR] "Active GitHub Pages block" vs "migrated from" note is defined prose-only. The plan wants the factual historical migration note preserved but bans active GitHub-Pages-as-current language. The regression test `test_readme_has_no_active_github_pages_block` is described in English but the plan never pins the discriminator (e.g. must not contain the literal phrase "Deploy to GitHub Pages" or "GitHub Pages Settings" outside of a banner/history section). Without a concrete discriminator, two implementation agents will produce two incompatible tests. Recommendation: list the concrete banned strings and concrete allowed strings inline in the TDD row.

- [MINOR] DEPLOYMENT_GUIDE rewrite path is genuinely dual. Offering (a) rewrite-to-Vercel or (b) rename-with-legacy-banner is reasonable, but the plan does not include an acceptance test for path (a): a rewrite-to-Vercel result could pass all stated tests while containing factually wrong Vercel deployment details. Recommendation: if the implementation picks rewrite-to-Vercel, add a content sanity check (site URL, build command, CNAME file present) or require a reviewer sign-off comment referencing `aceengineer-website/README.md`'s Vercel description.

- [MINOR] The "minimal validation" contract is one-sided. It guards against the four listed conditions but does not guard against new legacy-style references creeping into future edits of the operator map or `docs/README.md`. The #2460 contract plan uses `tests/docs/test_banned_stale_references.py` for exactly this purpose. Recommendation: either extend that existing test to cover the new docs, or explicitly note that this is deferred to a follow-up so the gap is visible.

- [MINOR] Source-hygiene is not addressed for aceengineer-website. The #2460 contract plan names source-hygiene as a universal tier-1 rule (no backup artifacts, no runtime noise under tracked source paths). The #2463 plan inherits the routing part of #2460 but is silent on whether aceengineer-website needs any source-hygiene cleanup. The 2026-04-22 scorecard does not flag backup artifacts for this repo, so this is probably a no-op in practice, but the plan should say so explicitly rather than omitting.

- [NIT] `PHASE_4_AND_6_PLAN.md` and `PHASE_6_EXECUTION_CHECKLIST.md` are at the repo root. The plan permits them to be kept if clearly labeled strategic-planning, but the root is already noisy and these are strategic-planning docs, not architecture. Minor: consider recommending they be moved under `docs/strategy/` in a follow-up, but do not block this plan on it.
