### Verdict: MAJOR

### Summary
A thorough, well-structured T3 contract plan that has already absorbed most r1 adversarial findings (source_class collision, enum-config-as-source-of-truth, allowlist projections, legal-scan freshness, determinism). It is close to approvable, but a few residual gaps remain that matter because the plan is TDD-driven: the validator behavior is fixed by tests, so spec/pseudocode mismatches will be baked in. Recommend resolving the items below before fresh r2 sign-off and user approval (do not self-approve).

### Issues Found
- [P2] AC↔pseudocode mismatch on approved-with-notes: AC (line 414) restricts approved-with-notes to private targets 'when no notes leave unresolved source, legal, or privacy gates,' but classify_publication_state (lines 310-313) admits approved-with-notes for private unconditionally with no gate-resolution check. As written, the validator cannot inspect free-text notes for 'unresolved gates,' so the test (test_public_review_state_policy_is_explicit covers public only) and pseudocode will diverge from the AC. Specify a structured gate-resolution field rather than relying on note prose, and add a private-target test.
- [P2] Legal-scan attestation window is underspecified: the plan requires timestamp comparison 'against the bundle reference_time window' (lines 319, 412) but never defines the window bounds or tolerance. Without an explicit, deterministic window definition the freshness check is non-falsifiable and test_forged_or_stale_legal_scan_evidence_fails cannot be written deterministically. Define the exact reference_time relationship (e.g., scan timestamp must equal/precede reference_time and follow last input-hash timestamp).
- [P2] Scope/feasibility for a single issue: one validator covering provenance completeness, citation coverage, public/private contamination, duplicate-run and duplicate-ledger semantics, broken-link + stale-pointer detection, legal-scan attestation, two-clean-run scheduler readiness, plus 46 pre-written tests and 8 templates is a large surface for one T3 issue even hermetic-only. Hook/CI is correctly deferred, but the validator itself may warrant a phase split (e.g., manifest/history + classification first; ledger/projection + scheduler second) to keep TDD batches reviewable.
- [P3] Standard-doc enum table vs config drift test is brittle: test_standard_enum_table_matches_config implies parsing a Markdown table out of ECOSYSTEM_WIKI_FLYWHEEL_CONTRACT.md and diffing against YAML. Markdown-table parsing is fragile; prefer generating the doc table from the config at build/test time, or embedding a fenced machine-readable block, rather than scraping prose.
- [P3] Cross-repo issue evidence depends on the GitHub connector: worldenergydata #450-#453 OPEN status (lines 122-126, 210) was verified via connector, and same-number workspace-hub #450-#453 are CLOSED. The plan flags this honestly, but per the local-verify-connector-evidence rule the open state of the four trigger issues should be re-confirmed via a local `gh issue view --repo vamseeachanta/worldenergydata` at r2 time, since the whole worldenergydata backlink contract hinges on it.
- [P3] 'Resolved recommendation' framing leaves no genuine open questions for the user: the validator-scope, enum-location, and #2945-missing-plan items are all self-resolved. At least the validator-scope/phase-split decision is a scope judgment the user should confirm rather than the plan deciding unilaterally.

### Suggestions
- Replace free-text 'notes' gating with a structured approved_with_notes_gate_status enum (e.g., all-gates-resolved | gates-open) so the private-publish path is validator-checkable, and add a private-target approved-with-notes test to the TDD list.
- Add an explicit, deterministic definition of the legal-scan reference_time window (lower bound = max input/output hash timestamp; upper bound = reference_time) to the pseudocode and the Acceptance Criteria.
- Consider splitting the validator into two TDD waves within #2975 or a fast-follow, keeping the first wave to manifest/history/classification/contamination so the initial review is tractable.
- Generate the standard-doc enum table from config/ecosystem-wiki-flywheel/source-classification.yaml (or embed a fenced YAML block) instead of parsing a Markdown table, to make test_standard_enum_table_matches_config robust.
- At r2, capture a local gh issue-view transcript for worldenergydata #450-#453 in the review artifacts so the open-state evidence is locally attested, not connector-only.
- State whether config/ecosystem-wiki-flywheel/source-classification.yaml needs its own shape/registry-hygiene check (mirroring check-client-wiki-registry.sh) so the new config tier doesn't itself become an unvalidated drift surface.
