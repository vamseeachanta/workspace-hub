### 2. Severity-ranked findings

#### CRITICAL
None.

#### HIGH
- **F1 — `108 cases` in C1 caption is provably wrong.**
  - Storyboard line 82 (caption) and line 79 (verification scope) state "108 cases across mudmat, jumper, and shallow-pipelay screening."
  - Actual sum across all 6 vessel × capability rows in `vessel_comparison_matrix.json`: **156** (Large CSV mudmat=18 + Large CSV jumper=30 + Medium CSV mudmat=18 + Medium CSV jumper=30 + Large PLV shallow_pipelay=30 + Shallow Water Barge shallow_pipelay=30).
  - Even narrowed to "shallow-pipelay screening only" = 60 cases, not 108. There is no obvious subset selection that yields 108.
  - Codex flagged "treat 108 as a headline number to recompute" but didn't compute it. The plan's verification scope tags `108 cases` as deferred-to-render-slice, but the *caption draft* embeds the wrong number without inline `(pending recomputation)` framing — so a reviewer scanning only the caption reads it as fact.
  - **Severity rationale**: HIGH because (a) the artifact's whole premise is "evidence-backed claims for external send"; (b) `status:plan-review` reviewers eyeball captions; (c) once approved with the wrong number embedded, the implementation slice can drift further.

#### MEDIUM
- **F2 — C1 caption violates the plan's own standards-completeness pseudocode rule.**
  - Plan pseudocode (line 146): `assert set(C.inherited_standards) <= set(C.caption.standards) | set(C.omission_rationale.keys())`.
  - C1's data inputs trace to both `pipelay_vessels.json` and `csv_hlv_vessels.json` (via `vessel_comparison_matrix.json`).
  - Inherited standards (verified): DNV-ST-F101, DNV-OS-F101, API RP 1111 (from pipelay JSON) ∪ DNV-RP-H103, DNV-ST-N001, DNV-OS-H101 (from CSV/HLV JSON) = **6 standards**.
  - C1 caption cites: DNV-RP-H103, DNV-ST-N001, DNV-ST-F101, API RP 1111 = **4 standards**.
  - Missing without `omission_rationale`: DNV-OS-F101 (likely intentional — superseded by DNV-ST-F101) and **DNV-OS-H101** (which the plan AC §218 explicitly lists as "where applicable").
  - Plan §250 closes the loop on API RP 1111 only. The two `-OS-` standards are unaddressed.
  - **Severity rationale**: MEDIUM not HIGH because (a) the rule fires at render-time per plan, not at planning-time; (b) the omissions are defensible if rationale is recorded. But the plan currently passes the plan-AC §218 word-for-word while violating its own pseudocode rule — that contradiction itself is the defect.

- **F3 — Frontmatter and Artifact Map say review artifacts are `(TBD)`, but they exist on disk.**
  - Plan line 7 (frontmatter): `Review artifacts: scripts/review/results/2026-04-29-plan-2555-claude.md (TBD) | ...-codex.md (TBD) | ...-gemini.md (TBD)`.

  - Plan §229 (Adversarial Review Summary table) attests they are live canonical MINOR.
  - This is internal self-contradiction: the same plan tells two different stories about review state in two different sections. Once this Claude artifact lands, the `(TBD)` markers will be triple-stale.

#### LOW
- **F5 — "Shallow Water Barge pair is the highest pass-rate vessel-job pair" implies uniqueness, but three pairs tie at 100%.**
