- **`SUPPORTED_STANDARDS` drops two NACE standards the Deliverable promises to preserve.** §Pseudocode P3 declares `SUPPORTED_STANDARDS` with 13 entries (lines 521–535). The tuple includes `NACE-SP0169` but **omits `NACE-SP0176` and `NACE-SP0207`**. Risk #1 mitigation (line 824–825) says "baseline tests prove byte-identity restoration" on rollback. Neither claim holds if the test is a math identity check decoupled from the live function. If `flush_anode_resistance()` carries a unit-conversion bug today (it converts in→cm internally, so the function-output magnitude differs from the test's metric recompute), this test cannot detect it.

### gemini

- **Missing Source Code:** Plan references multiple code paths (e.g., `digitalmodel/src/digitalmodel/cathodic_protection/dnv_rp_b401.py`, `digitalmodel/infrastructure/base_configs/domains/cathodic_protection/cathodic_protection.yml`). None of these files or directories exist in the current workspace at HEAD. Evaluated against the retrieval skepticism rule, the plan's claims about the actual codebase state cannot be empirically verified because the codebase is entirely absent.
- **Silent Regression via Default Edition:** Plan §P1 `normalize_edition` warns and defaults to `"2021"` if `edition=None` is passed. Because `DeprecationWarning` is suppressed by default in standard Python execution, legacy callers of the functional package (which currently implements the 2017 standard) will receive no visible warning but will experience a massive, silent numeric shift in CP design (e.g., 5.6x harsher FBE breakdown). This violates the regulatory-hazard mitigation against silent undersizing/oversizing.
- **Missing `run` Dispatcher:** Plan §P4 pseudocode refactors the router to invoke `digitalmodel.cathodic_protection.run(...)`. However, no such `run` entrypoint exists in the current facade, and neither §P1 nor §P2 implements this function. The refactored router will fail unconditionally with an `AttributeError` at runtime.
- **Invalid Dataclass Method Invocation:** Plan §P4 pseudocode invokes `**result.dict()` on the return value. However, plan §P1 explicitly defines the result objects (e.g., `AnodeSizingResult`) as standard Python `@dataclass` classes. Standard dataclasses do not possess a `.dict()` method; this will raise an `AttributeError` unless `dataclasses.asdict(result)` is used.
- **Dangling Duplicate Module and Lost Formula:** Plan AC-P2.2 claims `cp_sacrificial_anode_b401.anode_resistance_flush` uses a unique `ln(2L/r) - 1` formula. Plan §P4 explicitly deletes the deprecation shim `infrastructure/common/cp_sacrificial_anode_b401.py`, but completely omits the actual implementation module `infrastructure/base_solvers/hydrodynamics/cp_sacrificial_anode_b401.py` from the "Files to Change" table. Furthermore, `FLUSH_RESISTANCE_FORMULA` in §P2 only preserves `mccoy` and `dwight` (`ln(4L/r) - 1`), dropping the `ln(2L/r) - 1` formula variant entirely. This fails to preserve the documented numerical divergence.
- **Splash Zone Type Incompatibility:** Plan §P2 `SPLASH_CURRENT_DENSITY` defines the 2017 splash zone return as `{"coated": 0.0, "bare": 0.0}`. However, plan §P1 `test_baseline_splash_zone_divergence` demonstrates that the existing `marine_structure_cp.py` expects and returns a 3-tuple `(0.0, 0.0, 0.0)` for different tide levels. Replacing the tuple with a scalar dictionary lookup will cause a `TypeError` in existing functional package calculations that expect a tuple.
