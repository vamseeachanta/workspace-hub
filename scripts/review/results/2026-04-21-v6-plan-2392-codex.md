### Verdict: MAJOR

### Summary
The plan still leaves correctness-critical behavior undefined around source identity normalization, supplemental input schemas, and scheduled execution prerequisites. Those gaps prevent affirmative verification that the detector will distinguish true gaps from unresolved/unsupported data without false positives or silent automation failures.

### Issues Found
- `## Identity Join Contract` / `### Source-side compatibility reads` step 2 is internally inconsistent: it says a bare 64-hex source key should be `classify[ied] ... as identity-unresolved unless a canonical sha256 match is separately established during normalization`, but the plan never defines any lawful transformation or secondary source that can upgrade a bare hex value into a canonical `sha256:<64hex>` key. That leaves a correctness-critical branch undefined, and the test list only covers the unresolved case (`test_bare_hex_source_key_emits_source_identity_warning_and_does_not_become_true_gap_without_canonical_match`), not the claimed promotion path.
- `## Resource Intelligence Summary` says the supplemental join corpus includes `data/document-index/dde-standards-inventory.yaml`, `data/document-index/standards-transfer-ledger.yaml`, and `data/document-index/promotions/*.yaml`, and `## Candidate Record Shape` claims `ledger / promotion-manifest` records can be normalized into the common shape. The plan never specifies the field-level extraction contract for those sources: where `doc_key`, `source_path`, `title`, `availability_tier`, and `discipline` come from, how conflicting fields are resolved, or what makes a supplemental record "joinable" versus `identity-unresolved`. Without that schema contract, the detector cannot be verified to produce stable classifications across heterogeneous ledgers.
- `## Scheduled Task Contract` hard-wires weekly execution of `uv run python scripts/knowledge/detect_wiki_gaps.py --config config/ai-tools/wiki-gap-detection.yaml`, while `## Resource Intelligence Summary` marks `data/document-index/index.jsonl` as a required input. The attested evidence does not verify that `data/document-index/index.jsonl` exists, and the plan does not add any scheduler precheck or upstream dependency to ensure it exists on the scheduled checkout. The result is an automation path that can fail every week on a valid checkout even though the plan treats the detector as schedulable production work.
- `## Resource Intelligence Summary` defines `data/document-index/promotions/*.yaml` as a supplemental input pattern and says "if config explicitly expects a supplemental coverage input/pattern and it is missing, run status becomes degraded," but the plan never defines whether a glob with zero matches counts as "missing" or as a normal empty expansion. That ambiguity directly affects `_summary.md`, `run_status`, and the approval gate because the same repo state could be reported as clean or degraded depending on implementation choice.
- `## Pseudocode` does not fully satisfy the claimed duplicate-doc-key diagnostic contract. In the duplicate branch it first stores both pages when the second duplicate is seen, but any later duplicate only appends `{"doc_key": key, "pages": [page]}` after the key is already invalidated. That loses the complete page set for the duplicate group, which conflicts with `## Deliverable` / `## Acceptance Criteria` claims about durable `duplicate wiki doc_key diagnostics` in `_summary.md`. The plan needs an explicit aggregation rule for all colliding pages, not just the first two.

### Suggestions
- Replace the bare-hex normalization clause with one explicit rule: either bare 64-hex is always unresolved, or define the exact source field and normalization step that can convert it into a canonical `sha256:` key, then add a test for that positive path.
- Add a per-source schema table for `dde-standards-inventory`, `standards-transfer-ledger`, and `promotions/*.yaml` that names the authoritative fields for identity, path, title, discipline, availability tier, and domain, plus the fallback behavior when any field is absent.
- Amend the scheduled task contract to fail closed before execution when required inputs are absent, or declare the upstream job/artifact dependency that produces `data/document-index/index.jsonl` on the scheduled checkout.
- Define zero-match glob behavior explicitly for supplemental patterns and add tests for both unconfigured-empty and configured-but-missing cases.
- Define duplicate wiki-key aggregation as a set of all pages sharing the key and require `_summary.md` to report the full collision group deterministically.

### Questions for Author
- What exact input field(s) allow a bare 64-hex source key to be upgraded into a canonical `sha256:<64hex>` join key during normalization, if that path is intended to exist at all?
- For each supplemental source (`dde-standards-inventory`, `standards-transfer-ledger`, `promotions/*.yaml`), what is the authoritative field mapping into the normalized record shape?
- What guarantees that `data/document-index/index.jsonl` exists on the weekly scheduled checkout before the detector runs?
