# Codex review — plan #2311

Verdict: MAJOR

**Strengths**

- The plan identifies the right core problem: stale stage-transition script names should be confined to intentional legacy/history surfaces, not live workflow guidance.
- It correctly avoids blanket deletion and recognizes the need to preserve historical/audit artifacts.
- The deliverable is mostly bounded to test and documentation hardening rather than codebase-wide refactoring.

**Gaps**

- The plan is not implementation-ready because it does not resolve its central classification rule. In `Risks and Open Questions`, it still asks whether allowed surfaces should be explicit allowlists or directory/type classification. That is not an execution detail; it is the core design choice.
- `Resource Intelligence Summary` claims a gap around targeted confinement, but the plan never enumerates the actual current live hits that must be fixed. “If any live instructional hit exists” is too vague for a T2 issue.
- `Files to Change` includes `docs/plans/README.md`, but that is plan bookkeeping, not issue implementation. It dilutes scope.
- The plan does not define the scan universe for “current docs/templates/instructions.” Without that, the tests can pass while missing the real surfaces that agents read.
- The acceptance criteria do not require a concrete before/after inventory of offending paths.

**Risks**

- The largest risk is false confidence from a narrow curated test list. If the new test only checks a small set of docs, stale references can remain in active agent-facing files and the issue still appears “done.”
- The proposed audit refresh couples implementation success to a generated report. That is brittle and can fail for reasons unrelated to stale-reference confinement.
- If classification is directory-based instead of explicit-path-based, legacy mentions can quietly spread into new files under an “allowed” folder.

**Missing tests**

- A test that scans the full intended live-surface corpus, not just a curated subset, and proves zero matches for `start_stage.py`, `exit_stage.py`, and `verify_checklist.py`.
- A test that proves the allowlist is closed: only explicitly named legacy/history files may retain these references.
- A test covering agent-facing instruction surfaces specifically if they are in scope, such as repo instructions, templates, skill docs, or workflow guides.
- A regression test that fails when a new file is added to an allowed directory with one of these names, if the design uses directory classification.

**Scope creep concerns**

- `test_provider_audit_report_still_lists_cluster_without_becoming_instructional_surface` is scope creep. The issue is stale-reference cleanup, not preserving specific generated audit wording.
- “Refresh provider-session audit after cleanup” is also likely scope creep unless the issue explicitly requires regenerated audit artifacts.
- Updating `docs/plans/README.md` should not be part of the implementation plan for this issue.

**Weakest assumption and what breaks if it is false**

- Weakest assumption: the stale references are already confined to a small, well-understood set of intentional legacy/history surfaces.
- If false, the plan’s bounded test additions are insufficient, because there may be active agent-read docs still pointing to deleted scripts. The issue would then need real content cleanup across current workflow surfaces, not just guardrails.

**Most likely implementation failure mode**

- The implementer adds a targeted test with a permissive or incomplete allowlist, gets green tests, and leaves one or more live instructional references untouched because the scan corpus was under-defined.

**Most likely test gap**

- Missing active prompt/instruction surfaces outside the curated docs tests. The plan talks about “docs/templates/instructions,” but the proposed tests do not clearly prove coverage of all three.

**Future issues suggested**

- Keep broader stale-reference expansion in the existing follow-up issue for wider enforcement rather than widening this issue.
- If legacy redirect content needs architectural separation from current guidance, keep that in the existing follow-up rather than mixing it into this cleanup.
- If generated reports need a stable classification framework, split that into a separate harness issue.

**Review confidence**

- Medium. The review is based on the plan text provided. The main issues are structural and execution-readiness problems inside the plan itself, not subtle repo-state details.
