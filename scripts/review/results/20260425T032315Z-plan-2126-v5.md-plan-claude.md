### Verdict: MAJOR

### Summary
Plan v5 is exceptionally well-iterated and resolves the v4 hyphen-path P1 cleanly. However, two concrete runtime defects remain that would break the suite at execution time: (1) the oracle .md files carry a YAML-comment header (`# oracle_authored_by: ...`) whose syntax is identical to markdown H1 headings — the locked heading-preservation scorer (regex `^(#{1,6})\s+(.*)$`) will treat these metadata lines as real H1s in the oracle but not in `actual_md`, contaminating dim-1 scoring on every fixture; (2) the plan creates `markdown_qa/__init__.py` AND uses bare-name sibling import `from fixtures_sampling import check_floor_occupancy` in conftest.py — with `__init__.py` present, pytest's default importmode puts `tests/` on sys.path, not `markdown_qa/`, so the import will fail and the session-finish hook will never load. Both are fixable with small edits.

### Issues Found
- [P1] Heading scorer / oracle metadata collision: oracle .md files start with a YAML-comment header block (`# oracle_authored_by: <handle>`, `# oracle_review_method: from-source`, etc.). The locked heading-preservation regex `^(#{1,6})\s+(.*)$` will match each of these ~6 lines as a markdown H1 heading in `expected_md`, but `actual_md` from `html_to_markdown()` won't contain them. Result: every oracle gains ~6 false H1 headings, the Jaccard set diverges from actual on all 20 fixtures, and dim-1 scores are systematically depressed below the 0.90 floor. Either strip the header block before invoking heading_scorer, or replace `# key: value` with HTML comments `<!-- key: value -->` (which the heading regex won't match). Neither remediation appears in v5.
- [P1] Sibling import + package init conflict: Files-to-Change creates `scripts/data/llm-wiki/tests/markdown_qa/__init__.py` (line 337) AND the conftest pseudocode does `from fixtures_sampling import check_floor_occupancy` (line 193) — a bare-name import. With `__init__.py` present, pytest's default `importmode=prepend` adds the package parent (`scripts/data/llm-wiki/tests/`) to `sys.path`, NOT `markdown_qa/` itself. The bare import resolves only if `markdown_qa/` happens to also be on sys.path, which it isn't by default. Result: conftest.py fails to load, `pytest_sessionfinish` never registers, and the floor-occupancy gate silently never fires. Fix: either drop `__init__.py` (rely on rootdir-based path injection) OR change to `from markdown_qa.fixtures_sampling import ...` / `from .fixtures_sampling import ...`. The same hazard reproduces when conftest.py is `shutil.copy()`d into `tmp_path` for the regression test — Risks bullet acknowledges 'sibling imports work in any directory both files share' but that statement is only true without `__init__.py`.
- [P2] No drift test between manifest timestamps and oracle .md YAML-header timestamps: `oracle_authored_at` and `oracle_reviewed_at` live BOTH in `sample-manifest.yaml` AND in each `.md` file's header block. Test #8 reads only manifest fields; nothing asserts they equal the corresponding lines in the .md file. Drift between the two surfaces would not be caught.
- [P2] Solo-contributor 24h-delay is honor-system: `oracle_authored_at` and `oracle_reviewed_at` are author-supplied manifest fields. Test #8 (v5) compares them but does not anchor either to an external clock (e.g., commit timestamp, signed timestamp, CI-recorded fetched_at). An author can satisfy the gate by setting both fields ≥24h apart while authoring the fixture in one sitting. The blinding tightening in v5 reduces the converter-leak risk but doesn't address timestamp-fabrication risk.
- [P2] Regression-test stderr capture under pytest subprocess: the v5 rewrite asserts `b"FLOOR-OCCUPANCY VIOLATIONS" in result.stderr`. `pytest_sessionfinish` runs after pytest's per-test capture is torn down, so the `print(..., file=sys.stderr)` should land in real stderr — but pytest still routes child-process stderr through its own machinery in some configurations. The subprocess invocation does not pass `-s` / `--capture=no`. Recommend adding `-s` to the subprocess args to make the assertion robust across pytest versions.
- [P3] Hard-tier encoding_stress feasibility unverified: validator requires `>=2` Hard entries with `encoding_stress: true` (formula-heavy pages with UTF-8 Greek/degree/math). Plan does not enumerate which Orcina topics qualify, so the manifest-author will be picking these from the 717-corpus blind. If <2 candidates exist within the Hard quota, fixture authoring stalls.
- [P3] `empty_safe_ratio` naming vs dim-6 mismatch: dim 6 (list nesting) does NOT call the helper because its formula is `1 - tree_edit_distance / max(size)`. Plan documents 'same both-empty semantics' applied inline. Helper name implies universal applicability; a future contributor may try to retrofit dim 6 to use it and break the formula. Consider renaming the helper or adding an inline docstring note in dim 6.
- [P3] `pytest --collect-only` exit-code semantics not pinned: AC commands chain `... | grep -c '::'` and rely on grep's exit code being 0 (matches found) for the `==` assertion. If pytest collection itself errors (exit non-zero, partial stdout), the grep may report a misleading count. Pipefail isn't set in the AC commands. Recommend `set -o pipefail` documentation or splitting into a two-step assertion (collect succeeds, count matches).

### Suggestions
- Replace YAML-comment headers in oracle .md files with HTML comments (`<!-- oracle_authored_by: <handle> -->`) — these are markdown-legal, invisible when rendered, and cannot collide with the heading regex.
- Decide explicitly whether `markdown_qa/` is a Python package: drop `__init__.py` if you want bare sibling imports, OR keep `__init__.py` and use relative imports (`from .fixtures_sampling import ...`) in conftest.py. Add an AC that the chosen pattern works under `pytest --collect-only` AND under the regression test's `subprocess.run` against `tmp_path`.
- Add a new structural test (#14) that for each manifest entry opens the `.md` file, parses the `# oracle_authored_at: ...` and `# oracle_reviewed_at: ...` lines, and asserts equality with the manifest values. Catches drift in either direction.
- Add `-s` (or `--capture=no`) to the subprocess pytest args in `test_session_hook_fails_run_on_injected_violation` to make the stderr-substring assertion immune to pytest capture changes across versions.
- Before locking the manifest, run a one-off scan of the 717-topic corpus for pages containing `\xb0` (degree), Greek letters, or math operators in their HTML; document at least 4 candidate slugs in the plan so fixture-authoring isn't blocked by corpus-availability discovery.
- Add an explicit positive scoping check: a test under `scripts/data/llm-wiki/tests/` (NOT under `markdown_qa/`) that opens a TCP socket and asserts it succeeds. This proves the `_disable_network` fixture is actually subdirectory-scoped, not just intended to be.
- Document an estimated person-days budget for authoring 20 hand-blinded fixtures with HTML+live-rendering review (T3 implies multi-day; explicit budget helps reviewers calibrate).
- Consider using `pyyaml` to parse a fenced YAML frontmatter block at the top of each oracle .md (e.g., `---\n...\n---`) rather than line-prefixed `# ` headers — frontmatter is a well-known markdown convention that many parsers ignore by default and that won't collide with heading syntax.
