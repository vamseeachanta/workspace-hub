2. The review gate is not satisfied. `Acceptance Criteria` says “Adversarial review (Claude + Codex + Gemini) is invoked on this plan before user approval,” but `Adversarial Review Summary` says “Gemini rerun unavailable/pending,” and `scripts/review/results/2026-05-02-plan-2541-claude.md` is `UNAVAILABLE (claude CLI failed, rc=124)`. Treating “invoked” as sufficient allows approval with no usable Claude signal and no fresh Gemini signal.

3. The tranche contradicts the canonicalization rule. `Scope` says “pick `.pdf` over `.doc`/`.docx` for content extraction,” but `.planning/intel/elements-overnight-wave/sesa-first-tranche.tsv` includes both `GSM-AO-L-MCA-10025-0000-A.docx` and `GSM-AO-L-MCA-10025-0000-A Free Span Calculation MKII.pdf` as extraction rows. The planned `test_canonical_path_picks_pdf_over_doc` would reject the DOCX, so the selected tranche and the stated canonicalization contract disagree.

4. The TSV cannot encode the row-level clearance the plan requires. The `Adversarial Review Resolution Addendum` requires allowed extraction level per row, and vendor/TBE material defaults to metadata-only unless row-level clearance explicitly allows it. But `Acceptance Criteria` fixes the TSV schema to 9 columns: `priority, theme, content_kind, bytes, absolute_path, rationale, extraction_method, target_wiki_page, risk_note`. There is no `clearance_level`, `owner_approval_ref`, or `allowed_content_classes` field.

5. Vendor/TBE rows are still operationally marked for body extraction. `.planning/intel/elements-overnight-wave/sesa-first-tranche.tsv` gives PIETRO and RMT vendor brochures `extraction_method=pdftotext-layout`, while the plan addendum says vendor/TBE rows are excluded from tranche-1 extraction unless row-level clearance explicitly allows them. Without a metadata-only extraction method or clearance field, an executor can follow the TSV and run text extraction against vendor brochures contrary to the default policy.

6. The pseudocode still omits the clearance gate before source-body access. `Pseudocode` starts with `rows = read_tsv`, `canonical_paths = canonicalize(rows)`, then enters parser branches for `pdftotext-layout`, `pandoc-to-markdown`, and `python-pptx-text`. The clearance check appears only later in prose/addendum. This is risky because the same section is explicitly presented so reviewers can “validate the approach.”
