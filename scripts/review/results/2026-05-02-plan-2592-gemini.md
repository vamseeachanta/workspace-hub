### Verdict: MAJOR

### Summary
The plan has logical flaws regarding file counting and test path resolution that will cause CI failures. The manual override of `page_count` to include uncatalogued files will conflict with the automated index regenerator. Additionally, an undocumented frontmatter field is proposed without a corresponding schema update.

### Issues Found
- Test failure risk: Pytest executes from the repository root, but the pseudo-code for `test_index_page_count_matches_on_disk` uses a relative glob pattern `glob('wiki/**/*.md')`. This will resolve to 0 files and fail. It must use `knowledge/wikis/maritime-law/wiki/**/*.md`.
- Regenerator conflict: The plan forces `page_count == 32` by suddenly including `index.md` and `overview.md`, which the plan explicitly notes are currently uncatalogued (20 catalogued out of 22 on disk). Adding 10 new catalogued pages should yield a `page_count` of 30. Setting it to 32 manually will cause the automated index regenerator to fail or revert the count back to 30.
- Schema validation failure: The plan dictates that `ism-code.md` must explicitly state `embedded_in: solas-1974` in its frontmatter, but the `embedded_in` key is not defined in the `CLAUDE.md` schema, nor is there a precondition to add it under the default routing option.

### Suggestions
- Update the glob path in `test_index_page_count_matches_on_disk` to use the repository-relative path: `knowledge/wikis/maritime-law/wiki/**/*.md`.
- Change the target `page_count` to 30 to remain consistent with the existing cataloguing logic that correctly excludes index/overview files.
- Either add the `embedded_in` field to the `CLAUDE.md` schema update as part of the default routing steps, or drop the custom key and simply use the standard `see_also` array to link ISM Code to SOLAS 1974.
- Remove conditional logic (e.g., 'skipped under default') from the test plan; the test suite should deterministically reflect the chosen (default) routing option.

### Questions for Author
- Will the automated wiki regenerator break if it detects undocumented frontmatter keys like `embedded_in`?
- Does the index regenerator script need to be updated to catalogue `index.md` and `overview.md` if we are forcing the count to 32?
