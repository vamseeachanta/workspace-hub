# Plan review artifact — 2817v3 codex — 2026-05-30 (dispatched via submit-to-{codex,gemini}.sh)

### Verdict: MAJOR

### Summary
The plan is directionally right, and the referenced #2798 helper/workflows do exist on origin/main, but the proposed design still has fail-open and bypassable authority gaps. Do not approve as written.

### Issues Found
- MAJOR: `docs/plans/2026-05-30-issue-2817-plan-approval-label-authority.md:72` plus `:75`, `:92`, `:95`, `:96`, `:141`, `:150` create a window where neither authority enforces. The new gate is explicitly disabled behind `PLAN_APPROVAL_GATE_ENABLED` until ruleset/owners are confirmed, while the same plan demotes `require-plan-approval.sh` to advisory and retires marker parity. Concrete failure: merge the implementation with the flag unset or false; local hooks warn only, `require-plan-approval.sh` exits 0, marker parity is gone, and the server-side label authority is skipped.
- MAJOR: `docs/plans/2026-05-30-issue-2817-plan-approval-label-authority.md:68`, `:80`, `:117`, `:118`, `:119`, `:136`, `:152` define freshness against `pr_head_time` without specifying a non-forgeable timestamp. If implementation uses git commit author/committer time, an agent can force-push a malicious head commit with `GIT_COMMITTER_DATE` before the label application time; `label_at >= pr_head_time` passes after `synchronize` without re-approval. Freshness must anchor to GitHub-observed head SHA transition time / PR event time, not commit metadata.
- MAJOR: `docs/plans/2026-05-30-issue-2817-plan-approval-label-authority.md:62`, `:79`, `:120`, `:135` do not actually close anti-substitution. The resolver trusts PR body and commit trailers, which are PR-author-controlled. Concrete failure: branch `feat/misc-cleanup` changes unrelated code, PR body says `Refs #2817`, and the attacker gets or already has a fresh label on #2817. The gate has no non-forgeable proof that this PR implements the approved plan artifact, only that some referenced issue is approved.
- MAJOR: `docs/plans/2026-05-30-issue-2817-plan-approval-label-authority.md:54`, `:81`, `:111`, `:112`, `:124`, `:137` overclaims PAT/machine-user rejection. GitHub timeline actors for PAT-backed actions and machine users can be ordinary `type: User`; the event does not expose whether a human clicked or a PAT automated it. Concrete failure: `PLAN_APPROVAL_OWNERS` includes a machine-user login that resolves as `User`; its PAT applies `status:plan-approved`; `actor in owners` passes. The plan needs to narrow the claim or add an enforceable external control.
- MAJOR: `docs/plans/2026-05-30-issue-2817-plan-approval-label-authority.md:42`, `:59`, `:141` says the PR-to-main server gate is the authority, but the acceptance criteria only require documenting a label-restriction ruleset, not verifying that the `Plan Approval Check` status is required by branch protection/ruleset. Concrete failure: the check fails closed but is not a required status check, so a maintainer or auto-merge path can merge despite the red job.
- MINOR: `docs/plans/2026-05-30-issue-2817-plan-approval-label-authority.md:54`, `:57`, `:90`, `:126`, `:151` claims the #2798 refactor is behavior-preserving, but the proposed shared helper defaults to `allow_bots=False` while the current completeness decision only checks membership in `authorized_appliers` (`scripts/workflow/completeness_gate_check.py:90`). Concrete regression: if `COMPLETENESS_OWNERS` currently contains a service/machine account, completeness closes start failing after a nominally non-regressive refactor.

### Suggestions
- Keep the existing CI hard gate active until `PLAN_APPROVAL_GATE_ENABLED=1` is verified in CI, or make disabled config fail closed for implementation PRs rather than skip.
- Define `pr_head_time` as a GitHub-observed transition timestamp tied to the exact head SHA, and test force-push with forged commit dates.
- Require a non-forgeable binding: issue number from branch naming or GitHub linked issue metadata plus plan artifact path/revision recorded in the issue by an authorized actor, not PR body/trailers alone.
- Replace PAT/machine-user rejection claims with enforceable controls: strict human owner allowlist, protected label ruleset, audit logging, and no machine users in owners.
- Add acceptance criteria and tests that verify the Plan Approval Check is a required status check before retiring marker-based enforcement.
