1. **[BLOCKER] The cited T3 cross-review was never produced — all three provider artifacts are empty/errored.** Plan header (line 9) and Artifact Map (lines 215-217) list `scripts/review/results/2026-06-08-plan-2975-{claude,codex,gemini}.md` as review artifacts. The "Adversarial Review Summary" table (lines 355-362) presents a MAJOR→APPROVE progression attributed to subagent personas ("Arendt, Feynman, Halley, Archimedes, Kant") that are **not** the cited provider artifacts and are not independently verifiable. T3 requires 3-provider review (Claude+Codex+Gemini per AGENTS.md); zero produced output. The plan is honest at line 353 ("Formal provider artifacts may still be regenerated"), but the header and summary overstate review completion. This review fills the Claude slot; Codex and Gemini must be re-run (or documented UNAVAILABLE per `scripts/review/results/` convention) before `status:plan-review`.

2. **[BLOCKER] Enum source-of-truth is placed under `tests/fixtures/`, deviating from established config-loading precedent.** Plan line 91 + AC line 329 + Risk line 385 make `tests/fixtures/ecosystem_wiki_flywheel/source-classification.yaml` the authoritative enum config consumed by the production validator `scripts/enforcement/check-ecosystem-wiki-flywheel.py`. The analogous existing validator `check-wiki-sibling-frontmatter.py:89-101` loads its registry from `config/`/`.workspace-hub/`/env var — never from `tests/`. `grep tests/fixtures scripts/enforcement/*.py` returns zero hits: there is **no precedent** for enforcement code sourcing authority from a fixtures directory. This is fragile for the explicitly-deferred hook/CI promotion (line 214, 344): a pre-commit/CI gate depending on a `tests/fixtures/` path is surprising, may be absent under sparse checkout, and signals "disposable test data" to maintainers. Recommend the canonical enum live in `config/` (or a `docs/standards/` companion data file) with fixtures referencing it — not the reverse.

3. **[MINOR] Dual-sourced enums with no reconciliation test → drift risk.** AC line 329 and Risk line 385 state the enums live in BOTH the standard doc AND the YAML fixture, "with the YAML fixture as the validator source of truth." The TDD list (lines 293-322) has `test_enum_fixture_is_source_of_truth` but **no test asserting the standard doc's enum tables match the YAML**. Two hand-maintained copies of the same enum set will drift. Add a reconciliation test or generate one from the other.

4. **[MINOR] Codex review failure root cause is a pre-existing broken SKILL.md — generalizable.** `codex.md.err` shows: `failed to load skill .../flywheel-closeout/SKILL.md: invalid YAML: mapping values are not allowed in this context at line 2 column 132`. `SKILL.md:2` has an unquoted colon inside the `description:` value ("...durable assets: skills, scripts..."), which YAML parses as a nested mapping. This silently broke Codex review dispatch for this plan (and will break it for every future codex review run in this tree until fixed). Per the "promote generalizable review findings" rule: fix the frontmatter (quote the description) and consider a Level-2 check that SKILL.md frontmatter is valid YAML. Not #2975's scope, but it is why the cross-review failed and should be filed/fixed.

5. **[MINOR] Legal-scan AC does not prove the intentionally-dirty fixtures survive the scan.** AC line 347 requires `scripts/legal/legal-sanity-scan.sh` to pass. The plan deliberately seeds `invalid-ledger-leak/` and `invalid-mixed-provenance/` fixtures with "client/project identifiers, private repo URLs, local absolute paths, raw source snippets, ... private source titles" (lines 102, 211, 302, 339). `check-no-abs-paths.sh` auto-excludes `tests/fixtures/` (safe), but `legal-sanity-scan.sh` has no such blanket exclusion — it relies on `.legal-deny-list.yaml` exclude_paths. The plan covers self-blocking for its OWN validator (`test_self_artifacts_are_validator_safe`, `test_invalid_fixtures_are_sentinel_scoped`) but does not state that the dirty fixtures must use **synthetic, non-deny-listed** identifiers (current block patterns are specific real client names: "Prelude FLNG", "West Boreas", "Perdido"). Add an explicit constraint: invalid fixtures use fabricated identifiers only, OR add `tests/fixtures/ecosystem_wiki_flywheel/` to the legal-scan exclude_paths with a documented rationale.

6. **[MINOR] Determinism test vs. timestamped attestation may be contradictory.** `test_validator_json_output_is_deterministic` (line 322) requires "byte-identical JSON" across two runs of the same fixture, while the flywheel legal-scan attestation (lines 250, 336) and freshness checks (`last_checked_at`, line 312) involve timestamps/hashes. If the validator echoes any wall-clock time or run-time-derived value into its JSON output, the determinism test fails. The hedge makes this non-false, but the new standard will have no index to be linked from — decide whether to create the index or link from `docs/plans/README.md` only.
