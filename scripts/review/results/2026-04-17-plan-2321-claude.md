## Retrieval adequacy
insufficient — plan does not verify where plugin-installed skills actually live on disk. `.claude/skills/_archive/` is proposed as archive target but plan skills are often installed by the plugin manager outside this directory. No inspection of actual plugin install paths was done before writing.

## Findings
- **Correctness — fundamental mechanism may not work for plugin-owned skills.** The plan's archival step is `git mv .claude/skills/<family>/<sibling>/ .claude/skills/_archive/...`. If `gsd:*`, `sparc:*`, `workflows:*`, `agents:*` skills are installed via the Claude Code plugin system (which the session history suggests — user ran `/plugin` and "✓ Installed github"), their canonical location is plugin-managed, not under repo `.claude/skills/`. Moving via `git mv` either (a) does nothing if the skills aren't in the repo tree, or (b) breaks the plugin install if they are. The plan has not verified which.
- **Correctness — plugin config location is "TBD".** `Files to Change` row 1 says "plugin config (tbd — one of `.claude/settings.json` / `settings.local.json` / `~/.claude/settings.json`)". A plan that can't state which file to edit is not ready to implement. Step-1 discovery is required before the plan is approvable.
- **Correctness — `regression_plugin_health` requires a fresh Claude Code session.** This is a manual human step. `Acceptance Criteria` row 5 ("Fresh session `/plugin` shows no failed reconnects") cannot be verified programmatically. Implementation would land and claim completion despite not being tested.
- **Scope — "≥5 canonical-vs-archive decisions" is a gameable floor.** Plan lists candidate clusters only in Open Questions, not as committed deliverables. Five trivial archives (e.g., archiving already-unused skills) satisfy the criterion without meaningful consolidation.
- **Scope — no dependency on #2320 invocation data explicitly declared.** Plan's `Risks` mentions #2320 data would strengthen decisions, but the plan does not gate its decisions on that data — so archive decisions will be made blind, on reference-graph heuristics only.
- **Scope — no rollback plan.** If archiving `sparc:orchestrator` breaks an active workflow, there is no stated recovery procedure beyond "revert commit" (implicit).
- **Scope — missing discovery step.** Before any decisions, the plan should list actual skill paths per family (e.g., `gsd:plan-phase` → where is it physically located?). This is a prerequisite that Resource Intelligence did not fulfill.
- **Scope — `_archive` README stub pattern not defined.** Plan says "archive READMEs … forward-pointer to canonical" but doesn't give the README content template, so implementations could vary.
