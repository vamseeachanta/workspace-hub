## Findings

1. **`five_hour_pct: null` (present-but-null) is not explicitly covered by the missing-branch handling.** Pseudocode line 273 says `codex_five_hour_remaining()` will "tolerate cache files that **lack** five_hour_pct by returning missing." But `scripts/ai/assessment/lib/providers.sh:169` emits an explicit `five_hour_pct:null` in at least one code path. `100 - null` in jq yields `null`/error, not the intended `missing`. The plan handles the *absent-key* spelling but not the *explicit-null* spelling. The TDD list (`codex_shows_weekly_reset_and_5h_remaining`, `codex_fresh_cache_wins_for_5h_window`) uses present values, and the "safe-missing branch" test (plan line 22) is described as "missing `five_hour_pct`" — ambiguous as to which spelling. Fix: have the helper treat both `null` and absent as `missing` (e.g. `(.five_hour_pct // empty)` or an explicit `type=="number"` guard), and pin a `five_hour_pct:null` fixture test.

2. **Inverted polarity across two repo-owned surfaces is a documented-but-unreconciled footgun.** After this change, `.claude/statusline-command.sh` renders `5h<100−x>%` (*remaining*) while `scripts/ai/assessment/lib/display.sh:84` prints `5h: <x>%` (*used*) for the identical `five_hour_pct` field. The plan scopes display.sh out and only documents the divergence in the contract doc (pseudocode line 370). That is a defensible scope cut, but two workspace-owned surfaces showing the same number with opposite meaning is a real future-reader trap. Recommend the contract doc call this out *prominently* (not just a passing clause) and file a follow-on issue to align `display.sh` polarity — otherwise the next person "fixes" one to match the other and silently inverts a live readout.

3. **The dirty-guard requires the new test files to be committed before the helper can ever report COMPLETE — sequencing note, not a defect.** The measured-path set (pseudocode lines 300-319) includes the directory `tests/statusline/` plus the new `.md`/`.html` plan artifacts (currently untracked per `git status`: `?? ...2893...md`, `?? ...2893...html`). `git status --porcelain --untracked-files=all -- tests/statusline/` will flag any newly-created-but-uncommitted bats file as dirty → `MISSING-EVIDENCE`/refuse-COMPLETE. This is the intended anti-self-report behavior, but the implementer must commit the new tests *and* the plan docs before the helper passes locally. Worth stating explicitly in the build sequence so the first helper run isn't mistaken for a bug.

4. **`git ls-files --error-unmatch tests/statusline/` on a directory pathspec is order-dependent.** Pseudocode line 302 verifies tracked-ness via `git ls-files --error-unmatch` on "paths that should be tracked." For the directory entry `tests/statusline/`, this succeeds only if ≥1 tracked file exists under it (true post-implementation) but says nothing about whether the *specific new* test files are tracked — those are caught only by the porcelain pass in Finding 3. The two checks together are sufficient, but the plan should not imply `--error-unmatch` on the directory validates the individual new files; it validates the directory has *some* tracked member.

5. **No independent verification that `pct_remaining`/`five_hour_pct` polarity assumption survives the `source=estimated`/`history.jsonl-estimate` paths.** The plan correctly extends the estimate classifier to exact `source=estimated` (patched per r13).
