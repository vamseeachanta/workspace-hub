### Verdict: APPROVE

### Summary
Comprehensive T2 plan for unblocking three runtime-layer CI failure clusters in worldenergydata after the #2433 collection fix. The plan is evidence-heavy (6 sources, embedded live-pytest reproduction, file-existence attestation, pyproject / CI inspection), treats every cluster as explicitly conditional with rejected-path reasoning, and addresses prior cross-provider review concerns on governance (tracker-with-fallback) and Cluster A branch-selection evidence (full logs + temporary diagnostic run). Scope is tightly bounded to the three clusters, `lint` is deferred to #2452, and README indexing is deliberately deferred per branch-contention guard.

### Issues Found
- [P3] Minor: Step V3d uses `git diff -- .github/workflows/ci.yml` without qualifying the worldenergydata worktree path. Since the plan is authored in workspace-hub but the CI file lives in a separate repo clone, the command should pin the worldenergydata working directory to avoid running the diff in the wrong repo when executing from the default shell.
- [P3] Minor: The plan's own acceptance criterion requires adversarial review across ≥2 providers to return APPROVE or MINOR, and Codex is currently MAJOR in Wave 10. The plan's revisions target the remaining Codex objections, but the plan is still `draft` pending the next rerun — this dependency is acknowledged in the document but worth re-confirming before applying `status:plan-review`.
- [P3] Minor: Cluster C default (C-skip) relies on a time-boxed grep at Step 0d to decide if C-repoint is even selectable. If that grep is executed on a stale checkout (e.g., before `git fetch`/rebase onto worldenergydata main), the executor could prematurely conclude C-repoint is blocked. A single line reminding the executor to refresh the worldenergydata branch before Step 0d would make this less brittle.
- [P3] Minor: `pytest.importorskip('pytest_benchmark')` in A2 only triggers when the module cannot be imported. If A2 is ever invoked for a reason other than proven package absence (which the plan forbids), the skip will not engage and tests will still error. The plan correctly forbids this, but a defensive assertion or pytest marker expression would make the misuse failure-loud rather than silent.

### Suggestions
- Add a regression check to Cluster B acceptance: after promoting `config_with_economics` to conftest, confirm that currently-passing `TestCashFlowComponents` tests still pass with identical numeric outputs (e.g., diff of revenue/NPV assertion values before vs after), not just that they run. Fixture promotion can silently change scope semantics if class-scoped state was being relied on.
- Given the observed namespace drift (`worldenergydata.modules.bsee.*` in tests vs `worldenergydata.bsee.*` in src), consider scheduling a follow-up audit issue to grep the entire `tests/` tree for `worldenergydata.modules.` imports — the three clusters in #2451 may not be the only stragglers, and catching them all now is cheaper than re-opening post-#2451.
- For Cluster A0b's temporary diagnostic CI run, specify exactly what to print (e.g., `python -c 'import pytest_benchmark; print(pytest_benchmark.__file__)'`, `uv pip list | grep benchmark`, `pytest --trace-config | grep benchmark`) so the diagnostic is reproducible and reviewable in the CI log rather than depending on executor judgment.
- Record the final selected Cluster A path (A1a / A1b / A2) plus the evidence that drove the choice in the PR description, not only in execution notes. This makes the workflow edit (or lack thereof) auditable to future reviewers without needing to chase .planning artifacts.
- Add a pre-flight check to Step -2 that verifies the worldenergydata worktree is clean and on the expected base SHA before running any RED commands; a dirty or diverged worktree could contaminate the RED baseline and invalidate the GREEN comparison.
