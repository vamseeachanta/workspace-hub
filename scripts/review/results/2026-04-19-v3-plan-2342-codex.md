## New v3 findings

1. **[MAJOR] `head-common` does not provide nav** — Plan sections `Resource Intelligence Summary`, `Pseudocode B`, `Acceptance Criteria` claim adding `partials/head-common.html` yields "GA + nav present". `content/partials/head-common.html` has no nav markup (only favicon/CSS/navbar-toggle JS/GA). The gallery's nav comes from a separate `<include src="partials/nav.html">` at line 249. Four new detail pages will render without a nav bar — GTM campaign users can't navigate back to the site. **Remediation:** add `<include src="partials/nav.html">` and `<include src="partials/footer.html">` to the page template.

2. **[MAJOR] "Fails CI" is overclaim** — Plan `Deliverable` says pages are "guarded by a Jest link-check that fails CI if any gallery anchor 404s", but `aceengineer-website/.github/workflows/` is empty and `Files to Change` adds no workflow. This is local-test wiring, not CI. **Remediation:** either add a real GitHub Actions workflow in the website repo, or rewrite the deliverable/AC language to say "fails local `npm test`".

3. **[MAJOR] Plotly integrity check measures the wrong thing and wrong algorithm** — Plan uses `npm view plotly.js-dist-min@2.32.0 dist.shasum` as the concrete integrity check. That probes the npm package tarball hash (SHA1, 40 hex), not the downloaded `plotly-2.32.0.min.js` browser asset, and the plan text simultaneously calls the result a "SHA256". **Remediation:** hash the committed file itself with `sha256sum` after download; store that in commit metadata; vendor the upstream BSD-3 license alongside the bundle.

4. **[MEDIUM] `RUNS demo-links` grep is optimistic** — Jest outputs `PASS demo-links` or `FAIL demo-links`, not `RUNS`. `Pseudocode G` and `TDD Test List` hardcode the wrong string. **Remediation:** verify config structurally (`package.json` contains the project stanza) and/or run `npx jest --selectProjects demo-links` rather than scraping human output.

5. **[MEDIUM] Internal contradiction on post-deploy Plotly expectation** — `TDD Test List` post-deploy row `prod_plotly_loads_locally` requires `5/5 match`, while `Pseudocode B`, pre-deploy `jumper_has_no_plotly_tag`, and `Acceptance Criteria` explicitly exclude Plotly from jumper. v3 still contains mutually inconsistent expected outcomes. **Remediation:** change post-deploy to `4/4 match` on chart pages only; add a separate assertion that jumper has no Plotly reference.

6. **[MEDIUM] `testEnvironment: node` unsafe for DOM parsing** — `Pseudocode G` registers `demo-links` with `testEnvironment: node` but describes the test as "parse `dist/demos/index.html`". If implemented with DOM selectors (cheerio, querySelector), that will fail in Node; if implemented with regex, the plan should say so. **Remediation:** either pin `jsdom` for this project or explicitly specify a regex/string-scanning strategy.
