### codex

- The plan changes the issue’s active-skill semantics without justification. Issue `#2488` defines active counts as excluding `_archive` and `_archived` only, but `Pseudocode -> build_skill_inventory_with_git active_filter(path)` and the matching acceptance criterion explicitly exclude `_diverged` too. That is not a neutral implementation detail: it changes the authoritative counts and can suppress live filesystem-only skills under `_diverged` even though the issue body never scoped them out.
- The plan treats an active untracked file as “resolved” without actually eliminating the loss risk. In `validate_and_render_dispositions_for_manual_reconcile()` the terminal-state rule for `ignore_generated_transient` says it is resolved while the file “remains active filesystem-only on disk,” and the acceptance criteria require `unresolved_filesystem_only_active = 0` while also allowing `risk_status=accepted` for those still-untracked active files. Issue `#2488` is specifically about reconciling active filesystem-only skills “before loss”; relabeling an active untracked file as accepted does not protect it from checkout cleanup or rebuild loss.
- The baseline-order guard overfits the implementation to a specific commit-history shape instead of a correctness property. `implementation_flow()` requires `tests/fixtures/skills/issue-2488-archived-duplicate-baseline.json` to land in a strict predecessor commit before any audit/policy edit, and `scripts/skills/verify_issue_2488_baseline_order.{py,sh}` then block closeout if the commit order is not exactly that. The workspace `AGENTS.md` says `Git: commit to main + push; branch only for multi-session work`; this plan adds a hard dependency on multi-commit ancestry engineering that is unrelated to runtime behavior and can block a valid single-session implementation on `main`.
- The manual trust gate is too broad: `manual CLI contract for scripts/skills/reconcile_filesystem_only_skills.py` hard-fails whenever `git config --bool core.sparseCheckout` is true, even though the same section already requires a path-specific `git ls-files -z -- <resolved skills_dir relative to repo_root>` check. A sparse checkout can still include the entire skills tree, so this rule rejects potentially authoritative inventories for no path-specific reason.
