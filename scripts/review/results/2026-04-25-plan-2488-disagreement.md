- The policy-schema part of the plan is internally inconsistent. In `Pseudocode -> run_weekly_audit_extension()`, the only renderer change specified is “refactor `_write_markdown_artifact()` to consume `ranking_policy.section_order`,” but the `TDD Test List` and `Acceptance Criteria` also require `weekly_summary_sections` to define and drive `filesystem_only_inventory`. As written, the plan either leaves `weekly_summary_sections` as dead metadata or is missing a required code change to make that schema authoritative.
- The plan makes correctness-critical ignore-rule claims without listing `.gitignore` in its verified sources. Because those ignore rules control whether promotion is safe and whether forced adds are required, this is an evidence gap in a core decision path, not a cosmetic omission.

The plan defines `classify_filesystem_only_skill(path)` and a separate “one-time #2488 disposition closeout” in `Pseudocode`, but `Files to Change` lists only the recurring cron-owned audit surfaces plus the final Markdown report. - The plan overstates scheduled-task doc drift. It says in `Documents consulted` and `Files to Change` that [docs/ops/scheduled-tasks.md](https://github.com/vamseeachanta/workspace-hub/blob/main/docs/ops/scheduled-tasks.md) “should update docs because recurring output semantics materially change,” but that file already has a `Skills Curation v2 Contract` section stating the task is local-only, writes JSON/Markdown artifacts, does not call `gh`, and does not mutate skills/state. The remaining delta appears to be only explicit mention of filesystem-only inventory, so the plan should narrow that claimed drift instead of treating the operator doc as broadly stale.
