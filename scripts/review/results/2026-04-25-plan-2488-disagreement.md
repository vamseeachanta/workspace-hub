### claude

- **`_diverged` active-loss semantics are asymmetric and undermotivated.** Plan §Pseudocode line 156 says `_archive` and `_archived` are excluded from active loss-risk counts but `_diverged` "remains included in #2488 active counts." Existing audit semantics treat `_diverged` like `_archive` — `EXCLUDED_DIRS = {"_archive", "_diverged"}` (verified at `scripts/skills/weekly_skills_audit.py:32`) and the existing test is named `test_excludes_archive_and_diverged` (`tests/skills/test_weekly_skills_audit.py:74`). The plan's only justification is "report legacy `_diverged` exclusion separately for compatibility metrics." If `_diverged` is conventionally archive-like, treating a future `_diverged` skill as active loss-risk will generate false positives. Either fold `_diverged` into the loss-risk exclusion alongside `_archive`/`_archived`, or document the convention reason `_diverged` differs.
- **The new manual-reconcile script's CLI contract is underspecified.** Files-to-Change line 229 creates `scripts/skills/reconcile_filesystem_only_skills.py`, and acceptance line 293 binds it to the exact invocation `scripts/skills/reconcile_filesystem_only_skills.py --disposition-report docs/reports/2026-04-25-skills-disposition-2488.md`. But §Pseudocode line 197 names only an internal function `validate_and_render_dispositions_for_manual_reconcile(disposition_yaml)` — never declaring `--disposition-report`, `--ledger`, default ledger path, or exit-code contract. Plan's own RED-before-GREEN flow (line 213) cannot write tests against an undeclared surface. Add an explicit CLI declaration to §Pseudocode or §Files-to-Change.
- **Sparse-checkout / partial-inventory detection signal is unspecified.** Acceptance line 297 requires sparse-checkout states to be "detected or warned," and §Pseudocode line 199 says "git errors, sparse checkout, or partial inventory are hard failures in manual reconcile but warning-only in weekly_report." Nowhere does the plan say HOW partial vs complete is distinguished — `git config --get core.sparseCheckout`? `git ls-files | wc -l` below a threshold? Without a defined signal, the corresponding test `test_sparse_checkout_or_partial_git_inventory_is_warned_not_trusted` (line 266) can only be exercised via a mocked adapter return value, which proves nothing about real behavior.
