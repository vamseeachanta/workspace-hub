### claude

- **`tests/cron/test_skills_curation.py` listed as `Modify` but does not exist at HEAD.** Plan §"Files to Change" line 226: `| Modify | tests/cron/test_skills_curation.py | Add/adjust wrapper dry-run coverage…|`. `ls tests/cron/` shows 18 files; none match. Action class is wrong — should be `Create`. Following the plan literally, an implementer who pattern-matches on action verb (e.g., `Edit` vs `Write`) will error or skip the wrapper-compatibility test.
- **Dual-walk requirement is implicit, not stated.** `scripts/skills/weekly_skills_audit.py:69-72` prunes `EXCLUDED_DIRS = {"_archive", "_diverged"}` via `dirs[:] = [d for d in dirs if d not in EXCLUDED_DIRS]` during `os.walk`, so `build_inventory` never *sees* `_archive`/`_diverged` files. The plan's new `inventory_summary.counts.filesystem_only_archived_total` (line 161) and the test `test_filesystem_only_archived_skills_do_not_escalate_active_loss_risk` (line 249) require a non-pruning walk. Plan pseudocode line 153 says `filesystem_skill_paths = all SKILL.md under skills_dir` but does not explicitly forbid reusing `build_inventory` for this purpose, nor mandate a separate walk routine. An implementer who reuses the pruning walk silently produces `filesystem_only_archived_total = 0` for any `_archive`-tree files. The TDD test fixture would catch this only if it includes `_archive` paths — which the test description does mandate, so this is recoverable but should be made explicit in the pseudocode.
- **Plan claims `signals.filesystem_only_active` will live in `config/skills/weekly-audit-policy.yaml`, but does not specify the schema shape.** Plan acceptance criterion line 276: `defines concrete signals.filesystem_only_active keys, and tests prove the weekly-audit parser consumes those keys`. Existing YAML uses `signals:` as nested arrays under classification entries (e.g., line 235: `signals: [same_canonical_name, same_primary_intent, substantial_overlap]`), not as a top-level keyed map. The plan does not specify whether `signals.filesystem_only_active` will be: (a) a severity/ranking dict, (b) a list of detection signals like the existing pattern, or (c) a thresholds/ratings entry. Three reviewers/implementers will pick three different shapes.
- **Cron wrapper line citation is off-by-3.** Plan §"File existence and excerpts" line 53 claims `scripts/cron/skills-curation.sh` "lines 51-55 print that command in dry-run mode". Actual dry-run block runs lines 51-58 (printf '\n' on 57, `exit 0` on 58). Doesn't change the truth value of the claim, but per the prompt's "evidence over opinion" rule, citations should be precise to the closing brace.
- **Acceptance criterion #2 mandates a `informational_namespace` JSON field but the TDD list contains no test verifying that field's shape.** Plan line 275 requires `paths are arrays of {path, informational_namespace} objects; _core/_internal paths remain active loss-risk but carry informational_namespace: true`. An implementer can satisfy that test with `{"path": "..."}` (no `informational_namespace` key) and the test will pass green — leaving the acceptance criterion silently violated.
