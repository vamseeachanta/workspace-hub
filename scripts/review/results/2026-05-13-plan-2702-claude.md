## Findings

### F1 — MINOR (load-bearing for D7 interpretation)

**Section affected:** *Resource Intelligence Summary → Gaps*, *Pseudocode → diff_and_decide*, *Acceptance Criteria → Anthropic-quota consumption check*

**Claim being challenged:** the test isolates "what Hermes consumes" by snapshotting Anthropic dashboard before/after a Hermes-driven `delegate_task` to the Claude Code hand.

**Why this is a defect:** Hermes' Anthropic API key is `✗ not set` (verified via `hermes status` in Step 1.5). The Claude Code hand therefore cannot route through the Anthropic Messages API; it spawns `claude` CLI as a subprocess, which uses the **user's** Claude OAuth and consumes the **same** Anthropic account budget that the human-driven main session uses. The dashboard counter does not distinguish Hermes-spawned vs human-driven activity on the same account.

**Implication:** any Δ_base / Δ_overage observed could be conflated with concurrent main-session activity. D7 reconciliation could be misled.

**Cited evidence:** plan Step 1.5 reproduction lines (`Anthropic    ✗ (not set)`); plan Gaps sub-section bullet 2 partially acknowledges this but the procedure does not enforce session isolation.

**Resolution applied in plan:** pseudocode `snapshot_pre` now requires "no other active Claude Code main session on this account"; GH findings comment template now has an "Isolation discipline" sub-section recording session state.

### F2 — MINOR

**Section affected:** *Pseudocode → AMBIGUOUS branch*, *Risks*

**Claim being challenged:** if a ~50-token call doesn't move the dashboard, a ~5000-token retry will.

**Why this is a defect:** Anthropic console.anthropic.com usage page granularity is not researched in the plan. If it is per-day, a 5000-token retry against an active day-bucket will likely also be lost in noise. The plan asserts the retry "will" register without evidence.

**Implication:** AMBIGUOUS branch could trigger on every attempt, leaving the audit perpetually inconclusive.

**Cited evidence:** plan Risk #1 (the load-bearing risk) does not name the dashboard granularity question.

**Resolution applied in plan:** acceptance criteria now bless three valid outcomes (CONFIRMED / REFUTED / INDETERMINATE-AT-CURRENT-DASHBOARD-RESOLUTION). The third is still a worthwhile finding — it tells the team that the current consumer dashboard is too coarse to support runtime D7 verification, which feeds back to #2665.

### F3 — MINOR (refinement)

**Section affected:** *Pseudocode → test_claude_code_hand*, *TDD Test List → check_claude_roundtrip*

**Claim being challenged:** the operator prompt "route this child to the OpenAI Codex provider explicitly" (or the Claude equivalent) actually causes Hermes to pick the requested provider for the child.

**Why this is a defect:** `delegate_task` exposes `override_provider` and `acp_command`/`acp_args` parameters (per `tools/delegate_tool.py:870-940`), but whether the **outer** Hermes session honors a natural-language steering request is unverified. Hermes may default to the parent's provider (`gpt-5.5` via `openai-codex`) regardless of prompt wording. If so, both children would route through Codex and we'd never actually exercise the Claude Code hand even though traces look successful.

**Implication:** silent verdict-flip defect class — see `feedback_silent_verdict_flip_defect_class`. Two children both routed to Codex would satisfy the surface "round-trip OK" check while quietly invalidating the D7 probe.

**Resolution applied in plan:** `check_claude_roundtrip` now requires the trace to show **claude transport, not the parent's default openai-codex provider**. The negation makes the check falsifiable.

### F4 — MINOR (refinement)

**Section affected:** *Files to Change* (implementation phase), *Acceptance Criteria*

**Claim being challenged:** the procedure produces trace artifacts that the GH findings comment can cite.

**Why this is a defect:** per `feedback_subagent_write_phantom`, a child process can report a successful write while the file doesn't land on disk. The pseudocode uses `tee` to a file but does not verify the file exists before treating the AC as met.

**Implication:** GH findings comment could cite a path that doesn't exist; reviewers can't verify the AC was actually satisfied.

**Resolution applied in plan:** acceptance-criteria sub-checks for every trace artifact now require `ls -la <path>` evidence cited in the GH comment, not bare paths.
