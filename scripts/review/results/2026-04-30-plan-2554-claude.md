`★ Insight ─────────────────────────────────────`
- Pattern worth promoting to a level-2 enforcement script (per `.claude/rules/patterns.md`): "review-artifact path-family + non-empty + canonical-provider" check. The current 0-byte/`.err` failure mode is exactly the kind of silent gate-bypass that a `scripts/enforcement/check-review-artifacts.sh` could fail-closed on, given a plan path.
- The `count_targets ≥ 20` over-permissive-grep finding generalizes: any AC that uses a structural regex (`^### Heading`) to verify a *semantic* property (`live countable`) inherits the gap. Either the regex must encode the semantics (e.g., exclude `(legacy)` / `Defer`), or the plan must add a second grep that bounds the legacy/Defer count.
- For research-artifact plans like this one, "the gate is itself an artifact" creates a chicken-and-egg risk that worked here (Hermes self-bootstrap). Future plans should require the live re-review artifact to be authored by a different runtime than the artifact under review — the "different-runtime" property is what makes adversarial review *adversarial*.
