**Missing tests**

- No test fencing the `config/agents/codex/state-snapshots/default.rules` file one way or the other.

**Weakest assumption and what breaks if it is false**
Assumption: `.planning/templates/stage-evidence-template.yaml` is still a live template consumed by something (generator, validator, or orchestrator). If it isn't — if it's a stub nobody reads — then editing it is cosmetic, the regression test protects a ghost, and the real fix is deletion or retirement. This would flip the plan from "patch template" to "decide template fate," a materially different scope.

**Most likely implementation failure mode**
The implementer picks a plausible-looking but fictional replacement path (e.g., `.planning/verified/<issue>/close.yaml`) for the Close/Archive `evidence:` slots; the new test passes because it only checks for absence of deleted scripts; reviewer approves; a month later another stale-reference sweep discovers the fabricated path and issues a duplicate cleanup.

**Most likely test gap**
Protection is defined by "files the plan happened to think of." A new file landed into `.planning/templates/` or `docs/modules/` next quarter will not be protected unless the targeted test uses a directory-glob rule plus an explicit allowlist for analytical fixtures — the plan proposes neither.
