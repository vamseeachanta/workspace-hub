## Findings

### MAJOR-but-non-blocking

1. **Cross-machine claude-version assumption not addressed.** The plan claims `--bare` "exists at claude 2.1.140" (verified locally on ace-linux-1). The fanout, however, is invoked across multiple machines (per `machine:multi` patterns elsewhere in the repo) where claude version may be older. With `claude --bare -p ...` on a pre-2.1.140 claude, the invocation will fail with "unknown flag" instead of producing a usable review — converting the current `SessionEnd` failure mode into a different `rc=2 unknown flag` failure mode.

   **Suggested resolution:** add a version precondition at the top of the `claude)` case branch. Either:
   - `if ! claude --help 2>&1 | grep -q -- '--bare'; then write_unavailable "$prov" "$rc" "claude installation lacks --bare flag — upgrade to ≥2.1.140"; return; fi`
   - OR document explicitly in the plan that "all fanout-running machines must have claude ≥ 2.1.140" and add a sibling enforcement check.

   Not a blocker for *this* machine today, but a structural follow-up before merging widely.

### MINOR

2. **Comment-block placement contradicts existing case-branch structure.** The plan proposes adding the explanatory comment block "above the `claude)` case", but the case branch already has a `# Path reference — no inline body.` comment INSIDE the branch (line 145). Standard bash convention is to extend the existing in-branch comment, not add new block-comments above the case label (which would visually associate with the previous branch, the `esac`, or whitespace).

   **Suggested resolution:** revise the plan to "Replace the existing `# Path reference — no inline body.` (line 145) with the longer block comment." Same outcome, cleaner integration.

3. **Acceptance criterion #1 doesn't verify the explanatory comment block landed.** The plan's only structural check is `grep -c 'claude --bare -p' scripts/review/plan-review-fanout.sh returns 1`. A future maintainer removing the explanatory comment block thinking it's noise leaves criterion #1 passing. Given the plan explicitly anticipates this risk ("so future maintainers do not 'clean up' the flag"), the criterion should defend against it.

   **Suggested resolution:** add criterion `grep -c '#2683' scripts/review/plan-review-fanout.sh returns ≥1` (a stable reference to this issue in the comment block).

4. **Test artifact path defers a decision that's actually determined.** Plan's Artifact Map says "scripts/review/tests/test-fanout-claude-bare.bats (or equivalent — verify what test harness the fanout already uses)". Verification: the existing test framework is shell (`scripts/review/tests/test_plan_review_fanout.sh`), not bats. The right surface is **extending the existing test file**, not creating a new `.bats` one.

   **Suggested resolution:** revise Artifact Map row to "Modify: `scripts/review/tests/test_plan_review_fanout.sh` — add regression test asserting `claude --bare -p` is present in the script."

5. **Risk discussion on CLAUDE.md auto-discovery is incomplete.** The plan acknowledges `--bare` disables CLAUDE.md auto-discovery and asserts the prompt is "fully self-contained". But the workspace-hub `CLAUDE.md` carries instruction context that may matter for review quality (planning-workflow conventions, repo-specific rules). The static `scripts/review/plan-review-prompt.md` is cited but not quoted in the plan to confirm it covers what CLAUDE.md does.

   **Suggested resolution:** either (a) quote a representative slice of `plan-review-prompt.md` to demonstrate self-containedness, OR (b) explicitly pass `--add-dir /mnt/local-analysis/workspace-hub` (per `claude --help`, `--add-dir` adds CLAUDE.md dirs back) as a belt-and-suspenders measure.

6. **Source count off-by-one in evidence block.** "Source count: 3 (issue body + plan-review-fanout.sh source + claude --help output + memory rule)" — that's 4 sources listed but the stated count is 3. Cosmetic; doesn't affect the validity of the count being ≥3.

But the related upstream follow-up ("Should the codex plugin's SessionEnd hook also be patched upstream? Yes — file an upstream issue against `openai/codex-plugin-cc`") is acknowledged as out-of-scope without a tracker.
