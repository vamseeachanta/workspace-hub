## Findings

1. **Plan front-matter and Artifact Map cite empty review files as authoritative r2 reviews.** Line 7 ("Review artifacts:") lists `scripts/review/results/2026-04-26-plan-2511-claude.md` and `…-codex.md`. Artifact Map rows at lines 130–131 repeat the same paths under "Plan review — Claude r2" and "Plan review — Codex r2". On disk both files are 0 bytes (`.err` sidecars confirm wrapper failure). The actual r2 content lives at `…-claude-r2.md` (8840 bytes) and `…-codex-r2.md` (3312 bytes), which the plan does **not** reference. An approver who follows the plan's own pointers reads zero bytes. This is the same defect Claude r3 already found at `scripts/review/results/2026-04-26-plan-2511-claude-r3.md`.

2. **Plan does not acknowledge that r3 review round occurred and produced MAJOR verdicts.** `grep -i "r3"` in the plan returns nothing. Adversarial Review Summary (lines 304–311) stops at r2 and reports "All r1 blockers resolved" (Claude r2 MINOR) plus retrieval-only Codex r2 MAJOR. But `scripts/review/results/2026-04-26-plan-2511-claude-r3.md` (11398 bytes, MAJOR) and `…-codex-r3.md` (3992 bytes, MAJOR) exist and were written against this plan revision. Plan line 313's "latest review CONDITIONAL" claim is therefore stale; the latest review is MAJOR/MAJOR.

3. **Plan status string at line 3 is stale.** "draft — r1 adversarial review MAJOR, revised for r2" omits the r3 round and its MAJOR verdicts.

4. **Standards-overclaim TDD spec is internally contradictory and underspecified.** TDD row at line 275 bans (case-insensitive) `bare affirmative certified` and `affirmative production signoff`, while plan line 159 (Scope), line 163 (Out of scope), line 296 (AC), and line 297 (AC) all require the report to use exactly the phrases `not production-certified` and `production signoff`. The plan whitelists only the specific strings `not production-certified` and `not for production signoff`, but the banned-token list also includes `JEDEC[- ]?compliant`, `IPC[- ]?compliant`, `validated to JEDEC`, `meets JESD22`, `per IPC` — and the plan does not enumerate corresponding negative-form whitelist entries (e.g., `not JEDEC-compliant`, `not validated to JEDEC`). A TDD author given this row must invent the regex strategy that distinguishes affirmative from negative across all banned tokens — that is design work, not test execution. This is the same class of defect Codex r3 cited.

5. **Plan's own gate ("commit/push reviews and plan before approval") is not currently met.** Line 313 requires "current review artifacts are committed/pushed and user explicitly approves" before posting for review. `git status` shows `M docs/plans/2026-04-27-issue-2511-...md` (plan modified, uncommitted) and r2/r3 review artifacts (`claude-r2.md`, `claude-r3.md`, `codex-r2.md`, `codex-r3.md`, `gemini.md`) are all `??` untracked. The gate cannot be claimed satisfied by the artifacts as they sit on disk now.

6. **Codex retrieval mitigation in plan line 310 is empirically falsified.** Plan asserts Codex r2's retrieval concern "is resolved by committing/pushing the plan before approval request." The plan was committed at `310904bc6`. The Codex round that ran after that commit (recorded at `scripts/review/results/2026-04-26-plan-2511-codex.md.err`) still failed with `bwrap: loopback: Failed RTM_NEWADDR`. Codex r3 only succeeded by switching to the GitHub connector. Committing the plan did not fix Codex's local-sandbox retrieval; it only moved the read off-disk. The plan should reflect this rather than claim the issue is resolved.

7. **Hermes preflight is prose-only and violates the project's enforcement-gradient rule.** Plan line 329 prescribes a manual `pgrep`/`git fetch`/`git status` sequence as risk mitigation. `.claude/rules/patterns.md` states: "When a prose rule can be expressed as exit 0/1, write a script. When it must fire on every commit, promote to a hook." Project memory `feedback_hermes_active_preflight_check.md` explicitly came from Hermes contention incidents that reverted parallel commits. The plan does not promote this control to a script (level 2) or an AC, and does not commit the worktree-isolation strategy to a verifiable artifact.

8. **TDD test row at line 273 has no falsifiable success criterion.** `test_summary_contains_sanity_checks_sources_manifest_and_solver_status` requires "numeric values in plausible ranges" for layer thermal resistance, ΔT estimate from heat flux, free thermal strain from CTE mismatch, and warpage-style estimate. Neither pseudocode (lines 213–216) nor the test row defines the ranges. AC line 287 requires "the initial focused test run fails for missing implementation/artifacts" (TDD red). A test with no committed numeric window cannot produce a deterministic red without the implementer authoring the range — that is design-time work hiding inside the test. Either pseudocode must commit to the analytical formulas and tolerances, or the TDD row must restate the falsifier (e.g., "non-empty key", "value > 0").
