2. **AC #7 "12 tests passing" contradicts the YAML-absent skip path.** Plan §Execution Contract (line 45): "if the YAML is not yet present, the integration test is skipped (`pytest.skip`), not failed." 3. **`test_provider_data_source_missing_field_raises` claims the wrong exception type.** TDD list line 514: "Missing required field raises ValueError ... ValueError containing 'vendor'". The pseudocode (lines 246–263) defines `ProviderDataSource` as a frozen dataclass with all required fields as positional arguments (no defaults). Calling `ProviderDataSource(vendor_slug=...)` omitting `vendor` raises `TypeError: __init__() missing 1 required positional argument: 'vendor'`, NOT `ValueError`. The `__post_init__` ValueError path triggers only when fields are present-but-empty-string. The test as specified would fail in either direction (TypeError raised when ValueError expected, or no exception when caller passes empty-string-fix). Spec the test as `pytest.raises((TypeError, ValueError))` and disambiguate which path is being exercised.

4. **AC #8 "no new failures" is unbaselined against a known-failing suite.** Plan line 540: `cd digitalmodel && uv run pytest -v` will pass with no new failures (no regression). Memory `feedback_qg_maxfail_undercounts` records that digitalmodel currently has 244+ failing tests (the "20 failed" QG output was a `--maxfail=20` ceiling). With no recorded baseline run, "no new failures" is unverifiable — any subset of pre-existing failures triggered by import-side-effects of the new `provider_data/` package would be falsely attributed. Plan needs an explicit baseline command (`pytest --co -q | tee baseline.txt && pytest 2>&1 | tee baseline-failures.txt`) and a delta-only assertion in AC.

5. **Unit conversions don't match the cited formulas.**
   - YAML line 412: `mwp_mpa: { value: 103.42, ..., note: "MWP converted: 15000 * 0.006895" }`. 15000 × 0.006895 = 103.425 (rounds to 103.43, not 103.42). The exact factor is 0.00689476; 15000 × 0.00689476 = 103.4214 → 103.42. The cited formula and the cited value are inconsistent; one must change.
   - YAML line 431: `subsea_package_weight_kg: { value: 109771.7, ..., note: "Converted: 242000 / 2.20462" }`. 242000 / 2.20462 = 109,769.96, not 109,771.7. Using the exact factor 0.45359237: 242000 × 0.45359237 = 109,769.35. Either the value is off by ~2.3 kg or the formula is wrong. Same for `subsea_package_weight_with_safety_head_kg` (280000 / 2.20462 = 127,005.92, plan says 127,006.4).
   These will fail any tight-equality test reviewers might add and they undermine the YAML's "factual values" license argument: factual values must be arithmetically defensible.

6. **`subsea_interface` mapping rationale conflicts with the YAML it cites.** OrcaFlex mapping table line 484: "the 18-3/4 in nominal size MAY inform `LineSectionProperties.outer_diameter` of the connector-stab section".
