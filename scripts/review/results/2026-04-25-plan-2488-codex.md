## Findings
1. `docs/plans/2026-04-25-issue-2488-reconcile-untracked-active-skill-files-before-loss.md` misstates the scheduler-test surface. The plan’s `Resource Intelligence Summary` and `Files to Change` only call out `tests/cron/test_skills_curation.py` for scheduler/wrapper regression, but the repo already has `tests/skills/test_weekly_skills_audit.py` `TestScheduleIntegration.test_validate_schedule_still_passes_with_skills_curation_task`, which is the existing automated guard for `config/scheduled-tasks/schedule-tasks.yaml`. Because the plan marks `config/scheduled-tasks/schedule-tasks.yaml` as “Maybe modify,” omitting that test path leaves a real regression surface unplanned.

2. The plan’s resolved-state model can hide active filesystem-only skills from the recurring weekly signal that issue `#2488` explicitly requires. The issue says future housekeeping must “report filesystem-only active skills explicitly,” but the plan’s `validate_and_render_dispositions_for_manual_reconcile()` says `ignore_generated_transient` is resolved when “a matching durable policy/ignore rationale exists,” and the acceptance criteria require `unresolved_filesystem_only_active = 0`. That allows an active untracked `SKILL.md` to remain on disk yet stop surfacing as a high-signal weekly finding once the ledger marks it resolved, which conflicts with the issue’s reporting contract.

3. The policy-extension design is still underspecified against the current implementation. The plan says to “Append a `filesystem_only_active` entry to the existing policy schema” and prove the parser “consumes those keys rather than hard-coding severity in Python,” but `scripts/skills/weekly_skills_audit.py` currently aggregates and renders only hard-coded families through `_all_active_findings()` and fixed Markdown sections in `_write_markdown_artifact()`. The plan does not specify the required refactor that would make `filesystem_only_active` a genuinely policy-driven family instead of another bespoke Python path, so the acceptance criterion is not implementable as written.
