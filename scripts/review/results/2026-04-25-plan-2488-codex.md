## Findings
1. The recurring JSON schema is internally contradictory. In `docs/plans/2026-04-25-issue-2488-reconcile-untracked-active-skill-files-before-loss.md` Pseudocode, `inventory_summary.paths` is defined as objects containing only `{path, informational_namespace, ledger_status}`, and the Acceptance Criteria repeats that exact object shape. A later Acceptance bullet then requires recurring weekly reports to emit `risk_status=accepted` for `accepted_ignored` entries. That adds a fourth field the earlier schema explicitly omits, so implementers and tests cannot tell whether `risk_status` belongs in recurring inventory objects or only in the one-time closeout report.

2. The plan contradicts itself about where `issue_body_drift_note` lives. In the same plan’s `build_skill_inventory_with_git` schema, it says “Issue-specific drift for the six #2488 paths is manual-closeout report content, not recurring weekly-audit schema.” Later, under `validate_and_render_dispositions_for_manual_reconcile`, it says `issue_body_drift_note lives on the ledger entry`, and the Acceptance Criteria requires `config/skills/filesystem-only-skill-dispositions.yaml` to contain `issue_body_drift_note when applicable`. Those are different source-of-truth decisions for the same field.

3. The baseline-proof requirement is mutually inconsistent. `implementation_flow()` says the `_archived` duplicate baseline fixture is “not branch-history enforcement,” but the Acceptance Criteria later requires it to be recorded “in a strict predecessor commit before audit/policy logic changes,” then later says the same behavior is “verified by tests rather than commit-history/branch-range enforcement.” `docs/plans/README.md` and the plan’s own implementation flow do not define any mechanism to enforce both at once. This leaves a correctness-critical gate impossible to satisfy unambiguously.

4. The plan’s core live-scope evidence is not independently reviewable from repository state. The Resource Intelligence Summary and “Live inventory proof” in `docs/plans/2026-04-25-issue-2488-reconcile-untracked-active-skill-files-before-loss.md` assert six active filesystem-only skills and 72 filesystem-only files based on a local shell snapshot, but those paths are absent from Git by definition, and repo search returned no tracked surfaces for the proposed reconciliation artifacts either. `docs/plans/_template-issue-plan.md` requires embedded verification reviewers can inspect; here the correctness-critical inventory is effectively an unpinned local observation plus the issue body, not a durable artifact another reviewer can re-check.
