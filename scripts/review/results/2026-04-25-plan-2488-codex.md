## Findings
1. The plan’s policy-driven integration is still underspecified against the actual audit code. In `Pseudocode`, it requires `weekly-audit-policy.yaml` to drive a new `filesystem_only_inventory` section and a new finding family through `_all_active_findings()` / `_write_markdown_artifact()`, but `scripts/skills/weekly_skills_audit.py` currently hardcodes both family aggregation and Markdown section rendering. `_finding_defaults()` also resolves `v2.rules` as `family.rule_id`, so the plan needs an explicit naming/refactor contract, not just “extend the existing policy loader.” Cite: plan `Pseudocode` under `run_weekly_audit_extension()`; `config/skills/weekly-audit-policy.yaml` `v2.rules`; `scripts/skills/weekly_skills_audit.py` `_finding_defaults()`, `_all_active_findings()`, `_write_markdown_artifact()`.

2. The new manual reconcile script does not have a stable CLI contract. The plan creates `scripts/skills/reconcile_filesystem_only_skills.py` and later binds implementation to `--disposition-report docs/reports/2026-04-25-skills-disposition-2488.md`, strict exit codes, and tests around partial inventory, but `Pseudocode` only names `validate_and_render_dispositions_for_manual_reconcile(disposition_yaml)`. There is no authoritative argparse surface for `--skills-dir`, `--ledger`, `--disposition-report`, `--inventory-json`, or defaults, so the TDD list and operator workflow are not actually pinned. Cite: plan `Pseudocode` under `validate_and_render_dispositions_for_manual_reconcile(disposition_yaml)` and `manual CLI contract`; plan `Files to Change` row for `scripts/skills/reconcile_filesystem_only_skills.py`; plan `Acceptance Criteria` bullet naming the manual command.

3. The pre-change baseline requirement is not fail-closed. The plan says the `_archived` duplicate/collision baseline fixture must be captured before any audit-logic edits, but `implementation_flow()` only states that as prose and does not define a verification guard that prevents generating `tests/fixtures/skills/issue-2488-archived-duplicate-baseline.json` after the logic has already changed. That leaves the core regression proof open to self-fulfilling evidence. Cite: plan `implementation_flow()` item `RED-FIRST HARD GATE`; plan `Acceptance Criteria` bullet requiring the baseline fixture.

Those are not equivalent contracts, and the proof block is being used as evidence for the same rule the tests are supposed to lock down. Cite: plan `Pseudocode` under `active_filter(path)`; plan embedded verification block `def active(p)`.
