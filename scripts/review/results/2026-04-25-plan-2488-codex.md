## Findings
1. `docs/plans/2026-04-25-issue-2488-reconcile-untracked-active-skill-files-before-loss.md` has an unverifiable review-evidence chain. In `## Adversarial Review Summary`, the plan cites mutable provider artifacts as current evidence, but `scripts/review/results/2026-04-25-plan-2488-disagreement.md` for the same review wave records `claude | MAJOR` while `scripts/review/results/2026-04-25-plan-2488-claude.md` says `MINOR`. The plan also requires, in `Acceptance Criteria`, fresh immutable artifacts before `status:plan-review`. It does not define which artifact is authoritative when provider and disagreement artifacts conflict, so the approval gate is not auditable.

2. The acceptance contract for vanished issue-body paths is unimplementable as written. `Acceptance Criteria` says “The six issue-body paths must each have either a terminal disposition or an explicit drift note if the path vanished before reconcile,” but `validate_and_render_dispositions_for_manual_reconcile(disposition_yaml)` only defines ledger fields for dispositions and terminal-state validation. The only drift structure in the plan is `inventory_summary.paths.issue_body_six_drift` under weekly audit JSON in `build_skill_inventory_with_git(...)`; no ledger field or report schema is defined for the required per-path “explicit drift note.”

3. The disposition-ledger hash schema is internally inconsistent. In `validate_and_render_dispositions_for_manual_reconcile(disposition_yaml)`, the required fields list includes singular `reviewed_file_sha256`, but the next lines require different shapes by disposition: `pre_redaction_sha256` plus `final_file_sha256`, `original_file_sha256` plus `final_consolidated_sha256`, and other multi-hash variants. The validator contract cannot be implemented deterministically while the required schema and per-disposition rules disagree on field names.

4. The replay/testing path contradicts the trust model. The manual CLI contract for `scripts/skills/reconcile_filesystem_only_skills.py` adds `--inventory-json PATH optional for replay/testing only`, but `validate_and_render_dispositions_for_manual_reconcile(disposition_yaml)` also says trusted live git/filesystem inventory is mandatory and that git errors, sparse checkout, or partial inventory are hard failures in manual reconcile. The plan never states whether `--inventory-json` bypasses trust checks, inherits a prior trust attestation, or is test-only and forbidden in real reconcile runs. That leaves the authoritative reconcile path ambiguous.

## Blockers
- Finding 1: the plan cannot clear the review gate while its own cited review artifacts do not yield one authoritative verdict set.
- Finding 2: the “explicit drift note” requirement needs a defined ledger/report schema before implementation.
- Finding 3: the hash-evidence schema must be reconciled before a validator can be written.
- Finding 4: the `--inventory-json` replay path must be reconciled with the hard “trusted live inventory” requirement.
