## Findings
1. `Acceptance Criteria` requires that “each cited immutable review artifact ... including ... disagreement artifact ... contains a parseable \`## Verdict\`,” but `scripts/review/results/20260425T125029Z-plan-2488-disagreement.md` does not contain a `## Verdict` section at all; it contains `## Verdicts`. That makes the criterion impossible as written.

2. The plan mixes the wrong policy surfaces for the new finding family. In `Acceptance Criteria`, the plan requires `config/skills/weekly-audit-policy.yaml` to define `filesystem_only_active` in `signal_vocabulary` plus a “classification/rule reference” and `v2.rules.filesystem-inventory.filesystem-only-active`. But `scripts/skills/weekly_skills_audit.py` uses `signal_vocabulary` and `classification_buckets` only in the legacy `_classify()` path, while v2 family findings are created through `_mk_v2_finding()` and `_finding_defaults()` from `v2.rules`. `filesystem_only_active` is specified as a v2 family finding elsewhere in the plan, not as a raw classifier signal. The schema contract is internally inconsistent.

3. The manual CLI exit-code contract is not implementable as specified. In `Pseudocode`, `scripts/skills/reconcile_filesystem_only_skills.py` assigns exit code `4` to “missing required flags or malformed ledger,” while exit code `2` is already assigned to “validation/terminal-state failures.” A malformed ledger is a validation failure, so those cases overlap. Separately, the same section says the CLI uses plain `argparse`; without an explicit custom parser error override, missing required flags will exit with argparse’s standard parse-error behavior, not the plan’s custom code `4`.

4. The `Tentative disposition table for the known active filesystem-only skills` cites the wrong ignore-rule evidence for `.claude/skills/memory/hermes-memory-bridge/SKILL.md`. The table points to “ignored-path evidence (`.gitignore:14 digitalmodel/`)”, but the relevant ignore rule in `.gitignore` is `memory/`, not `digitalmodel/`. That weakens the plan’s claimed pre-verified disposition evidence for one of the six issue-body paths.

## Blockers
