2. Plan §Pseudocode says “runtime orchestrator enforcement is deferred to filed follow-up issue unless explicitly implemented,” but §Files to Change only creates `docs/architecture/execution-follow-up-issue-backlog.md` with draft `gh issue create` commands. [#2728](https://github.com/vamseeachanta/workspace-hub/issues/2728) acceptance requires follow-up implementation work to be “split into issues,” not merely drafted in a backlog file. The plan has no step that actually files the enforcement follow-up issue.

3. Plan §Artifact Map does not list `docs/architecture/execution-entry-point-inventory.md` or `docs/architecture/execution-follow-up-issue-backlog.md`, even though §Files to Change creates both and §Acceptance Criteria depend on both. That breaks traceability for two correctness-critical deliverables.

4. Plan §TDD Test List `test_routing_policy_references_workstation_registry` names duplicated fields as `hostname`, `ip`, `os`, `roles`, and “license/provider capability fields,” but `config/workstations/registry.yaml` uses `role` singular and `tailscale_ip`, and provider/tool capability truth is nested under `capabilities.agent_clis`, `capabilities.tools`, and `telegram_hermes.data_access_profile`. A test written against the plan’s field names can miss actual duplicated registry truth.

5. Plan §Risks and Open Questions leaves “Should provider-agent prompts be first-class execution artifacts or only evidence attachments?” unresolved, while §Proposed Execution Layer Levels includes prompt bundles in E-L1 and §Issue [#2728](https://github.com/vamseeachanta/workspace-hub/issues/2728) explicitly scopes agent/provider routing. This decision affects the manifest schema and required test fields, so leaving it open at plan-review makes the implementation target ambiguous.

6. Plan §TDD Test List `test_input_data_boundary_crosswalk` depends on source IDs in `mounted-source-registry.yaml`, but that registry’s source IDs are mount/source abstractions such as `workspace_hub_local`, `ace_project_local`, and `api_metadata_virtual`, while the plan’s source classes include repo names such as `digitalmodel`, `worldenergydata`, `llm-wiki`, and `client_projects`. The plan says repo/client/wiki taxonomy is blocked on [#2731](https://github.com/vamseeachanta/workspace-hub/issues/2731)/[#2732](https://github.com/vamseeachanta/workspace-hub/issues/2732), but still requires a crosswalk test now. Without a bridging convention, that test is either trivial or unfalsifiable for realistic execution manifests.
