# Code Review — #2851 freshness-guard — Claude (code-stage, adversarial, high-effort)

Scope: `git diff origin/main...HEAD` for `scripts/readiness/collect-equality.sh` + `build-equality-matrix.py` (commit `4d5e3df1a`). 7 finder angles → verify. Verdict: **MAJOR (2 fixed) + 3 noted.**

## MAJOR (fixed in this branch)
- **C1 — negative `origin_ref_age_h` fails OPEN.** `is_stale()` returned `age > ORIGIN_REF_MAX_H`; a future ref mtime (NTP correction / VM clock jump / network-mount skew) yields a negative age, so `-3 > 12` is False → the contaminated checkout grades FRESH and its stale `behind_main` is trusted. **Fix:** `return not (0 <= age <= ORIGIN_REF_MAX_H)` — out of the trust window in EITHER direction is stale. Test: `test_is_stale_negative_age_failclosed`.
- **C2 — untracked noise false-STALEs a healthy machine.** `git status --porcelain -- <measured>` includes untracked `??` entries, so a `.DS_Store` / `__pycache__` / editor swap file inside a measured dir sets `dirty=true` → STALE-CHECKOUT for every dimension → excluded from all peer comparison. The plan specifies *"tracked changes"*. **Fix:** `git status --porcelain --untracked-files=no`. Test: `test_collect_dirty_false_on_untracked_noise`.

## Noted (intended / design tradeoff — not changed)
- **N1 — uniform dims collapse to PENDING until peers re-collect.** dev-secondary's committed report is pre-#2851 (no provenance) → correctly `is_stale` → excluded, leaving one fresh reporter → PENDING. This is the fail-closed contract: we decline to assert EQUAL without ≥2 *provably-fresh* reports. Self-heals when each machine runs its next scheduled collection (stamps provenance). Documented in the PR; cannot regenerate other machines' reports from here.
- **N2 — `origin_ref_age_h` is hashed (per approved A1 "exclude `checkout_sha` ONLY"), so a fresh→stale age transition forces a rewrite.** Between transitions the age value can change and trigger a rewrite, but the scheduled cadence is WEEKLY (`schedule-tasks.yaml`, asserted by `test_wiring_single_source_schedule`), so churn is at most weekly — negligible. Keeps the committed freshness fields always-live (no stale-staleness).
- **N3 — `FETCH_HEAD`-first age = "time since last fetch (any ref)", not "since origin/main moved".** Chosen deliberately: for the fail-closed purpose (did sync run recently?), last-fetch time is the right signal; repo-sync's `git fetch origin` updates both together. Falls back to the loose `refs/remotes/origin/main` mtime when FETCH_HEAD is absent.
