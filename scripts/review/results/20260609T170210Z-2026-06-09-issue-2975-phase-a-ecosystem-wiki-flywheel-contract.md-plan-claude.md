### Verdict: MAJOR

### Summary
A well-structured, defensively-scoped Phase A plan that correctly narrows #2975 to contract surfaces and carves executable validation to Phase B (#3013); the repair credibly addresses the r6 input-residency-fail-open and publication-sequence findings. However, the schema-edit verification mechanism relies on brittle raw-text occurrence counts (16 pre / 13 post) that conflate enum values, const guards, and prose description keys, and one disposition row (line 57 source_class_mix) may introduce a residency value into a source-class enum. These warrant changes/clarification before approval.

### Issues Found
- [P2] The occurrence-count contract (exactly 16 `public_llm_wiki` pre-edit, exactly 13 `public_federal_wiki` post-edit) is asserted against raw text grep that mixes enum values, `const:` guard predicates, and the line-379 `registry_backing` *description* key. A description or comment that merely mentions either token will silently break the count, producing false test failures or letting wrong content pass at the correct count. Counting should be performed against parsed YAML enum/const nodes, not text occurrences.
- [P2] Disposition row for `report-evidence-bundle.schema.yaml:57` broadens the `source_class_mix` closed enum by adding `public_federal_wiki`, which is described everywhere else as an *output_residency* value. Adding a residency token to a field named `source_class_mix` looks like a category error unless that enum already enumerates residency-like values (line 193 implies it currently uses `public_llm_wiki`). This needs explicit confirmation that `source_class_mix` is residency-typed, not source-class-typed, before the edit.
- [P2] The disposition table is anchored to hardcoded line numbers (55, 58, 93, 162, 179, 33, 57, 117, 124, 229, 253, 324, 331, 340, 342, 379). Line numbers rot as soon as either schema file changes upstream. The occurrence-count guard (16) is the only real anchor; if the count still equals 16 but lines have shifted, the per-line dispositions could be applied to the wrong nodes. Dispositions should key on a structural path (JSON pointer / YAML key path), not line number.
- [P3] `test_standards_readme_indexes_existing_standards_and_contract` requires the README to link every current `docs/standards/*.md` file. Once `docs/standards/README.md` is created it is itself a `*.md` file under that directory; the test could over-require the index to link itself, or under-count depending on glob handling. The self-reference exclusion should be specified.
- [P3] Issue states (#2975 OPEN, #3013 OPEN) and file existence/missing claims are asserted as verified but no `## Attested Evidence` block accompanies this review payload. The plan already mandates fresh `attest-plan-claims.sh` output plus manual `ls -la` proofs at label time (lines 77-81), so this is a sequencing reminder rather than a defect — but the r7 evidence comment must actually carry that attestation, including the `.jsonl` path workaround for the #3015 extractor gap.

### Suggestions
- Replace raw-text occurrence counting with structured assertions: parse both schema YAML files and assert on the set of enum members / const values at named paths. Keep a human-readable count only as a secondary sanity check, not the primary guard.
- Re-key the Schema Guard Occurrence Disposition table on stable structural identifiers (e.g. `$.properties.output_residency.enum`, `$.allOf[2].then...const`) instead of line numbers, so the table survives upstream schema edits between approval and implementation.
- Explicitly state the type/contents of `source_class_mix` and why a residency value belongs in it, or correct the row if it is a category error.
- Add a negative-path test asserting that the standards README is NOT required to index itself, and that a missing real standard does cause failure (to prove the index test is not vacuous).
- Since both Claude and Codex returned MAJOR at r6 (not just one provider), have the r7 review explicitly confirm each prior r6 finding is closed with a line/test citation, rather than relying on the prose claim that the repair addresses them.
