### Verdict: MAJOR

### Summary
Wave-3 draft is substantially improved — scope is locked to Wave-1 tier-1 repos, terminology is deterministic, and evidence is embedded. However, the validation strategy enforces lexical consistency (phrase presence/absence) without verifying semantic consistency, the AGENTS.md contradiction predicate is still partly subjective, and the actual mission/non-goals content is delegated to pseudocode rather than specified.

### Issues Found
- [P2] Tests are lexical-only: test_required_phrases_present and test_forbidden_phrases_absent verify that strings appear/don't appear, but a reconciled document could contain every required phrase and still retain contradictory surrounding claims (e.g., a tier-1 role table that conflicts with the mission contract). No test asserts that role attributions in BUSINESS_BRAIN.md and WORKSPACE_HUB_REPOSITORY_OVERVIEW.md actually align with the contract's role map.
- [P2] AGENTS.md contradiction rule has three OR triggers, but only the first (forbidden-phrase match) is deterministically checkable. Trigger 2 ('contains a repo-role statement that contradicts the mission contract') has no operational definition, and trigger 3 depends on a 20-line count that is not asserted against the current AGENTS.md line count in the plan. test_agents_touch_is_rule_driven therefore cannot fail deterministically if a human disagrees with the 'contradicts' judgment.
- [P2] The mission contract's actual content is underspecified. Required phrases are enumerated, but the concrete non-goals list, the glossary terms, and the prose defining each repo's role are left to pseudocode. Acceptance criterion 'explicit non-goals sufficient to guide downstream repo mission revisions' is subjective and not testable.
- [P2] Artifact Map still lists Claude/Codex/Gemini review files under 'Planned outputs' with 'and later reruns', but the Revisions-made list claims these were clarified as already-existing wave-1/wave-2 artifacts. The header also lists six specific review filenames as existing. Internal inconsistency between header, artifact map, and revisions narrative.
- [P3] docs/plans/README.md plan-index row shape is specified (issue 1525, slug, path) but the plan does not cite the existing plan-index table's column schema, so test_plan_index_updated could pass against a freshly appended row while the table format silently drifts.
- [P3] scripts/validation/check_workspace_hub_mission_contract.py location and naming convention are asserted without confirming that scripts/validation/ is an established directory with sibling scripts and a runner pattern; one-off script may end up unreferenced by CI and rot.
- [P3] BUSINESS_BRAIN.md currently says 'GSD is the control plane' (line excerpt 80), which is a different subject from 'workspace-hub is the ecosystem control plane'. The reconciliation strategy must distinguish 'workflow control plane' from 'ecosystem/portfolio control plane' or the required shared phrase 'control plane' will gloss over a real semantic gap.
- [P3] Open question on CI enforcement of the validation script is deferred, but without CI the phrase contract will decay the first time a reconciled document is edited outside this packet — mitigation is a future issue that is not filed.

### Suggestions
- Add a semantic consistency test: parse the role map from docs/reports/workspace-hub-mission-contract.md and assert that BUSINESS_BRAIN.md and WORKSPACE_HUB_REPOSITORY_OVERVIEW.md's role-table rows do not contradict it (e.g., by forbidding any sentence of the form '<repo> is the control plane' where <repo> != workspace-hub, and any sentence claiming a different role for digitalmodel/assetutilities/aceengineer-website than the contract states).
- Reduce the AGENTS.md contradiction rule to a single deterministic predicate: either forbidden-phrase match OR explicit role-string mismatch detectable by regex. Drop the subjective 'contradicts the mission contract' trigger, or reduce it to a concrete scanner.
- Quote the current AGENTS.md line count in Resource Intelligence so the 20-line-cap trigger is auditable at plan-review time, not discovered during execution.
- Enumerate the non-goals list inline in the plan (even provisionally). Three to five concrete non-goals (e.g., 'workspace-hub does not execute engineering computations', 'does not host GTM content', 'does not own durable knowledge corpora') would make the acceptance criterion testable.
- Reconcile the review-artifact status: either move the six existing wave-1/wave-2 review files to the 'Existing evidence inputs' section and drop 'and later reruns', or state clearly that the table reflects any cumulative review artifacts for this plan.
- Explicitly resolve 'GSD is the control plane' (BUSINESS_BRAIN.md) vs 'workspace-hub is the ecosystem control plane' (mission contract) by stating the distinction in the canonical terminology section — e.g., GSD is the workflow control plane within workspace-hub, which is the ecosystem control plane across the portfolio.
- File the CI-enforcement follow-up issue as part of this packet's deliverables so the phrase contract has a scheduled gate, rather than leaving it as an open question.
- Verify docs/plans/README.md's existing Plan Index column layout and restate test_plan_index_updated against that exact schema (columns, order, and markdown row format).
