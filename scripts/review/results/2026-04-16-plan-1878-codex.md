## Key Findings

1. **[blocking] `conference-index-batch.jsonl` coverage not proven.** Plan defers this file as out-of-scope with a follow-up-issue note, but does not empirically demonstrate that the deferred scope does not also carry the same broken-metadata condition. Without that evidence, the fix for #1878 may leave a parallel corpus silently broken. **Fix:** run a one-shot coverage count on `conference-index-batch.jsonl` (records with/without `content_type`) and either pull it into scope or cite the number so the follow-up issue has a known baseline.

2. **[blocking] No safe-write / backup path specified for Phase A regeneration.** Plan adds `--preserve-metadata` carryover to `phase-a-index.py` but does not require Phase A itself to emit a timestamped backup before writing. If Phase A fails mid-write, the prior enriched index is destroyed with no recovery path. **Fix:** make Phase A's write path itself atomic — `.tmp` staging + `.backup-YYYY-MM-DD` creation before rename — mirroring what the new enrichment script promises.

3. **[blocking] Metadata preservation not locked across ALL `index.jsonl` rewrite paths.** Plan addresses Phase A carryover. But Phase C (`phase-c-classify.py`) bounded-writeback mode and Phase E (`phase-e-backpopulate.py`, `phase-e-registry.py`) also rewrite `index.jsonl`. Any one of them can clobber `content_type` / `summary_done` unless they too carry the fields forward. **Fix:** either add the same carryover guarantee to Phase C/E or add an integration test that runs Phase A → enrichment → Phase C writeback → Phase E writeback and asserts `content_type` + `summary_done` survive the full chain. Phase-A-only fix is insufficient.

## Root-Cause Fidelity

Codex's core objection: the plan treats Phase A as the sole rewrite surface. It is not. The true root cause is that **every** write path to `index.jsonl` assumes the schema it emits is complete — none of them carry forward fields they don't know about. Fixing Phase A alone creates a false sense of durability.

## Implementation Risk

- Phase C/E clobber (Finding #3) is the highest operational risk — it will silently regress after the first post-enrichment classification run.
- Atomic rename is mentioned in the new enrichment script but not in Phase A (Finding #2).
- Conference-batch divergence (Finding #1) is a latent risk, not immediate, but shapes whether #1878 is actually "fixed."

## Missing Deliverables

- Phase C / Phase E metadata-preservation patches or explicit integration coverage.
- Phase A atomic write + backup (separate from the enrichment script's backup).
- Empirical baseline for `conference-index-batch.jsonl`.

## Test Gaps

- Integration test: full pipeline replay (A → enrich → C → E) asserting field survival.
- No test that Phase C bounded writeback preserves `content_type`.
- No test that Phase E backpopulate preserves `summary_done`.

## Recommendation

Do not approve as-is. Required before approval:

1. Extend carryover guarantee to Phase C and Phase E, OR add a pipeline-chain integration test that proves the enriched fields survive a full A→C→E replay.
2. Make Phase A write atomic (`.tmp` + dated `.backup`) before rename, independent of the enrichment script.
3. Add an empirical record count for `conference-index-batch.jsonl` missing-metadata rate to either fold it in or size the follow-up issue.
