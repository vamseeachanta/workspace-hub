## Defect inventory

### P2-1: Off-by-one in cited `__init__.py` insertion-point line numbers
**Location:** plan §"Implementation diff (precise)" — claims insertion "after the `b1528_sirocco_time_trace` block at line 51, before the `yaw_moment` block at line 53"
**Live state (verified 2026-05-03 via `sed -n '50,55p' __init__.py`):**
```
50: )
51: from digitalmodel.naval_architecture.yaw_moment import (
52:     load_packaged_typical_ship_yaml,
```
The yaw_moment block actually begins at line **51**, not line 53. The b1528 block's closing `)` is at line 50.
**Why it matters:** Implementer following the plan literally will look at line 53 and see the *body* of the import block, not the start. Confuses sequencing.
**Fix:** Update plan to say "after line 50 (`)` closing the b1528 block), before line 51 (`from digitalmodel.naval_architecture.yaw_moment import (`)".

### P2-2: Plan does not specify how `__all__` insertions interact with `RigHullEstimate` / `RigHullValidation` (PascalCase) ordering
**Location:** plan §"Implementation diff" — instructs "alphabetical positions" for `__all__` insertions
**Live state:** Current `__all__` mixes lowercase function names with PascalCase class names, and the existing entries are NOT strictly alphabetical (e.g., `RigHullEstimate` appears after `merge_template_into_registry` and before `normalize_drilling_rig_record` — this only sorts if uppercase letters sort before lowercase, which is ASCII behavior).
**Why it matters:** The plan's "alphabetical insertion" instruction is ambiguous under mixed-case sort. Implementer may pick a different position than reviewer expects, producing diff churn at PR time.
**Fix:** Either (a) specify explicit anchor names ("after `load_packaged_typical_ship_yaml`, before `load_yaw_moment_input`") OR (b) note that the existing list uses ASCII sort and the new entries match that convention.

### P3-1: "Decision: include the writer for symmetry" not justified by acceptance criteria
**Location:** plan §"Gaps identified" — "include the writer (matches yaw `write_yaw_moment_results` pattern) for symmetry; skip charts/heatmap helpers"
**Concern:** Including `write_rudder_stock_torque_results` is a *judgment call*, not test-driven. The failing test only requires `load_packaged_*` and `run_*_sweep`. Adding a third export is correct-by-symmetry but increases blast radius (any future renaming of the writer becomes a public-API break).
**Why it matters:** Pure YAGNI argument — exports should be test-driven OR explicitly required by external consumers; "for symmetry" is a soft justification.
**Fix:** Either (a) add a test asserting `from digitalmodel.naval_architecture import write_rudder_stock_torque_results` succeeds (TDD-justify the export) OR (b) remove `write_rudder_stock_torque_results` from this plan and file as separate "rudder writer parity" issue if needed.

### P3-2: Acceptance criterion #4 makes a regression claim without evidence
**Location:** plan §"Acceptance Criteria" — "Full file `pytest test_rudder_stock_torque_sweep.py` reports 19 passed, 0 failed (vs. current 18 passed / 1 failed)"
**Concern:** "19 passed" assumes there are exactly 19 tests in the file. The #2566 validation report observed 18 passed + 1 failed = 19 total — but that count was as-of 2026-05-02. Tests may have been added/removed since.
**Fix:** Soften to "all tests in `test_rudder_stock_torque_sweep.py` pass (was 1 failure pre-plan)" and have the implementer record the actual final count in the closeout comment.
