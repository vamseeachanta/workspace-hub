### gemini

Plan §Files to Change introduces a new script `assethold/scripts/ci/verify_python_tests_workflow.py`. Because the new script resides in `scripts/ci/`, it falls entirely outside the narrowed linting boundary and will not be checked by flake8.

Ad-hoc installation of a typing dependency in the CI runner without adding it to the canonical project dependencies (e.g., `pyproject.toml` or `uv.lock`) creates CI-to-local drift, requiring developers to rely on the undocumented `uv run --with types-PyYAML` hack locally.

The introduction of `uv run`, `python -m`, and `-c pyproject.toml` alters the execution context significantly, meaning the local command lacks true parity with CI execution.
- Plan §Deliverable relies on "enforcing a persisted workflow verifier inside the test job". Running a verifier inside the exact workflow file it validates provides zero true enforcement against drift; a pull request that improperly alters the flake8/mypy constraints can simply delete the step invoking `verify_python_tests_workflow.py` to achieve a green build.
- Plan §TDD Test List only provides a single happy-path integration run for the new verifier (`verify_python_tests_workflow_contract` expecting "exit 0"). The plan defines no negative test cases to prove the script actually fails (returns non-zero) when the workflow contract is violated, meaning the verifier itself is untested logic.
