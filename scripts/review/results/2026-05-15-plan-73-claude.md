## Findings

### MINOR-1: API standards existence claims are not verified

**Evidence:** Plan §"Sub-issue scope breakdown" names API standards: RP 19B (perforating evaluation), RP 19SC (sand control), RP 19WC (smart completion).

- **API RP 19B** — verified real (API "Evaluation of Well Perforators").
- **API RP 19SC** — **does not exist as a standalone published API RP** to my best knowledge. Sand-control standards are scattered across SPE Monograph 9, vendor practices, and API RP 90 (annular casing pressure management — adjacent but not sand-control).
- **API RP 19WC** — **does not exist** to my knowledge. "Smart completion" standards are vendor-driven; the closest is ISO 14998 (intelligent-well completion architecture) which is paywalled.

**Why this matters:** Plan acceptance criteria says "≥1 standards page per sub-issue." If RP 19SC and RP 19WC don't exist, the plan can't deliver standards pages for sub-issues 2 and 3 — only cross-links to other domains.

**Recommendation:** Replace assumed standards with verified alternatives. For sand control: API RP 90, SPE Monograph 9. For smart completion: ISO 14998 (cite-only) + SPE 35545 (Gao 1996) historical reference.

### MINOR-2: Sub-issue 1 (perforating) scope is large enough to risk single-issue completion

**Evidence:** Plan lists shaped-charge mechanics, overbalanced / underbalanced / EOB / wellbore underbalanced perforating, gun systems (TCP/wireline/CT-conveyed), perforation strategy (shot density, phasing, EHD, EHL). That's 5 distinct topic clusters in one concept page.

**Why this matters:** Phase 1 sub-issues (e.g., #62 ESP) covered single topic clusters and produced focused 5-page sub-issues. Perforating-as-one-issue risks 10+ pages in one PR, making review hard.

**Recommendation:** Either (a) accept that perforating concept page will be larger (~500 lines) and one standards page, or (b) split into two sub-issues: "perforating fundamentals" + "perforation strategy." Lean toward (a) — single concept page with sectioned content. Surface the split-vs-bundle decision in the plan §"Open questions."

### MINOR-3: Cross-link plan assumes Phase 1 page names without verification

**Evidence:** Plan references Phase 1 pages by inferred names: `concepts/electric-submersible-pumps.md`, `concepts/gas-lift-overview.md`. These may differ from the actual landing names from #62-#66.

**Recommendation:** Plan should run a quick `ls wikis/production-engineering/wiki/concepts/` and update the cross-link section with verified filenames. Implementation Step 1 should re-verify before writing cross-links.

### MINOR-4: Phase 1 ↔ Phase 2 cross-link directionality is asymmetric

**Evidence:** Plan §"Cross-links to install" specifies Phase 2 → Phase 1 links. But Phase 1 pages already landed (epic #61 closed) — updating them requires either touching closed-issue artifacts or filing a Phase-1-amendment sub-issue.

**Recommendation:** Plan should explicitly include "Phase 1 page edits to add reverse cross-links" in Files to Change. Without this, only Phase 2 → Phase 1 direction lands; the reverse won't.
