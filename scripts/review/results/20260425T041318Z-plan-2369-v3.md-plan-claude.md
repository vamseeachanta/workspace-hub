### Verdict: MAJOR

### Summary
Plan v3 is detailed, well-revised against prior reviewer P1/P2/P3 findings, and substantially audit-ready. However, three load-bearing issues remain: (1) the "Attested Evidence" block is still a placeholder, not an attestation — the very gap Gemini r2 P1 flagged; (2) the path-guard via `builtins.open` monkey-patch has wide blast radius and weakens determinism guarantees; (3) the byte-identical idempotency claim (Test 17 / AC6) directly contradicts the schema's runner-start `generated_at` and the R24 collision suffix using `generated_at_epoch`. These should be resolved before approval.

### Issues Found
- [P1] The `## Attested Evidence` block is a placeholder describing what the script *will* verify, not an attestation payload. Per the dispatch policy and Gemini r2 P1, the attest script should be run and its output embedded before plan review — otherwise this v3 still ships with the same defect that earned the v2 P1.
- [P1] Idempotency is contradicted by the schema. AC6 + Test 17 require byte-identical outputs across runs, but Appendix A defines `generated_at` as ISO-8601 UTC at runner start, and R24 uses `generated_at_epoch` as the stub_id collision suffix. Without freezing `generated_at` (e.g., env-var injection or `--now` flag), Test 17 cannot pass and AC6 is unsatisfiable.
- [P1] `builtins.open` global monkey-patch (R19) has process-wide blast radius: it intercepts opens by pytest plugins, third-party libraries, stdlib modules (e.g., logging file handlers, json/yaml loaders), not just the runner's own reads. A scoped `safe_open()` helper or context manager used at every read site would be safer and more testable. The current design also bypasses the guard for file-descriptor (int) opens and for any code that uses `os.open` / low-level IO.
- [P2] xfail-then-pass workflow for Test 12 is fine for the test bar, but the runner's refusal to start when `STOPWORDS_SHA == "<unpinned>"` means AC2 (runner exits 0) is unsatisfiable until `make pin-stopwords-sha` runs. The plan should explicitly sequence the pin step as a prerequisite of AC2 and call it out in the runbook, not just in the Risks section.
- [P2] Test 7 and Test 8 "expected outputs updated" deserve a flagged callout rather than two inline notes. The plan is now revising fixtures to match a rewritten rule, which is defensible — but reviewers should be able to see at a glance which previously-locked expectations were rotated and why.
- [P2] AC13 ("ISOPE re-index follow-on issue is filed (or flagged for user to file)") is non-deterministic. The Open Question says default is "leaving it to a human," so acceptance is met just by writing a proposed body — but the AC text reads as if filing is also acceptable. Pick one and lock it.
- [P3] DOMAIN_KEYWORDS places `riser`/`risers` under `pipeline` (weight 4) rather than `subsea`. A paper titled simply "Riser analysis" classifies as pipeline. This may or may not be intended — worth a one-line rationale or a Test 6.5 fixture pinning the call.
- [P3] Cluster_count_min=2 conflicts with R23's N_d=1 case (k clipped to 1). The pseudocode resolves it implicitly ("clipped to 1") but the contract dict still shows `cluster_count_min: 2`. Add an explicit precedence note: N_d-clip wins over min.
- [P3] R28 grep target (`llm-wiki\.`) checks only the dotted-module form; the plan still embeds many `llm-wiki/` and `llm-wiki-` references in resource intel. That's intentional per the feedback rule, but worth saying out loud so a future agent doesn't "fix" it.
- [P3] generator_version `1.0` at first emit while schema_version is `1.1` is a small narrative wrinkle — the runner emits a 1.1 schema on its first 1.0 release. Either start runner at 1.1, or note that runner versioning is decoupled from schema versioning.

### Suggestions
- Run `scripts/review/attest-plan-claims.sh` against the committed v3 plan path now and replace the placeholder paragraph with the actual attestation payload (issue states + file existence + sha256). This is the single highest-leverage fix and was already a Gemini P1 in r2.
- Replace the `builtins.open` monkey-patch with a `safe_open(path, ...)` helper that all runner read sites must use, and add a static check (grep) in CI that the runner module imports no other open functions. Move the path-guard test to assert the helper raises, not the global open.
- Make `generated_at` injectable: accept a `--now ISO-8601` flag or `BP2_NOW` env var; default to runner-start. Test 17 fixes `--now` to a constant and asserts byte-identical output. Same hook used to make stub_id collision suffix deterministic in tests.
- Add a sequencing note in the runbook: (1) `make pin-stopwords-sha`, (2) verify Test 12 transitions xfail→pass, (3) AC2 becomes runnable. Otherwise a reader following AC order will hit a hard fail.
- Add a small "Fixture deltas vs v2" callout listing every test whose expected output changed in v3 (currently Tests 7 and 8). Reviewers do not have to scroll to find them.
- Lock AC13 to one of: "runner emits a proposed issue body to the report; user files it" OR "runner files it via gh." The current `or` makes the AC trivially satisfied by either branch.
- Promote the path-guard, idempotency-vs-timestamp, and pin-required-before-runner notes into a brief Runbook section so the agent executing the plan does not learn them from Risks-section prose.

### Questions for Author
- Why is STOPWORDS_SHA pinned via a follow-up `make` target rather than computed once at plan-write time and embedded as a literal in the plan? Embedding it would let Test 12 ship as a hard `pass` and remove the xfail/AC2-unrunnable window.
- How does Test 17 (idempotent byte-identical outputs) reconcile with `generated_at` and the R24 epoch-based stub_id collision suffix? Is there an injection seam I'm missing?
- Is the `riser`→`pipeline` mapping (weight 4) intentional, or should risers map to `subsea` so that a riser-fatigue paper without VIV signal lands in subsea+structural rather than pipeline+structural?
- When two domains tie *after* weighting (rare but possible — e.g., empty-tokens corner cases), is alphabetical tie-break the desired outcome, or should `conference` or `path` be a secondary signal first?
- On `pathlib.Path.open` patching (R19): is this verified across Python 3.11/3.12 behaviors, or relying on Path.open routing through the patched `builtins.open`? Worth a one-line verification in Test 5.
- What exactly does "flagged for user to file" look like operationally for AC13 — a stub markdown section in the report, a TODO entry, a stdout banner? Pin the artifact so reviewers can confirm presence.
