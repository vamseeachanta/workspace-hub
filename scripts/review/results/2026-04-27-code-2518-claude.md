## Findings
1. **`codex exec -` syntax is unverified live** — `scripts/review/plan-review-fanout.sh:153`. The mock CLI captures argv and stdin separately, so the test passes whether or not the real OpenAI codex-cli treats `-` as a stdin sentinel. If `-` is unrecognized, real codex receives literal prompt `"-"` and ignores stdin. Per memory entry `feedback_codex_cli_0_124_upstream_regression.md` (2026-04-23), codex-cli 0.124.0 hangs all `codex exec` calls regardless of stdin redirection — so in production this fix produces a timed-out UNAVAILABLE every run, not a working review. The diff bounds the failure but does not fix codex; that nuance is missing from both the plan and the script comment at lines 150–152.
2. **Header docstring is stale** — `scripts/review/plan-review-fanout.sh:14-23`. The header still describes `codex exec "<prompt>" </dev/null` as the canonical invocation, including the `</dev/null` rationale. The body now uses `codex exec - < "$combined_file"`. Future readers debugging codex will be misled.
3. **Stderr promotion bypasses rc** — `scripts/review/plan-review-fanout.sh:106-109`. The `mv "$err" "$out"; return 0` runs unconditional of `$rc`. A process that emits `## Verdict\nMAJOR\n` on stderr and then crashes (rc != 0) is treated as a clean review. There is no integrity gate (e.g., requires both `## Verdict` *and* `## Findings`). A truncated stderr could be promoted as a complete artifact.
4. **`timeout` does not kill the process group** — `scripts/review/plan-review-fanout.sh:141,153,163`. `timeout` defaults to signaling only its direct child. If codex/gemini spawns helpers, they survive as orphans after the launcher is killed. The plan title claims to address "orphaned provider processes"; that is true for the parent process only. `timeout --foreground` + `setsid`, or piping through `setsid -- timeout ...`, would actually kill the group.
5. **Timeout test name overclaims isolation** — `scripts/review/tests/test_plan_review_fanout.sh:435-451`. Uses global `MOCK_SLEEP_S=3` with `PLAN_REVIEW_PROVIDER_TIMEOUT_SEC=1`. All three mocks (`mocks/claude:5`, `mocks/codex:4`, `mocks/gemini:5`) sleep on this var, so all three time out. The test only asserts codex's UNAVAILABLE; it does not actually prove "without aborting other providers." The pre-existing `test_gemini_unavailable_does_not_abort_codex` is the real isolation guarantor.
6. **mktemp / printf failure in codex branch is not graceful** — `scripts/review/plan-review-fanout.sh:146-149`. Under `set -e`, a failed `mktemp` aborts the function before the case body completes; `normalize_provider_output` is never called and no UNAVAILABLE stub is written. Inconsistent with the diff's stated graceful-degradation contract. Either trap the failure or call `write_unavailable` on the path.
7. **Stderr `head -c 400` may include control bytes** — `scripts/review/plan-review-fanout.sh:113,124`. The reason field strips newlines and escapes double quotes but does not strip ANSI or control characters. Codex/Gemini stderr commonly contains escape sequences; the resulting UNAVAILABLE stub can render unreadable in artifact diffs and confuse the disagreement aggregator. Consider `tr -d '\000-\037'` after the existing `tr`.
8. **Test asserts exact `^ARGV: exec -$`** — `scripts/review/tests/test_plan_review_fanout.sh:167`. If anyone adds a flag to the codex invocation (e.g., `--cd`, `--model`), the test fails on a regex anchor mismatch instead of a semantic mismatch. Low priority but brittle.

## Required fixes
1. Update the header docstring at `scripts/review/plan-review-fanout.sh:14-23` to describe the real `codex exec - < file` invocation and drop the `</dev/null` rationale.
2. Tighten stderr promotion: either gate on `rc == 0`, or require both `## Verdict` and `## Findings` headings before promotion.
3. Either land live evidence that `codex exec - < file` is consumed by the installed codex-cli (capture the artifact from a real run on a small plan) or annotate the script + plan that codex remains UNAVAILABLE pending the 0.123.0 downgrade workaround for #2479.
4. Either rename `test_provider_timeout_becomes_unavailable_stub` to reflect the global-timeout reality or split MOCK_SLEEP_S per provider so the test actually proves isolation.

## Residual risk
Codex provider remains de facto UNAVAILABLE in production while codex-cli 0.124.0 stdin-hang persists; the wrapper now reliably *reports* that rather than hanging the orchestrator. Grandchild processes spawned by codex/gemini can still leak past `timeout` because the kill is not process-group scoped. Stderr-promotion is intentional but can launder truncated reviews if a CLI dies mid-write.
