## Summary of findings

Top findings:

- **Jest link-check will not run** — `aceengineer-website/package.json` uses an explicit `jest.projects` allowlist; adding `tests/js/demo-links.test.js` has no effect unless `package.json` is also modified. The plan does not list `package.json` in Files to Change. This is the same "write-only guard" defect as v1, now more subtle.
- **Rollback claim vs. reality** — the plan asserts `git revert <merge-commit>` as atomic rollback, but repo policy is direct commits to `main` (no merge commits). Single-commit revert does not cleanly unwind an 11-file change set, and would regress the already-live Demo 5 jumper page alongside the new work.

Secondary gaps:

- **Node / Vercel runtime version not pinned.** `package.json` has no `engines` field; `vercel.json` does not specify a Node runtime. Local `npm run build` may pass under Node 20 while Vercel defaults shift, producing silent build drift.
- **Vendored Plotly provenance / license handling.** Plan proposes committing a 3.5 MB binary blob with the text "verify checksum against upstream release" but cites no concrete SHA256, no `.gitattributes` rule, no `LICENSE` file for the third-party asset, and no dependency-manifest entry. Provenance is asserted without proof.
- **Apex vs `www` sitemap host mismatch.** New sitemap entries use `https://aceengineer.com/` while `vercel.json` 301-redirects apex to `www.aceengineer.com`. Googlebot will follow the redirect; every new entry is canonically poisoned on day one.
