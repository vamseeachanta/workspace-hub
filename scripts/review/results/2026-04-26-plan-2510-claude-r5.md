## Findings

1. **Manifest path-encoding contract is undefined for non-canonical output dirs.** Determinism Contract §line 325 mandates the manifest "include repo-relative paths" and validate via `sha256sum -c data/semiconductor/layout_cad_demo/artifact_manifest.sha256` from repo root. CLI Contract §line 156 takes `--output <dir>` with no constraint that `<dir>` lies under the repo. The TDD test `test_outputs_are_deterministic_across_runs` (line 242) invokes the CLI in **two temp dirs** and asserts equal hashes "for manifest-covered artifacts." The plan never specifies how the CLI computes manifest keys when `<dir>` is `/tmp/...` (outside the repo): absolute paths break determinism across runs; basenames contradict the "repo-relative" rule; cwd-relative requires the test to chdir. Implementation has no path-resolution rule to follow. **Pin one of: (a) entries are relative to the manifest file's parent directory (basenames + report key, mirroring #2511 — but the plan explicitly rejected that pattern at line 153), or (b) entries are cwd-relative and tests must chdir, or (c) entries are repo-rooted only when `<dir>` is under the repo and the test contract bypasses path comparison.**

2. **Transitive dependency drift is unaddressed; deterministic-hash claim is fragile.** `uv run --with gdsfactory==9.40.2` (lines 157, 251–253) pins only `gdsfactory`. The probed determinism path uses `kfactory.utilities.save_layout_options()` (line 84) — `kfactory` is a transitive dep with an open version range, as is `klayout` (the underlying binding referenced in the empirically observed `kdb.SaveLayoutOptions` type annotation). On a future date, `uv` may resolve a different `kfactory`/`klayout` patch, producing different GDS bytes and breaking AC #5 (manifest re-validation) and `test_outputs_are_deterministic_across_runs`. Pin transitive deps explicitly (`--with kfactory==X.Y.Z --with klayout==A.B.C`) or commit a `uv.lock` for the demo; otherwise the determinism guarantee is best-effort, not falsifiable.

3. **`gds2_write_timestamps=False` is asserted to "zero GDSII timestamp fields" but never byte-verified.** Plan line 326 claims this option "zeroes GDSII timestamp fields rather than writing wall-clock time." The probe at lines 80–89 only confirms the default attribute value is `False`; it does not run the CLI twice and diff the resulting `.gds` bytes. The flag could equally mean "skip the write" (leaving uninitialized memory), "write zeros," or "preserve the prior file's timestamps." The entire determinism strategy hinges on this primitive. The plan must either embed a documented two-run byte-diff probe or treat hash equality as a runtime guard with clear failure mode if bytes differ.

4. **Round-trip "at least N polygons" lacks an upper bound.** GDS Round-Trip Contract line 171: "Per-layer flattened polygon counts must be **at least** the generated counts." A reader that incorrectly explodes one rectangle into 1000 pieces (a common failure mode of buggy boolean / flatten implementations) would pass the test. For axis-aligned shapes that survive GDS round-trip losslessly, the contract should be tighter — equality, or `≤ generated × small_factor`. Without an upper bound the test cannot detect reader misbehavior.

5. **`test_csv_and_manifest_use_lf_line_endings` omits the report.** Determinism Contract line 322 covers "CSV/manifest/**report-generated tables**." Test name and intent (line 244) cover only CSV and manifest. If the report is regenerated on a Windows runtime emitting CRLF, its hash diverges from the manifest entry but no test catches it; AC #5 manifest re-validation will fail with no localized signal. Add `\r` byte assertion to the report path.

6. **No test verifies the report's embedded SVG link resolves from the report's location.** Pseudocode line 215 says "embed SVG preview via correct relative path." Test `test_cli_regenerates_artifacts_manifest_and_report` (line 241) only states "report links resolve" — vague, with no concrete assertion. Report is at `docs/reports/...`; SVG is at `data/semiconductor/...`. The relative link must traverse `../../data/...`. Easy to ship a broken link that no test catches. Add `Path(report.parent / svg_link).exists()` style assertion.

7. **Missing-dependency test is monkeypatch-dependent on an unspecified helper.** Test `test_missing_open_layout_dependency_blocks_rather_than_fakes_gds` (line 243) "monkeypatch[es] the lazy import helper to raise `ModuleNotFoundError`." The CLI Contract (line 158) only says imports may be lazy; it never names the helper to be patched. Without that name in the contract, the test contract is incomplete and the implementer can pick a helper the test cannot reach (e.g., inline `try: import gdsfactory`), turning the test into an API-surface design constraint that is invisible until implementation. Pin the helper symbol in the CLI Contract.

8. **Probe output for `Component.write_gds` signature is not embedded in the plan.** Plan line 86 runs `print(inspect.signature(gf.Component.write_gds))` but only the comment "# includes save_options" is recorded — the actual signature string is omitted. My adversarial probe confirms the plan's claim (signature includes `save_options: 'kdb.SaveLayoutOptions | None'`), but for retrieval-skepticism this should be embedded as evidence rather than asserted. Future reviewers/implementers cannot verify "save_options exists at gdsfactory==9.40.2" without re-running the probe.

9. **Plan summary's "Codex r4 verified plan is on main" claim is stale relative to current HEAD.** Adversarial Review Summary line 277 says Codex r4 "Verified plan is on main." Plan evidence line 62 cites commit `90bfa08d3`. Current `origin/main` is at `1830d17` (post-r4 hardening, this revision). For r5 reviewers fetching from `main`, "on main" is true but refers to a different content than r4 reviewed. The traceability statement should explicitly note "plan content reviewed at r4 lived at 90bfa08d3; r5 reviews HEAD at 1830d1…" so the audit trail does not silently elide an in-place revision.

10. **AC #1 invokes pinned `uv run --with gdsfactory==9.40.2 pytest` to "capture TDD RED" before implementation exists.** Most tests in the list (geometry invariants, CSV LF endings, default spec layers) do not require `gdsfactory`. Forcing every TDD-RED run through `uv run --with gdsfactory==9.40.2` adds first-run dependency resolution cost (acknowledged at line 335) to tests that have no need for that dependency. This is friction without benefit; alternatively, split the AC: tests that require `gdsfactory` (round-trip + missing-dep) get the `--with` invocation; the rest run plain `uv run pytest`.
