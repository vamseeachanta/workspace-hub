# Code Review — #2851 freshness-guard — Codex (code-stage, adversarial)

Scope: `git diff origin/main...HEAD` for the two source files (post Claude r1 fixes). Dispatched via `submit-to-codex.sh --file`. Verdict: **MAJOR.** Non-overlapping with Claude's findings (cross-provider payoff).

## MAJOR (fixed)
- **X1 — local-*ahead* checkouts grade FRESH.** `git rev-list --count HEAD..origin/main` measures only *behind*; it never sees local commits *ahead* of `origin/main`. A machine on an unpushed branch with committed changes to a measured path reports `dirty:false, behind_main:0` and grades fresh despite a non-canonical tree — the symmetric hole to the behind-case the guard targets. Codex reproduced: empty local commit → `dirty:false, behind_main:0, origin_ref_age_h:0`. **Fix:** collector emits `ahead_main` (`git rev-list --count origin/main..HEAD`); `is_stale()` treats `ahead_main not in (0,"0")` as stale. Tests: `test_collect_ahead_main_counts_local_commits`, `test_is_stale_ahead_main_positive` + `_unknown_failclosed`.

## MINOR (fixed)
- **X2 — `is_stale` dirty check failed open on missing/garbled field.** Only `dirty is True` was stale; a provenance block with `dirty` omitted or a string value slipped through. **Fix:** `if p.get("dirty") is not False` (require an explicit clean bool). Test: `test_is_stale_dirty_missing_failclosed`.

## MAJOR (acknowledged — documented limitation, not changed)
- **X3 — `FETCH_HEAD` mtime ≠ `origin/main` freshness.** Any fetch (incl. an unrelated branch) refreshes `FETCH_HEAD` while the local `origin/main` ref stays stale, so `origin_ref_age_h` can read fresh while `behind_main` is computed against a stale ref. No clean network-free fix exists: `FETCH_HEAD` overstates freshness (any fetch); the loose `refs/remotes/origin/main` mtime overstates staleness (only updates when the ref moves). The deployed signal is acceptable because (a) the automated repo-sync runs `git fetch origin`, which refreshes `origin/main` and `FETCH_HEAD` together, and (b) the guard is fail-closed — `unknown`/absent ref ⇒ STALE bounds the downside. Flagged by both providers; tracked as a follow-up if a reflog-based origin-ref-freshness signal proves warranted.

## MINOR (acknowledged — pre-existing pattern, follow-up)
- **X4 — `date -r <file>` is GNU-specific.** BSD/macOS `date -r` expects an epoch, not a path, so a macOS host would emit `origin_ref_age_h: unknown` → STALE. The *existing* collector already uses `date -r <file>` for `context_md_mtime` (line 111), and the only non-Linux roster machine (`macbook-portable`) is `status:unreachable`. Best addressed as a separate portability pass covering both `date -r` sites (GNU `date -r` + BSD `stat -f %m` fallback).

## Disposition
2 MAJOR + 1 MINOR fixed in-branch (r-inline). 1 MAJOR + 1 MINOR acknowledged with rationale (no clean fix / pre-existing + unreachable). Cross-provider review converged on the FETCH_HEAD semantics (Claude N3 = Codex X3).
