### Verdict: MAJOR

### Summary
Plan is thorough, well-structured, and responsive to three prior review rounds — the v4 empty-denominator fix, subdirectory-scoped conftest, and scipy attestation correction all land cleanly. However, the newly added session-hook regression test (introduced to close r3 Claude's "AC injection mechanism unspecified" finding) has concrete defects in its subprocess invocation that will prevent it from actually exercising the hook under test, and the conftest.py pseudocode omits the env-seam the regression test depends on. These are real v4 regressions, not nits.

### Issues Found
- [P1] test_session_hook_fails_run_on_injected_violation uses `-p scripts.data.llm-wiki.tests.markdown_qa.conftest` as the plugin argument, but (a) Python module paths cannot contain hyphens, so `llm-wiki` is not importable as a dotted name — the subprocess will fail with ModuleNotFoundError before the hook runs; (b) pytest `-p` loads plugins, not conftest.py files by dotted path (conftest autodiscovery is triggered by rootdir/collection path). The plan elsewhere acknowledges the hyphenated-package problem and solves it via `importlib.util.spec_from_file_location`, which makes the inconsistency here more visible. As specified, the regression test will not actually invoke the session hook it claims to verify — which means the AC-regression mechanism is still effectively unspecified, reopening r3 Claude's P3.
- [P2] conftest.py pseudocode hardcodes `ARTIFACTS_DIR = Path(__file__).parent / '.artifacts' / 'per-topic'`, but the regression test depends on a `MARKDOWN_QA_ARTIFACTS_DIR` env override that is only mentioned parenthetically ('narrow test seam added to conftest.py'). The env-read is not in the conftest pseudocode, so two implementers following the plan exactly would produce a conftest the regression test cannot exercise.
- [P2] The 24-hour-delay self-review escape hatch permits the reviewer at T0+24h to `read the current html_to_markdown output for comparison` (step 2 of §Solo-contributor escape hatch). This weakens the blinding discipline — the point of blinding is to prevent oracles from drifting toward converter behavior, but explicit comparison-against-converter during the sign-off commit is exactly that drift vector. The first commit is blinded; the second sign-off is not. This is not flagged in Risks or Non-goals as a protocol concession; it is presented as equivalent to two-reviewer sign-off, which it is not.
- [P3] `test_oracle_has_second_reviewer` verifies the ≥24h interval for sentinel entries by inspecting `git log --format=%aI -- <oracle_md_path>`. In shallow CI clones (GitHub Actions default `fetch-depth: 1`, most third-party runners), the fixture's authoring commit will not be reachable — the test will either pass spuriously (no history → no assertion) or fail structurally. Mitigation requires either pinning `fetch-depth: 0` or storing the two timestamps in the manifest alongside the sentinel rather than derived from git history.
- [P3] Collection-count ACs rely on `grep -cE "^[^ ]+::test_"` against `pytest --collect-only -q` output. Pytest's `-q` mode output is format-unstable across versions and terminal widths (parametrized IDs with long slugs can wrap). Prefer `pytest --collect-only --quiet -q -p no:cacheprovider` with a guaranteed one-line-per-test format, or count via `pytest --collect-only --quiet -q | grep -c '::'` which tolerates ID variation. As written, the ACs are brittle to environmental differences.
- [P3] `test_rubric_scorer_handles_empty_oracle_and_actual` (structural test #12) is documented in prose as covering both dims 2–5 both-empty → 1.0 AND asymmetric oracle-empty/actual-nonempty → 0.0, but there is no assertion listed for the other asymmetric quadrant (oracle-nonempty / actual-empty). The helper falls through to `0 / max(|oracle|, 1) = 0.0` so the behavior is correct, but since test #12 is the sole guard on the helper's contract, the test should assert all four quadrants explicitly to prevent regressions.

### Suggestions
- Replace the subprocess regression test with an in-process invocation of `pytest_sessionfinish` using a mock/stub `_pytest.main.Session` object and a `tmp_path`-redirected ARTIFACTS_DIR. This is simpler, faster, needs no `-p` plugin gymnastics, sidesteps the hyphenated-module issue entirely, and still pins the AC injection mechanism. Alternatively, if a subprocess is preferred for isolation, copy markdown_qa/conftest.py into tmp_path before invoking pytest there and drop the `-p` flag.
- Add the `MARKDOWN_QA_ARTIFACTS_DIR` env-seam directly to the conftest.py pseudocode, e.g., `ARTIFACTS_DIR = Path(os.environ.get('MARKDOWN_QA_ARTIFACTS_DIR', Path(__file__).parent / '.artifacts' / 'per-topic'))`, so the regression test's environmental contract is visible at the point of consumption.
- Tighten step 2 of the solo-reviewer escape hatch: the T0+24h review MUST be against HTML + live rendering again, NOT against converter output. The 24h window provides detachment; permitting converter comparison at sign-off is a separate, weaker concession that should either be excluded or called out explicitly as a blinding relaxation in Risks.
- Store `oracle_authored_at` and `oracle_reviewed_at` as manifest fields for sentinel entries, then have test #8 compare those two fields rather than parsing git log. This makes the 24h check independent of clone depth and cheaper in CI.
- For structural test #12, assert all four quadrants explicitly: (both empty → 1.0), (oracle empty, actual non-empty → 0.0), (oracle non-empty, actual empty → 0.0), (both non-empty with partial match → expected ratio). Currently only the first two are named.
- Consider adding a Risks entry noting that `test_heading_preservation_detects_reordering` uses exact expected values (tau ≈ 0.333, K ≈ 0.667, Score ≈ 0.9) that are version-dependent on scipy's kendalltau; assert a range or tolerance rather than a specific float.
