This is a process-correctness blocker — the plan cannot proceed to user-approval bookkeeping until those findings are addressed and the table is updated honestly.

2. **Issue deliverable "temperature/stress/warpage-style plots" is unplanned.** Issue #2511 body (verified via `gh issue view 2511 --json body`): *"Output temperature/stress/warpage-style plots and an engineering report."* Plan §Files to Change (lines 213–227) creates `package_stackup.svg` (input schematic), `mesh_summary.csv`, `benchmark_summary.json`, two `.inp` decks, and a Markdown report — no temperature/stress/warpage result plots. §Pseudocode `render_report` (lines 203–207) embeds "generated tables and simple SVG/ASCII schematic references" — still no result plots. §TDD Test List (lines 230–246) has no test asserting result-plot artifacts. A stated issue deliverable has zero plan coverage. (Concurs with prior Codex review Finding 1.)

3. **Engineering code-registry retrieval used the wrong path.** §Resource Intelligence (line 26): *"`data/document-index/code-registry.yaml` | missing | Plan must not depend on this registry for implementation discovery."* The canonical engineering registry under the workflow's engineering bundle (`docs/plans/README.md` line 52) is `data/design-codes/code-registry.yaml`, which exists (3512 bytes; verified by `ls -la`). The plan checked one path, found nothing, and stopped — and the engineering-class retrieval contract (#2208 / `docs/plans/README.md`) requires the registry to be consulted, not declared absent. (Concurs with prior Codex review Finding 2.)

4. **Acceptance Criterion "suitable for a small CalculiX demonstration" is unfalsifiable as written.** Line 255: *"Generated `.inp` files document units and contain mesh/material/step sections suitable for a small CalculiX demonstration."* But §Scope (line 146) and the optional-solver test (`test_optional_solver_wrapper_skips_cleanly_when_ccx_missing`, line 244) declare `ccx` execution explicitly optional and skip-safe. With no mandatory ccx-smoke gate before merge, this criterion can be ticked while shipping a deck that ccx rejects. Either add a manual or guarded-mandatory smoke step (e.g., when `shutil.which("ccx")` is non-None on the author's machine, fail commit on solver-rejection) or weaken wording to "contains required sections" to match what tests actually verify. (Concurs with prior Codex review Finding 3.)

5. **Pseudocode internal inconsistency on mesh layout.** Lines 163–164: `PackageLayer` carries a per-layer `mesh_divisions_z`. Lines 180–181: `structured_hex_mesh(spec)` says *"create nodes on regular x/y/z grid"*. A regular grid forces a single z-pitch globally; per-layer z-divisions imply a non-uniform z. The implementation will have to abandon one of the two specifications. The plan does not say which, so two implementations could legitimately diverge — and the test `test_structured_hex_mesh_counts_and_sets` then either over-fits to one or the other.

6. **Forward-dated review artifact paths do not match observed filenames.** Header line 7 and Artifact Map lines 123–127 advertise `scripts/review/results/2026-04-27-plan-2511-{claude,codex,gemini,disagreement}.md`. None of those four files exist. The actual reviews of *this same 2026-04-27-titled plan* are at `scripts/review/results/2026-04-26-plan-2511-{claude,codex,gemini}.md` (verified via `head` showing `Read inline plan docs/plans/2026-04-27-issue-2511-...`). The plan's artifact bookkeeping does not match its own review-artifact reality, and Acceptance Criterion #1 ("Canonical plan and review artifacts exist") is therefore vacuously unprovable on the path it advertises.

7. **`test_cli_regenerates_expected_artifacts` lacks an invariant.** Line 243: *"CLI can regenerate all committed artifacts in a temp output directory"*, expected output: *"expected files exist and summary matches schema"*. The committed artifacts at `data/semiconductor/package_fem_benchmark/` are themselves outputs of this same generator. If the test only checks that files appear in `<tmp>`, it is circular — any change to the generator silently mutates committed artifacts without test-detected drift. If the test must diff `<tmp>` against the committed tree, the plan needs to say so. As written, neither contract is stated, and the regen-vs-committed drift problem is unaddressed.

8. **Material constants ship without provenance hooks.** Lines 142–143 and 178: a "Material table with SI units: elastic modulus, Poisson ratio, CTE, thermal conductivity" with "representative educational material values, not proprietary data". The repo's calc-citation contract (`.claude/rules/calc-citation-contract.md` and the workspace memory entry on #2481) requires citation emission for standards-derived constants and fail-closed validation. The plan correctly avoids JEDEC/IPC overclaiming, but elastic modulus / CTE / k for Cu / Si / FR-4 / mold compound are conventionally sourced from material handbooks; "educational" framing alone does not relieve the citation requirement, and the plan offers no Citation sidecar, no source list per material, and no test that material values are traceable. At minimum the plan should declare that the materials section ships with a per-material `source` field in `benchmark_summary.json` and that tests assert its presence.
