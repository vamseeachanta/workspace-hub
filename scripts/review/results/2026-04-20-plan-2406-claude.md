### Issues Found
- [P2] test-count inaccuracy: Acceptance Criteria claim "all 25 existing cases still green" but `grep -cE "^# ── T[0-9]+:" tests/review/test-submit-scripts.sh` returns 22. Should be "all 22 existing cases still green" or (after additions) "all 25 cases including T26/T27/T28".
- [P2] pipefail semantics not documented: the new `printf '%s' "$p" | timeout … codex exec -` pipeline interacts with `set -euo pipefail` at submit-to-codex.sh:6. Plan should explicitly state that pipefail is active and that `${PIPESTATUS[1]}` (codex's exit) is what gets captured via the existing `|| exec_exit=$?` pattern — not printf's exit (always 0). Not a bug in the fix, but undocumented assumption.
- [P3] guard-interaction: plan does not explicitly state that the `CODEX_MAX_PROMPT_CHARS=120000` pre-truncation guard at submit-to-codex.sh:216 runs BEFORE `run_codex_exec` and is unaffected by the fix. Readers may wonder if stdin delivery obviates the guard; it does not (argv is no longer constrained, but truncation is still useful for prompt-context-window limits).
- [P3] codex-version compatibility: plan does not specify a minimum codex CLI version that documents `-` positional support. The current installed version does (verified via `codex exec --help` in the Evidence block), but future reviewers may want an explicit minimum-version claim or a runtime fallback.
- [P3] exit-code AC coverage: AC "No change to exit-code semantics (1/2/3/5/6)" — T07 covers exit 2, T01/T02/T03/T24 cover exit 1, but quota (3), NO_OUTPUT (5), and renderer fail (6) are not explicitly regression-tested. Not a new gap introduced by this plan, but the AC implies verification that isn't happening automatically.
