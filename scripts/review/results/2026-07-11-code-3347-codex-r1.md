# Issue #3347 implementation review — Codex r1

**Reviewed commit:** `bd42c9464`  
**Verdict:** REQUEST_CHANGES

## Findings

1. **MAJOR:** `--machine` could select another Linux host's schedule while still writing the local crontab.
2. **MAJOR:** rollback reacquired the advisory lock but could overwrite a non-cooperating concurrent writer without comparing current state to the post-write snapshot.
3. **MAJOR:** character-boundary `command_token` matching also matched assignment and redirection uses of the configured path, allowing unrelated lines to be claimed.
4. **MAJOR:** validator treated substring-based `owner_repo` as cwd identity.

## Test-first disposition

- Linux reconciliation will require requested canonical machine == physical canonical machine; Windows guidance will remain non-mutating.
- Rollback will compare current crontab to the captured post-write state and abort rather than overwrite concurrent changes.
- Ownership will require an adjacent tokenized `[python, catalog_delta.py]` sequence plus exact cwd basename.
- `owner_repo` will remain an optional matcher field but will not satisfy the required cwd identity class.
- Exclusive backup creation will write content in the same `x`-mode open and fsync it.
