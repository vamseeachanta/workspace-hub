## MINOR findings

### [MINOR-1] Smoke test #3 inverts the regression sentinel logic

**File:** `tests/ci_smoke/test_workspace_hub_importable.py` (planned)

The plan describes `test_workspace_hub_import_fails_without_pythonpath_src` as a regression sentinel: "if someone adds a real `__init__.py` upstream, this catches it." But that's exactly backwards — adding a real `__init__.py` to `src/workspace_hub/` would NOT make `import workspace_hub` succeed without PYTHONPATH=src; it still requires `src/` on sys.path.

What the test actually catches: someone installs a sibling `workspace-hub` PyPI package (or creates `workspace_hub/` in repo root), at which point the import would START succeeding without PYTHONPATH and the sentinel fires.

**Why it matters:** the test is correct mechanically but the docstring/comment will mislead future readers and reviewers.

**Suggested fix:** rewrite the rationale comment to say "this fails if a colliding `workspace_hub` ever appears earlier on sys.path (e.g., site-packages install)" rather than "if someone adds __init__.py upstream."

### [MINOR-2] `_ms_now` fallback chain has a precision-loss case but no warning

**File:** `scripts/enforcement/require-review-on-push.sh` (planned helper)

The pseudocode's third branch (`echo $(( $(date +%s) * 1000 ))`) silently drops millisecond precision. Latency telemetry consumers (audit cron) may compute distributions that get long-tail-distorted by these zero-precision entries, with no signal in the JSONL that the entry is degraded.

**Why it matters:** memory `feedback_attestation_enables_contradiction_detection` warns that silent fallbacks make plan-vs-live-state contradiction detection harder. A degraded telemetry entry is indistinguishable from a real low-latency entry.

**Suggested fix:** when falling through to the last branch, append `"_precision":"seconds"` to the JSONL line OR emit a one-line warning to stderr. Plan's "Open" section already flags this — promote to a MUST in implementation.

### [MINOR-3] Acceptance criterion "demonstrate by re-running enforcement-gate workflow" needs a concrete branch

**File:** plan §Acceptance Criteria

"PR CI on a re-trigger of #2530-style change is green" — both PRs are MERGED. There is no live PR to re-trigger. `workflow_dispatch` of enforcement-gate.yml on main wouldn't exercise the same code paths (no merge-base diff with itself).

**Why it matters:** non-actionable acceptance criterion → cannot verify PASS.

**Suggested fix:** rephrase to "open a draft PR with a no-op change (touch a docs file) and confirm `Stage Prompt Drift Guard` and `Review Evidence Check` both report SUCCESS." Or: "add the smoke tests to `Baseline Testing > Run Tests` and confirm green on the implementation PR itself."
