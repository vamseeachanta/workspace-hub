1. Plan can close without satisfying the Gemini half of the issue. `Deliverable / Phase 2c` says if Gemini has no import support, “document the limitation explicitly in `GEMINI.md`; SOUL rules remain by-reference-only for Gemini,” and Acceptance Criteria allows “Empirical Gemini session test … or limitation explicitly documented if Phase 2c.” That contradicts the plan title, “Auto-load SOUL.runtime.md into Claude + Gemini session surfaces.” This is not an implementation of Gemini auto-load.

2. The Gemini research branch is stale against official docs. The plan’s `Resource Intelligence Summary / Gaps identified #2` says Gemini import syntax “requires research before approach selection,” and `Phase 2c` assumes Gemini may have no import support. Official Gemini CLI docs document `GEMINI.md` imports using `@file.md` syntax. The plan should remove the no-autoload acceptance path and specify the actual Gemini import mechanism to test.

3. The Claude empirical-test sequence is internally contradictory and risks pushing bad wiring. `Deliverable / Phase 1` says “If verified, commit,” but `Pseudocode / Phase 1 — Claude` says edit `CLAUDE.md`, commit, push, then run the manual fresh-session test. If `@config/agents/claude/SOUL.runtime.md` fails, the plan has already published an unverified runtime instruction.

4. The drift-check negative test is wrong. `TDD Test List / Drift-check regression test` says “Manually break wiring (remove @import line from CLAUDE.md)” but the shown command is `git stash -- CLAUDE.md` before running the drift check. Stashing the modified file restores the clean committed file, so the drift check will see healthy wiring, not the broken case. This does not verify the new enforcement.

5. The fallback claim overstates evidence. `Resource Intelligence Summary / .claude/rules/ as a proven auto-load surface` proves regular `.claude/rules/*.md` files were materialized, but `Artifact Map` proposes `.claude/rules/SOUL.runtime.md` as a symlink to `config/agents/claude/SOUL.runtime.md`. The plan does not cite evidence that Claude Code follows symlinked rule files or reads the target content rather than ignoring or reporting the symlink path. The fallback test exists later, but the risk table calls the fallback “proven.”

6. The plan labels the work `Complexity: T2` while requiring T3 review artifacts. The header says `Complexity: T2`, `config/agents/SHARED_SOUL.md` says T2 maps to 2 providers and T3 maps to 3 providers, but Acceptance Criteria requires “T3 adversarial plan review: Claude + Codex + Gemini.” This is gate ambiguity: either classify it T3 because it is cross-provider/systemic, or keep T2 and align review requirements.

7. The planned drift assertion conflicts with the allowed Gemini limitation branch. `Artifact Map / Drift detection` says `check-soul-runtime-drift.sh` will verify `GEMINI.md` references the runtime artifact, while `Deliverable / Phase 2c` permits documenting that Gemini remains by-reference-only. Those cannot both be true without conditional logic and a defined limitation marker.
