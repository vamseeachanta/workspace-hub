# Codex review — plan #2312

**Verdict:** MAJOR

**Strengths**
- The plan correctly identifies the real contradiction: [.planning/templates/stage-evidence-template.yaml](/mnt/local-analysis/workspace-hub/.planning/templates/stage-evidence-template.yaml) still points `Close`/`Archive` at deleted lifecycle scripts, while [docs/work-queue-workflow.md](/mnt/local-analysis/workspace-hub/docs/work-queue-workflow.md) already says those helpers are not part of the live workflow.
- It mostly separates live current surfaces from intentional legacy/reference surfaces, especially by preserving [docs/ops/legacy-claude-reference-map.md](/mnt/local-analysis/workspace-hub/docs/ops/legacy-claude-reference-map.md).
- The issue is bounded enough to stay out of the larger wrapper/allowlist redesign tracked by #2213 and #2214.

**Gaps**
- The plan leaves the central contract unresolved: what exact `evidence:` value should replace `scripts/work-queue/close-item.sh` and `scripts/work-queue/archive-item.sh` in the stage template? Without that, the implementation and tests are underspecified.
- The proposed file list is not evidence-tight. [docs/work-queue-workflow.md](/mnt/local-analysis/workspace-hub/docs/work-queue-workflow.md) already states the correct current model and is already covered by [tests/docs/test_banned_stale_references.py](/mnt/local-analysis/workspace-hub/tests/docs/test_banned_stale_references.py). The plan does not show an actual stale lifecycle-script hit there that requires editing.
- Same problem for [notes/agent-work-queue.md](/mnt/local-analysis/workspace-hub/notes/agent-work-queue.md): it already declares GitHub labels as source of truth and refresh helpers as the regeneration path. The plan treats it as “modify if needed” instead of proving a needed change.
- `docs/plans/README.md` is already indexed for issue `2312` on `main`, so “add this plan to index” is stale plan metadata, not current evidence.
- The acceptance criterion for the refreshed provider-session audit is not measurable. A refresh alone is not success. The plan never states what audit outcome would validate the cleanup, especially if historical/allowlisted references still produce reads.

**Risks**
- The implementation may invent a new close/archive evidence contract ad hoc, then write tests around that invention rather than around an existing authoritative workflow contract.
- A bespoke targeted test may duplicate existing stale-reference coverage instead of extending it cleanly, increasing maintenance and masking whether strict coverage should be promoted later.
- The audit-refresh step may create noise: intentional historical surfaces can still be read, so counts may not materially drop even if live guidance is fixed.

**Missing tests**
- A deterministic test for the exact replacement authority in `.planning/templates/stage-evidence-template.yaml` once chosen, not just “no deleted strings found.”
- A test that the replacement `Close`/`Archive` evidence entries are non-placeholder and match an explicitly approved authority contract.
- A test proving only the intended current surfaces are protected by the new targeted scan, so this issue does not quietly absorb broader #2213 strict-coverage expansion.

**Scope creep concerns**
- Editing [docs/work-queue-workflow.md](/mnt/local-analysis/workspace-hub/docs/work-queue-workflow.md) and [notes/agent-work-queue.md](/mnt/local-analysis/workspace-hub/notes/agent-work-queue.md) without evidence they still contain stale lifecycle-script guidance.
- Touching [tests/helpers/stale_reference_docs.py](/mnt/local-analysis/workspace-hub/tests/helpers/stale_reference_docs.py) when current patterns already include lifecycle scripts; helper changes may broaden policy rather than solve this issue.
- Letting “refresh provider-session audit” turn into a broader audit-methodology or legacy-surface cleanup issue.

**Weakest assumption and what breaks if it is false**
- Weakest assumption: there is already an agreed canonical replacement for final-stage `evidence:` fields in the stage template.
- If false, the issue is not a cleanup task anymore; it becomes a contract-definition task, and the proposed tests become arbitrary.

**Most likely implementation failure mode**
- The author patches only `.planning/templates/stage-evidence-template.yaml`, adds a narrow regex test, and optionally tweaks nearby docs, but never resolves what the authoritative close/archive evidence should actually be. The repo goes green while the workflow contract stays ambiguous.

**Most likely test gap**
- The new test only bans old script names and checks for vague anchor presence, so meaningless replacements like a generic `.planning/` string or another unstable artifact path still pass.

**Future issues suggested**
- Define the canonical close/archive evidence contract for stage templates if the team cannot name exact replacement anchors during planning.
- Promote newly cleaned current files into the existing strict stale-reference suite under #2213 instead of leaving long-term bespoke tests.
- If audit counts remain noisy after cleanup, create a follow-on to distinguish intentional legacy-reference reads from live-guidance reads in the provider-session audit.

**Review confidence**
- Medium. I verified the current repo surfaces via GitHub-backed file reads and the issue text, but I could not read the local workspace directly because shell access was blocked in this session.
