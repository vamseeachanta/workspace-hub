### Issues Found (MINOR)

- **PyYAML dependency risk.** The plan relies on 'uv run python' to parse YAML and addresses missing PyYAML via troubleshooting documentation ('uv add pyyaml'). Running 'uv run python -' does not guarantee PyYAML is available. If 'uv' is present, the script should use 'uv run --with pyyaml python' to ensure the dependency is dynamically provided, avoiding manual environment mutation.
- **Redundant damBreak filter.** The wrapper explicitly invokes the runner with '--tutorials <list>' but is also instructed to 'filter out damBreak' during YAML normalization. Since the runner only executes the tutorials it is told to via the list, damBreak will never be in the output unless explicitly requested, making the post-run filtering redundant and confusing.

### Suggestions
- Change the wrapper's python invocation to `uv run --with pyyaml python -` to guarantee the yaml module is present without requiring manual operator intervention.
- Remove the 'filter out damBreak' step from the wrapper's normalizer logic, and instead rely entirely on passing the correct '--tutorials' argument to the runner.
- Consider migrating the intermediate runner-to-wrapper handoff format to JSON in the future to completely remove the need for external parsing libraries.

### Questions for Author
- Why does the wrapper need to explicitly filter out 'damBreak' from the parsed YAML if the wrapper itself is already passing an explicit '--tutorials' list that excludes it?
- Instead of documenting a failure mode for `ModuleNotFoundError: yaml`, can we just use `uv run --with pyyaml` to inject the dependency ephemerally?
