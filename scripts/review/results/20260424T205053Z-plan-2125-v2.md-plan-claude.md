### Verdict: MAJOR

### Summary
Strong v2 that cleanly closes the r1 Codex findings (output-root hygiene, all-three-surface refresh, cron split, P3 edge cases) and carries a solid Attested Evidence block. Remaining gaps are localized spec ambiguities — HEAD-request failure handling mismatch between caller and helper, unstated pytest discovery mechanism for the new sibling-import tests, under-specified cross-product merge schema, and a fragile PDF-deletion path — all fixable in-plan without rescoping.

### Issues Found
- [P2] Feasibility — `head_pdf` / caller contract mismatch. Caller in `ingest_papers` guards with `if (cached and head ...)`, implying `head_pdf` returns `None` on failure. But the `head_pdf` pseudocode does `with urllib.request.urlopen(req, timeout=15) as resp: return {...}` with no try/except. A single 405/403/timeout on one PDF HEAD will crash the whole refresh. Either wrap in try/except and return `None`, or make the caller catch. Risks section says refresh 'falls back to download-and-hash-compare' but the control flow does not express that fallback.
- [P2] Testing — pytest discovery mechanism for sibling-import tests is not documented. The new `test_ingest_orcina_refresh.py` and `test_orcina_version.py` must import `orcina_refresh` / `orcina_version` from the parent dir. Plan asserts 'bare sibling imports work' and cites the existing `test_resolve_wiki_path.py` (185 lines, confirmed in attestation), but does not state HOW discovery works (conftest.py? sys.path hack? pytest rootdir?). Without an explicit reference, an implementer may reinvent and drift. Add one line citing the existing mechanism by file+line, or add a conftest.py row to Files-to-Change.
- [P2] Completeness — `merge_of_per_product_changes` is left as a placeholder. Three products feed the product-topics surface, but the changelog payload only shows `product_topics: {added, removed, modified}` as a merged blob. Without product attribution, a reader cannot tell whether a removed URL belonged to orcaflex vs orcawave vs orcfxapi. Lock the schema now (e.g. `{orcaflex: {added, removed, modified}, orcawave: {...}, orcfxapi: {...}}`) and update the relevant TDD row.
- [P2] Feasibility — PDF deletion path is fragile. `(papers_dir / stored_meta[url]['entry']['file'].split('/')[-1]).unlink()` assumes a specific schema for `entry['file']`. If a legacy `papers_meta.json` is missing the `entry` key (older run, or hand-edited), this raises `KeyError` during prune. Also no test covers this branch. Define the `papers_meta.json` entry schema explicitly, and add a defensive lookup + a test for legacy/partial meta.
- [P3] Atomicity — `write_changelog` uses 'atomic_write_json-equivalent for markdown'. Introduce a named `atomic_write_text` helper and bind the TDD row `test_refresh_changelog_write_is_atomic` to it explicitly rather than an 'equivalent'.
- [P3] Decision churn risk — same-day + same-version changelog collision (`<date>-<version>-T<HHMMSS>.md` suffix) is 'deferred to implementation'. Picking the rule now avoids a second review cycle later. The filename template is a 15-line decision, not an implementation discovery.
- [P3] Minor inconsistency — `fetch_conditional` uses `timeout=30`; `head_pdf` uses `timeout=15`. Justify the asymmetry in a comment or unify to a single configured constant at module top.
- [P3] Concurrency is unmentioned. Two concurrent `--refresh` invocations on the same output root would race on `index.json` / meta side-files. Even if out-of-scope for this plan, add a single 'single-writer invariant — caller must serialize' line to Risks so the follow-on cron wrapper inherits a clear contract.

### Suggestions
- Add a one-line pytest discovery reference in Artifact Map or Files-to-Change: either 'follows existing pattern at scripts/data/llm-wiki/tests/conftest.py line N' or a new conftest.py row if none exists.
- Change `head_pdf` pseudocode to explicit `try: ... except (HTTPError, URLError, socket.timeout): return None` so the caller's `and head` guard is satisfied by construction; add `test_head_pdf_network_failure_returns_none` and `test_refresh_falls_back_to_download_when_head_fails`.
- Promote `merge_of_per_product_changes` to a concrete schema in Pseudocode and Deliverable, with changelog markdown section template (e.g. '### Product: OrcaFlex — Added (N) / Removed (M) / Modified (K)'). Update `test_refresh_records_supplementary_changes_in_changelog` sibling rows to assert per-product attribution for product-topic changes.
- Document `papers_meta.json` entry schema explicitly in Pseudocode (keys: `last_modified`, `content_length`, `bytes_sha256`, `entry.file`, `entry.title`, `entry.source_url`) and add a TDD row `test_refresh_prunes_legacy_papers_meta_without_entry_key` that exercises the defensive branch.
- Introduce an explicit `atomic_write_text(path, text)` helper next to `atomic_write_json`; bind the changelog-atomicity TDD row to that symbol for unambiguous mocking.
- Lock the same-day+same-version filename rule in-plan: suggest `<date>-<version>-T<HHMMSS>.md` unconditionally when a prior file exists, not 'decide at implementation'.
- Extract timeouts to a single module-top constant (or dict) — `FETCH_TIMEOUT_S = 30`, `HEAD_TIMEOUT_S = 15` — and reference both from the helpers for traceability.
- Add one sentence to Risks: 'Single-writer invariant — two concurrent `--refresh` invocations on the same output root are unsupported; the follow-on cron wrapper will provide a flock. Interactive users must serialize manually.'
