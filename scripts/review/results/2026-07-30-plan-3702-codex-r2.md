### Issues Found
- MAJOR: The plan’s claim that “No Windows file is touched, so no Windows regression is possible” is false. Plan `docs/plans/2026-07-30-issue-3702-equality-artifacts-out-of-tree.md:306` says Windows is separate, but `scripts/readiness/collect-equality.ps1:196-206` delegates directly to `collect-equality.sh`, whose current default output is `STATE_DIR="${WS}/.claude/state"` at `scripts/readiness/collect-equality.sh:18`. If Phase 1 changes that shell default out-of-tree while leaving `collect-equality.ps1` unchanged, Windows collection no longer preserves the current in-tree contract.
- MAJOR: `scripts/windows/equality-report.ps1` will break or publish stale artifacts under the Phase 1 plan. It invokes the PowerShell collector without any state-dir seam at `scripts/windows/equality-report.ps1:372-377`, then requires `.claude/state/equality-$Machine.yaml` at `scripts/windows/equality-report.ps1:306-308`, and with `-RefreshMatrix` commits report paths from `Get-MatrixReportPaths` at `scripts/windows/equality-report.ps1:111-117` via `scripts/windows/equality-report.ps1:313-314`. The plan explicitly excludes `scripts/windows/*.ps1` and `scripts/readiness/collect-equality.ps1` at plan line 302 and acceptance line 364, so it does not update the caller that depends on the old locations.
- MAJOR: The reader grep is incomplete for Phase 1 safety. Active scripts under the requested search scope still hard-code the in-tree artifacts: `scripts/readiness/refresh-equality-matrix.ps1:54-59` calls `equality-report.ps1 -RefreshMatrix`, then reads `.claude\state\equality-*.yaml` at `scripts/readiness/refresh-equality-matrix.ps1:63-65`; `scripts/readiness/gap-actions/ace-win-2/01-refresh-curation-and-matrix.sh:47-48` runs Windows curation and equality report, then stages `.claude/state/equality-${MACHINE}.yaml` and `docs/reports/*machine-equality-matrix.html` at `scripts/readiness/gap-actions/ace-win-2/01-refresh-curation-and-matrix.sh:52-65`. The plan acknowledges these as readers in the dedicated-ref alternative at plan line 214, but Phase 1 excludes the Windows files.
- MINOR: The proposed cron preflight is not serialized with the publisher and the existing publisher lock cannot provide fleet-level serialization. Plan line 219 says no cross-host serialization lock is proposed. The actual lock is per host, `publish-equality-${HOST}.lock`, at `scripts/readiness/publish-equality.sh:71-77`, so another host can push after this cron’s preflight but before `collect-equality.sh`/`publish-equality.sh` finishes. That can publish evidence stamped with `behind_main: 0` even though origin moved before the publish landed. The test list covers dirty/diverged local checkouts, but not this inter-host interleaving.
- MINOR: The TDD claim is not verified by the repo state. Plan line 313 says “Written and confirmed failing before any implementation,” but `tests/readiness/test_equality_tree_cleanliness.py` is absent, and `rg` finds none of the named cleanliness/FF-pull tests under `tests/readiness/`. Existing tests do cover pieces of the old behavior, such as `.claude/state` not self-triggering dirty at `tests/readiness/test_collect_equality.py:538-545` and `--json` writing no HTML at `tests/readiness/test_build_equality_matrix.py:525-549`, but the new RED suite is not present to inspect for non-vacuous failure modes.
