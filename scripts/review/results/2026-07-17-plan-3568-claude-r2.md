AC-10 enumerates roster coverage "from `config/workstations/registry.yaml` at execution time" — which silently drops `home-win`, exactly the stale-roster-hides-a-machine failure the plan claims to prevent. The contract must state the disposition: either #3567 adds `home-win` to the registry with explicit status, or removes it from the projection, and any projection-only machine must fail reconciliation loudly rather than vanish.

2. **AC-16's evidence requirement cannot be produced by the named tool.** AC-16 requires "the scan's non-empty target list plus exit 0 will be recorded", but `scripts/legal/legal-sanity-scan.sh` never prints its target list (`file_args` at lines 184-215 is consumed internally, no listing output) and its usage (lines 86-103) accepts no positional path arguments for a path-scoped scan. The operator would have to record `git diff --name-only HEAD` separately as a proxy; the plan should say that explicitly or the requirement is unfalsifiable as written.

3. **`test_legal_scan_passes` is vacuous after commit.** TDD row `test_legal_scan_passes` claims to verify "no restricted identifier… enters the artifacts", but `--diff-only` derives targets from `git diff --name-only HEAD` (`legal-sanity-scan.sh:187-188`) and returns 0 on an empty list — so once the artifacts are committed, the pytest passes forever without scanning anything. As a durable regression test it proves nothing; it only has teeth at pre-commit time. Specify it as a pre-commit/CI-diff gate check or scope it to assert scanner behavior on a synthetic fixture instead.

4. **`> **Project:** workspace-hub` misuses the template field's defined semantics.** Template line 8 defines `Project:` as "populate when plan scopes to a single project under the client; consumed by check-wiki-sibling-frontmatter.py Rule E", and `.claude/rules/wiki-sibling-routing.md` Rule D says projects exist only inside client wikis. With `Client: N/A`, the value `workspace-hub` is not a client project; the field should be blank/N/A. (Claude r1 finding 3 asked for the header *line*; the populated value introduces a new, smaller inconsistency.)

5. **The r2 Gemini expectation is contradicted by current environment state.** The review table (r2 row) says Gemini is "expected fresh auth preflight", but the on-disk r2 slot `scripts/review/results/2026-07-17-plan-3568-gemini.md` already contains an UNAVAILABLE failure ("no non-interactive gemini auth configured") identical in size to r1's.
