## Findings

1. **§Standards row 2 mis-cites #2731 as authority.** Plan claims `docs/plans/2026-05-19-issue-2731-data-repo-location-contract.md` "establishes adjacent sibling checkout model and forbids inline moves without approved transaction plans." That plan is itself `Status: draft` (line 3) and lists the canonical contract document `docs/standards/REPO_AND_DATA_LOCATION_CONTRACT.md` as `MISSING (new — this plan will create/update via implementation)` (line 69). Treating a still-draft contract-to-be-written as an "applicable" governance source is the past-tense / phantom-counter hazard the project already documents (`feedback_plan_past_tense_artifact_claims`). The sibling-checkout norm currently only exists as a proposed contract, not an enforced one.

2. **`tier1_baseline` schema is wholly undefined.** §Gaps identified line 42 and §Files-to-Change line 145 commit to adding a `tier1_baseline` projection to `config/workstations/registry.yaml`, but neither the pseudocode (lines 112-137), the test list, nor the acceptance criteria specify the YAML shape. Is it a flat list, a map `required: [...] / optional: [...] / non_tier1: [...]`, or a per-repo `role:` field on a repo dict? `test_dev_primary_tier1_baseline_matches_user_decision` (line 159) reads a "Registry fixture" without naming a key path. Implementer must invent the schema, which collapses the TDD claim — you cannot write failing tests against an unspecified shape.

3. **Pseudocode `discover_checkouts` will self-trip on `workspace-hub/.git`.** Line 129 says "scan workspace_root maxdepth 2 for direct nested .git repos." `workspace_root = /mnt/local-analysis/workspace-hub`, and `find /mnt/local-analysis/workspace-hub -maxdepth 2 -name .git` returns `/mnt/local-analysis/workspace-hub/.git` — workspace-hub's own repo .git at depth 1. No `-mindepth 2` rule, no self-reference exclusion, and no test (`test_no_direct_nested_git_repos_under_workspace_hub` at line 160 only describes a positive nested-repo fixture, not the self-exclusion case). A literal implementation will fail on the clean state the plan claims to defend.

4. **Worktree gitlink hazard (`.git` as a file, not a directory) is ignored.** The repo memory carries a specific rule [[feedback_worktree_gitlink_pollution]] and `.gitignore` already accommodates `.claude/worktrees/`. The plan's checker spec only describes "scan ... for .git repos" without distinguishing `.git/` directories from `.git` gitlink files left by parallel-agent worktrees. If a stray `agent-worktrees/<name>/.git` (file) appears under `workspace_root`, the checker either false-positives or false-negatives depending on how `-type` is set. No test case covers this; the hazard is already known and pre-existing per project memory.

5. **`data_access_profile.repos` reconciliation is undefined.** Registry line 44 lists `data_access_profile.repos: [workspace-hub, digitalmodel, assetutilities, worldenergydata, assethold, OGManufacturing]` — missing `llm-wiki` and including `OGManufacturing`. The plan reclassifies `OGManufacturing` as `non_tier1_machine_access` and adds `llm-wiki` to required, but neither pseudocode nor TDD list specifies whether `data_access_profile.repos` should be (a) mirrored to the new required set, (b) left as-is, or (c) computed from `tier1_baseline`. `test_registry_repos_reconcile_with_tier1_baseline` (line 164) asserts "no silent drift" without defining the reconciliation policy.

6. **Acceptance criterion §5 (line 175) is non-falsifiable.** "Completion leaves a reusable machine-placement pattern for subsequent workstation issues: consistent tier-1 repo folder structure, methodical primary/reference repo placement decisions, and repo harness/file ecosystem handling all routed through the single workstation registry authority." There is no test that can return pass/fail on "reusable pattern," "methodical placement decisions," or "routed through ... authority." Either delete it or convert each clause into a binary check (e.g., "registry contains a `placement_pattern_version: 1` key," "skill `per-machine-repo-placement-outcome-contract.md` cites the registry path").

7. **Readiness integration shape is unspecified.** §Files-to-Change line 147 commits to modifying `scripts/readiness/telegram_hermes_readiness.py`, and `test_missing_required_repo_blocks_readiness` (line 162) asserts `dispatchable=false`, but the plan never defines: (a) checker as imported module vs subprocess, (b) the field name added to the readiness payload, (c) the blocker class label that distinguishes placement-blockers from provider/env blockers (§Acceptance criterion line 176), or (d) whether the readiness JSON schema gets versioned. The current readiness script is 22KB; reviewers cannot judge fit without a target call site.

8. **Drift not addressed for unlisted siblings.** `ls /mnt/local-analysis` returns 18 entries: the 6 required, 2 optional, plus `aceengineer-admin`, `achantas-data`, `achantas-media`, `agent-worktrees`, `CAD-DEVELOPMENTS`, `hobbies`, `kaggle-rogii-2026`, `llm-wiki-acma`, `sabithaandkrishnaestates`, `teamresumes`. Pseudocode `discover_checkouts` (line 126) and `reconcile_repo_authorities` (line 120) say nothing about how these are classified (warn / ignore / fail / require explicit allow-list). The reconciliation rule "classify remaining machine-access repos such as OGManufacturing as non_tier1_machine_access" implies a single non-tier-1 bucket, but the registry has no field for unlisted siblings. The plan punts the most likely real drift case.

9. **`OGManufacturing` is on the registry but not on disk at `/mnt/local-analysis`.** `dev-primary.repos` lists it (line 35), `data_access_profile.repos` lists it (line 44), but `ls /mnt/local-analysis` does not show it. The plan reclassifies it as `non_tier1_machine_access` but does not specify whether the new checker should error on "registered repo absent from filesystem" or treat non-tier-1 absence as expected. `test_registry_repos_reconcile_with_tier1_baseline` (line 164) uses a fixture, not the live state — the live drift is not asserted by any test.

10. **T2 declared but review fanout is T3-shaped.** §line 7 lists 3 review artifacts (claude / codex / gemini) and the §Adversarial Review Summary table (lines 184-187) enumerates 3 providers. Per SHARED_SOUL.md, T2 = 2 providers. Either downgrade the review fanout to 2 providers or upgrade the complexity declaration. Currently the plan over-spends on review for its declared tier.

11. **Open question at line 197 conflates two independent gates.** "Whether #2770 should be closed as decision-complete after this execution plan reaches `status:plan-review`." #2770 closure is a labeling question and #2766 plan-review is the user-approval gate; tying them creates a circular dependency in which closing the decision issue arguably authorizes the plan and vice-versa. The plan should either commit to a closure rule or strike the open question.

12. **`test_optional_repo_absence_is_warning_not_failure` (line 163) hedges on outcome.** "Expected output: Pass or warning by policy, not failure." A TDD test must commit to a single expected output. "Pass or warning" makes the test unwritable; the implementer will pick whichever passes their implementation, which is the textbook tautological-acceptance-criterion failure mode (`feedback_attestation_enables_contradiction_detection`).

13. **Plan-index entry already exists; "Update `docs/plans/README.md` to index this plan" is past-tense drift.** §Files-to-Change line 151 calls for "Update `docs/plans/README.md` | Index this plan." The index entry is already present at line 207 of `docs/plans/README.md` (verified by grep). Either drop the row or restate it as "Refine the existing index row once status changes from draft." Same pattern as the past-tense-claim hazard above.

## Blockers

The plan cannot be implemented as written until the following are resolved:

- **F2** (`tier1_baseline` schema undefined) — implementer cannot write the registry change or the failing TDD tests.
- **F3** (workspace-hub/.git self-trip) — checker spec will produce wrong-by-default behavior on the clean state.
- **F4** (worktree gitlink hazard) — known-class defect surface left unspecified.
- **F5** (`data_access_profile.repos` reconciliation rule missing) — drift outcome undefined.
- **F6** (Acceptance criterion §5 non-falsifiable) — "done" cannot be measured.
- **F7** (Readiness integration shape unspecified) — cross-file contract missing.
- **F12** ("Pass or warning by policy" hedge) — test is unwritable as stated.

F1, F8, F9, F10, F11, F13 are MINOR refinements but do not block implementation once F2-F7 + F12 are resolved.

`★ Insight ─────────────────────────────────────`
- The single most common defect class in this plan is the **specification-deferred-to-implementation** anti-pattern: introducing a new field (`tier1_baseline`), a new integration point (readiness payload), and a new validation rule (nested-repo rejection) without specifying the contract shape. TDD only works if the test can fail before code exists; tests against fixtures that don't pin a key path or output shape will pass trivially against any implementation.
- A second pattern is **citing draft plans as authoritative**, which the project already has a memory rule against (`feedback_plan_past_tense_artifact_claims`). The 2766 plan would be substantially stronger if it explicitly inherited #2731's *gap statement* ("contract does not yet exist") rather than its *aspiration* ("contract establishes sibling checkout model").
- A third subtle issue is **scan boundary self-reference**: rules like "scan workspace_root for nested .git" need an explicit exclusion of the root's own `.git`, plus disambiguation of `.git`-as-file (worktree gitlink, parallel-agent residue) vs `.git`-as-directory. This is the same defect class that `scripts/enforcement/check-no-conflict-markers.sh` historically had to learn — see the SHARED_SOUL.md rule about "Enforcement scripts must not block their own artifacts."
