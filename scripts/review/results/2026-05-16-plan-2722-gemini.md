## Findings
1. **Self-blocking plan file.** Plan §Pseudocode (`check-no-conflict-markers.sh`) exempts `docs/governance/**`, but this plan itself is located at `docs/plans/2026-05-16-issue-2722-pre-commit-conflict-marker-hook.md` and contains bare `<<<<<<< ` strings in its own pseudocode blocks. The hook will block the commit adding this very plan, as it is not covered by the whitelist pattern or the self-exclude rule.
2. **Worktree incompatibility (Detection).** Plan §Pseudocode (`check-no-conflict-markers.sh`) checks for active merges using `exists .git/MERGE_MSG OR .git/REBASE_HEAD`. In git worktrees, `.git` is a file containing a reference pointer, not a directory. The check for `.git/MERGE_MSG` will fail, causing the hook to incorrectly block legitimate merge resolution commits inside worktrees. It must resolve the git directory via `git rev-parse --git-dir`.
3. **Working-tree state leakage.** Plan §Pseudocode (`check-no-conflict-markers.sh`) evaluates the forensic whitelist by running `grep -q "<!-- CONFLICT_MARKER_FORENSIC_OK -->" "$file"`. This reads the unstaged file from the working tree. If a user adds the sentinel but forgets to stage it, the hook will read the working tree, see the sentinel, and improperly allow the commit of unresolved markers without the sentinel included in the commit. It must evaluate the staged blob via `git show :"$file"`.
4. **False positive on nested blockquotes.** Plan §Pseudocode (`check-no-conflict-markers.sh`) triggers a violation if `lines_lt is non-empty OR lines_gt is non-empty`. The claim "require co-occurrence with either anchor" is violated by the `OR` condition. The anchor `^>>>>>>> ` is valid Markdown syntax for deeply nested blockquotes (7 levels). Because it does not strictly require co-occurrence with `<<<<<<< `, this logic will incorrectly block valid markdown files.
5. **Undefined `$REPO_ROOT` in minimal stub.** Plan §Pseudocode (`install-pre-commit-hook-cross-repo.sh`) states `if not exists PRE_COMMIT: create minimal stub`, and then immediately appends a block executing `bash "$REPO_ROOT/scripts/enforcement/check-no-conflict-markers.sh"`. Because a newly created minimal stub does not define `$REPO_ROOT`, the path will evaluate to `/scripts/enforcement/...` and fail to execute.
6. **Worktree incompatibility (Installer).** Plan §Pseudocode (`install-pre-commit-hook-cross-repo.sh`) defines the hook target as `PRE_COMMIT = "$REPO_PATH/.git/hooks/pre-commit"`. In git worktrees, `.git` is a file and the `.git/hooks` directory does not exist. The installer will fail to wire the hook for sibling repos checked out as worktrees. It must determine the hooks directory via `git -C "$REPO_PATH" rev-parse --git-common-dir` or `--git-dir`.
7. **Invalid hashing command.** Plan §Pseudocode (`check-pre-commit-hook-drift.sh`) generates hashes using `CANONICAL_SHA = sha256(CANONICAL)`. The command `sha256` does not natively exist on standard Linux or macOS systems (the standard is `sha256sum` or `shasum -a 256`), which will cause the drift check to fail unconditionally.
8. **Unsafe space handling in filenames.** Plan §Pseudocode (`check-no-conflict-markers.sh`) iterates over staged files with `for file in STAGED`. If `STAGED` is expanded in bash natively, word-splitting will break filenames containing spaces into invalid partial paths, causing `git show` to fail or evaluate the wrong files. Iteration must use a `while IFS= read -r` loop or `git diff -z`.
