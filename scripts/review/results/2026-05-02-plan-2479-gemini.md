## Findings
1. **Guard bypass for alpha versions (MAJOR).** Plan section §Pseudocode lines 104-105 enforces `[[ "$ver" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]]`. For alpha releases like `0.129.0-alpha.1` (which the plan acknowledges contain the regression), this regex will fail and the guard returns `rc=2` ("unparseable"). Plan section §Pseudocode lines 149-152 shows the wrapper integration only fast-fails on `rc=3`. Thus, `rc=2` falls through the guard, calling the hanging `codex exec` binary and exposing the user to the exact regression this plan intends to fix.
2. **Undefined variable crash in fanout worker (MAJOR).** Plan section §Pseudocode line 144 instructs `plan-review-fanout.sh` to source `. "$LIB_DIR/codex-version-guard.sh"`. However, `LIB_DIR` is never initialized in `plan-review-fanout.sh` (the script correctly uses `SCRIPT_DIR`). This will expand to `. /codex-version-guard.sh`, fail to source the library, and crash the fanout orchestrator worker under `set -e`.
3. **Broken PATH logic during new-machine bootstrap (MAJOR).** Plan section §Pseudocode line 132 shows `pin-codex.sh` invoking `new="$(codex --version | awk '{print $NF}')"` immediately after `npm install -g`. Plan section §Files to Change instructs adding this to `scripts/setup/new-machine-setup.sh` after the npm-prefix step. However, `new-machine-setup.sh` only sets the prefix configuration but does not export `~/.npm-global/bin` to the running shell's `PATH`. The newly installed `codex` binary will not be found by the subsequent command, causing `pin-codex.sh` to exit 1 and break the machine bootstrap.
4. **Variable encapsulation leak (MINOR).** Plan section §Files to Change instructs `scripts/setup/verify-setup.sh` to "compare against CODEX_PIN_VERSION". But `CODEX_PIN_VERSION` is defined inside `scripts/install/pin-codex.sh`, which is an executable script. `verify-setup.sh` cannot natively read this variable without sourcing the script (which would inadvertently trigger a recursive install run) or relying on brittle string parsing.

## Resolution (in-plan, before user review)

All four findings are legitimate. The plan was patched to address them:

| Finding | Resolution in plan |
|---|---|
| F1 (alpha version bypass) | Pseudocode regex extended to permit `(-[A-Za-z0-9.]+)?` suffix; pre-release detection emits an explicit `INCOMPATIBLE` (rc=3) for any pre-release at-or-above floor (alpha versions are uniformly suspect — none have been verified safe). Test list extended with `test_guard_alpha_blocks` for `0.129.0-alpha.1`. |
| F2 (`$LIB_DIR` undefined) | Pseudocode wiring rewritten to use `SCRIPT_DIR/lib/codex-version-guard.sh` (matching `submit-to-codex.sh` convention which already uses `SCRIPT_DIR/$(dirname "$0")`); Files-to-Change row notes the variable contract explicitly. |
| F3 (PATH on bootstrap) | `pin-codex.sh` updated in pseudocode to resolve `npm bin -g` → use `${NPM_GLOBAL_BIN}/codex` directly when `command -v codex` fails; new-machine-setup.sh modification now invokes via `PATH="${NPM_GLOBAL}/bin:$PATH" bash scripts/install/pin-codex.sh`. New AC: pin script must succeed on a fresh machine where codex is not yet on PATH. |
| F4 (CODEX_PIN_VERSION encapsulation) | Pin moved to a tiny shared `scripts/install/codex-pin.env` (single-line `CODEX_PIN_VERSION=0.123.0`) sourced by both `pin-codex.sh` and `verify-setup.sh`. Updated Files-to-Change accordingly. |
