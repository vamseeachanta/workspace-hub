### Summary
Well-scoped T2 hardening of skill-validation uv resolution: extracts source-safe uv-env.sh/uv-resolver.sh libs with a validated fallback chain, actionable diagnostics, and strong test + CI coverage. All 12 new tests pass, shellcheck is clean, and the repo's own abs-path enforcement passes. Only minor (P3) concerns remain.

### Issues Found
- [P3] Minor: scripts/lib/uv-resolver.sh:4 and scripts/lib/uv-env.sh:4 — `set -euo pipefail` runs at top level, so sourcing these libs mutates the CALLER's shell options. Harmless for validate-skills.sh (already sets the same), but undercuts the stated 'source-safe' contract; the source-safety test only asserts exit code, not option preservation, so a future caller that sources the resolver without -e would silently inherit it.
- [P3] Minor: scripts/lib/uv-resolver.sh resolve_uv() — the failure diagnostic's `searched` array prints literal `$HOME/.local/bin/uv` / `$HOME/.cargo/bin/uv` even when HOME is set and those paths were actually probed with expansion, which can mislead an operator reading the error (shows the template, not the concrete paths tried).
- [P3] Minor/Process: docs/plans/2026-06-09-issue-2986-cron-uv-resolution.md and docs/plans/README.md flip Status plan-review -> plan-approved in the same change set; cannot confirm from the diff that the GitHub `status:plan-approved` label was applied by an authorized owner rather than self-applied (must-fire never-self-approve gate).

### Suggestions
- Consider not setting `set -euo pipefail` at the top of files intended to be sourced; instead document the expected shell options, or scope strictness inside functions, to make the source-safe contract literally true.
- Build the diagnostic 'searched' list from the actual expanded candidate paths (and UV_BIN/PATH state) at failure time rather than hardcoded `$HOME/...` template strings, so the error shows what was really probed.
- Optionally add a test asserting the resolver does NOT alter the caller's shell options when sourced (e.g. source it then run a command expected to fail-soft), to lock the source-safe contract.
- The `_uv_resolve_candidate_path` uses `command -v` for bare names, which could resolve a shell function/alias/builtin named 'uv'; minor, but anchoring to executable files would be marginally safer.
