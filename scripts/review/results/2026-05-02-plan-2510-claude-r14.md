## Findings

1. **[P1] PDK-activation step missing from execution contract — plan-vs-real-codebase contradiction.**
   Location: §CLI and Dependency Contract (lines 170–179), §Pseudocode (lines 197–242), §Resource Intelligence Summary embedded probe (lines 99–110), Acceptance Criteria (line 280).
   Claim: the plan asserts that with the pinned dependency set the implementation can `create a GDSFactory Component from deterministic rectangles/polygons/layers/labels` (line 217) and the live execution invocation works against `gdsfactory==9.40.2`.
   Evidence: live probe in this worktree shows `gdsfactory 9.40.2` requires `gf.gpdk.PDK.activate()` (or another PDK activation) before `Component.add_polygon(..., layer=(1,0))` will succeed; otherwise the call raises `ValueError: No active PDK …`. The plan never names PDK activation as a required step, never specifies *which* PDK is activated (this is a determinism input — the active PDK influences layer naming/serialization), and `_load_gdsfactory()` is described as returning `gf, import_gds, save_layout_options, version fields` only. An implementer following the plan literally will hit a runtime error on the very first `add_polygon` call.
   Recommended fix: add an explicit PDK-activation step to §CLI and Dependency Contract and to §Pseudocode `write_exchange_artifact`, name the PDK (`gf.gpdk.PDK` or an equivalent), and either include `pdk` in the `_load_gdsfactory()` return contract or require the helper to perform activation as a side effect with the activated PDK name recorded in `layout_metadata.json` for determinism provenance. Add a TDD assertion that the metadata records the active PDK name.

2. **[P1] Forbidden-phrase test still has a coverage hole vs. its own AC.**
   Location: §TDD Test List row `test_report_and_metadata_have_role_relevance_and_no_signoff_overclaims` (line 272) and §Acceptance Criteria (line 285).
   Claim: AC 285 says "Report and metadata explicitly avoid PDK DRC/LVS, JEDEC/IPC, **or tapeout/signoff claims**, including the exact forbidden variants enumerated in `test_report_…`."
   Evidence: the enumerated forbidden list at line 272 contains `tapeout-ready` and `tapeout ready` but does **not** contain bare `tapeout`, `production tapeout`, `production-tapeout`, `signoff`, or `signoff-ready` (only the hyphenated `signoff-ready`). The plan's own out-of-scope sentence at line 165 uses the exact phrase `production tapeout`, and §Risks at line 403 uses `tapeout evidence`. A report claiming "this is production tapeout" or "ready for signoff" passes the test but violates AC spirit and the §Scope Out boundary. Codex r11 was credited with patching this category but only the *disclaimer* avoidance was patched; the *positive-claim* enumeration remains incomplete.
   Recommended fix: extend the enumerated forbidden list at line 272 to include at minimum `tapeout`, `production tapeout`, `production-tapeout`, `ready for signoff`, `signoff complete`, and `manufacturing release`. Re-state the canonical disclaimer wording verbatim (`not a foundry or PDK signoff flow and not evidence for manufacturing release`) so an implementer cannot accidentally emit a near-miss variant that passes the test.

5. **[P2] Recorded `write_gds` signature probe at line 105 is truncated and silently hides a determinism-relevant default.**
   Location: §Resource Intelligence Summary, GDSFactory API probe (lines 99–110).
   Claim/Evidence: the recorded probe output shows `(self, gdspath=None, gdsdir=None, save_options: kdb.SaveLayoutOptions | None = None, ...)`. The live signature in `gdsfactory==9.40.2` is `(self, gdspath, gdsdir, save_options, with_metadata: 'bool' = True, exclude_layers: 'Sequence[LayerSpec] | None' = None, no_empty_cells: 'bool' = False)`. The hidden `with_metadata=True` default is a determinism-relevant policy decision — when `True`, GDSFactory may emit a metadata sidecar (YAML) alongside the GDS that the manifest does not enumerate. In my live two-run probe the sidecar did not appear for a trivial component, but real components with ports/labels can emit it. The plan does not pin `with_metadata` either way.
   Recommended fix: state the exact `Component.write_gds(..., with_metadata=<True|False>, no_empty_cells=False)` invocation in §GDS Round-Trip Contract, justify the choice (most likely `with_metadata=False` to keep the manifest single-source on the artifacts the CLI explicitly writes), and add a TDD assertion that no unenumerated sidecar files appear in `--output` after CLI completion.

6. **[P2] kfactory log noise can leak into stderr and break LF-determinism / artifact-equality assertions.**
   Location: §Determinism Contract (lines 384–395) and §TDD test `test_outputs_are_deterministic_across_runs` (line 269).
   Claim/Evidence: live probe shows `kfactory.kcell` logs an `ERROR | Name conflict in kfactory.kcell::name at line 688` to stderr the second time the same component name is constructed in one process (the active PDK retains the cell registry across calls). Tests that build the same default design twice in one pytest session — exactly what `test_outputs_are_deterministic_across_runs` does — will hit this. If the implementation captures stderr into the report or includes it in any LF-line-ending check, the test will be flaky.
   Recommended fix: require the CLI to either (a) construct components in a fresh `gf.Component` namespace per invocation (e.g., reset the PDK cell registry before each run) or (b) explicitly silence `kfactory.kcell` logger above WARNING for the test lifecycle. Add a TDD assertion that the second of two CLI runs in one process produces no `ERROR`/`WARNING` on stderr.

7. **[P3] `_load_gdsfactory()` return-shape contract is under-specified for the `pdk` axis.**
   Location: §CLI and Dependency Contract line 177.
   Claim: helper returns "a small object/dict with `gf`, `import_gds`, `save_layout_options`, and version fields."
   Evidence: combined with finding 1, the helper is the only legitimate seam for GDSFactory access yet does not surface PDK activation. A monkeypatched test that injects a fake helper has no contract for telling the production code which PDK is active, so the determinism story is not fully testable.
   Recommended fix: add `pdk_name: str` and (optional) `activate_pdk: Callable[[], None]` to the helper's return contract; record the active PDK name in `layout_metadata.json` and assert it in `test_metadata_extracts_layers_bboxes_ports_counts_and_final_hashes`.

8. **[P3] `geometry_summary.csv` row schema is not specified — falsifiability gap in the determinism test.**
   Location: §Determinism Contract line 389 ("`geometry_summary.csv` must contain only deterministic geometry rows/columns") and §TDD test list line 269.
