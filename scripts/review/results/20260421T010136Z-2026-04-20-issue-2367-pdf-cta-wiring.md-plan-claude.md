### Verdict: APPROVE

### Summary
A mature v4 T1 plan to wire a "Download Capability Summary (PDF)" CTA across a gallery page and 4 methodology pages in the nested aceengineer-website repo. Both sequencing predecessors are cleared (PDF at 6f16cbd; Commit 2 at 1b4adf1), prior review findings (Claude rounds 1–3, Codex rounds 2–3) are tracked and resolved, and the TDD list now includes independent 1-page verification and structural placement gates. The plan is feasible, well-scoped, and rollback is trivial (single git revert).

### Issues Found
- [P3] Minor: The `cta_in_methodology_method_cta` test relies on non-greedy `.*?` regex plus a manually re-verified flat-structure invariant (zero nested <div> inside `.method-cta`). This is acknowledged in the plan but remains fragile — any future nested <div> in that block silently under-scopes the gate; consider promoting the flat-structure invariant check from an implementer instruction to an explicit pre-commit assertion (e.g., expected count of inner `<div>` tags == 0).
- [P3] Minor: `prod_cta_in_rendered_html` post-deploy test only greps the basename `capability-summary-v1.pdf` against the rendered HTML, not the resolved href attribute specifically. A stray comment, JSON-LD reference, or unrelated mention could satisfy the gate without a functioning anchor. Tightening to `href="[^"]*capability-summary-v1\.pdf"` would close the gap cheaply.
- [P3] Minor: The `pdf_is_one_page` gate's fallback of "swap copy to '(PDF, N pages)' and open corrective issue" risks on-the-fly scope expansion at commit time. A cleaner discipline is abort + file corrective issue against #2344, keeping all 5 anchors consistent with the plan's reviewed copy.
- [P3] Minor: Copy `"Download Capability Summary (PDF, 1 page)"` omits file-size hint; at 314,972 bytes (~307 KB) this is inconsequential, but the Risks section's conditional about ">1 MB" retroactive copy-swap creates a second on-the-fly edit path with the same consistency concern as above.
- [P3] Minor: Q1–Q4 'approver objects; otherwise accept' discipline is pragmatic but silently couples 4 defaults (copy, methodology placement, scope, gallery placement) to a single approval comment; an approver scanning only the header could miss the implicit consent. A short 'Defaults to confirm' checkbox list would surface them at approval time.

### Suggestions
- Add an explicit pre-commit assertion that `grep -c '<div' ` inside the extracted `.method-cta` span equals 1 per methodology file, making the flat-structure invariant machine-checked rather than implementer-attested.
- Tighten `prod_cta_in_rendered_html` to grep `href="[^"]*capability-summary-v1\.pdf"[^>]*download` so the test validates the actual anchor rather than any textual occurrence of the basename.
- Replace the `pdf_is_one_page` fallback language with a single policy: abort the CTA-wiring commit on any page count != 1, file a corrective issue against #2344, and block this plan until resolved. Avoids conditional on-the-fly copy edits.
- Promote the 4 open-question defaults to a small bulleted 'Defaults to confirm at approval' block near the top of the plan, so approvers explicitly tick (or object) rather than implicitly consent via silence.
- Consider adding a lightweight mobile-viewport CSS smoke check (e.g., Puppeteer headless at 375 px capturing the `.method-cta` bounding box height vs. a threshold) to automate the currently-manual wrap-collision QA; if out of T1 scope, file a follow-up issue for it alongside the deferred detail-pages issue.
