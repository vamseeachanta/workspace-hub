With the plan promising registry as single source of truth, leaving the YAML untouched re-introduces the very false-readiness risk called out in the Risks section (line 306). Required fix: add a "Modify" row for `scripts/readiness/harness-config.yaml` and a corresponding acceptance criterion that no readiness config may carry workspace paths that disagree with `registry.yaml`.
- [MINOR] **Internal path-naming inconsistency for the new dispatch module.** Resource Intel line 17 says `scripts/telegram-dispatch/` (hyphen), but Artifact Map line 115, Files to Change line 207, and TDD line 212 say `scripts/telegram_dispatch/` (underscore). Per `feedback_llm_wiki_hyphen_module_path_pattern.md`, a hyphenated `scripts/telegram-dispatch/` cannot be a Python dotted import path. Pick one form (the underscore form is the only Python-safe option) and replace line 17 to match — otherwise the plan ships a 1-line landmine for whoever later writes `from scripts.telegram-dispatch import ...`.
