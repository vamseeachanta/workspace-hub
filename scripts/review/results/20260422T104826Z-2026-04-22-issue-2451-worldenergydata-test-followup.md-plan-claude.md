### Verdict: APPROVE

### Summary
Thorough, evidence-dense plan that correctly decomposes a cross-repo CI failure into three bounded clusters with explicit conditional branching. Strong points: live pytest reproduction, class-scope vs. module-scope fixture analysis, refusal to commit to Cluster A workflow edit without CI log proof, and explicit deferral of the plan-index edit to avoid branch contention. Weak points: the plan's own acceptance criterion requires "APPROVE or MINOR" across ≥2 providers but the current wave 4 summary records "MAJOR"; Cluster C repoint depends on a not-yet-confirmed financial-module path; and the follow-up issue contract is under-specified.

### Issues Found
- [P2] Self-referential acceptance gap: the plan requires adversarial review ≥ 2 providers to return APPROVE or MINOR, but its own 'Wave 4 overall result' explicitly records MAJOR across Claude and Codex (only Gemini is APPROVE). The plan states revisions were made in response, but there is no captured re-review proving those revisions cleared the MAJOR verdicts. Status remains 'draft' — so the plan does not currently satisfy its own approval gate.
- [P2] Cluster C default path is partially underspecified: C-skip is the 'approval-safe default' but requires a worldenergydata follow-up tracker issue for re-enablement, yet the plan does not specify the follow-up issue's title/template/labels or whether filing it is a blocker for merging the fix or a parallel bookkeeping step. 'Create / link required tracker' in Files to Change is ambiguous about ordering.
- [P3] Step 0d (locate post-refactor NPV entry point) has no explicit terminating condition beyond 'record in execution notes'. If discovery finds no non-legacy replacement, the plan says C-repoint is blocked — but does not prescribe whether to escalate to module owner, re-scope to deletion, or land skip-only. This judgment call is implicit.
- [P3] Acceptance criterion allowing 'residual failures' in the full CI run is explicitly enumerated but lacks a required-format contract — no mandate that residual failures must be filed as new issues before merge, only that they 'are explicitly enumerated as unrelated follow-up work'. This could enable soft-closing of #2451 with open debt not in the issue tracker.
- [P3] Commit-separation/PR strategy is absent. Three clusters with conditional branches could each land as a separate commit or as one omnibus commit; the plan does not specify. If a reviewer wants to revert just Cluster A, commit granularity matters.
- [P3] Local-provenance check (Step 0c) already showed pytest_benchmark imports successfully under `uv run --all-extras`, which implies A1b (plugin-loading) is the most probable root cause — yet the decision rule still says 'start from A1b by default. Use A1a only after the CI log proves...' This is consistent, but the plan does not pre-commit to A1b investigation's time-box or abort-to-A2 criteria, leaving unbounded diagnosis risk.

### Suggestions
- Add an explicit re-review row to the Adversarial Review Summary table once the post-revision wave completes, so the plan's own acceptance gate is visible as satisfied (or explicitly marks the gate pending before moving to plan-approved).
- Spell out the worldenergydata follow-up tracker's minimum content: title pattern (e.g., 'follow-up(tests): re-enable or delete legacy NPV tests after financial-module audit'), labels, body reference back to #2451, and whether the issue number must be embedded in the skip-reason strings or merely linked from the #2451 execution comment.
- Add a terminating condition to Step 0d: 'If no non-legacy NPV entry point is identified after a bounded search (src/**/financial/** and src/**/npv/**), C-repoint is abandoned for this pass and C-skip proceeds with the follow-up issue explicitly noting no replacement was identified.'
- Add an A1b time-box: 'If bounded plugin-loading diagnosis (pytest config, CI env vars, wrapper scripts) does not surface a one-line fix within N commits/attempts, fall back to A2 with the same follow-up tracking contract used for Cluster C.' This prevents open-ended investigation drift.
- Specify commit/PR granularity: e.g., 'one commit per cluster with reference to #2451, pushed as a single PR against worldenergydata main' — so reviewers can revert surgically.
- Strengthen the residual-failure clause to require that any non-#2451 residual failures observed during V2 are filed as new worldenergydata issues (or enumerated inline in the PR description) before #2451 is closed.
- Consider adding a pytest.ini / conftest.py inspection step explicitly (not just 'pytest configuration in pytest.ini, pyproject.toml, conftest.py') — what exact addopts or PYTEST_DISABLE_PLUGIN_AUTOLOAD findings constitute proof for A1b vs. a dead end.
