## MAJOR

**M1 — Roster is hardcoded in build-equality-matrix.py, duplicating harness-config.yaml authority.**
The plan's pseudocode hardcodes `ACTIVE(4) + UNREACHABLE(2)` as a Python constant, while `scripts/readiness/harness-config.yaml` is the established single source of truth for the workstation roster (consumed by nightly-readiness.sh + compare-harness-state.sh). Two roster definitions will drift — exactly the `home-win`-missing-from-config gap this plan itself flags. Fix: build-equality-matrix.py MUST read the roster from harness-config.yaml; ACTIVE/UNREACHABLE classification can be a small overlay (e.g., a `linux_reachable`/`status` field) but the machine LIST comes from config. Add `test_matrix_roster_from_config`.

**M2 — Behavior dimension is permanently masked by EXPECTED_DIFF.**
Putting "Behavior" in EXPECTED_DIFF means it can never surface DIVERGES. When the cross-machine identical-prompt probe lands later, real behavioral divergence (the highest-value parity signal) would render as a green "expected difference." Fix: behavior must be PENDING/MISSING-EVIDENCE until the probe exists, NOT EXPECTED-DIFF. Remove "Behavior" from EXPECTED_DIFF; it carries its own `deferred` status that maps to MISSING-EVIDENCE.

## MINOR

**m1 — test_collect_references_readiness asserts an unobservable negative.**
"no R-check executed" is not testable from output. Reframe to a positive: assert the harness dimension's `readiness_overall` equals the `overall:` field of a fixture harness-readiness-<machine>.yaml (i.e., value is SOURCED from the file), and that the collector does not write/modify that file.

**m2 — .gitignore negation ordering is correctness-critical but under-specified.**
`!.claude/state/equality-*.yaml` only works if placed AFTER line 168 `.claude/state/*`, and relies on `.claude/state/` (the dir) being re-included at line 164 — git cannot re-include a file whose parent DIR is excluded. The existing `!harness-readiness-licensed-win-1.yaml` (line 178) proves the pattern. Plan should pin the insertion point (adjacent to line 178) and the test must assert via `git check-ignore -v` returning non-match.

**m3 — Adding home-win to harness-config.yaml has unscoped consumer blast radius.**
nightly-readiness.sh and compare-harness-state.sh read `workstations:`. Adding `home-win` without `ssh_target: null` + `linux_reachable: false` could make compare-harness-state.sh attempt to reach it or expect a report. Fix: add home-win with the same shape as licensed-win-* (no ssh, not linux-reachable) and verify the two consumers tolerate the new entry (grep their iteration logic).
