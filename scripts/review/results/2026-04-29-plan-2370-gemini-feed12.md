### Finding R2 — MINOR: Already-ingested issue identification is correctly resolved, but the `--already-ingested` default path is not specified

**Severity:** MINOR
**Dimension:** CLI usability

**Evidence:** The patched plan defines the `--already-ingested` input format as newline-delimited text (lines 131-143 per feed10) and documents that the canonical source is `knowledge/wikis/engineering/wiki/sources/closed-engineering-issues.md`. However, the plan does not specify what the **default** `--already-ingested` path should be when the flag is omitted. Options:
1. Require the flag (fail if missing) — safest, but annoying.
2. Default to parsing `closed-engineering-issues.md` — convenient, but couples the script to wiki layout.
3. Default to empty (assume nothing ingested) — dangerous, could re-promote.

**Impact:** Low. The implementer will make a sensible choice. But option 3 (empty default) could silently mark already-ingested issues as candidates, which contradicts the plan's own acceptance criterion: "5 previously-ingested issues (Class 11 in SOURCE_INVENTORY) are marked `already_ingested: true`."

**Recommendation:** During implementation, make the flag required (option 1) or default to parsing the source file (option 2). Do not default to empty. This is an implementation note, not a plan defect.
