## MAJOR

**M1 — The pseudocode's overlay semantics silently corrupt the published render.**
Plan §Pseudocode defines `resolve_state_inputs()` as `repo_state` merged with `local_state`, "local wins". The publisher then invokes the builder with `--state-dir "$WT/.claude/state"`. If `--state-dir` merely *sets* `local_state`, the overlay still folds in `REPO/.claude/state` from the interactive checkout — which on a behind box holds **stale peer evidence** — and, worse, a stale local seam copy could override a fresher origin copy inside the worktree. That defeats the entire "union of freshest evidence" guarantee `publish-equality.sh:11-15` exists to provide, and it would ship a wrong matrix to GitHub Pages. The plan does not define `--state-dir` precedence against the default list at all. **Fix required:** `--state-dir` (repeatable) must *replace* the default input list entirely, and the publisher must pass exactly one — the worktree's. Add a test pinning it.

**M2 — The FF-pull preflight is added to only one of the two collection entry points, so `behind_main` still ratchets.**
Plan §Files to Change adds the preflight to `scripts/readiness/equality-matrix-cron.sh` only. But `scripts/curation/curate-session-memory.sh:75-82` independently runs `collect-equality.sh` + `build-equality-matrix.py` every 6 hours on **six** machines (`config/scheduled-tasks/schedule-tasks.yaml:169-180`), and that path never publishes and would never pre-pull. Those runs would keep stamping `behind_main > 0` into the evidence, so the matrix would keep showing STALE-CHECKOUT on those boxes even after this issue lands. The plan's own Resource Intel section identifies this second path (and calls it "a second, higher-frequency dirtying path the issue body does not mention") and then fails to apply the fix to it. **Fix required:** factor the preflight into a shared helper and call it from both entry points.

**M3 — A mid-run `git merge --ff-only` can rewrite the currently-executing script.**
The proposed preflight runs `git merge --ff-only origin/main` *from inside* `equality-matrix-cron.sh`. A fast-forward that touches `scripts/readiness/equality-matrix-cron.sh`, `collect-equality.sh`, or `publish-equality.sh` replaces those files on disk while bash is still reading the running script incrementally — a well-known way to make bash execute truncated or garbage input. The publish path is exactly the surface that changes most often in this subsystem, so this is not hypothetical. **Fix required:** move the preflight into a separate thin `scripts/readiness/equality-preflight.sh` that performs the fetch+FF and then `exec`s the cron script, so no updated file is mid-read when it is replaced.

**M4 — Several "TDD" tests are green today; the plan claims all are RED before implementation.**
Plan §TDD Test List opens with "Written and confirmed failing before any implementation." At least five listed tests pass against `main` unchanged: `test_build_matrix_json_mode_writes_nothing` (verified — `build-equality-matrix.py:802-811` returns before the write), `test_measured_allowlist_unchanged`, `test_is_stale_semantics_unchanged`, `test_publish_allowlist_still_refuses_unexpected_paths` (already exists as `test_refuses_unexpected_staged_paths`), `test_publish_still_publishes_when_checkout_diverged_and_dirty` (already exists). These are legitimate *regression guards*, not RED tests. Presenting them as TDD RED cases inflates the apparent test rigour and would let an implementer "pass" the gate without writing a single failing test. **Fix required:** split the table into RED (must fail first) and REGRESSION (must stay green) and state which is which per row.

**M5 — `test_collect_leaves_working_tree_clean` is vacuous as specified.**
`collect-equality.sh:523-529` suppresses the rewrite entirely when the canonical payload is unchanged. A fixture that seeds no prior yaml, or seeds an identical one, will produce a clean tree **today**, so the test passes against unfixed code. The plan's fixture notes do not require the seeded yaml to be *tracked* and *differing*. **Fix required:** specify the fixture precisely — commit a tracked `equality-<machine>.yaml` whose canonical payload differs from what the collector will produce — or the headline test of this issue proves nothing.

**M6 — Acceptance criterion 5 cannot be met and the plan half-admits it.**
AC5 requires `dev-primary` to publish `dirty: false, behind_main: 0, ahead_main: 0`, "or the residual is attributable to operator commits". `dev-primary` currently carries `ahead_main: 1` (was 17), and `is_stale()` fails closed on `ahead_main != 0` (`build-equality-matrix.py:235`). So the single box that motivated this issue can land the entire fix and still grade **27/27 STALE-CHECKOUT**. The escape clause makes the criterion unfalsifiable. **Fix required:** either state plainly that this issue does not restore dev-primary to green while local commits exist on `main`, and pick a box that can actually demonstrate the fix (`gpu-claw` is at 0/0), or scope the `ahead_main` question into this issue. Do not ship an AC that cannot fail.

**M7 — No rollback plan for a change that runs unattended on six machines.**
The plan changes the default output location of two schedulers' generators across the fleet, with a phased rollout, and defines no revert path. If the seam resolution misbehaves on one OS (see the `$HOME`/Git-Bash risk the plan itself raises), the failure mode is silent: `publish-equality.sh:150` finds no `equality-*.yaml`, `attempt()` stages nothing, and line 176-179 reports `nothing newer … no commit needed` and **exits 0**. A box would go dark on the matrix while every cron reports success. **Fix required:** add a rollback section (single env var `EQ_STATE_DIR=$WORKSPACE_HUB/.claude/state` restores old behaviour) **and** make the publisher fail loud when the resolved seam directory contains zero `equality-*.yaml` files for this machine.

## MINOR

**m1 — Reader enumeration is incomplete.** `scripts/readiness/gap-actions/ace-win-2/01-refresh-curation-and-matrix.sh:54,62-64` reads `.claude/state/equality-${MACHINE}.yaml` and iterates `docs/reports/*machine-equality-matrix.html`. Add it as an explicit "unchanged, Phase 2" row.

**m2 — The manual path already works around the defect; the plan does not say so.** `refresh-equality-matrix.sh:42` uses `git pull --rebase --autostash`, which succeeds even with the artifacts dirty. Only the cron path ratchets. Stating this sharpens the blast radius and explains why the defect went unnoticed by operators running manual refreshes.

**m3 — `Project:` header is filled with `(n/a)`.** The template (`docs/plans/_template-issue-plan.md:8`) treats `Project:` as optional and `Client:` as the field that takes `N/A`. Leave `Project:` empty or omit it.

**m4 — The issue carries no `lane:` label.** Plan §Evidence notes this and defers the fix to the label step. Per `issue-planning-mode` Step 4.2 and [#3029](https://github.com/vamseeachanta/workspace-hub/issues/3029) the issue must carry exactly one `lane:` label matching the plan header before `status:plan-review` is applied. Track it as an explicit checklist item, not a parenthetical.

**m5 — 42 tracked matrix HTML files is a growth problem the plan defers without a bound.** One new dated file per day, forever, each ~100 KB of published render, all pushed to `main`. The deferral to a follow-on is reasonable, but the plan should state the current growth rate so the follow-on can be prioritised against it.
