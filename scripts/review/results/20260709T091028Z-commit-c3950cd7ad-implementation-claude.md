### Verdict: MAJOR

### Summary
Well-engineered installer/launcher pair with unusually thorough shell-based TDD coverage (12 test functions covering detection policy, installer contracts, stored-hotkey execution, stop semantics, and static/mode contracts). However, a start-recording race can leave an orphaned arecord process capturing the microphone indefinitely with no UI indication (privacy-relevant), and the share-dir symlink binds the hotkey to the repo checkout path — fragile when installed from a worktree that is later deleted.

### Issues Found
- [P2] Important: tools/voice-dictation/codex-dictate.sh:885-931 — Double-press race orphans a hot microphone. start_arecord writes the pidfile only AFTER the 0.15s grace sleep; a second hotkey press inside that window sees no pidfile, calls start_recording again, and overwrites the pidfile/metafile with the second arecord's PID. The first arecord is never tracked or killed: it keeps recording to the shared rec.wav (and after stop_and_type unlinks the wav, to an open-but-deleted fd) indefinitely. Silent, unbounded mic capture is a privacy defect, and the busy device can also block subsequent recordings. Fix: write the pidfile before the grace check (rolling back on failure), or use a lock (mkdir/flock) around the toggle.
- [P2] Important: scripts/agents/install-voice-dictation.sh:127-128 — ensure_share_links symlinks ~/.local/share/voice-dictation to ${repo_root}/tools/voice-dictation, where repo_root is derived from the script's own location. If the installer runs from a git worktree (e.g. .worktrees/issue-3403-approval-push, exactly where this commit sits), the stored gsettings hotkey command points into a directory that is deleted at worktree cleanup, leaving a dangling symlink and a silently dead hotkey. This is the worktree-incompatibility defect class the repo's own rules call out as must-promote. Fix: resolve to the primary checkout (e.g. refuse/warn when repo_root matches */.worktrees/*, or resolve via the main working tree).
- [P3] Minor: tools/voice-dictation/codex-dictate.sh:850-857 — stop_and_type removes the pidfile before the kill, and issues an unconditional kill -KILL after the wait loop even when the process already exited; a recycled PID in that window would be SIGKILLed. Low probability but trivially avoidable (skip -KILL when the loop broke via kill -0 failure).
- [P3] Minor: scripts/agents/tests/test_voice_dictation_detection.sh:674 — the bootstrap-guard assertion greps for the literal '|| true' anywhere in bootstrap-machine.sh, so any unrelated '|| true' elsewhere in that 200+-line script makes the test pass even if the voice-dictation invocation is unguarded. Anchor the grep to the actual invocation line (e.g. grep for 'install-voice-dictation.sh" || true' or the VOICE_DICTATION_INSTALLER block).
- [P3] Minor: scripts/agents/tests/test_voice_dictation_detection.sh:589 — test_missing_python_and_text_injector_guidance runs the installer with PATH=${tmp}/bin only; the installer's EXIT trap ('rm -f "${detect_err}"') then fails because rm is not stubbed, leaking one mktemp file per run into /tmp and emitting a stray 'command not found' on stderr that the test never inspects. Symlink rm (and sed) into the stub bin.
- [P3] Minor: tools/voice-dictation/transcribe.py:1054 — language='en' is hardcoded while DICTATE_MODEL is user-overridable; setting a multilingual model (e.g. DICTATE_MODEL=small) still forces English transcription. Expose DICTATE_LANGUAGE alongside the other env knobs, or document the constraint in README.md.

### Suggestions
- In start_arecord, create the pidfile/metafile before the grace-period check (or take an exclusive lock via mkdir "${state_dir}/lock") so a rapid second press always sees the in-flight recording and toggles into stop_and_type instead of double-starting.
- Add a worktree guard to the installer: if [[ "${repo_root}" == *"/.worktrees/"* ]]; then echo refuse-or-warn; fi — or resolve the primary checkout via 'git -C "${repo_root}" rev-parse --path-format=absolute --git-common-dir' and symlink to that tree instead.
- dictate-test.sh leaves ${state_dir}/dictate-test.err behind on the success path; rm it after a clean run for state-dir hygiene.
- The installer's 'source detect-os.sh' will hard-fail under set -e when run standalone from an incomplete checkout; a '[[ -f ... ]] || { echo ...; exit 0; }' guard would keep the standalone path as graceful as the bootstrap path.
- Consider running shellcheck in test_static_contracts in addition to 'bash -n' — bash -n catches parse errors only, not quoting/word-splitting regressions in future edits.

### Questions for Author
- Is the installer expected to ever run from inside a worktree (the commit itself lives in .worktrees/issue-3403-approval-push)? If bootstrap-machine.sh is only ever run from the primary checkout, the P2 symlink concern downgrades to a documented constraint — but the guard is cheap either way.
- Was the write-pidfile-after-grace ordering in start_arecord deliberate (to avoid a pidfile pointing at an already-dead arecord), or is a pre-write-then-rollback approach acceptable to close the double-press race?
- write_inert_hotkey only rewrites an EXISTING codex-dictate binding to the warning command and never creates one on first inactive install — intentional (avoid claiming Super+Shift+V on machines that never had dictation), or should first-time inactive installs also get the guidance binding?
