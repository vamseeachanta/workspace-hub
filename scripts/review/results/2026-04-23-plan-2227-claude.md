## FINDINGS

1. **§Resource Intelligence Summary line 19 is factually wrong about extraction state.** Plan asserts all three summary artifacts have `summary: ""` *and* `text_preview: ""`. Direct JSON inspection: `5e5f…` has preview length 0, but `b576…` (CSA Z276.1) and `3aa1…` (CSA Z276.18) have **text_preview of 1000 chars** (garbled OCR/encoding — excerpt shows Finnish-looking tokens `pyorat/pakota/makaamaan/…`). Preview is *corrupted*, not *missing*. This misrepresents the blocker: the remediation path is OCR/encoding fix, not "re-extract because preview is empty". Downstream of this, the Branch B follow-up issue description ("re-extract 3 DRM PDFs on alt toolchain") is scoped against a false premise.

2. **T2 (`test_prereq_marine_taxonomy_sub_gate`) is prone to false-PASS.** The test is specified as: "`marine-engineering/CLAUDE.md` lists `standards/` in sanctioned categories". `knowledge/wikis/marine-engineering/CLAUDE.md:11` contains the literal substring `standards/` under the `raw/` tree (`raw/standards/  # Standards documents (API, DNV, ISO, etc.)`), NOT under `wiki/`. A naive substring/regex match — which is what the plan's phrasing invites — would return PASS while the semantic requirement (sanctioning `wiki/standards/`) is FAIL. Pseudocode line 116 (`check marine-engineering CLAUDE.md for "standards/" in sanctioned categories`) has the identical vulnerability. Without explicit disambiguation (e.g., a block-scoped check tied to the `wiki/` section of the directory tree), the taxonomy sub-gate can be gamed or accidentally short-circuited.

3. **T7 (`test_ocimf_meg4_scope_narrow`) references an undefined threshold.** Spec: "Diff of `ocimf-meg4.md` has ≤ N lines added". `N` is never bound anywhere in the plan. Test is not implementable as written. The whole scope-narrowness gate resolves to whatever value the implementer picks — which is a load-bearing subjective decision the plan claims to have pinned.

4. **Gitignore line numbers are off by one.** Plan cites `.gitignore:491` (§Resource Intelligence) and `.gitignore:491-492` (Prereq Matrix row). Actual: `/knowledge/wikis/*` at line 492, `!/knowledge/wikis/engineering/` at line 493, `!/knowledge/wikis/cross-links.md` at line 494. Minor but signals that at least one rigor-check citation was not re-verified on v2; every other factual anchor in a plan that self-styles "pinned" is now suspect until checked.

5. **T12 word list is not a defense against title regurgitation.** Curated terms `tandem, FPSO, offloading, conventional tanker, berthing` — at least `tandem`, `FPSO`, and `conventional tanker` appear in the document title itself ("OCIMF Tandem Mooring and Offloading Guidelines for Conventional Tankers at FPSO Facilities"). See ledger entry." + 200 filler words would satisfy T12 trivially. The test purports to guard against "empty-summary regurgitation" but does the opposite.

Reading that file shows `## Standards (7 pages)` at line 99. Leaving a cheap verification unrun in a plan that explicitly claims to have pinned its prereq matrix is inconsistent.

T1's AND conjunction will therefore fail.
