## Scope Decision

Defer is correct and honest. Three facts support it:

- **Premise violation**: #2305 says "reuse enrichment unchanged." Enrichment keys on `ext` and `content_hash`; conference schema has `extension` (with dot) and no hash. Running "unchanged" is impossible — any run requires a new adapter, which is a new design, which is a new issue.
- **Path universe mismatch**: Conference paths are rooted at `/mnt/ace/docs/conferences/`. The ace summaries corpus does not cover that subtree (0/100 sample, 0% fallback match). Partial enrichment with `summary_done=False` everywhere would write 49,804 rows of metadata that asserts nothing useful and is indistinguishable from "not yet processed."
- **Signal-to-noise**: `content_type` from `extension` alone (strip the dot, map to MIME) is cheap but low-value without the summary join it was designed to support. Shipping it now risks a future reader assuming the conference corpus was "enriched" in the #1878 sense when it wasn't.

Not evasive. The memo explicitly names the follow-up and the reason.

## Missing Considerations

Candidates: (a) deduped vs raw, (b) a third index file (check `checkpoints/` yamls list other corpora), (c) the maturity figure counts record-events across revisions. Memo should name at least one hypothesis, not just "separate investigation."
2. **Conference summaries location**: Memo should state affirmatively that a search was done for a conference-specific summaries dir (`ls /mnt/ace/data/document-index/` result) and that none exists — future readers will ask "did we check?"
3. **`conference-phase-a-results.jsonl` sibling**: Present in the same dir. The memo should note whether it was examined; if it is a partial enrichment attempt, deferring a new one without acknowledging it looks careless.
4. **Revive criteria**: What triggers the follow-up issue being worked? (Summaries produced for conference corpus? A decision to skip summaries and enrich content_type only?) Without revive criteria, "defer" becomes "forget."
5. **Close-out mechanics for #2305**: If the deliverable is a decision memo, #2305 closes as "resolved-by-decision" — memo should name the follow-up issue number (or state "to be filed") so the trail is linkable.
