## Findings

1. **False retrieval citation (Roadmap):** Plan §Documents consulted claims `docs/roadmaps/chip-design-cad-fem-career-roadmap.md` "defines #2510 as the Python layout/CAD automation workstream". This is false. A read of that file shows it outlines a "4. layout/CAD automation demo" step but does not contain the string "2510" or map any specific GitHub issues to the workflow.
2. **False retrieval citation (Knowledge Base):** Plan §Documents consulted claims `docs/reports/semiconductor-cad-fem-knowledge-base.md` maps roles to "deterministic portfolio artifacts". A grep of that file returns zero matches for "deterministic portfolio". The plan is hallucinating exact wording not present in the referenced taxonomy.
3. **Determinism contract contradiction:** Plan §Determinism Contract states that if GDS timestamp pinning fails, we should "exclude `chip_package_demo.gds` from byte-for-byte determinism assertions but still include it in the manifest generated for the checked-in run". However, Plan §TDD Test List states `test_outputs_are_deterministic_across_runs` will expect "equal content hashes for manifest-covered artifacts". If a non-deterministic `.gds` file is included in the manifest, the manifest itself becomes non-deterministic (its content changes per run as the GDS hash changes). This guarantees that a hash equality check on the manifest or manifest-covered artifacts across two runs will fail.
4. **Testing environment contradiction:** Plan §Acceptance Criteria mandates running tests via `uv run --with gdsfactory pytest ...`. However, `test_missing_open_layout_dependency_blocks_rather_than_fakes_gds` expects an "import-path/subprocess check without `gdsfactory` plus monkeypatched writer path". If the test suite is launched with `--with gdsfactory`, the dependency is injected globally into the environment. A subprocess check cannot simultaneously lack the dependency *and* have a "monkeypatched writer path" applied from the parent pytest process. 
5. **Manifest pathing divergence:** Plan §Acceptance Criteria asserts the manifest "validates from repo root with `sha256sum -c data/semiconductor/layout_cad_demo/artifact_manifest.sha256`" and "must include repo-relative paths". However, the plan also claims its CLI shape "must mirror the semiconductor lane convention from #2511". Grepping `#2511`'s `scripts/semiconductor/package_fem_benchmark.py` reveals it writes basenames (`p.name`), not repo-relative paths. If #2510 mirrors #2511, a repo-root `sha256sum -c` will fail; if #2510 implements repo-relative paths, it explicitly breaks the #2511 pattern it claims to follow.

## Blockers
- Finding 1 and 2: Remove hallucinated citations/wording from the Resource Intelligence summary.
- Finding 3: Resolve the determinism contradiction. Either the `.gds` file must be excluded from the manifest entirely during the determinism test, the manifest itself must be excluded from the strict equality check, or the test must safely tolerate manifest diffs.
- Finding 4: Redesign the missing-dependency test to be compatible with a `--with gdsfactory` injected test environment, or isolate it to a strict subprocess execution that does not rely on parent-process monkeypatching.
- Finding 5: Clarify whether the manifest pathing should break from the #2511 pattern to support repo-root validation, and adjust the CLI contract claims accordingly.
