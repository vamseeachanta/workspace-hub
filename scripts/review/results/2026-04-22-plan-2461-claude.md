## Findings

### F1. Operator-map host decision is asserted in the acceptance criteria while also being explicitly deferred to #2460 — internal contradiction
- Acceptance criterion: `docs/maps/assetutilities-operator-map.md` exists in workspace-hub and covers all 10 observed top-level source directories.
- Risks section: "If #2460 chooses the in-repo location as the canonical one, the artifact moves."
- These two statements cannot both be true once #2460 lands. Either the acceptance criterion is wrong until #2460 freezes, or the risk is moot.
- Fix: rephrase the acceptance criterion to read `the canonical operator map exists at the host/path determined by #2460, and covers all top-level source directories observed at implementation time`. Keep the current workspace-hub path only as a default that applies if #2460 explicitly ratifies it.

### F2. Registry acceptance criterion is unfalsifiable while #2460 is still draft
- Acceptance criterion: `Canonical machine-readable module/domain registry exists at the path defined by #2460 and covers all 10 top-level domains.`
- Files-to-change row: `Create | assetutilities/<registry path per #2460> | Canonical machine-readable module/domain registry.`
- While the plan is correctly deferring the filename to the contract, the registry test (`test_registry_exists`) has no resolvable path today. A reviewer cannot verify the criterion until #2460 freezes the shape. This is acceptable for a draft, but must be flagged as a blocking precondition on `status:plan-review`.
- Fix: add an explicit plan-level precondition: `Implementation MUST NOT begin until #2460 has frozen the registry filename.` Mirror that in the Risks section as a blocker, not just a risk.

### F3. Operator-map row count hard-coded at 10 — creates drift guarantee
- TDD row `test_operator_map_covers_all_top_level_source_dirs` enumerates 10 directories: `agent_os, base_configs, calculations, cli, common, constants, devtools, modules, tools, units`.
- The plan's own pseudocode stresses "re-derives the required directory list from `git ls-tree src/assetutilities` at test time rather than hard-coding it", but the test list contradicts that by listing 10 exact names.
- Fix: change the acceptance criterion to "operator map covers every top-level package directory observed under `src/assetutilities/` at implementation time (derived from the live tree)" and change the test spec to derive the expected set, not hard-code it.

### F4. `.bat` deletion risk asserted but unverified
- Plan proposes deleting `tests/visualizations_tests.bat` and `tests/visualizations_tests_temp.bat`.
- Risk section says: "If a real Windows test path is needed it belongs under `tests/platform/windows/`, not in the top-level tests tree." That is a should-statement, not a must-verify step.
- The plan does not require checking whether any CI workflow, packaging step, or nightly batch invokes either `.bat` file. If they are referenced anywhere (for example from a GitHub Actions workflow file or from a documented Windows quickstart in `docs/UV_SETUP.md`), deletion silently breaks that path.
- Fix: add a TDD-independent discovery step: `grep -r visualizations_tests` across workspace-hub and assetutilities before the deletion step; if any hit is found, reclassify the deletion as a move/rename, not a delete.

### F5. `MODULE_STRUCTURE.md` rewrite is test-covered only for absence, not for correctness
- Tests include `test_readme_no_stale_directory_claims` and `test_module_structure_matches_observed_tree`.
- The `test_module_structure_matches_observed_tree` wording says "does not reference non-existent `core/` or `utils/` directories and does list the real directories", but "list the real directories" is a presence assertion against a non-specified set. The set should be derived from `git ls-tree src/assetutilities` at test time.
- Fix: replace "does list the real directories" with "lists exactly the package directories observed under `src/assetutilities/` at test time, derived from the tree, not hard-coded".

### F6. Curated-vs-raw boundary test has no inspection criterion
- `test_docs_readme_states_curated_vs_raw_boundary` asserts the rule is "present" but does not bind the rule to a specific statement or sentence. This lets implementation satisfy the test trivially with a hand-waving sentence that doesn't actually partition the subtrees.
- Fix: require the rule to list at least which `docs/` subtrees are curated routing surfaces (for example `docs/README.md`, the operator map link, the registry link) and which are supporting/raw (for example `docs/sub_automation/`, `docs/sub_data/`, report PDFs). Bind the test to a concrete subtree list.

### F7. Downstream-consumer risk acknowledged but not gated
- Risks section acknowledges digitalmodel depends on assetutilities but the mitigation is the implicit assumption that the `.bak`/`.orig` files have no importers and that the test suite will catch surprises.
- There is no explicit `grep -r` check committed to the implementation sequence, and no test that asserts "no non-test file in `src/assetutilities/` imports from any `.bak`/`.orig` target".
- Fix: add a pre-delete discovery step to the pseudocode and an acceptance criterion: "before deletion, `grep -r 'ApplicationManager.py.bak' .` and `grep -r 'file_management.py.bak' .` across `src/` and `tests/` must return no hits; if any hit exists, stop and surface for review."

### F8. Plan does not specify the `MODULE_STRUCTURE.md` ↔ operator-map relationship
- After this issue, the repo has two separate current-state listings: `MODULE_STRUCTURE.md` and the operator map. The plan rewrites both but does not state which is canonical when they disagree in the future.
- Fix: pick one as canonical (likely the operator map plus the registry) and state in `MODULE_STRUCTURE.md` that it is a human-readable mirror regenerated from the operator map / registry, not an independent source of truth. Optionally deprecate `MODULE_STRUCTURE.md` entirely if #2460 does not require it.
