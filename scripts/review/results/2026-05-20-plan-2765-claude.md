## Findings

1. **Classification mapping ("same logical job across planes") is undefined.** Pseudocode line 60 (`if same logical job exists in multiple scheduler planes`) and TDD row `test_detects_duplicate_logical_job_across_planes` require equating a YAML `id:` (e.g. `gsd-researcher`) with a Hermes job name (e.g. `memory-bridge-daily`, `tier1-indexing-daily`). The plan never specifies how the equivalence is determined — exact-string match? alias table? command-line substring? Without a mapping spec, the duplicate-detection test is testing a fixture-shaped tautology, not a real contract. This is the core deliverable; leaving it under-specified will produce divergent implementations across review/implement cycles.

2. **Plan ignores the pre-existing `is_claude_task` flag in schedule-tasks.yaml.** Line 36 of `config/scheduled-tasks/schedule-tasks.yaml` already carries `is_claude_task: true` on `gsd-researcher` (and `false` elsewhere). The plan introduces "native-provider AI bypass" classification (test `test_native_provider_ai_bypass_is_highlighted`) without referencing the field that already encodes this. Either the plan should explicitly consume `is_claude_task` as the source of truth, or it must justify why a new heuristic is needed. As written, two parallel signals will drift.

3. **Acceptance criterion #1 contradicts the Files-to-Change and pseudocode coverage.** AC #1 requires reading "all four surfaces". Issue body explicitly names four: YAML, setup-cron dry-run, `crontab -l`, `hermes cron list`. But pseudocode (lines 55-56) collapses to "canonical schedule/config fixtures" + "optional live scheduler evidence", and the Files-to-Change description for `scripts/cron/scheduler-parity-report.py` (line 70) lists "YAML, setup-cron dry-run text, optional crontab text, and Hermes cron list text" — `crontab -l` is "optional" in the script row but "all four" is required in AC #1. Pick one.

4. **No TDD test covers the YAML parser surface.** The five TDD rows test setup-cron dry-run parsing, Hermes list parsing, duplicate detection, read-only behavior, and AI-bypass highlighting. The YAML schedule file is the first canonical surface and the issue body's #1 input, yet no test verifies the report parses YAML correctly. AC #5 says "Tests cover parsers" (plural) but only two of three parsers have tests.

5. **Risk-vs-AC mismatch on "external crontab lines".** Risks section line 108 states `report must distinguish workspace-hub-managed entries from external cron lines`. Without an explicit subcommand-arg allow-list, the test is either tautological (monkeypatch fully blocks subprocess and report can't run) or weak (monkeypatch allows everything `crontab*` and a future `crontab -r` ships silently).
