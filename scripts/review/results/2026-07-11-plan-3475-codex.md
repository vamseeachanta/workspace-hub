## Findings
1. The mandatory runtime reproduction has not been performed. The plan says, “The defect **will be reproduced** hermetically before implementation,” but its “Evidence and reproduction proofs” contains only `gh issue view`, `git ls-remote`, and the scheduler registry checker—none executes `run_cutover()` or demonstrates the alleged false `applied` result. `.claude/skills/coordination/issue-planning-mode/SKILL.md` requires the exact failing command, timestamp, and observed output before drafting and directs reviewers to reject runtime-defect plans lacking it.

2. The planned identity matcher does not establish command semantics. Design §1 only requires `command_tokens` to occur as an “exact adjacent” sequence anywhere in the token stream. That still authorizes deletion when the sequence appears as data to another command, such as arguments to `printf`, `echo`, `sh -c`, or a command on the wrong side of a control operator or pipeline. The proposed test `test_command_identity_requires_adjacent_tokens` covers prefix/suffix/path-substring collisions but does not require executable position, command-segment boundaries, control-operator structure, or rejection of nested shell strings. This fails the parsed destructive-identity requirement in `.claude/rules/scheduler-mutation-safety.md`.

3. `cwd_basename: workspace-hub` is not exact working-directory identity. Design §1 and `test_command_identity_parses_exact_workspace_cwd` explicitly accept basename variants, meaning `/tmp/workspace-hub`, `/attacker/workspace-hub`, and the known `/mnt/local-analysis/workspace-hub` are indistinguishable. Because this identity authorizes deletion, an unrelated cron command in any directory sharing that basename can be claimed. The plan must enumerate accepted cwd forms or bind them to canonical machine/context paths instead of describing basename equality as exact identity.

4. The plan omits the live audit consumer that currently shares the destructive substring routes. `scripts/cron/cron-audit.py:134-154` and `scripts/cron/cron-audit.py:250-275` build `catalog_commands` using `catalog_command_keys()`, while `scripts/cron/cron_transaction.py:264-273` classifies those substring matches as `cataloged`. Yet neither `scripts/cron/cron-audit.py` nor `tests/cron/test_cron_audit.py` appears in Files to Change or the TDD list. Removing or changing `catalog_command_keys()` only for apply can leave audit and apply with divergent ownership decisions, or break the audit API outright.

5. The transaction design has no failure contract for write/read exceptions. Design §3 assumes `_write(planned_B)`, `observed_C = read()`, rollback `_write(baseline_A)`, and restoration `read()` all return normally. If the initial write partially succeeds and the post-write read raises, the code cannot establish equality and the pseudocode never enters rollback. If rollback write or verification read raises, no defined result preserves the promised backup diagnostics. The TDD list tests mismatched returned text but contains no initial-write, post-write-read, rollback-write, or rollback-read exception cases. This contradicts Acceptance Criteria claims that every mismatch enters rollback and successful application requires observed equality.

6. The plan’s claim that external/private and machine-local rows “without `catalog_task_id`” remain non-destructive leaves the schema’s dangerous inverse unstated. Current `scripts/cron/cron_transaction.py:240-254` promotes any matching preserved entry carrying a selected `catalog_task_id` to `cataloged`. The plan migrates `notification-purge`, but it does not specify validation that `catalog_task_id` is forbidden unless the row uses a valid `command_identity`, nor a test for a substring preservation row with `catalog_task_id` other than the selected fixture. `test_non_destructive_preservation_substrings_never_promote` says “Always `preserved_external`” without defining this metadata case, leaving a future config row able to reactivate destructive substring authority.

## Blockers
1. Add an actual hermetic RED reproduction with command, timestamp, and observed `applied` output.
2. Define a closed command grammar with command-segment/executable-position semantics and adversarial tests for argument, pipeline, control-operator, and nested-shell collisions.
3. Replace basename-only cwd authority with an enumerated, machine-context-bound exact cwd contract.
4. Include `cron-audit.py` and `test_cron_audit.py` in the migration and prove audit/apply classification parity.
5. Define and test transaction behavior for write/read exceptions at every post-backup stage.
6. Enforce that `catalog_task_id` cannot promote substring-based preservation identities.
