## Checks performed (so this review is not empty)
- **Cleanup `rm -rf` safety (Codex plan-review #3):** 6 fail-closed guards each tested — missing
  sentinel, non-`*-cxc-*` name, outside dispatch root, the source repo, `/`, `$HOME`. All rc≠0 with
  `run_rm` never called; only a fully-valid managed clone is removed.
- **Write-isolation property (the load-bearing claim):** integration tests + live e2e confirm a
  `--no-hardlinks` clone has a DISTINCT object inode from the source (src 360669 ≠ dest 360842) and
  commits with no sandbox grant; `--local` shares the inode (documented hazard, opt-in only).
- **`set -e` safety of test idiom:** tests source the helper and call functions in subshells without
  invoking `main`, so `set -e` is scoped to real CLI runs only — tests behave deterministically.
- **`path_dev` infinite-loop check (cf. `feedback_path_parent_infinite_loop`):** the `dirname` walk
  terminates at `/` (guarded) or `.` (always exists); no unbounded loop.
- **shellcheck:** clean on the helper; the test carries a scoped disable for the dependency-injection
  idiom (override functions invoked via `source`, vars read in subshells/`eval`).
- **Route doc:** states Option A runs ON TOP OF the #2804 base route; documents the worktree fallback's
  three layers + blast radius; carries a generalizable "hardlinked clone ≠ write-isolation" lesson.
