## Findings

1. **Pseudocode `pending_work_report` does not scope-filter local-state counts (plan §Pseudocode `pending_work_report`).** D2 says the low-level store accepts any `account_id`, and D7 says disabled-alias records "never make `mailbox_empty` false," but the pseudocode computes `inbound_count`/`decision_count`/`needs_schema_count` over all local-state rows with no account-scope filter. A disabled-account (e.g., `skestates`) or placeholder-account thread persisted via the permissive low-level store would flip `tracked_empty`/`mailbox_empty` false, contradicting the prose. No test in the TDD list covers disabled-account rows in *local state* — `test_rejects_out_of_scope_account_alias_at_report_boundary` only covers inbox-snapshot records. Add an explicit test: out-of-scope local-state rows are excluded from (or separately bucketed in) tracked counts.

2. **Inconsistent sentinel in the `config_missing` branch (plan §Pseudocode, `pending_work_report` early return).** The fail-closed return sets `unknown_count`, `out_of_scope_count`, `reactivation_pending_count` to `None` (not evaluated) but `noise_excluded: 0`, which reads as "evaluated, none found." Use `None` for consistency or document why noise exclusion is evaluable without a config.

3. **Cross-cycle no-trigger duplicates are silently skipped instead of raising `StaleStateError` (plan D5 last bullet + D11).** The historical-retry search matches on `(account_id, thread_id, from_state, to_state, dedup_event_id)` — `cycle_id` is excluded. For no-trigger events `dedup_event_id` is the constant `legacy:no-trigger`, so a stale caller replaying a cycle-1-shaped transition after reactivation (current state differs) matches the cycle-1 key and is skipped as an "idempotent retry" rather than rejected as stale. State is not corrupted (nothing appends), but the loud-failure signal D11 promises for stale `from_state` is lost for exactly this class. Either include cycle candidates in the historical match or document the silent-skip as accepted behavior with a test.

4. **Cold-start bootstrap is mechanically open to all callers, restricted only by prose (plan D5, D11, §Pseudocode `reactivate_reply`).** D5 says the bootstrap fallback is "only for the existing single-call #2017 contract test," but the pseudocode grants `bootstrap_reactivation` to any `reactivate_reply` call whenever no snapshot record exists — no id of any kind required, and `MissingReactivationId` is unreachable in the cold-start branch. The mitigations (stamped `bootstrap_reactivation: true`, checker reports `baseline_missing` instead of calling cold) are real but normative. This is the residual of R5 blocker #1; acceptable as an audit-trailed compatibility seam, but the implementation notes must record it as such, and the production reactivation checker must be tested to never invoke `reactivate_reply` for threads absent from local state.

5. **Sweep apply can purge a thread with an unprocessed new reply (plan D9 + issue body "Grace Period Logic").** Issue #2026 specifies "If new unread message arrives during grace period: revert to inbox." `sweep_grace(apply)` checks only still-`completed` local records and never consults an inbox snapshot; if the reactivation checker has not run first, a replied-to thread is purged locally. Mitigated because purge is local-only and `purged -> extracted/inbound` reactivation is valid, but the plan should state the ordering contract (reactivation check before sweep apply) for the scheduled job and any future #2423 wiring, where purge stops being harmless.

6. **The r6 dispatched-provider artifacts are zero-byte files, not UNAVAILABLE records (plan line 9 + `scripts/review/results/2026-06-11-plan-2026-r6/`).** The 17:37 fanout failed (gemini: sandbox/tool errors in `.err`; codex: 325 KB `.err`; claude: empty). Per the repo's documented degradation convention, failed provider rounds must be recorded as explicit UNAVAILABLE files — empty `.md` files can be misread as silent passes. The plan's review-artifact inventory (line 9, Artifact Map) also stops at r5 and should be updated to reflect r6 disposition.
