### claude

- **Nonexistent registry path — Resource Intel line 23.** The plan cites `packages/worldenergydata-core/src/worldenergydata_core/fields_registry.py`. That path does not exist. `src/` contains `worldenergydata/` and `worldenergydata_core.egg-info/` only; the module lives at `.../src/worldenergydata/common/fields_registry.py`, importable as `worldenergydata.common.fields_registry` (the egg-info name `worldenergydata_core` is packaging metadata, not an import namespace). Any implementation slice importing the cited path fails at import. The *behavior* claim (fail-closed, duplicate check) is otherwise correct.
- **Referenced Round-1 review artifacts are empty/errored — plan line 11.** The header points to `2026-07-16-plan-1045-{claude,codex,gemini}.md` as "Round 1 artifacts." On disk: `claude.md` = 0 bytes (with 0-byte `.err`), `codex.md` = 0 bytes with a **201 KB `.err`** (the Codex run crashed), `gemini.md` = 338 bytes. The Adversarial Review Summary (lines 250–255) correctly shows all three PENDING / "review not run." The tri-provider gate the workflow requires has produced no substantive signal; citing these files as "artifacts" overstates the review state.
- **Live-publish acceptance criterion depends on unowned admin-only infra — lines 105, 171, 238.** The plan requires a `field-explorer-publish` GitHub environment, a protected-environment approval policy, a configured automation actor, SHA-pinned actions, and an HF token secret *in the worldenergydata repo*. These are repo-admin settings, not code produced by this issue. The plan neither verifies they exist nor names an owner/prerequisite for provisioning them. The criterion "Live publication will run only through the protected manual GitHub Actions environment" (line 238) is un-satisfiable until someone with admin creates the environment + secret + approval rule.
- **Test-list numbering is corrupt — lines 219–221.** Items run `…27, 28, 29, 28` with no `30`: line 219 "28. live mode refuses execution…" and line 221 "28. expected-parent conflict…" are both numbered 28, and 29 (line 220) is sandwiched between them. The list claims 29 publisher tests but the numbering is inconsistent, which will confuse the "failing test precedes each slice" bookkeeping (acceptance line 227).
- **Redirect test conflates unit-fixture with live external behavior — test 25 (line 216) vs acceptance (line 240).** Test 25 asserts "same-origin raw cache redirect is bounded and preserves the exact SHA; off-origin browser-JSON redirects fail" — a property of HuggingFace's live edge/redirect layer. Acceptance line 240 says this is "fixture-tested." A fixture proves the fixture, not HF's real behavior. The plan's own immutable-read reproduction (line 70) shows the datasets-server surprised the authors (HTTP 200 for a fabricated SHA), which is exactly why the same-origin browser-cache guarantee needs an *empirical probe transcript*, not a hand-authored fixture. Specify how (mock vs. live probe) or the criterion is untestable.
- **Single T3 issue carries an unusually wide surface — Files to Change (lines 169–179) + Deliverable (lines 103–105).** One issue bundles: a pure builder, a transactional publisher, a protected GH Actions workflow, three JSON schemas, deprecation/deletion of the existing publisher, regeneration of the tracked bundle+card, a human-contract HTML doc, cross-repo parent verification (#3559), and a website fixture (#74) — behind 29 tests. This risks an unreviewable mega-PR and couples the low-risk deterministic-builder work to the high-risk live-HF-mutation + admin-infra work. Consider splitting the builder/publisher-core slice (fully local, testable now) from the protected-workflow/live-publish slice (blocked on Finding 3).
- **Load-bearing immutable-read claim is unverified offline — line 70.** "datasets-server returned identical HTTP 200 bytes for the real HF SHA and a fabricated all-zero SHA; raw `resolve/<fake-sha>` returned 404" drives test 23 (no datasets-server for verification) and the entire exact-SHA-readback design. It is plausible and self-consistent, but I could not verify it without network access. The plan should retain the probe transcript as committed evidence, since the verification architecture is unrecoverable if this claim is wrong.
