## Findings
1. Plan §Evidence line 58 falsely identifies `a26881d49d064ea6ae6c8200ae1a874bf944e1bb` as current `worldenergydata/main`. Live `refs/heads/main` is `090228fb4a1193e4190fc4da90644d9f40a20b5a`, 21 commits ahead. Even though the GitHub comparison did not show the named Explorer inputs among changed files, the child plan must reconcile current HEAD and replace the false baseline before approval.

2. Plan §Existing repo code line 23 cites nonexistent `packages/worldenergydata-core/src/worldenergydata_core/fields_registry.py`. The implementation is at `packages/worldenergydata-core/src/worldenergydata/common/fields_registry.py`. Retrieval evidence that names an absent correctness-critical source is invalid.

3. Plan §Acceptance Criteria line 228 and §Risks line 262 promise a pinned toolchain, but §Files to Change lines 165–179 omit `pyproject.toml` and `uv.lock`. Root `pyproject.toml` does not declare `huggingface-hub`; it only appears transitively in `uv.lock`, and the normal `.venv` raises `ModuleNotFoundError`. The proposed publisher therefore lacks a declared runtime dependency and clean locked-install test. Add explicit dependency/lock changes and a clean `uv sync --locked` workflow/test.

4. The receipt sequence is impossible as written. Plan §Pseudocode line 158 writes the receipt immediately after HF readback, while §Deliverable line 105 requires that receipt to contain the Actions artifact ID/digest/attestation, environment approval, and conclusion. Artifact ID/digest exist only after `upload-artifact`; attestation requires a subject digest; final run conclusion does not exist until the run finishes. §Files to Change line 179 also gives no durable finalization/commit or second-artifact mechanism. The plan needs separate publisher output, evidence upload/attestation, and post-run receipt finalization with an explicit durable location.

5. Plan §Pseudocode line 157 verifies only artifacts listed inside the manifest. The manifest cannot include its own hash without a self-reference, so `browser/manifest.json` is not covered by that loop. This contradicts §Acceptance Criteria line 235 requiring every raw artifact to be revalidated. The exact-SHA manifest bytes must be fetched, compared with the staged manifest, hashed and schema-validated separately before processing its entries.

6. The legal-admission gate is not executable. Plan lines 34, 140, 191 and 241 rely on a legal scan plus “approved license classes,” but `worldenergydata/.legal-deny-list.yaml` excludes `*.md`, `*.csv`, `*.json`, and `data/`; Parquet is binary and is not meaningfully covered by the `rg` scanner. The Explorer provenance is narrative and lacks source-specific license/redistribution evidence. §Risks line 261 acknowledges the unresolved rights question but defines no authoritative classification record, required evidence fields, owner, or resolution step. A config value that merely asserts an approved class cannot prove redistribution rights.

Plan §Evidence lines 56–74 supplies only selected hashes and prose, misses issue-state evidence, cites the wrong loader path, and uses the now-stale HEAD.
