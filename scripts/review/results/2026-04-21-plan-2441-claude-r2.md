### Issues Found
- Stale commit-hash cite: Evidence and Gaps sections cite `git log --oneline -1 docs/plans/...-2441-...md → 3b09fc067 chore(sync): auto-sync 2026-04-21`, but after the Wave 2 revision was itself committed, `git log --oneline -1` on this file now returns `bf2222da2 docs(plans): #2424 Wave-2/Wave-3 — cross-review artifacts + 3 plan revisions`. The 3b09fc067 commit is historic (first landing) but is no longer the HEAD commit for the file — a reviewer running the cited command verbatim will see a mismatch and may (wrongly) flag this as evidence drift. Language should say 'first landed in 3b09fc067; current HEAD commit bf2222da2' or equivalent.
- TDD step 2 ordering is fragile: 'confirm they fail (or collect-error) in a clean venv without pylife installed' is placed before step 3 (append pylife to pyproject.toml). But `uv run pytest` auto-syncs from pyproject.toml, so the assertion 'venv has no pylife' holds only if the developer hasn't run `uv sync` or `uv run` in the repo since pylife was added to any transient lock state. The step should explicitly say 'on an interpreter where `python -c "import pylife"` fails' or scaffold a throwaway venv — otherwise the TDD red-step is non-deterministic.
- Acceptance criterion 'Quality Gates workflow ... returns success on the first run after the fix commit lands' silently assumes pylife was the only red signal. `quality_gates_cli check --json` likely gates on lint/bandit/coverage in addition to pytest (the workflow runs `continue-on-error: false`). If any OTHER gate is currently red on main (plausible — this repo has 60+ red runs), the first post-fix run won't be green. Criterion should be narrowed to 'pytest collection succeeds; ModuleNotFoundError for pylife no longer appears in quality-gates logs' or explicitly state the pre-check that pytest-collection was the sole blocker.
- Acceptance criterion 'Adversarial-review artifacts ... zero MAJOR findings outstanding' creates a self-referential gate (this very review is the artifact). Harmless in practice but worth flagging — the criterion can't be 'checked' by the implementing agent without a separate review-complete signal from outside the implementation scope.
- Scope of smoke test is narrower than advertised: `__init__.py` imports from `.sn_curves`, `.damage`, `.crack_growth`, `.woehler_fitting`, `.rainflow`, `.sn_library`, and more — the first test catches any broken import, but `test_fatigue_exports_get_sn_curve` / `test_fatigue_exports_dnv_curves` verify only 2 symbols of dozens and can give false confidence that 'the package API is whole'. Not a blocker; labeling the tests as 'sn_curves module re-export guard' rather than 'fatigue package exports' would be more truthful.
