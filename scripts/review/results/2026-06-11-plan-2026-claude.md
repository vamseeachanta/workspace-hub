## Findings

1. **BLOCKER — Missing-extraction reactivation targets a transition the contract forbids.** Plan §Adversarial Review Summary claims the r1 fix "Changed missing-extraction reactivation to return to `inbound`, matching the design contract," and §Pseudocode `reactivate_reply` executes `transition(from_state=prior_state, to_state="inbound")`. But §Pseudocode `transition()` first does "validate from_state -> to_state transition is allowed," and the design contract's State Machine table (`docs/design/email-as-queue.md:57-67`) defines exactly eight edges — **none of which target `inbound`**. `purged -> inbound` (and `awaiting-reply/completed -> inbound`) is an invalid transition under the plan's own validator, so `test_missing_extraction_logs_learning_event_and_returns_inbound` (TDD list) contradicts `transition()` as specified. The design doc's prose at line 43 ("treats the message as new inbound") conflicts with its own transition table, and the plan inherits this contradiction without resolving it: the Files-to-Change entry for `email-as-queue.md` covers only "runtime state path, two-account scope, pending-work semantics" — not transition-table extension. The plan must explicitly add the reactivation-to-`inbound` edge(s) to the state machine and the design doc, or define the missing-extraction path as a non-transition event.

2. **Plan header cites review artifacts that are empty at review time.** §Header "Review artifacts" points to `scripts/review/results/2026-06-11-plan-2026-{claude,codex}.md`, which are 0 bytes (their `.err` siblings show in-flight/failed CLI runs); only the gemini file has content. The verdicts the §Adversarial Review Summary table reports actually live in the `-r1-*` files, which the header does not reference. An approver following the header paths finds two of three reviews missing. Update the header to cite the r1 artifacts for the recorded round and ensure r2 artifacts are non-empty before `status:plan-review`.

3. **Pseudocode API shape diverges from the frozen contract tests.** `tests/email/test_state_machine_contract.py:18,27,41-44,54-61` call `transition(log, ...)`, `lookup(log, acc, thr)`, `count_entries(log)`, `reactivate_reply(log, ...)` with an explicit JSONL **path as the first positional argument**. §Pseudocode instead resolves the state dir from `EMAIL_QUEUE_STATE_DIR` and operates on a `store`, and D1 says "Tests will use temp directories and `EMAIL_QUEUE_STATE_DIR`" — but the existing contract tests use no env var. Where snapshot/meta/learning-log files land when the caller supplies a bare log path is unspecified. The plan should pin the public signature (path-first, with derived sibling-file locations) so implementation doesn't break the #2017 contract tests it promises to un-xfail.

4. **`pending_work_report` return shape misses its own acceptance criterion.** §Pseudocode returns only `(tracked_empty, mailbox_empty, unknown_status)`, dropping `unknown_count` and the **per-account counts** that AC #4 requires ("includes per-account counts"). Additionally, D3's non-pending bucket "`extracted` with no action pending" implies a computable "extracted with action pending" class, but the only pending classes computed are `inbound` and `needs_user_decision` — an extracted thread needing a reply that hasn't yet transitioned to `awaiting-reply` is silently non-pending. Risk of an "empty" report over-claiming.

5. **Dedup fallback rule under mixed `triggering_message_id` presence is undefined.** D5 makes `triggering_message_id` "part of the dedup-key contract," yet the existing contract test `test_transition_retry_preserves_dedup_under_fresh_ts` dedups two events that carry **no** triggering id (must keep passing). The mixed case — event A without id, event B with id, same `(account_id, thread_id, from_state, to_state)` — is unspecified: one row or two? The schema's `dedup_key` is a flat required list (`email-queue-state-schema.yaml:60-64`); conditional key membership isn't expressible in that shape, and the plan says "revise dedup semantics" without stating the fallback rule the schema modification must encode.

6. **Cosmetic evidence defect:** the gh-issue verification and the pytest reproduction both claim the identical instant `2026-06-11T20:21:48Z` (§Evidence) — copy-paste timestamping. Both facts independently reproduce today, so this is presentation, not substance.
