## Verdict: MAJOR

## Summary
The plan contains a major operational flaw regarding systemd unit management and security risks with token handling. Editing the main systemd unit directly guarantees it will be overwritten by future `hermes update` runs; an override file (`override.conf`) must be used instead. Furthermore, the token validation tests expose the token to bash history or the process list, and the systemd `EnvironmentFile=` directive uses a leading dash which masks failures if the critical `.env` file goes missing.

## Findings

1. **[MAJOR] Pseudocode Wave 1 / Files to Change** — Directly editing `/etc/systemd/system/hermes-gateway.service` is an anti-pattern when the file is managed by an external tool (`hermes update`). It will be overwritten.
   - **Evidence:** `sudo cp /etc/systemd/system/hermes-gateway.service ... sudo edit unit:` (Pseudocode Wave 1 step c) plus the Risks section acknowledging "`hermes update` may overwrite `/etc/systemd/system/hermes-gateway.service`".
   - **Fix:** Use `sudo systemctl edit hermes-gateway` to create a drop-in override (`/etc/systemd/system/hermes-gateway.service.d/override.conf`) containing `[Service]\nEnvironmentFile=/home/vamsee/.hermes/.env`. Drop-in overrides natively survive base-unit overwrites.

2. **[MAJOR] Pseudocode Wave 1 / TDD t05** — Token exposed to shell history / process list. The verification command passes the token as a command-line argument to `curl`, making it visible in `ps` output and potentially `.bash_history`.
   - **Evidence:** `curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getMe"` (TDD test list, t05).
   - **Fix:** Read the token into a subshell-scoped variable from the `.env` file, then pass via stdin or a heredoc. Note that `ps` may still briefly show the URL; consider redirecting via `--data-urlencode` from a file or sourcing then immediately `unset`.

3. **[MINOR] Pseudocode Wave 1** — The `EnvironmentFile=-/home/vamsee/.hermes/.env` directive uses a leading dash. Since `.env` is strictly required for the bot to function, it should fail fast if missing.
   - **Evidence:** Pseudocode Wave 1 step c — `EnvironmentFile=-/home/vamsee/.hermes/.env  # leading "-" → systemd does not fail if file missing`.
   - **Fix:** Remove the leading `-` so systemd refuses to start the unit when the env file is absent (fail-closed default matches the security model).

4. **[MINOR] TDD t10** — The destructive action test does not actually verify the file remains intact after being denied.
   - **Evidence:** t10 row: `manual: ask bot to rm /tmp/test-approval-gate, observe journalctl` — no subsequent existence check.
   - **Fix:** Add explicit `test -f /tmp/test-approval-gate && echo "GATE HELD"` post-condition; create the canary file before the test.
