`★ Insight ─────────────────────────────────────`
- The trap here is **tautological parity testing**: when two code paths are unified onto one shared module, an "are they identical?" test becomes vacuously true and stops protecting behavior. Parity tests after a consolidation must anchor to an *external golden value* (the pre-refactor observable), not to the sibling path.
- **Identity aliasing is a precedence hazard, not just a lookup convenience.** The moment a registry lets one machine answer to `{canonical, hostname, alias}` *and* a per-machine map keys on more than one of those names with different values, resolution order silently picks a winner. setup-cron's `sorted()` and the renderer's insertion-order list disagree — invisible until the values differ.
- Six adversarial rounds verified *existence* claims (files, markers, repo counts) exhaustively but missed a *semantic ordering* defect, because the defect only surfaces when two `schedule_by_machine` keys for the same host hold different values — a data condition none of the cited reproductions exercised.
