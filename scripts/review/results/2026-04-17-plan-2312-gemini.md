# Gemini review — plan #2312

- Verdict: MINOR
- Strengths:
  - Correctly identifies the core issue: deleted lifecycle scripts (`close-item.sh`, `archive-item.sh`, `claim-item.sh`) are still referenced in active templates and need removal.
  - Explicitly recognizes the need to separate live workflow surfaces from intentional historical artifacts (like `legacy-claude-reference-map.md`).
  - Emphasizes the need for regression tests to prevent the reintroduction of these specific stale references.
- Gaps:
  - Leaves the replacement evidence target for Close/Archive as an "Open Question". A plan should propose the solution (e.g., requiring a GitHub Issue URL or PR URL), not defer the decision to implementation.
  - Vague about the "curated current-file list" for tests. It fails to explicitly list critical agent configuration files (`.claude/rules/*`, `AGENTS.md`, `.gemini/GEMINI.md`, etc.) where references to deleted scripts are most dangerous.
- Risks:
  - If the new evidence target for the Close/Archive stages is too complex or undefined, agents will struggle to fill out the `.planning` template correctly, leading to validation loops or blocked task completion.
  - Fragmenting the test suite by creating a hyper-specific test file for three scripts instead of leveraging the existing banned-reference test architecture.
- Missing tests:
  - Explicit inclusion of agent prompt directories and rule files (e.g., `.claude/rules/`, `.claude/skills/`, `.gemini/`) in the targeted regression test to ensure agents aren't being instructed to use the old scripts.
- Scope creep concerns:
  - Creating a brand new `tests/docs/test_lifecycle_script_reference_cleanup.py`. It would be cleaner and more maintainable to integrate these scripts into the existing `tests/docs/test_banned_stale_references.py` and `tests/helpers/stale_reference_docs.py` infrastructure rather than building a bespoke test.
- Weakest assumption and what breaks if it is false:
  - *Assumption:* The only active surfaces that need updating are standard documentation and the stage-evidence template.
  - *What breaks:* If the references are actually embedded in agent skills (like `workflow-gatepass`) or system prompts, fixing the template won't stop agents from trying to call the deleted scripts, resulting in persistent execution errors.
- Most likely implementation failure mode:
  - The developer updates the `.planning` template to require a new type of evidence for closure but forgets to update the corresponding workflow documentation or agent skills that teach the agent *how* to gather that new evidence.
- Most likely test gap:
  - The test's "curated file list" only globs `docs/**/*.md` and misses dot-directories (like `.claude/` and `.planning/`), allowing hidden references to survive.
- Future issues suggested:
  - Unification of all stale reference testing into a single data-driven configuration file (e.g., a YAML list of banned terms and their allowlisted files).
  - A comprehensive review of all `.planning/templates/` to ensure no other legacy `scripts/work-queue/` scripts remain.
- Review confidence: High
