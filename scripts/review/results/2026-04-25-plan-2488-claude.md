## Findings

1. **Plan promises a "narrow `.gitignore` negation" alternative that is not actually narrow for any of the six known active filesystem-only paths** (Plan §"Files to Change", `.gitignore` row, line 230; §"Risks and Open Questions" decision bullet, line 313; §"Files to Change" promotion row, line 229; §Acceptance Criteria item 7, line 276; TDD list `test_promote_ignored_skill_requires_force_add_attestation`, line 259). All six known paths sit under directories matched by `digitalmodel/`, `memory/`, or `personal-*`, which are *parent-directory* ignore patterns. Per `gitignore(5)`: "It is not possible to re-include a file if a parent directory of that file is excluded." I empirically verified this in `/tmp/giproof`: a single-line `!.../SKILL.md` negation is silently overridden by the parent rule. Re-inclusion requires a multi-line cascade (re-include parent dir → re-exclude its siblings → re-include the child file). The plan's wording invites an executor to write a one-liner negation, observe it not working, and burn time. Either drop the negation alternative for these paths and require `git add -f`, or rewrite the bullet to specify the multi-line cascade and forbid single-line negations.

2. **The plan introduces three new CLI flags but never enumerates the existing CLI surface** (Plan §Pseudocode `validate_and_render_dispositions`, line 195; §Acceptance Criteria, line 280). The audit script today exposes `--skills-dir / --output-dir / --policy / --waivers / --render-github-payload` (script lines 1035-1059). The plan adds `--mode`, `--disposition-ledger`, `--disposition-report`, but the "Files to Change" row for `weekly_skills_audit.py` (line 222) does not list them, and acceptance criterion at line 280 references `--mode manual_closeout --disposition-report ...` without naming the existing flags that must continue to behave identically. An executor cannot tell from this plan which flags are preserved verbatim, which are renamed, and which are added — backward-compatibility cannot be reasoned about from the plan alone.

3. **`test_existing_weekly_audit_behavior_remains_backward_compatible` is not a test, it is a sentinel statement** (Plan §TDD Test List, line 263). "Existing fixture tests" → "existing tests still pass" describes a regression *property*, not an executable assertion. Either delete this row (the property is implicit in CI) or replace it with a concrete fixture that asserts a *specific* duplicate/collision finding count on a frozen fixture before and after the inventory extension.

4. **The `_archived` legacy-collision-baseline acceptance bullet contradicts the corresponding TDD test** (Plan §Acceptance Criteria item starting at line 273 vs. TDD `test_archived_loss_filter_does_not_create_new_duplicate_findings`, line 260, plus the next-to-last acceptance bullet at line 283). The acceptance text simultaneously requires (a) "no new duplicate/collision finding is introduced" AND (b) "if current legacy behavior already reports `_archived` collisions, document that as pre-existing" AND (c) "records a pre-change `_archived` duplicate/collision baseline ... so regression tests cannot claim 'pre-existing' without evidence." The TDD test asserts (a) absolutely. If today's audit (with `EXCLUDED_DIRS = {"_archive", "_diverged"}` per script line 32) already emits `_archived` collisions, the unit test will fail in implementation even though the acceptance criterion accepts the pre-existing case. The plan needs one consistent posture: either compute the baseline first and assert delta = 0, or assert absolute count = 0. Pick one.

The pseudocode signature shows `symlink_resolver=None` but the test row only says "resolver-injection seam supplies `.codex/skills` and `.gemini/skills` link targets." The signature/contract (does it return a `Path`, a string, raise on non-symlink, accept absolute or repo-relative inputs?) is not pinned, so the RED test cannot be written deterministically before implementation. Updating `docs/plans/README.md` to `status:plan-review` is part of the planning gate workflow, not the implementation diff.
