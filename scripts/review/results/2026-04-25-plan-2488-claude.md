1. **Internal contradiction on Complexity.** Frontmatter line 4 declares `**Complexity:** T2`. 2. **Embedded evidence block contains author annotations presented as stdout.** The heredoc at lines 58–81 prints labels like `tracked_active_excluding_archive_archived` (line 69) and unsuffixed integers, but the "Output:" block at lines 83–99 shows relabeled keys (`tracked_active`, `fs_active`, `missing_active_tracked_from_fs`) and inline `# strict active filter excludes _archive, _archived, _diverged` comments that the heredoc never emits. This violates the evidence-purity convention: hand-edit annotated commentary should live outside the fenced "Output:" block, not be presented as if produced by the command. MINOR but corrosive across many plans if normalized.

3. **Soft acceptance criterion with contingency escape (line 270).** The criterion ends with: *"if current legacy behavior already reports `_archived` collisions, document that as pre-existing rather than changing `EXCLUDED_DIRS`"*. The plan never records the **current** pre-#2488 baseline of `_archived` collision findings (e.g., a snapshot of `weekly_skills_audit.py` output today against the six tracked `email/_archived/*/SKILL.md` files). Without that baseline captured before implementation, the regression test `test_archived_loss_filter_does_not_create_new_duplicate_findings` (line 257) can pass vacuously: an implementer can claim "pre-existing" without proving it. The criterion should require the baseline JSON/Markdown to be checked into the disposition report or fixture so the regression test has a falsifiable reference.

4. **Wrapper invariance asserted but not regression-tested.** Line 277 acceptance: *"`scripts/cron/skills-curation.sh` remains unchanged unless a test proves wrapper changes are necessary; the audit script CLI defaults to `--mode weekly_report`"*. The TDD list contains `test_default_cli_mode_is_weekly_report_for_cron_wrapper` (line 251), which asserts the **script** default is `weekly_report`, but does not run or shellcheck the actual wrapper's `AUDIT_CMD` (lines 32–47 of `scripts/cron/skills-curation.sh`) against the new argparse surface. A subtle change (e.g., `--mode` becoming required, or `--skills-dir` collision with a future `--disposition-*` arg) would silently break the cron path. Add an end-to-end test that invokes the wrapper in `--dry-run` mode and asserts the printed command parses cleanly under the new argparse without `--mode`.

5. **Review-artifact paths declared in frontmatter point to empty files.** Plan frontmatter line 7 advertises `scripts/review/results/2026-04-25-plan-2488-claude.md | …-codex.md | …-gemini.md` as the review artifacts. 6. **`_core`/`_internal` loss-risk semantics lack a corresponding policy update.** Pseudocode line 152: *"`_core` and `_internal` remain in-scope for filesystem-only loss-risk reporting; do not reuse `INFORMATIONAL_DIRS` to suppress them"*. Without that, downstream consumers of the JSON cannot triage. Recommend adding an `informational: true|false` field to each entry under `inventory_summary.paths`.

7. **No mention of how `git ls-files` behaves under sparse-checkout / overlay paths.** The user's auto-memory records *"Sparse overlay (`~/workspace-hub` may be overlay — write to `/tmp/` first)"* and a recent feedback memory: *"Gemini sandbox overlay blindness — sandbox can't see sparse-checkout overlay; verify with `git ls-files` before accepting MAJOR"*. The pseudocode mentions a `git_list_fn` injection seam and `test_git_inventory_failure_is_reported_not_cron_fatal`, but neither addresses the **partial-result** failure mode (Git succeeds, returns subset). Plan should specify: either (a) the audit refuses to run on sparse worktrees, or (b) the inventory cross-checks `git ls-files` count against `git rev-parse --is-inside-work-tree` + `git config core.sparseCheckout`.
