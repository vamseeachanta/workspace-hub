## Findings

1. **Internal contradiction — r2 §2 vs. `_coating_translation.py` pseudocode.** r2 Revision Summary §2 (lines 13–14) explicitly states: "enum members `THREE_LAYER_PE`/`THREE_LAYER_PP`/`CONCRETE_WEIGHT` (not `3LPE`/`3LPP`/`CONCRETE`)." But the same plan's `_coating_translation.py` pseudocode (lines 499–506) still uses the old short forms as keys: `"3LPE"`, `"3LPP"`, `"CONCRETE"`. `COATING_BREAKDOWN_2017` (lines 433–443) uses `THREE_LAYER_PE`/`THREE_LAYER_PP`/`CONCRETE_WEIGHT`. So within one plan, the translation map keys do not match the breakdown-table keys, and the r2 fix that promised to correct exactly this is not actually carried through.

2. **Internal contradiction — `calculation_type` schema fate.** r2 §5 (line 17) and pseudocode line 546 (`calculation_type: DNV_RP_B401_offshore   # legacy dispatch key — UNCHANGED`) say `calculation_type` is **preserved** for back-compat. But the §Files to Change row for the YAML (line 614) says: "Replace `calculation_type: ABS_gn_ships_2018 # …` with `standard:` + `edition:` two-key dispatch". These cannot both be true. AC-P4.7a tests one outcome (legacy `calculation_type` still routes); AC-P4.1/4.2 test the other (dead keys removed + new `edition:` key added). The contradicting "Replace … with `standard:`" instruction must be reconciled with the keep-`calculation_type` story.

3. **`SUPPORTED_STANDARDS` drops two NACE standards the Deliverable promises to preserve.** §Pseudocode P3 declares `SUPPORTED_STANDARDS` with 13 entries (lines 521–535). The tuple includes `NACE-SP0169` but **omits `NACE-SP0176` and `NACE-SP0207`**. The §Standards table (lines 63–65) explicitly lists SP0176 (CP of fixed offshore steel structures, docstrings in `marine_structure_cp.py`) and SP0207 (close-interval survey, docstrings in `cp_survey.py`) as covered by the functional package. AC-P3.2 asserts `len(SUPPORTED_STANDARDS) == 13` — passing this AC **proves** the omission silently lands. Deliverable line 331 claims "preserves all 8 additional standards (… NACE SP0169/SP0176/SP0207 …)" — directly contradicted by the manifest.

4. **Standards count inconsistency throughout (8 vs. 9 vs. modules).** Plan §Standards "Net" sentence (line 72) reads "8 standards (ISO 15589-2, API RP 1632, NACE SP0169/SP0176/SP0207, NORSOK M-506, EN 50162/15280, ISO 18086)" — that enumeration is **9 distinct standards** (3 NACE + 2 EN + 4 others), not 8. The same "8 additional standards" string appears in Deliverable (line 331) and Finding-8 closure (line 20). AC-P3.1 verifies importing **8 modules** (`iso_15589_2, api_rp_1632, cp_monitoring, cp_survey, stray_current, corrosion_rate, anode_depletion, iccp_design`) — but `cp_monitoring`, `anode_depletion`, `corrosion_rate` are methodology modules, not named-standard modules. So "8 modules importable" does not verify "9 standards preserved." The Finding-8 closure premise is unfalsifiable as currently written.

5. **`test_baseline_flush_anode_resistance_ratio_geometry_dependent` does not anchor production behavior.** Lines 202–218: the test recomputes McCoy and Dwight in pure Python (`r_mccoy = (1/(π*L_m))*(ln(2L/r) - 0.5)`) and asserts the ratio of those recomputed values. It **never calls `flush_anode_resistance()`** from the production module. The plan's premise (line 285–287) says "this file is created and committed as the very first thing in P1, before any source edit, so the merge phases (P2 especially) can run it to prove no unintended collapse occurred." Risk #1 mitigation (line 824–825) says "baseline tests prove byte-identity restoration" on rollback. Neither claim holds if the test is a math identity check decoupled from the live function. If `flush_anode_resistance()` carries a unit-conversion bug today (it converts in→cm internally, so the function-output magnitude differs from the test's metric recompute), this test cannot detect it.

6. **Unit-contract gap — the silent-verdict-flip class the plan promised to prevent.** `digitalmodel/src/digitalmodel/cathodic_protection/dnv_rp_b401.py:325-328` accepts `L_a_in, r_eq_in` (inches) and `rho_ohm_cm` (CGS), converts inches→cm internally. `digitalmodel/src/digitalmodel/infrastructure/base_solvers/hydrodynamics/cp_DNV_RP_B401_2021.py:339` accepts `L, r, rho` in unspecified-but-clearly-SI units and returns ohms. The merged signature in §P1 pseudocode (lines 380–397) does not name parameters, so the unit contract of the post-merge `flush_anode_resistance(..., edition=...)` is undefined. `_edition_tables.FLUSH_RESISTANCE_FORMULA` (lines 458–461) stores only formula identifiers — it has no slot for unit-system or conversion. Per `feedback_silent_verdict_flip_defect_class.md` step 2.iii, "Different units (kN vs N, m vs mm)" is one of the exact diffs to look for; this plan introduces no AC, no test, and no schema field for the unit divergence. A caller passing `L=2 (meters)` while the dispatcher routes to the 2017 McCoy path expecting inches would silently produce a CP design under-sized by ~6× (2.54² inches/m factor squared inside log argument).

7. **Counts mismatch between AC-P1.1 (6 tests) and AC-P2.5 (5 tests).** AC-P1.1 (line 692): "all **6** baseline tests pass (r2: expanded by 1 for internal-router-Dwight divergence)." AC-P2.5 (line 709): "Baseline tests STILL pass (no silent collapse): … — same **5 tests**." The TDD test list (lines 635–640) shows 6 entries. If AC-P2.5 only re-runs 5 of the 6 after P2 changes, the missing test (presumably `test_baseline_internal_router_dwight_divergence`) is the **exact** test that would catch a P2 silent-collapse onto a single Dwight variant. This is a structural reviewer hazard, not just a typo.

8. **r2 §1 inline formula is mathematically wrong as written.** r2 Revision Summary line 13: "Python recompute: `(ln(4)−0.5)/(ln(53.33)−1) × 2 ≈ 1.8702`." Substituting: `(1.386 − 0.5) / (3.976 − 1) × 2 = 0.886 / 2.976 × 2 = 0.595` — not 1.8702. The correct expression at L=2, r=0.15 is `2 * (ln(26.67) − 0.5) / (ln(53.33) − 1) ≈ 1.870`. The asserted test numeric (1.8702) happens to be right, but a future engineer reading the r2 doc-explanation and re-deriving will arrive at 0.595 and either "fix" the test or lose trust in the plan.

9. **AC-P4.5(c) calls `design_cp_system(...)` with empty arguments.** Line 731: `r = design_cp_system(...); assert hasattr(r, 'citations')`. The literal `...` ellipsis is not a callable arg-list; if this AC is copy-pasted into a CI runner, it raises `TypeError`. 10. **Risk #2's `DIGITALMODEL_CP_REQUIRE_EXPLICIT_EDITION` env-var has no AC, no test, no file-change entry.** Line 770 introduces a "paranoid production" mode that requires explicit `edition=`. But §Files to Change does not list the file that reads the env var, §Acceptance Criteria does not test it, and §TDD Test List has no corresponding case. Either drop the mitigation or wire it.

11. **`Citation` sidecar wiring spans both #2685 dependency and `coating_breakdown_factor`'s contract.** §P1 Pseudocode line 388 returns a plain `float` from `coating_breakdown_factor`, and the r2 §6 fix explicitly says citations emit at **`anode_sizing.design_cp_system`** (the call-graph parent). But `coating_breakdown_factor` is the function that resolves the standards-derived constant (a/b coefficients). Per `.claude/rules/calc-citation-contract.md` step 3 ("Emit a `Citation` instance ... alongside every standards-derived numeric constant you introduce"), the **emission site** is `coating_breakdown_factor`, not `design_cp_system`. The plan moves emission upstream to the result aggregator; this trades step-3 directness for step-6 sidecar compatibility. The plan does not name this trade-off explicitly, and the rule itself is currently *aspirational* at the emission-site level (per the rule doc's own caveat). Reviewer-visible gap: the plan resolves Finding 6 in a way that adds distance between the constant and its citation, which the rule discourages.

12. **`anode_depletion`/`cp_monitoring`/`cp_reporting` inheriting edition "via `result.edition_used`" is asserted but not enforced.** Non-goal closure (lines 346–348) reads: "`anode_depletion`, `cp_monitoring`, `cp_reporting` are post-design instruments that read result objects produced by the 6 edition-sensitive modules and inherit edition via the `result.edition_used` field already carried." Add at minimum a smoke test that constructs an `edition='2017'` result, hands it to each of the three, and asserts no edition-coupling escapes.
