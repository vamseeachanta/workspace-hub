# Plan Review — #2851 freshness-guard — Claude (r1, adversarial)
Verdict: MAJOR (1 MAJOR + 2 MINOR). Plan reviewed pre-push.

## MAJOR
- **A1 — provenance-excluded-from-hash defeats the guard.** Plan excludes all of `provenance` from the commit-on-change canonical hash. But `dirty` and `behind_main` are freshness STATE: if excluded, a re-run from a now-dirty/now-behind tree with unchanged measured dims won't rewrite → the committed report keeps stale `dirty:false`/`behind_main:0` → matrix sees it as fresh = the very bug being fixed. Fix: hash EXCLUDES `checkout_sha` only (pure churn); INCLUDES `dirty` + `behind_main` so freshness transitions force a rewrite.

## MINOR
- **A2 — uniform-exclusion test expectation wrong.** `test_matrix_stale_excluded_from_uniform` expects "fresh pair stays EQUAL", but a stale+fresh pair, after excluding the stale peer, leaves ONE real reporter → `PENDING` (not EQUAL). Fix the expectation: stale excluded ⇒ the fresh machine's uniform dims read `PENDING` until a 2nd FRESH report exists.
- **A3 — dirty scope self-trigger.** `git status --porcelain -- .claude ...` could include the collector's own `.claude/state/equality-*.yaml` output. Mitigated by capturing `dirty` BEFORE write + committed-prior-report; make this explicit and test the no-self-trigger case.
