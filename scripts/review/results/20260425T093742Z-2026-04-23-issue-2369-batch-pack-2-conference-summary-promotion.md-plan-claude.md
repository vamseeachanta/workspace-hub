### Verdict: MAJOR

### Summary
v4 successfully closes the v3 cross-provider-converged P1 (Attested Evidence is now populated with a sha256-stamped payload at HEAD 3e0e7c2b) and resolves Claude r3's idempotency, blast-radius, and tie-discard P1/P2 items via R30/R31/R32. The plan is mature and well-reviewed. However, there is a concrete, internally inconsistent contradiction between the tokenizer contract (`title_ascii_lower_alphanum_v1` — alphanum implies underscores are non-alphanumeric) and the four underscore-containing keywords in DOMAIN_KEYWORDS (`vortex_induced`, `christmas_tree`, `semi_submersible`, `stress_concentration`, `offshore_wind`). Under any reasonable alphanum tokenizer, those keywords cannot match real paper titles, and the 3-way-tie worked example (Test 7b) is constructed assuming underscore preservation that the tokenizer name disclaims. This affects AC5 verification and a test fixture, so it must be reconciled before execution.

### Issues Found
- [P1] Tokenizer/keyword contract contradiction: `tokenize_v1` is named `title_ascii_lower_alphanum_v1` (alphanum-only), but DOMAIN_KEYWORDS contains five underscore-bearing keywords (`vortex_induced`, `christmas_tree`, `semi_submersible`, `stress_concentration`, `offshore_wind`). An alphanum tokenizer either strips underscores (yielding `stressconcentration`) or treats them as separators (yielding `stress`, `concentration`); in neither case does the `stress_concentration` keyword match. The Test 7b worked example explicitly shows tokens `{viv, jumper, fracture, stress_concentration}` and asserts `secondary_domains = ["pipeline", "structural"]` — but if the tokenizer drops underscores, structural's score would be 2 (only `fracture`), fall below threshold 3, and the correct expectation is `["pipeline"]`. AC5 is therefore underspecified or the fixture is wrong. Either (a) explicitly document that the tokenizer preserves underscore boundaries (rename to `title_ascii_lower_alphanum_underscore_v1` or similar), (b) replace the underscore keywords with unigram alternatives, or (c) make the classifier emit bigrams from adjacent tokens with `_` joiner.
- [P2] Test 24 (AC15 anchor-guarded fallback) only asserts a footnote IS present in each contradicting doc; it does not test the two distinct branches (anchor present → footnote at anchor; anchor missing → footnote at end-of-doc). The fallback behavior is the load-bearing safety property of R22 — please add a fixture with the §-anchor stripped to verify the end-of-doc fallback path actually fires.
- [P2] AC10 forbids `misc` in `secondary_domains`, and the schema parser is supposed to reject it at parse time, but the test list does not include an explicit fixture for `misc`-in-secondary rejection. Test 16 only verifies `secondary_domains` is a list-of-string and rejects `null`/single-string. Add a `test_cross_link_jsonl_schema_rejects_misc_in_secondary` test or fold it into Test 16.
- [P2] AC14 specifies an `ubuntu-latest`-class runner performance budget, but no CI workflow is referenced and the runner is invoked via `uv run` locally per the Runbook. Where is this benchmark actually executed, and is the budget enforced (PR-blocking) or informational? Without a concrete host, the budget is unfalsifiable.
- [P2] `safe_open` accepts arbitrary `mode` (including `"w"`/`"a"`) and only checks the deny-prefix on read OR write paths; the threat model in §Risks (PDF read-through prevention) is read-focused. Either narrow `safe_open` to read modes (the runner only reads), or add an assertion that `safe_open` is also write-safe by design, so a future agent doesn't add `safe_open(path, "w")` under a deny-prefix and re-introduce the regression in the other direction.
- [P3] `data/document-index/conference-phase-a-results.jsonl` is the load-bearing input for the runner (cited in §Resource Intelligence Summary as the 14,180-record source) but does NOT appear in the Attested Evidence file-existence list. The four other `data/document-index/*.{yaml,json}` files do appear. If the regex extractor missed it, the existence claim is unverified at HEAD 3e0e7c2b. Either re-attest with this filename included or cite the existing attestation that covers it.
- [P3] Open Question about `--collections` flag is contradicted by the pseudocode signature `run_batch_pack_2(catalog_path, phase_a_jsonl, output_report_path, now=None)` — no `--collections` parameter appears. Either spec the flag in the runner signature or close the Open Question by removing the flag.
- [P3] Schema v1.2 strictly rejects `null` for `secondary_domains` (R31), which is fine since #2068 is not yet built — but the Risks section's note about "governance on schema drift" leaves arbitration as "whichever issue is open files a PR amending the other". This is a vague conflict-resolution rule; consider naming an explicit owner (this issue or #2068) for the schema until #2068 lands.

### Suggestions
- Resolve the tokenizer/keyword contradiction by adopting one of: (a) explicit `tokenize_v1` spec preserving underscore as a token-internal character with regex `[a-z0-9_]+`; (b) replace underscore keywords with single-token equivalents (`vortex` already covers `vortex_induced`; `tree` covers `christmas_tree`; `semi`/`submersible` separately; `concentration` separately; `wind` separately) and adjust worked examples; or (c) compute classifier hits over both unigram tokens AND adjacent-token bigrams joined by `_`. Pick one and update the Test 7b worked example to be consistent.
- Add Test 24a/24b as separate fixtures for the anchor-present and anchor-missing footnote-placement branches (AC15).
- Add `test_cross_link_jsonl_schema_rejects_misc_in_secondary` to make AC10 falsifiable.
- Pin the AC14 host environment explicitly — either name a CI workflow file (e.g., `.github/workflows/batch-pack-2-perf.yml`) that runs the OMAE sub-slice and enforces <5min, or downgrade AC14 to an informational reference benchmark.
- Narrow `safe_open` signature to read modes only (`mode in {"r", "rb", "rt"}`) and raise on write modes — the runner only reads, so this tightens the contract and removes a future-foot-gun.
- Re-run `attest-plan-claims.sh` on a v4 staging copy that explicitly references `data/document-index/conference-phase-a-results.jsonl` so the load-bearing input is in the attested-evidence list, or note inline that the file's existence was verified by separate `ls` invocation with the captured output.
- Either implement `--collections` with a documented enum and default (`all`), or remove the Open Question about it.
- In the schema-governance section, name a single owner for cross-link schema arbitration until #2068 lands (recommend: this plan, #2369, owns schema until #2068 opens an amending PR).
