### Issues Found
- [P3] Minor: The `sitemap_loc_count_preserved` acceptance criterion hard-codes `39 <loc> rows before and after`, but the plan does not attest to the current count with a command-line count output (e.g., `grep -c '<loc>' sitemap.xml`). If the true pre-edit count differs from 39, the regression test will incorrectly fail on an otherwise-correct rewrite.
- [P3] Minor: The TDD Test List marks `sitemap_xml_is_still_well_formed` as verifying a shell-level `xmllint --noout` invocation, but Jest tests cannot directly own a shell exit code as a pass/fail gate unless wrapped in `child_process.execSync`. The plan should clarify whether this lives inside Jest (with shell-out) or as a separate Make/CI step, so the TDD-first ordering is unambiguous.
- [P3] Minor: The Adversarial Review Summary table lists Claude/Codex/Gemini as PENDING but the plan header already cites three pre-allocated review artifact filenames with a fixed timestamp `20260421T102749Z`. If any provider later produces a review under a different dispatch timestamp, the artifact-map path will drift from the actual filename on disk.

### Suggestions
- Add a single verification line under Evidence recording the exact current `<loc>` count (e.g., output of `grep -c '<loc>' aceengineer-website/sitemap.xml`) so the `sitemap_loc_count_preserved` test anchors to measured reality instead of a plan-asserted 39.
- Specify in the TDD Test List how `xmllint` is invoked — either (a) a Jest test that shells out via `execSync` and asserts `status === 0`, or (b) a documented separate step in the execution runbook. This removes ambiguity about what 'passes before implementation' means for that gate.
- When the apex→www rewrite runs, also scan for `<loc>http://...` (non-HTTPS) variants and `<loc>https://aceengineer.com` without a trailing slash or path; add those as negative assertions so the regression test catches any future regression that reintroduces non-canonical host+scheme combinations.
- Consider adding an explicit check that the `<urlset>` root element and XML declaration are preserved byte-for-byte aside from the host substitutions — a stray editor-added BOM or newline change could silently alter crawler parsing.
- Log the pre-edit and post-edit SHA-256 of `sitemap.xml` in the implementation summary so the rewrite is reproducible and auditable.
