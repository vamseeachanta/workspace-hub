### Summary
The plan is directionally correct and scoped tightly to `aceengineer-website/sitemap.xml`, and the attested evidence supports the key repo-state assumptions. It still needs changes before approval because the migration-verification baseline is brittle, the durable test strategy can miss malformed or missing `<loc>` rows, and the execution evidence path is underspecified.

### Issues Found
- [P1] Important: The one-time verification baseline is defined as `git show HEAD:aceengineer-website/sitemap.xml`, which is not a safe source of truth for this migration run. If execution starts from a dirty worktree, from a later commit, or after any unrelated sitemap edit, the comparison can validate against the wrong pre-edit content. The plan should require capturing the exact on-disk pre-mutation snapshot before editing and comparing against that snapshot.
- [P2] Important: The durable regression coverage is still too weak as written. `zero apex-host <loc>` plus `unique loc values` plus the existing 5 demo-detail assertions does not prove that every `<url>` entry still has a valid `https://www.aceengineer.com/...` `<loc>`. A malformed edit could remove a `<loc>`, leave it blank, or change it to a non-apex/non-www value and still satisfy the listed durable checks. The plan should require parsing all `<loc>` values and asserting the full set is non-empty, count-preserving, and uniformly `https://www.aceengineer.com/...`.
- [P3] Minor: The plan leaves sign-off evidence too implicit. It names `xmllint` and Jest, but it does not pin the exact test command or where the one-time migration comparison output will be recorded. That makes later review harder, especially since the attested evidence shows `.planning/plan-approved/2357.md` is currently missing and governance drift is already a concern.

### Suggestions
- Replace the `git show HEAD:...` baseline with an explicit pre-edit snapshot captured from the current working-tree file before any modification, then compare that snapshot to the post-edit file.
- Strengthen the Jest plan to extract all sitemap `<loc>` values and assert: every `<url>` has one `<loc>`, the count is preserved, and every value matches `^https://www\.aceengineer\.com/`.
- Add the exact verification commands and the recording location for one-time migration evidence, for example the precise Jest invocation, the `xmllint --noout aceengineer-website/sitemap.xml` step, and where the before/after comparison summary will be written or commented.
