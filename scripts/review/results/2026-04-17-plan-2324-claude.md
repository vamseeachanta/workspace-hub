Plan mis-identifies which system it is curating.

T1 with "cross-check with GH issues + cross-machine sync wrinkle" is ambiguous — if acceptance is unrunnable in CI, complexity rating is academic.
- **Scope — no resolution of open question.** `Risks` still asks "Is the memory dir ... git-tracked?" despite empirical evidence already gathered that it is not. Plan has not incorporated that finding into Deliverable or Acceptance.
- **Scope — cross-machine sync claim contradicts target.** `Risks` says "Memory dir is shared across machines via sync (per `user/CLAUDE.md` 'git-tracked, same on every machine')" — that statement is about a different directory. The auto-memory dir is NOT shared across machines. Plan inherits a false premise.
- **Scope — report is the only durable artifact.** `docs/reports/memory-curation-2026-04.md` is in the repo, good. But the plan's primary deliverable (rewritten MEMORY.md) is local-only. Plan should foreground the report as THE deliverable and demote the MEMORY.md edit to "optional machine-local side effect".
