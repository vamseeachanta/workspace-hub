This is an exceptionally thorough v6 plan for a markdown conversion quality test suite. After 5 rounds of adversarial review (10 reviews across Claude and Gemini), all previously identified P1 and P2 defects have been convincingly resolved with structural fixes and regression-proof tests. The plan demonstrates rare rigor: locked scorer formulas, blinding protocols, stratified sampling with marginal-only validation, 16 structural tests + 120 parametrized tests, and three new v6 tests (#14, #15, #16) that structurally prevent regression of the two critical P1 fixes. ### Issues Found
- [P3] Minor: The `ingest_orcina` import is referenced in `test_conversion_quality.py` pseudocode (`_, actual_md = ingest_orcina.html_to_markdown(...)` at line 347) but the `importlib.util.spec_from_file_location` shim that creates the `ingest_orcina` module reference is not shown in the test module pseudocode — it is only mentioned in the comment at line 327. The conftest or a fixture should handle this import and make it available, or the pseudocode should show the import shim explicitly.
- [P3] Minor: The `write_report` function signature takes `filename` as first arg and writes to `base.parent / filename` (line 301), while `ARTIFACTS_DIR` points at `.artifacts/per-topic/`. This means the report lands at `.artifacts/conversion-quality-report.json` (one level up from per-topic). The path arithmetic is correct but slightly non-obvious — a reader might expect the report in the same directory as `ARTIFACTS_DIR` rather than its parent.
- [P3] Minor: The `check_floor_occupancy` function indexes `PER_TOPIC_FLOOR` by `entry['dim']` (line 266), but the `PER_TOPIC_FLOOR` dict keys are human names like 'heading', 'link', 'table' while the dim values written by `write_per_topic_artifact` come from `RUBRIC_DIMENSIONS` (imported from `rubric_scorers`). The plan does not explicitly pin the canonical dim name strings used in `RUBRIC_DIMENSIONS` — if they don't match the `PER_TOPIC_FLOOR` keys exactly, a `KeyError` will occur at session finish. This coupling should be documented or validated.
- [P3] Minor: Build Sequence step 0 uses a grep pattern `'\xc2\xb0\|[\xce\xb1-\xcf\x89]\|[\xe2\x88]'` with escaped pipe characters for BRE alternation. This is correct for `grep -E` with `\|` being literal pipe in ERE, but the `-E` flag is present so `|` should be unescaped for ERE alternation. The actual grep pattern may need adjustment depending on whether BRE or ERE is intended. This is a one-off scan so impact is minimal.

### Suggestions
- Consider adding the `ingest_orcina` importlib shim explicitly to the test module pseudocode (or to conftest.py as a session-scoped fixture) rather than leaving it as a comment — this is the most likely implementation stumble point for an executor.
- Add a brief cross-reference table mapping `RUBRIC_DIMENSIONS` string values to `PER_TOPIC_FLOOR` keys to make the coupling explicit and prevent a runtime KeyError if someone changes one without the other.
- The plan is at v6 after 10 reviews. Consider adding a 'Plan Maturity' note indicating that further review iterations should only be triggered by implementation-discovered issues, not by re-reviewing the plan document — the plan has reached diminishing returns on document-level review and value now shifts to execution.
- For Build Sequence step 0, consider using `grep -P` (PCRE) for the UTF-8 byte-sequence matching, which handles multibyte patterns more reliably than ERE across different grep implementations.
