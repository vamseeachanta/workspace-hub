## Findings
1. Plan §Resource Intelligence Summary explicitly notes: "Option A must therefore wire SFs into a calc — emission alone with no consumer is theatre." However, Plan §Files to Change dictates leaving `check_mbl()` "untouched for backward compat" and adds `check_mbl_with_safety_factor()` without migrating any existing callers. As a result, the new method has zero callers in `src/`, meaning the safety factors are still unconsumed in production and the pilot delivers the exact "theatre" it criticized.
2. Plan §Pseudocode for `_resolve_sf_for_condition` correctly honors user overrides (`user_overrode = user_value != field_default`). However, `MooringLineDesign.get_intact_safety_factor()` unconditionally calls `get_mooring_safety_factor(MooringCondition.INTACT_QUASI_STATIC...)`, completely bypassing the override logic. If a user sets `safety_factor_intact=2.5`, `get_intact_safety_factor().value` will falsely return the registry default (1.67).
3. Plan §TDD Test List specifies `test_check_mbl_with_sf_fail_closed_on_missing_wiki` should assert `reason == "page_missing"` and `code_id in msg` when `DIGITALMODEL_REPO_ROOT=tmp_path`. However, Plan §Pseudocode for `_default_repo_root()` intercepts this exact invalid-path case at Step 2 and raises a generic `CitationResolutionError` that lacks the `reason` keyword argument. The test will fail against the pseudocode implementation.
4. Plan §Pseudocode for `_resolve_sf_for_condition` uses `**{**cited.citation.__dict__, "note": ...}` to copy the citation. Plan §Resource Intelligence Summary identifies `Citation` as `@dataclass(frozen=True)`. Accessing `__dict__` directly on dataclasses is unidiomatic and brittle (it fails if `slots=True` is ever applied). `dataclasses.replace(cited.citation, note=...)` must be used instead.
5. Plan §Acceptance Criteria AC5 mandates `grep -E 'check_mbl_with_safety_factor.*2026-05-13' .claude/rules/calc-citation-contract.md` returns ≥ 1. If formatting in the modified rules file wraps the line such that the function name and date fall on separate lines, this single-line grep verification will falsely fail.

## Blockers
- 1 (Must either migrate an actual callsite in `src/` to use the new method, or replace the legacy method, to avoid delivering unused code)
- 2 (Must align `get_*_safety_factor()` methods with `_resolve_sf_for_condition()` to respect user instance overrides)
- 3 (Must align test expectations with the actual exception raised by `_default_repo_root()` at Step 2)
