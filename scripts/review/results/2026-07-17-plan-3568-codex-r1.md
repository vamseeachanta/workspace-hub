## Findings

1. The plan assigns capability authority to the wrong file. Plan lines 34–37, 50, 238, and 328 call `scripts/readiness/harness-config.yaml` authoritative for roster roles and require an explicit GUI/headless capability. `config/workstations/registry.yaml:1-4` instead declares itself the single source of truth for all machine identity and capability data, reinforced by `tests/readiness/test_registry_sso_completeness.py:30-35`. Neither registry currently contains a GUI/headless capability, and Plan §Files to Change provides no child obligation to add it to the authoritative registry. The proposed grading therefore has no valid source for applicability.

2. Plan §Gaps lines 110–111 requires semantic shortcut parity to remain separate from privacy parity, but §Pseudocode lines 241–244 returns one `EXPECTED-DIVERGENCE` verdict whenever a passing outcome has an OS/privacy difference. Acceptance Criteria lines 340–342 repeats that collapse. A dictation outcome cannot be represented as semantic `EQUAL` with a separate privacy-boundary annotation/divergence, contradicting the stated contract.

3. The machine-wide headless shortcut in §Pseudocode lines 236–244 is not predicate-specific: any explicitly headless machine immediately returns `EXPECTED-DIVERGENCE` for the whole interaction family. That can suppress applicable terminal or remote-input predicates merely because desktop dictation is inapplicable. The contract needs applicability per machine-and-predicate, not a blanket role verdict.

4. The supposedly exact contract is undefined. Plan lines 287 and 307 require an exact set of “four initial predicates” without naming them anywhere. Lines 295 and 309 likewise require an exact, complete child DAG without specifying its edge set; line 322 only implies that 3567 consumes interfaces from 3565 and 3566. The issue body for 3567 names the predicates, but the durable contract plan must freeze them and the dependency edges explicitly so tests do not invent their own oracle.

5. Epic closeout would fail the repository’s enforced completeness gate. Plan lines 275 and 354–357 provide an HTML report and owner label only. `.github/workflows/completeness-gate.yml:54-61` requires a fenced machine-readable `completeness` JSON record in the issue body, while `scripts/workflow/completeness_gate_check.py:72-114` validates issue binding, class, percentage, label authority, and post-edit freshness. None of those required closeout transactions appears in the plan.

6. The privacy validation is denylist-based while the acceptance contract is allowlist-based. Plan line 230 and `test_privacy_denylist_rejects_raw_interaction_content` only reject enumerated field names, but lines 333–336 promise that evidence will serialize *only* bounded allowed types. Renamed fields such as `payload_text` or arbitrary additional properties could pass. The plan needs a closed schema, rejection of unknown fields and nested values, and adversarial alias/value tests.

7. The legal gate can pass without scanning the principal new artifacts. Plan lines 299 and 349–350 invoke `legal-sanity-scan.sh --diff-only`, but `scripts/legal/legal-sanity-scan.sh:185-188` derives targets solely from `git diff --name-only HEAD`, which omits untracked files and returns success on an empty list. The YAML, HTML, and Python test all begin as new files. The plan must require intent-to-add/staging or a direct path-scoped scan before accepting this result.

8. The plan silently weakens the paste child’s contract. Plan lines 90–93 and 337–339 change parity from exact clipboard content to post-normalization composer text. Live issue 3566 §Desired behavior requires “the exact same clipboard bytes,” while Codex v0.144 intentionally converts CR/CRLF to LF. That is an unresolved scope contradiction, not an implementation detail; either the child issue must be amended by the owner or the plan must test route equivalence and normalization loss separately.

9. Plan lines 162–177 and 386–388 say a configuration collision was reproduced, but the recorded bindings are `<Super>h` for minimize and `<Super><Shift>v` for dictation—distinct chords. The evidence proves that the *proposed migration* to `<Super>h` would collide; it does not reproduce a current collision.
