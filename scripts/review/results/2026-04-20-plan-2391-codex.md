## Verdict: MAJOR

## Option rejection validity (B, C)

- **B rejection is materially wrong.** The plan says Vercel rewrites "cannot reach files/functions outside `outputDirectory`." Current Vercel docs explicitly allow same-application rewrites and rewrites to external origins via `vercel.json`; they are not constrained to `dist/` in the way the plan claims. `outputDirectory` controls what is served statically, not what rewrites can target. Sources: [Rewrites](https://vercel.com/docs/routing/rewrites), [vercel.json `outputDirectory`](https://vercel.com/docs/project-configuration/vercel-json), [Configure a Build](https://vercel.com/docs/deployments/configure-a-build).
- Option B can still be rejected, but on **fitness**, not impossibility: adding a proxy/function/rewrite for one static XML file is more operationally complex than copying it into `dist/`.
- **C defer is defensible only as prioritization.** Auto-generation is the more robust design, and the current repo already shows sitemap drift. If C stays deferred, the plan should say: "not required to restore 200 today; must be a tracked fast-follow," not imply it is merely optional polish.
