# Gemini review — plan #2311

**Verdict: MINOR**

**Strengths:**
- **Clear objective:** Accurately targets the specific high-frequency stale reference cluster (`start_stage.py`, `exit_stage.py`, `verify_checklist.py`).
- **Nuanced approach:** Correctly recognizes that not all occurrences should be deleted; separating "live instructional surfaces" from "intentional historical/legacy artifacts" is the right architectural move.
- **Test-driven:** Proposes a targeted regression test (`test_stage_transition_reference_confinement.py`) to prevent recurrence, which enforces long-term repository hygiene.

**Gaps:**
- **Vague surface definitions:** The pseudocode says "scan current instructional surfaces and classify each hit" but the TDD section mentions a "curated current-file list." Relying on an ad-hoc or dynamic scan during execution is prone to error. The plan must explicitly define *what* constitutes a live instructional surface (e.g., `AGENTS.md`, `.claude/rules/`, `.gemini/prompts/`, `.github/ISSUE_TEMPLATE/`) versus what constitutes history (`.planning/`, `docs/reports/`).
- **Audit refresh mechanism:** The acceptance criteria requires a "Post-implementation audit refresh," but the plan does not specify *how* to run this refresh or if it requires external API calls/tools. If the audit generation is complex, this step needs explicit commands or should be decoupled from this specific cleanup PR.

**Risks:**
- **Exclusion list whack-a-mole:** If the new test defaults to scanning *all* markdown files and relies on a `exclude` list for historical reports, it will become a maintenance burden as new reports or planning docs are generated. An `include` list of highly-leveraged instructional surfaces is much safer.
- **Provider-specific gaps:** If the developer only curates `.claude/` files as "instructional," they might leave stale references in `.gemini/` or `.codex/` surfaces, breaking workflow parity.

**Missing tests:**
- **Destination existence validation:** The test `test_legacy_reference_map_points_to_current_redirect_targets` checks that the legacy map has the anchors, but it should explicitly verify that the *files it redirects to* (e.g., `docs/governance/SESSION-GOVERNANCE.md`) actually exist in the current repository state, preventing broken legacy links.

**Scope creep concerns:**
- The requirement to "refresh provider-session audit after cleanup" might pull in unrelated script debugging or token usage if the audit script is heavy. Consider making the audit refresh a "nice-to-have" or delegating it to a scheduled CI job rather than a hard acceptance criterion for this PR.

**Weakest assumption and what breaks if it is false:**
- **Assumption:** There is a clean, binary distinction between "live instructional" and "historical report" surfaces.
- **What breaks:** If a document serves a dual purpose (e.g., a "lessons learned" document that also prescribes future workflow rules), the developer will struggle to classify it, leading to either a skipped file (leaving stale instructions active) or a mutilated report (destroying historical context).

**Most likely implementation failure mode:**
- The implementer writes a test that blindly scans `**/*.md`, immediately fails on `docs/reports/provider-session-ecosystem-audit.md` (which contains 318 hits), and then spends hours writing a brittle regex exclusion system instead of just explicitly targeting the known live instruction directories.

**Most likely test gap:**
- Failing to include `.env.example`, `scripts/workflow/*.sh`, or other non-markdown operational files in the "curated current-file list", allowing the stale scripts to still be referenced in shell comments or environment variables.

**Future issues suggested:**
- **Centralized repo surface taxonomy:** Create a definitive helper module in `tests/helpers/` that categorizes repo paths into canonical buckets (`LIVE_INSTRUCTIONAL`, `LEGACY_REFERENCE`, `HISTORICAL_REPORT`, `SOURCE_CODE`). This would allow all future documentation and governance tests to use a single source of truth rather than ad-hoc allowlists.

**Review confidence:** High. The core logic of the plan is sound, but it needs tighter bounding on how it defines and tests "instructional surfaces" to avoid implementation churn.
