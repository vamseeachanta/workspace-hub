## Findings

1. **MAJOR — Cross-wiki location split is unaddressed.** The plan creates 10 pages at `knowledge/wikis/engineering-standards/wiki/standards/api-*.md`, but every other standards page in the repo — `api-579-ffs.md`, `dnv-os-e301.md`, `dnv-rp-c203.md`, `dnv-rp-c205.md`, `dnv-rp-f101.md`, `dnv-rp-f105.md`, `ocimf-meg4.md`, `ocimf-tandem-mooring.md` — lives at `knowledge/wikis/engineering/wiki/standards/`. The existing citation registry (`digitalmodel/src/digitalmodel/citations/registry.py:30`) hardcodes the `engineering/` path. The plan's §RIS line 47 names the OCIMF precedent as a "cross-domain precedent (OCIMF page in engineering wiki, not engineering-standards)" but does not justify creating *two parallel* `wiki/standards/` directories that both ostensibly own API pages. There is already an existing `api-579-ffs.md` in `engineering/`, so this is not a clean greenfield split.

2. **MAJOR — Acceptance criterion line 245 is structurally incapable of verifying what it claims.** The criterion executes `Citation(code_id='api-rp-2sk', ...)` and calls it a "Citation downstream-resolution check (resolver verified to exist at .../citations/schema.py)". `Citation.__post_init__` (`schema.py:49-54`) only validates that fields are non-empty strings and that `wiki_path` starts with `knowledge/wikis/`, contains no `..`, and uses forward slashes. **It does not check the file exists, does not read frontmatter, does not compare frontmatter fields.** The actual fail-closed resolver is `validate_citation(citation, *, repo_root)` at `schema.py:102` — the plan never calls it. The check passes even if the wiki page does not exist on disk.

3. **MAJOR — TDD test `test_citation_schema_resolvable` (line 231) inherits the same defect.** Description: "constructs without error; `CitationValidationError` not raised; `wiki_path` exists." The constructor cannot verify `wiki_path exists`; only `validate_citation()` does. As written, a wiki page that fails to be created would still pass this test. The test must call `validate_citation(citation, repo_root=REPO_ROOT)` and the page frontmatter must round-trip the constructor's `code_id`/`publisher`/`revision` exactly (per `schema.py:118-132`).

4. **MAJOR — `test_body_word_count_bounded` (100 < N < 1500) is incompatible with the pseudocode template.** The api-17e stub the plan claims to "replicate ten times" has **29 body words** (verified). The pseudocode template at lines 174-191 has six short headers and ≤80-word scope plus a few one-liners — likely 60-100 body words. The OCIMF guard the plan inherits uses the same `100 < word_count < 1500` floor (`test_ocimf_tandem_no_raw_pdf_text.py:125`), but OCIMF's actual page is 557 words because it is curated content, not a templated stub. The plan must either lower the floor for stubs, or commit to writing ≥100 words of curated paraphrase per page (which raises copyright-leak risk, contradicting Risk #1).

5. **MINOR — Frontmatter schema drift.** Pseudocode template (lines 161-172) emits `revision_source`, `verified_on`, `public_url`, `extraction_policy`, `raw_copy_allowed`. The wiki's CLAUDE.md schema (`knowledge/wikis/engineering-standards/CLAUDE.md` lines 30-50) documents only `title`, `tags`, `added`, `last_updated`, `sources`, `domain`, `cross_links`, plus standards-extras `code_id`, `publisher`, `revision`, `jurisdiction`, `supersedes`. The five new fields are introduced de novo. Plan must either amend CLAUDE.md (and bump page_count appropriately for the schema doc) or restrict to documented fields.

6. **MINOR — Acceptance line 247 invents a "kebab-case `code_id` matches filename stem" rule** not present in CLAUDE.md (line 46 only gives examples, no constraint). The api-17e stub has `code_id: api-17e` matching its stem, but that is convention-by-precedent, not a documented rule the test can cite.

7. **MINOR — Denylist phrase "American Petroleum Institute" (line 234) will fire false positives.** This is the publisher's full name — likely needed in scope paragraphs to disambiguate from `American Petroleum Index` or to expand the publisher tag for new readers. The plan acknowledges deliberately excluding "the standard's title (which is allowed) and code identifier (which is required)" but the publisher's full name is in neither category and is now denylisted.

8. **MINOR — STD 2RD revision is contradictory.** Plan §Open Questions line 272 lists priority #2 as "API STD 2RD (3rd Ed, 2025)". The /mnt/ace corpus contains only `API_STD_2RD_2nd_Ed_(2013)_Dynamic_Risers_for_Floating_Production_Systems.pdf` (verified). The pseudocode template's `sources:` field requires a `/mnt/ace` path; the 3rd Ed has no on-disk pointer. Plan must commit to either anchoring the wiki page to the 2nd Ed or accepting URL-only sourcing for the 3rd Ed.

9. **MINOR — Standards ledger canonical-ID claim overstated.** §RIS line 53 says the ledger "already contains canonical IDs for every priority code (`API-RP-2A-WSD`, `API-STD-2RD`, …); the wiki promotion will not invent new IDs." The ledger actually contains **truncated, edition-stamped IDs** like `API-RP-2A-WSD-22ND-EDITION-NOV` (truncated at ~30 chars), `API-RP-2GEO-1ST-EDITION-ADDEND`, `API-RP-2MET-1ST-EDITION-NOV-20`, `API-RP-2SK-2ND-ED`, `API-RP-2SK-3RD-ED`, etc. — multiple per code, not a single canonical scheme. The kebab-case stems the plan derives (`api-rp-2sk`, `api-rp-2a-wsd`) match no specific ledger ID; the wiki page IDs **are** new, just not the truncated-edition flavor.

10. **MINOR — Cross-reference style inconsistency in pseudocode (lines 188-190).** Mixes Obsidian-style `[[api-17e]]` with standard markdown `[Calc citation contract](../../../../../.claude/rules/calc-citation-contract.md)` in the same template. Pick one (CLAUDE.md line 56 hints at `[[entity-name]]` or `[text](path)` either-or).
