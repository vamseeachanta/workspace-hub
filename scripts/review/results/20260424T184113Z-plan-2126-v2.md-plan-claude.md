### Verdict: MAJOR

### Summary
Plan v2 substantively addresses the r1 P1/P2/P3 findings (arithmetic, threshold coherence, stratification scope, oracle blinding, provenance schema) and provides an Attested Evidence block for reviewer verification. However, two load-bearing mechanics remain under-specified: the aggregate floor-occupancy gate depends on artifact files written by parametrized tests without a pinned execution-order contract, and the heading-preservation Kendall-tau formula is ambiguously defined in a way that risks either always-1.0 scoring or scorer non-determinism (contradicting test #10). Several smaller inconsistencies (zss dep missing from Files-to-Change, AC grep pattern drift, collection-time manifest validation racing structural tests) should be resolved before execution.

### Issues Found
- [P1] Test-order dependency is not pinned: `test_aggregate_floor_occupancy` (structural #11) reads `.artifacts/per-topic/<slug>-<dim>.json` produced by the 120 parametrized `test_per_topic_dimension` runs. pytest does not guarantee this ordering across `-k` filters, `pytest-xdist` parallelism, or when the aggregate test is invoked in isolation. Without `pytest-ordering`, `@pytest.mark.dependency`, or a session-scoped teardown hook, the gate can spuriously fail or pass on incomplete data.
- [P1] Heading-preservation Kendall-tau formula is ambiguous. `K = 1 - kendall_tau_distance(common_subsequence(A, O)) / C(n,2)` — the common subsequence is itself an ordered sequence of equal-in-both-sides tuples, so its Kendall-tau distance to itself is trivially 0, yielding K ≡ 1 whenever n ≥ 2. The formula almost certainly intends tau between the rank vectors of the intersection elements in A vs O, but as written it is both wrong and a determinism hazard for `test_rubric_scorer_determinism` if an alternate implementer picks a different LCS tiebreak.
- [P2] `zss==1.2.0` (tree-edit distance for list-nesting scorer) is mentioned only in the Risks section; the Files-to-Change table's `pyproject.toml / test-deps` row names `pytest-socket` alone. The scorer cannot execute without zss, so the dependency addition is load-bearing and should be explicit in Files-to-Change and in AC.
- [P2] `load_sample_manifest()` runs at collection time as the argument to `@pytest.mark.parametrize`. If the manifest is malformed or schema-invalid, pytest collection aborts before `test_sample_manifest_loads` / `test_sample_manifest_schema_valid` / `test_sample_manifest_fixture_files_exist` can run and localize the error. The structural tests cannot do their diagnostic job in the error mode they are meant to cover.
- [P2] AC grep pattern inconsistency: line 323 uses `grep -c "::"` while the TDD collection assertion at line 317 uses `grep -c "::test_"`. On the same pytest --collect-only output these return different counts (pytest inserts lines like `<Module ...>` and session headers). The AC predicts 133 against the wrong matcher.
- [P3] Image alt-text scorer uses positional matching (`alt_a[i] == alt_o[i]`). If the converter drops or reorders a single `<img>`, every subsequent index shifts, cascading false-negatives across an otherwise-correct document. Matching by normalized `src` before comparing alts would isolate the real bug signal.
- [P3] Artifact Map r2 filenames use the stub `plan-2126-v2.md` while the plan's actual filename is `2026-04-24-issue-2126-markdown-conversion-qa.md`. Review harness writes results keyed to the actual filename; the recorded path will not match.
- [P3] The `_disable_network` fixture calls `pytest_socket.disable_socket()` from a custom autouse fixture AND performs an active `socket.socket(...)` probe inside the same fixture body. pytest-socket's idiomatic activation is via the `--disable-socket` CLI flag or the library's own fixtures; mixing direct function invocation with an in-fixture assertion is nonstandard and couples setup to a probe that belongs in a dedicated test.
- [P3] Complexity label T2 is optimistic given the deliverables: 20 hand-authored blinded oracle markdown files across 3 products, a JSON-schema'd manifest, 13 structural tests, 6 rubric scorers, and two new dependencies. T3 reflects the authoring effort more honestly and better protects the blinding protocol from time-pressure corner-cutting.

### Suggestions
- Pin test-order: either add `pytest-ordering` and annotate `test_aggregate_floor_occupancy` with `@pytest.mark.order('last')`, or move aggregation into a `pytest_sessionfinish` hook in `conftest.py` that reads the written artifacts and emits a final failure via `session.exitstatus`. Document the `-k`/`xdist` interaction in the module docstring.
- Rewrite the heading Kendall-tau formula explicitly: for each element e in set(A)∩set(O), record rank_A(e) and rank_O(e); compute tau_b over those two rank vectors via `scipy.stats.kendalltau` (pin scipy version) OR specify an exact reference implementation. Remove the `common_subsequence` language entirely.
- Add `zss==1.2.0` to the Files-to-Change `pyproject.toml / test-deps` row and to the AC next to `pytest-socket`. If offline CI availability is uncertain, decide up front whether to vendor it or pre-populate the wheel cache — don't leave this as a follow-up.
- Replace collection-time manifest validation with a two-step: (a) a minimal-safe loader used by parametrize that returns `[]` on error, plus (b) structural tests that re-open the manifest and assert each schema property. Collection then always succeeds and structural tests localize the error.
- Reconcile the AC grep to `grep -c "::test_"` (matches the TDD section) so 133 is what the matcher actually returns.
- Change image alt-text scoring to match by `src` first (multiset), then score alt equality over the matched set; separately surface unmatched images as a penalty component so dropped/reordered images produce a localized signal, not a cascade.
- Align the Artifact Map r2 filename stubs with the plan's actual filename so `scripts/review/` outputs are retrievable without manual rewiring.
- Split the network-block fixture: keep `disable_socket(allow_unix_socket=False)` in a session-scoped autouse fixture; move the active `SocketBlockedError` probe into test #12 where it belongs.
- Consider bumping complexity to T3 in recognition of the 20-fixture authoring effort; T2 pacing may pressure reviewers to shortcut the blinding protocol.

### Questions for Author
- How is `test_aggregate_floor_occupancy` guaranteed to run after all 120 parametrized `test_per_topic_dimension` cases under `pytest -k`, `pytest-xdist -n auto`, and `pytest --lf` reruns? If not guaranteed, which mechanism (ordering plugin, session hook, dependency marker) will enforce it?
- For the Kendall-tau computation on headings, is the intent tau over rank vectors of the intersection set, or something else? A worked two-heading example would lock the semantics.
- Is `zss` available in the offline CI image, or will it need to be vendored/pre-cached? The 'vendored fallback' reads as a pre-authorized scope expansion — is that intended?
- Under the marginal-only stratification, can a deterministic sampler produce degenerate joint cells (e.g., nearly all OrcaFlex × Medium × API in one bucket) that undermine coverage even with valid marginals? Is cell-level distribution inspected at manifest-build time?
- Does `pytest-socket`'s `disable_socket(allow_unix_socket=False)` interfere with any local test-helper that uses unix sockets (e.g., `uv` subprocess IPC, pytest plugins)? Has this been probed on the actual CI image?
- If the r2 cross-review cannot produce a Codex artifact (per #2479), the deferred AC asks the user to choose between waiting and a two-provider exception — which default would the author prefer, and is there a time-box on waiting?
- Is there any risk that the `html_sha256` check turns the fixture set brittle against trivial whitespace changes in snapshot capture, and if so, should the hash be computed over a normalized HTML form?
