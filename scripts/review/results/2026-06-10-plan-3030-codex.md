### Summary
Not approval-ready. The provider tuple change and main WIP interaction are mostly covered in the current draft, but the quota-source semantics still diverge from the governing rule and can route incorrectly under stale or overridden quota inputs.

### Issues Found
- MAJOR: The plan treats any successful `query-codex-usage.sh --json` result as authoritative, but that script explicitly falls back to stale session logs. `scripts/ai/assessment/query-codex-usage.sh` documents that session-log parsing can freeze across weekly window rollovers, while the plan claims in `docs/plans/2026-06-10-issue-3030-codex-quota-dispatch-gate.md:71-73` that rechecking remaining% is equivalent to 'rest of week' suspension because remaining only recovers at reset. That is false when live app-server fails and stale local logs remain below 10 after reset, or stale logs remain above 10 while live would suspend. This conflicts with `.claude/memory/agents.md:58`, which keys the gate to live codex quota availability.
- MAJOR: `DISPATCH_CODEX_REMAINING` is a production backdoor as planned. `docs/plans/2026-06-10-issue-3030-codex-quota-dispatch-gate.md:51` says the env var short-circuits the subprocess and is also an operator escape hatch; `docs/plans/2026-06-10-issue-3030-codex-quota-dispatch-gate.md:65` says quota is read from `query-codex-usage.sh --json`. Those cannot both be correctness-critical behavior. An inherited env var can force routing above or below the 10% gate without consulting live quota, directly bypassing `.claude/memory/agents.md:58`.
- MINOR: The doc-sync step updates only `.claude/memory/templates/agents-template.md`, but the active governing text being interpreted is `.claude/memory/agents.md:58`. The plan’s `docs/plans/2026-06-10-issue-3030-codex-quota-dispatch-gate.md:53` claim that this keeps rule text and mechanism in sync is incomplete unless the live memory rule is updated or the plan explicitly says the template is the only intended source to change.

### Suggestions
- Gate on `source == "app-server-live"` or require a max-age/reset-window validity check before using fallback quota values for demotion; otherwise return `None` and fail open with a warning that names the source.
- Remove `DISPATCH_CODEX_REMAINING` from production behavior, or restrict it to tests through monkeypatching. If an operator override is required, make it an explicit CLI flag with loud output and tests proving it cannot be inherited silently by cron/dispatch.
- Update `.claude/memory/agents.md` if evaluate-at-dispatch-time/fail-open semantics are intended to be canonical, or keep the implementation strictly aligned with the existing text.

### Questions for Author
- Should non-live fallback quota sources ever be allowed to suspend the codex lane, or should they only inform status output?
