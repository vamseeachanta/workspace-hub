## Findings
1. **`codex exec -` Hang Regression:** `plan-review-fanout.sh` modifies the `codex` invocation to use `exec - < "$combined_file"`. As explicitly documented in the sibling `submit-to-codex.sh` script, the installed CLI (`codex v0.121.0`) has a known bug where `exec -` blocks and hangs indefinitely on stdin. This change reinstates the stall risk it was meant to avoid.
2. **Timeout Error Masking on Stderr Promotion:** In `normalize_provider_output`, the promotion logic (`if [[ ! -s "$out" && -s "$err" ]] && grep -q '^## Verdict' "$err"`) moves the file and immediately calls `return 0`, completely bypassing the subsequent `if (( rc != 0 ))` block. If a provider times out (`rc=124`) but emitted a partial review to stderr before being killed, the script promotes the corrupted, truncated artifact and reports success.
3. **Missing Test Coverage for Partial Timeouts:** The test `test_provider_timeout_becomes_unavailable_stub` relies on `MOCK_SLEEP_S=3`, but `mocks/codex` executes the sleep *before* writing any output. It completely fails to test or prove the masking bug described in finding #2, as it never simulates a timeout interrupting an active stderr stream.
4. **Orphaned Background Processes:** The fanout script launches providers into the background (`invoke_provider "$prov" &` around line 178) but lacks an `EXIT` trap. If the orchestrator terminates the script (e.g., via `SIGTERM`), the parent bash process exits but the AI CLI child processes remain orphaned, continuing to consume system resources.
5. **Temp File Leak:** The diff introduces `combined_file="$(mktemp)"` without an `EXIT` trap. If the script aborts on `set -euo pipefail` (e.g., if `printf` fails), the file is permanently leaked in `/tmp`.

## Required fixes
1. Revert the `codex exec - < "$combined_file"` invocation back to the reliable argv delivery method: `codex exec "$combined" </dev/null` (which also resolves the temp file leak).
2. In `normalize_provider_output`, either evaluate `if (( rc != 0 )); then` and write the UNAVAILABLE stub *before* attempting stderr promotion, or explicitly require `rc == 0` for promotion to occur.
3. Add a cleanup trap for background jobs at the top of `plan-review-fanout.sh`: `trap 'kill $(jobs -p) 2>/dev/null || true' EXIT`.
4. Update the test suite (e.g., by adding a `MOCK_SLEEP_AFTER_VERDICT` hook to the mock) to explicitly assert that a timeout paired with partial stderr output correctly produces an UNAVAILABLE stub rather than a canonical artifact.

## Residual risk
Relying on string matching (`## Verdict`) and process signal propagation via shell `timeout` can be fragile. However, enforcing strict `rc == 0` checks before promotion and ensuring all background jobs are trapped guarantees that corrupted artifacts and stalled processes won't leak into the main orchestration pipeline.
