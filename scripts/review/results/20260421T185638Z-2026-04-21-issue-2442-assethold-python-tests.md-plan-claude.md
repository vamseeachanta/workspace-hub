### Verdict: MAJOR

### Summary
Plan is substantially mature after two adversarial review waves — fix sites are enumerated with line-numbered evidence, phased commits have an enforceable gate, and the sibling-dep blocker is resolved via actions/checkout. However, residual internal inconsistencies (stale "uv sync --frozen" wording contradicting the Wave-2-adopted `uv pip install --system -e` approach, fix-site math in the complexity stanza), one unverified prerequisite (existence of `tests/test_smoke.py` used as a pre-push gate), and a material unaddressed risk (cascading sibling deps + unpinned `ref: main` coupling assethold CI to assetutilities main-branch stability) warrant revision before execution.

### Issues Found
- [P1] Internal inconsistency on line 217: the fix-site recount justification still reads "replacing 3 requirements-file edits with 3 `uv sync --frozen` switches + 3 new sibling-checkout insertions" — this contradicts the Wave 2 revision that explicitly rejected `uv sync --frozen` in favor of `uv pip install --system -e ../assetutilities` (see lines 143-145, 285, 297). A reviewer or executor reading the Files-to-Change table's justification prose will be misled about which install command to commit.
- [P1] Unverified prerequisite for the local pre-push gate: acceptance criterion at line 262 requires `cd assethold && uv run pytest tests/test_smoke.py -v` to pass, and TDD row at line 241 asserts `test_smoke.py::* PASSED` as a phase-2 gate. The Resource Intelligence inventory (line 20) lists the test tree (unit/, integration/, net_lease/, options/, portfolio/, contracts/ + 7 top-level `test_*.py`) but never confirms `tests/test_smoke.py` exists. If it doesn't, both the local pre-push gate and the smoke-cell CI gate are undefined.
- [P2] Unmitigated cascade risk: P2 resolves `assetutilities` by checking it out and running `uv pip install --system -e ../assetutilities`, but does not verify `assetutilities`'s own pyproject.toml is self-contained. If `assetutilities` itself declares a local-path sibling dep (e.g., via `[tool.uv.sources]`), P2 install will fail on the hosted runner in exactly the same way the top-level sibling-dep blocker failed. No check in Resource Intel confirms this.
- [P2] Unpinned sibling ref creates CI coupling: the proposed checkout step uses `ref: main` for `vamseeachanta/assetutilities` (line 167). Any breaking change or transient red on `assetutilities` main will flip `assethold` CI red for reasons unrelated to assethold. Plan does not discuss pinning to a SHA or tag, nor does it list this as a risk.
- [P2] Smoke-cell concept is unanchored to the workflow's actual matrix structure: acceptance at line 260 requires "At least one matrix cell (py3.11 / ubuntu-latest) completes smoke with conclusion=success" and TDD row at line 242 says "py3.11 ubuntu smoke job green." The workflow is described (line 16) as a matrix workflow (3.9–3.12 × ubuntu/windows/macos) with test + integration + financial-data + quality-gate jobs. It's unclear whether "smoke cell" refers to a specific matrix index in the `test` job or a distinct smoke job. The plan does not define how the executor distinguishes "smoke cell green" from "the test job's py3.11/ubuntu-latest cell green."
- [P2] rg pattern at line 238 uses `\|` as alternation (`'upload-artifact@v3\|upload-sarif@v2\|codecov-action@v3'`). Ripgrep treats `|` as alternation only inside proper regex syntax; with the backslash-pipe encoded in Markdown it may be read literally. If this gate runs and matches zero results for the wrong reason (literal `\|` not found), it would silently pass when deprecated actions remain.
- [P3] Complexity stanza at line 324 says "6 known fix sites + 3 install-path sites" (=9), contradicting the plan's own reconciled "13 (7 P1 + 6 P2)" count from line 217.
- [P3] Evidence section contains non-ASCII Unicode replacement characters (`���` at lines 22, 78, 285, 303 in place of em-dashes/arrows), which can cause tooling drift when the plan is machine-parsed or diffed.
- [P3] Acceptance criterion at line 258 requires the new sibling-repo checkout "before the main checkout in every dep-installing job." The pseudocode block at lines 163-167 shows the step but doesn't address the subtle GHA concern that `path: ../assetutilities` places the repo outside `$GITHUB_WORKSPACE`, and some setup actions' post-steps may not tolerate files outside workspace. No mitigation discussed if CI rejects the out-of-workspace path.

- Before execution, run `ls assethold/tests/test_smoke.py` and either (a) confirm existence and cite it in the Resource Intel inventory, or (b) pick an existing minimal test (e.g., one of the 7 top-level `test_*.py` files) and update all smoke-gate references (lines 241, 247, 262) to match.

- Replace `ref: main` on the assetutilities checkout with either a pinned SHA or an explicit note under Risks that tight-coupling is accepted for now with a plan to pin post-green. At minimum add this to the Risks section.
- Clarify the "smoke cell" definition: either point at the specific matrix entry (e.g., `job: test, strategy.matrix.python-version: 3.11, os: ubuntu-latest`) or rename the acceptance gate to match the workflow's actual job/cell naming so the executor can mechanically check conclusion state.
- Rewrite the rg pattern as three separate checks (`upload-artifact@v3`, `upload-sarif@v2`, `codecov-action@v3`) or use unambiguous rg syntax (`-e 'pat1' -e 'pat2' -e 'pat3'`) so the deprecated-action sweep gate is not defeated by pipe-escaping ambiguity.
