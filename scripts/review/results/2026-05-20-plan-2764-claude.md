## Findings

1. **§Pseudocode (lines 52-65) is copy-pasted from an unrelated scheduler plan and has nothing to do with this issue.** Quoted plan text: `"classify each scheduled job by scheduler plane and runtime type / if job executes AI/provider work and bypasses Hermes runtime: emit migration/exception finding"`. That describes the scheduler-routing/parity work in #2762 / #2765 (also indexed at `docs/plans/README.md:203` and `:206`), not "skip undated session filenames under set -e." This is the single most diagnostic defect in the plan — it indicates the plan was assembled by cloning a sibling plan and the implementation-shape contract was never authored for this issue. Without a real pseudocode block, the executor has no specification of where to insert `|| true`, how to log the skip, or how to count it.

2. **TDD test #3 (`test_conversion_error_still_fails`) contradicts current code AND falls outside the plan's stated scope.** `scripts/cron/hermes-session-export.sh:78` invokes the python heredoc as `uv run --no-project python - … 2>/dev/null && exported=$((exported + 1)) || true`. Stderr is discarded; the trailing `|| true` swallows every non-zero exit. Additionally, the heredoc itself catches load failures at lines 113-114: `except Exception: sys.exit(0)`. Therefore malformed JSON CANNOT currently produce a non-zero exit from the exporter. To make this test pass, the plan must also rewrite the python invocation to surface errors — but the Files to Change row for the exporter says only "preserve fail-closed behavior for real conversion errors," wrongly implying that behavior already exists. Either the test is wrong, or the patch scope is materially larger than stated.

3. **"Temp HOME" test isolation does not isolate the exporter's writes.** Plan lines 70 and 104 promise `Temp HOME` isolation. But `scripts/cron/hermes-session-export.sh:16-20` derives `OUTPUT_DIR="${WORKSPACE_HUB}/logs/orchestrator/hermes"` from `SCRIPT_DIR` via `cd "$SCRIPT_DIR/../.." && pwd`, NOT from `$HOME`. Running tests will write to the real `/mnt/local-analysis/workspace-hub/logs/orchestrator/hermes/session_<date>.jsonl` and mutate the real `.last-export-ts`. Worse: if any test invokes `--all`, line 34 executes `rm -f "$OUTPUT_DIR"/session_*.jsonl "$CORRECTIONS_DIR"/session_*.jsonl "$STATE_FILE"` against the live repo's export directory. Tests must override `WORKSPACE_HUB` (or set `OUTPUT_DIR`/`CORRECTIONS_DIR`/`STATE_FILE` env hooks the script doesn't currently expose). The plan must either (a) add an env-var override surface to the exporter, or (b) run the script with `WORKSPACE_HUB` shimmed via a wrapper. Neither is mentioned.

4. **`--all` invocation against an unsandboxed OUTPUT_DIR is destructive blast-radius.** Per `scripts/cron/hermes-session-export.sh:33-35`, `EXPORT_ALL=true && DRY_RUN=false` triggers `rm -f "$OUTPUT_DIR"/session_*.jsonl ...`. The plan's TDD test list does not cover `--all`, but neither does it forbid it — and existing untracked files in `logs/orchestrator/hermes/` (per the initial `git status`: `logs/orchestrator/hermes/corrections/session_20260520.jsonl`, `logs/orchestrator/hermes/session_20260520.jsonl`) would be deleted by an inadvertent test invocation. Add an explicit `WORKSPACE_HUB`/`OUTPUT_DIR` override OR a `--all`-during-tests-forbidden assertion.

5. **TDD acceptance criterion #1 ("RED test reproduces undated filename abort before patch") has no commit-order guarantee in Files to Change.** Both the test file (create) and the script (update) sit in the same change table. The executor could plausibly write tests + patch in one commit and never observe RED. Per workspace-hub TDD policy (`.claude/rules/`, `AGENTS.md`), the plan should explicitly require a RED-commit before the fix commit, or at minimum document a `git stash`/checkpoint workflow that proves RED was observed.

6. **The proposed fix shape is not pinned in the plan.** The Files to Change row says "Make date extraction no-match safe" without specifying where `|| true` goes. The issue body proposes `|| true` inside the command substitution — empirically verified to work — but the plan's Risks #1 ("A too-broad `|| true` could hide real conversion failures") implies the plan-author is aware of the trap without naming the safe locus. A T1 plan must contain the exact patch shape (`session_date=$(echo "$basename" | grep -oE '[0-9]{8}' | head -1 || true)`) so adversarial review can verify scope and the executor cannot drift to `set +e` or wrapping the whole loop.

7. **Skip-counter and log-line are required by Files to Change but absent from any TDD test.** The Files to Change row says "count/log skipped unsupported filenames." No test in the TDD list (rows 78-81) asserts that the new `unsupported_skipped` counter is incremented OR that the skip log line is emitted. Test #1 asserts only "Exit 0 with skip message" — vague; what message, on which stream, what counter? Without explicit assertions, the implementer can satisfy the test with a silent skip.

8. **T1 complexity is mis-scaled given the actual surface.** The plan creates a new shell test harness, modifies a cron-edge script that feeds the comprehensive-learning nightly pipeline (`scripts/cron/hermes-session-export.sh:8`), and per finding #2 may need to also modify the python conversion path. Under workspace-hub's tier scale (`SHARED_SOUL.md` §4 — T1 = simple single-file, T2 = multi-file or harness), this is closer to T2. Mis-classification leads to single-provider review under the AI Review Policy and risks under-reviewed scope creep.

9. **§Adversarial Review Summary lists three providers (Claude/Hermes, Codex, Gemini) as required, but T1 = 1 provider per the scale rule.** Either correct the complexity to T2 (consistent with finding #8) or trim the required-providers list to one. As written, the plan is internally inconsistent.

10. **The exporter glob filters out `request_dump_*.json` so they're NOT the root cause population, but the plan never names what `session_bg_*.json` and `session_<unknown>.json` cases exist.** Live `/home/vamsee/.hermes/sessions/` contains `request_dump_*.json` (excluded by `session_*.json` glob) and `session_<datestamp>_*.json` files. The undated-but-matched class is `session_bg_<hash>.json`. The plan should enumerate the known unsupported-name patterns (at minimum `session_bg_*`) so the skip-log message and any future allowlist are well-defined. Without enumeration, "unsupported" is unbounded and the regression test in #1 only covers one shape.

11. **No guidance on caller behavior.** Per `scripts/cron/hermes-session-export.sh:8`, this script is invoked by `comprehensive-learning-nightly.sh`. The plan does not verify whether the caller propagates the export's exit code, ignores it, or already wraps it. If the caller swallows exit-1, this defect would not manifest in nightly logs — yet the issue reports it as a freshness-blocker. The plan must cite the caller's handling of the exporter exit code as evidence that the bug truly blocks the pipeline, or downscope the issue's severity.

12. **§Risks does not cover the bash-version drift class.** Per workspace-hub deployment, cron jobs run under varying bash versions (CI may be GitHub Actions Ubuntu — bash 5.x; local could be ace-linux-1 — varies). The empirical exit-1 on `pipefail` depends on bash >=4.4-era semantics. A regression-test acceptance criterion should pin the shell explicitly (`#!/usr/bin/env bash` plus an early `bash --version` echo, or `BASH_VERSION` gate) — not mentioned.

13. **Plan §Reproduction proofs claims "earlier live debug trace" without a path to the artifact.** Lines 14, 19 say "Earlier debug trace found …", but no path to a stored trace under `scripts/review/results/`, `docs/sessions/`, or `logs/`. Per the adversarial-review evidence requirement (rule §4), the reproduction trace must be a citable artifact, not a paraphrased recollection. Resolution: paste the actual trace into the plan (or attach it under `docs/sessions/`) so reviewers can audit `RC=1` was the script's exit, not a shell wrapper.
