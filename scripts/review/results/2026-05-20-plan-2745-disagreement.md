### claude

- **MAJOR: Trigger 1 (disk-fill >85%) is already crossed at 95%; option A (retain) is no longer defensible without explicit acknowledgment.** Plan §Pseudocode `STATUS-FROZEN.md` lists "Disk-fill alert on `/mnt/ace/` exceeds 85% capacity → file a new issue and plan option B" as a *future* revisit trigger. Live state shows the threshold already exceeded by 10 percentage points. Two valid resolutions: (a) Change the plan's disposition pick from option A to option B (tar to slower storage) now, with the implementation work added to this plan's task list; (b) Raise the threshold to a higher number (e.g., 98%) that is not yet crossed and document why the existing 95% is acceptable (e.g., 382 GB margin is sufficient for projected 3-month growth). Option (b) requires a growth projection the plan does not include.
- **Reproduction Evidence section absent.** Per `coordination/issue-planning-mode` Step 1.5, plans that allege current state should reproduce. The plan's evidence section lists timestamps but does NOT include the `du -sh /mnt/ace/acma-projects.preexisting-before-repo-move-*` output. The 1.8 TB number cited (§Resource Intel + §Pseudocode) comes from a session-start measurement during brainstorming. Re-running would take minutes but would currently confirm. Fix: include a `du -sh` output line in Evidence, dated.
- **T5 pushurl `no_push://vamseeachanta/acma-projects (frozen per workspace-hub#2745)` may parse incorrectly.** Git treats URLs with spaces and parentheses as opaque strings for fetch/push, but some git transport plugins might choke. Cleaner alternatives: `no_push://frozen` (terse), or use `git config remote.origin.pushurl ""` (which some report works to disable push), or use `git remote set-url --push origin no_push`. The plan's choice works but is fragile. Plan should empirically test the final form.
- **T5 "Try push (should fail): `git push --dry-run origin main`" may not test what is intended.** `--dry-run` skips the network connection entirely on some versions of git — it doesn't necessarily attempt to resolve the pushurl. If a real push is wanted to verify, use `git push origin main 2>&1 | grep -i "Could not resolve\|no_push"` and accept the network error. Or rely solely on the GH archive (T4) for hard enforcement and treat T5 as informational documentation.
- **STATUS-FROZEN.md commits to `vamseeachanta/acma-projects` BEFORE archive (T3 → T4 order).** This is correct — once archived, the repo is read-only and new commits fail. But the plan should explicitly say the order matters and that T3 must succeed before T4 fires. Currently the dependency is implicit in task ordering. Fix: add to T3 "MUST complete before T4 can fire (archive blocks subsequent pushes)".
- **Acceptance criterion "Paired plan #2746 completion confirmed BEFORE this freeze closes" creates a circular dependency risk.** Per Plan #2746 §Acceptance, [#2746](https://github.com/vamseeachanta/workspace-hub/issues/2746) closure is conditioned on its own work + checker passing. This plan ([#2745](https://github.com/vamseeachanta/workspace-hub/issues/2745)) cannot close until [#2746](https://github.com/vamseeachanta/workspace-hub/issues/2746) does. If [#2746](https://github.com/vamseeachanta/workspace-hub/issues/2746) fails and gets reopened, this freeze plan can still proceed independently (the freeze does not depend on the wiki existing). Recommendation: weaken to "if [#2746](https://github.com/vamseeachanta/workspace-hub/issues/2746) has open blockers at this issue's closure time, surface in close comment but do not block [#2745](https://github.com/vamseeachanta/workspace-hub/issues/2745) closure."
- **The `STATUS-FROZEN.md` content references "vamseeachanta/llm-wiki-acma" as successor — depends on D4 amendment landing.** Per [#2731](https://github.com/vamseeachanta/workspace-hub/issues/2731) D4 amendment status (deferred to [#2731](https://github.com/vamseeachanta/workspace-hub/issues/2731)'s own planning round), the canonical name may change at [#2731](https://github.com/vamseeachanta/workspace-hub/issues/2731) approval. If D4 reverts to `<client>-llm-wiki`, the STATUS-FROZEN.md becomes stale. Mitigation: add to revisit triggers a 4th item "if [#2731](https://github.com/vamseeachanta/workspace-hub/issues/2731) D4 final differs from D4', edit STATUS-FROZEN.md successor reference."
- **Trigger 3 "sample-inventory confirms ≥80% redundancy" is operationally undefined.** What's the sample size? What's the redundancy metric (filename match? content hash? extension match?)? Implementer has no contract. Fix: either drop trigger 3 entirely (leave only disk-fill + 90-day age as triggers), or specify the method (e.g., "100-file random sample compared by sha256 against same relative path in `/mnt/ace/acma-projects/`").
- **`gh repo unarchive` is documented but path-untested.** The plan asserts archive is reversible ("`gh repo unarchive vamseeachanta/acma-projects` reactivates"). `gh repo unarchive --help` should be quick-checked. (Confirmed via gh CLI documentation: subcommand exists; no live test in this review.)
- **T6 "verify backup directory still present" lacks a hash-or-size invariant.** The check is `[[ -d /mnt/ace/acma-projects.preexisting-before-repo-move-20260520-075928/ ]] && du -sh ...` — directory presence + size. Size has roundoff issues across `du` invocations. More precise invariant: `find /mnt/ace/acma-projects.preexisting-before-repo-move-20260520-075928 -type f | wc -l` for file count, captured pre-T1 and post-T6 — verify identical.
