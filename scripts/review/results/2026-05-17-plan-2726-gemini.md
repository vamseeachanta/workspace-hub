## Findings
1. **False repository taxonomy:** Plan § "Initial known data/source classes" lists `workspace-hub`, `llm-wiki`, `aceengineer-website`, and `aceengineer-strategy` as "Tier-1 repo data". This contradicts `docs/WORKSPACE_HUB_CAPABILITIES_SUMMARY.md` (under "Tier-1 Repositories"), which explicitly defines only four Tier-1 repositories: `digitalmodel`, `assetutilities`, `assethold`, and `worldenergydata`. `workspace-hub` is the control plane, not a Tier-1 data repo.
2. **Fabricated repository target:** Plan § "LLM Wiki pages consulted" asserts that "`llm-wiki/` sibling and nested repo presence was detected via filesystem search". This is factually false; a filesystem search yields zero matches for `llm-wiki`. Furthermore, `docs/WORKSPACE_HUB_CAPABILITIES_SUMMARY.md` § "Knowledge & Intelligence Ecosystem" confirms that LLM-Wikis reside at `knowledge/wikis/` within `workspace-hub`, not in a standalone repository. The plan's open question ("Which repo is canonical for private llm-wiki...") is based on this false premise.
3. **Missing Acceptance Criterion coverage:** Plan § "Acceptance Criteria" #4 mandates that the generated matrix defines "report/chatbot eligibility" for each source class. However, the corresponding test in § "TDD / Validation List" (`test_source_matrix_has_required_columns`) explicitly checks only for `source_class, owner, canonical_path, layer, level, public_posture, promotion_gate` and omits the required `report_chatbot_eligibility` column.
4. **Missing issue verification:** Plan § "Evidence (embedded verification)" claims to have verified issue statuses via `gh issue view`, but it erroneously lists issue `#2726` twice and omits verification for `#2727`, `#2728`, and `#2729`. Yet, Plan § "Acceptance Criteria" #1 sets the curation of these three missing issues as a hard gate.

## Blockers
- Finding 1: You cannot build an architecture layer mapping based on an incorrect Tier-1 repository inventory.
- Finding 2: The LLM-Wiki paths and repo owners must be corrected to point to `knowledge/wikis/` within `workspace-hub` before proceeding.
- Finding 3: The matrix validation test must be updated to include the chatbot eligibility column to enforce Acceptance Criterion #4.
