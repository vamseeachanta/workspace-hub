### Verdict: MAJOR

### Summary
The plan does not yet justify a green first CI run. It leaves the highest-risk pytest dependency decision unresolved, misses an already-visible import-path failure in the existing tests, and loses template fidelity on trigger scoping by replacing positive `paths` filters with broad `paths-ignore` only.

### Issues Found
- `docs/plans/2026-04-21-issue-2444-aceengineer-admin-ci.md`, `Deliverable` and `Acceptance Criteria` claim CI is `scoped to src/ + tests/ only`, but `Detailed CI Workflow Spec > Triggers` defines only `push`/`pull_request` plus `paths-ignore`. That does not restrict runs to `src/**` and `tests/**`; any non-ignored change will trigger CI, including unrelated root files. The source template at `digitalmodel/.github/workflows/workflow-automation-tests.yml` uses positive `paths:` filters, so this is a fidelity regression, not a neutral adaptation choice.
- `docs/plans/2026-04-21-issue-2444-aceengineer-admin-ci.md`, `Risks and Open Questions` leaves the key first-run decision unresolved: `tests/knowledge/ ... either (a) install [knowledge-semantic] extra ... or (b) exclude tests/knowledge ... Open for reviewer: which mitigation is preferred?` But `Acceptance Criteria` still requires the `First GitHub Actions run ... is GREEN`, and `Detailed CI Workflow Spec` freezes `uv pip install -e ".[dev,test]"` plus plain `uv run pytest`. That is not an executable plan for the stated acceptance target.
- The plan underestimates immediate pytest failure risk. `aceengineer-admin/tests/unit/automation/test_cli.py` imports `aceengineer_automation.cli`, and `aceengineer-admin/tests/unit/automation/common/test_config.py` imports `aceengineer_automation.common.config`, but the packaged entry point in `aceengineer-admin/pyproject.toml` is `aceengineer = aceengineer_admin.cli:main`, and the current implementations are in `aceengineer-admin/src/aceengineer_admin/cli.py` and `aceengineer-admin/src/aceengineer_admin/common/config.py`. The plan's risk section focuses on `tests/knowledge/` extras and does not account for these stale imports, so its `green first run` claim is not verified.

### Suggestions
- Change trigger design to match the stated scope: add positive `paths:` entries for `src/**`, `tests/**`, and `.github/workflows/ci.yml`, then keep `paths-ignore` only for sensitive exclusions that overlap those paths if still needed.
- Resolve the `knowledge-semantic` decision in the plan itself before approval. Either include the extra in the frozen install command and justify the dependency cost, or explicitly exclude the affected tests in the frozen pytest command and make the follow-up issue part of acceptance.
- Add a pre-implementation verification step for existing tests and account for the stale `aceengineer_automation` imports. The plan should either include fixing those tests in-scope or explicitly state that first-run green is impossible until a separate repair lands.
- Remove the internal command mismatch between `Deliverable` (`uv sync --extra test --extra dev`) and `Detailed CI Workflow Spec` (`uv pip install -e ".[dev,test]"`). The plan should freeze one install path.
