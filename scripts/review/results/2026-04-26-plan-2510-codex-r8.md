## Findings
1. Plan header corrupts r7 archive traceability. The header says `Review artifacts (r7 archive after run): scripts/review/results/2026-04-26-plan-2510-claude-r6.md | ...-codex-r6.md | ...-gemini-r6.md`. Those are r6 archive paths, not r7. This contradicts `Pre-Approval Review Artifact Checklist`, which requires each wave to be archived to the corresponding `-rN.md` snapshots before rerun. The actual r7 files exist at `scripts/review/results/2026-04-26-plan-2510-{claude,codex,gemini}-r7.md`, so the plan is pointing reviewers at the wrong archival evidence.

2. The overclaim guardrail is materially undertested. `Acceptance Criteria` says “Report and metadata explicitly avoid PDK DRC/LVS, JEDEC/IPC, or tapeout/signoff claims.” But `TDD Test List` only checks the generated report and only excludes `JEDEC compliant`, `DRC clean`, and `tapeout-ready`. It does not test metadata at all, and it misses obvious forbidden variants such as `IPC compliant`, `LVS clean`, `signoff-ready`, `production tapeout`, `PDK-qualified`, or `meets JEDEC`. This leaves the core standards/signoff boundary unenforced.

3. Artifact-hash metadata ordering is underspecified. `Scope Boundaries` includes metadata extraction of “artifact hashes,” but `Pseudocode` writes `layout_metadata.json` in `write_metadata(...)` before `render_report(...)` and before `write_manifest_after_report(...)`. There is no second metadata pass after report/manifest generation, and the TDD row `test_metadata_extracts_layers_bboxes_ports_and_counts` does not assert artifact hashes. An implementation can satisfy the pseudocode and tests while omitting final report/GDS/readback hashes from `layout_metadata.json`.

## Blockers
1. Finding 1: fix r7 archive paths in the plan header before approval routing.
2. Finding 2: expand the report/metadata overclaim tests to cover the full acceptance-criteria boundary.
3. Finding 3: define and test whether `layout_metadata.json` must include final artifact hashes, or remove “artifact hashes” from the metadata scope.
