One of them was presumably meant to test the on-disk working tree (e.g., `find . -path ./.git -prune -o -name '*\\*' -print`) — as written they are redundant.
- [P2] Important — False-positive risk in `P1-ci-no-windows-invalid-path`: `gh run view <id> --log | grep -c 'invalid path'` will hit any downstream step (pip, flake8, pytest) that happens to print the phrase `invalid path` in unrelated output. Scope the grep to the Windows Checkout step (e.g., filter by job name + `##[error]error: invalid path`) to avoid accidental green and accidental red.
- [P2] Important — `P2-ci-log-order-proof` awk gate matches the substrings `Run smoke tests first` and `Lint with flake8` anywhere in the log, including step-group echoes and tool output. Anchor the check to GitHub's `##[group]` markers (`/^##\[group\]Run smoke tests first/` and `/^##\[group\]Lint with flake8/`) to guarantee step-boundary semantics rather than substring semantics.
- [P3] Minor — P1 Windows acceptance (`reaches Install dependencies with uv`) depends on both `Clone assetutilities sibling dependency` and `Set up Python` / `Install uv` succeeding first. These are outside P1's fix surface; a transient failure in any of them would make P1 look red for reasons unrelated to the backslash purge.
