## Findings

1. **`_load_gdsfactory()` monkeypatch seam is contract-ambiguous; the dependency-blocker test can silently pass without exercising the failure path.**
   §"CLI and Dependency Contract" line 173: *"It may import GDSFactory lazily inside writer/import functions, but when generation is requested and GDSFactory is unavailable it must fail loudly…"* combined with line 264's test description: *"monkeypatch the lazy import helper to raise `ModuleNotFoundError`"*. For `monkeypatch.setattr("scripts.semiconductor.layout_cad_demo._load_gdsfactory", ...)` to actually intercept the writer's import, the writer/import functions MUST call `_load_gdsfactory()` to obtain the module — they may not write a direct `import gdsfactory` inside the function body. The plan's "may import GDSFactory lazily inside writer/import functions" allows the latter. If the implementer writes `def write_exchange_artifact(...): import gdsfactory as gf; ...`, the monkeypatch is dead code and the test passes vacuously while the production code retains a hidden hard import. Tighten to: "every callsite of GDSFactory MUST go through `_load_gdsfactory()`; direct `import gdsfactory` inside writer/reader functions is forbidden."

2. **The CLI's `--report under --output` guard has no failing-case test.**
   §"CLI and Dependency Contract" line 170: *"`--report <path>` required and must resolve under `--output`; otherwise the CLI must exit with a clear error before writing partial artifacts."* No entry in the §"TDD Test List" (lines 254–267) covers the failure path: invoking with `--report` outside `--output` and asserting (a) non-zero exit, (b) zero partial artifacts on disk, (c) error message wording. `test_cli_regenerates_artifacts_manifest_and_report` only exercises the happy path. Without a RED case, this guard can regress to a no-op without any test going red.

3. **Pseudocode `import_exchange_artifact` conflates CLI behavior with test-only comparison; CLI exit-status semantics on round-trip mismatch are unspecified.**
   §"Pseudocode" lines 217–220: *"compare read-back invariants against generated geometry metadata / write `gds_readback_metadata.json`"* runs inside the CLI. But §"GDS Round-Trip Contract" lines 180–188 describes comparisons as test-only (bbox tolerance, layer-key tuple, contract-matched per-layer counts). The plan never says whether a round-trip mismatch exits the CLI non-zero or merely records a mismatch entry into `gds_readback_metadata.json` and exits 0. If it exits 0, `test_gds_export_import_roundtrip_preserves_core_invariants` (line 261) is the only fence — meaning a runtime regression (e.g., a future GDSFactory bump that fractures one extra polygon) produces a passing CLI run that silently lies in the JSON.

4. **The "two-run byte-diff probe" requirement is duplicated and unscoped against the existing determinism test.**
   §"Determinism Contract" line 366: *"Execution must include a two-run byte-diff probe for `chip_package_demo.gds`: generate the same default design into two temp dirs … assert equal SHA256 for the `.gds` before accepting the deterministic manifest."* §"TDD Test List" line 263 already specifies `test_outputs_are_deterministic_across_runs`: *"two temp dirs … equal content hashes for manifest-covered artifacts and byte-identical `artifact_manifest.sha256` text"*. The plan does not state whether the determinism contract's probe is satisfied by running the test (in which case the contract item should reference the test, not restate it as if separate), or whether it is an additional CLI-shipped self-check (in which case there is no implementation directive for it). As written, an implementer could legitimately read either interpretation.

5. **Forbidden-claims filter (line 266) is enumerated as substrings without specifying case-sensitivity, word-boundary, or disclaimer-context handling.**
   `test_report_and_metadata_have_role_relevance_and_no_signoff_overclaims` (line 266) lists exact variants `JEDEC compliant`, `meets JEDEC`, `IPC compliant`, `DRC clean`, `LVS clean`, `signoff-ready`, `production tapeout`, `tapeout-ready`, `tapeout ready`, `PDK-qualified`, `foundry signoff`, `PDK DRC`, `PDK LVS`. A naive `"DRC clean" in report_text.lower()` will fire on disclaimers like "this demo does NOT claim DRC-clean status," forcing the implementer to phrase the disclaimer awkwardly. Conversely, a naive case-sensitive match misses `drc clean`. The plan should specify whether the test does a regex with negation context, a token match, or a strict-case check, and what the canonical disclaimer phrasing is.

6. **Plan status header conflicts with on-disk r10 review state.**
   Line 3: *"Status: plan-review — r9 MAJOR findings patched; r10 adversarial review pending after push."* Implies r10 has not run. But canonical `scripts/review/results/2026-04-27-plan-2510-{claude,codex}.md` are **0-byte files** (Apr 27 04:55), `2026-04-27-plan-2510-claude.md.err` exists (0 bytes), and `2026-04-27-plan-2510-codex.md.err` is **46733 bytes** (Apr 27 04:56). This indicates a fanout attempt did fire and partially failed. The plan's own §"Pre-Approval Review Artifact Checklist" line 349–351: *"Canonical unsuffixed files must not be 0 bytes after the review command completes … must be replaced by provider output or a non-empty `UNAVAILABLE` artifact before committing or requesting approval."* The plan header should be reconciled: either acknowledge a partial r10 fanout that needs recovery per the inverted-state rule (line 350) or clear the 0-byte placeholders before declaring r10 "pending." As-is, an executor following the header alone would not know to run the recovery procedure.

7. **`_load_gdsfactory()` is named and scoped only for GDSFactory, but the plan also lists KLayout as a secondary import-validation path.**
   §"Scope" line 154: *"KLayout scripting may be used as a secondary/import validation path if available."* §"CLI and Dependency Contract" only specifies the seam for `_load_gdsfactory`. If a future revision flips to KLayout as primary or wires KLayout into the import path, there is no `_load_klayout()` contract or monkeypatch test. Either narrow the scope to GDSFactory-only (and remove the "KLayout secondary" allowance) or define the symmetric seam now.

8. **Pseudocode `write_metadata_initial` writes `geometry_summary.csv` but the determinism contract (line 362) forbids wall-clock timestamps in CSV.**
   The pseudocode at lines 224–225 says *"write geometry_summary.csv with deterministic row order and LF endings."* Line 362 forbids wall-clock timestamps in CSV. CSV doesn't typically encode timestamps, but the plan also requires writer/reader package versions (line 152) — the implementation could end up serializing per-run version probe results into the CSV header. The plan should explicitly forbid putting any per-process metadata into `geometry_summary.csv` (versions belong in `layout_metadata.json` and the report).
