### G2 (MINOR) — `cta_in_methodology_method_cta` regex extraction under-specified

Plan line 135 says: "extract the span from `<div class="method-cta text-center">` up to (and including) its matching closing `</div>` on the minified body line". The extraction tool is named as "bash + regex-scoped grep" with no concrete pattern. On a minified line like:

```
<div class="method-cta text-center"><h2>...</h2><p>...</p><a ...>Talk to ACE Engineering</a></div></article></div></div></div></section>...
```

a greedy `grep -oE '<div class="method-cta text-center">.*</div>'` would match all the way to the trailing `</div>` near end-of-line, sweeping in `</article></div></div></div></section>...`. Non-greedy `.*?` with PCRE (`grep -oP`) is required. Because `.method-cta` contains no nested `<div>` today, a non-greedy first-`</div>` stop is sufficient — but this is an undocumented invariant, and the test will silently bloat or miscount if a future `.method-cta` rewrite introduces a nested div. **Fix: specify `grep -oP '<div class="method-cta text-center">.*?</div>'` (or equivalent awk/perl) in the TDD row, and note the no-nested-div invariant.** Non-blocking because the minified body is stable across all 4 methodology pages today.
