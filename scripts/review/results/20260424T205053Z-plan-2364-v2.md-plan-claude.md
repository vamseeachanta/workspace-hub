### Verdict: MAJOR

### Summary
v2 substantively addresses every v1 finding with strong attested evidence (40-entry registry survey, 25/15 dry-run, forbidden-path quote, fixture-id correction). However, the regex-based additive YAML patch still has under-specified idempotency and atomicity, the wall-clock benchmark test risks CI flakiness, and executing Python code (and pytest) from `docs/reports/` is spec-compliant but leaves module-import mechanics unspecified. These are tractable fixes but should land before plan-approved.

### Issues Found
- [P2] Registry write-back idempotency is only tested at the report layer (`test_run_is_idempotent` asserts no new stubs), not at the file layer. The anchored regex matches on `- id: <id>` and will happily append a second `processed: true` line on re-run unless the runner first checks whether the key already exists. Add a pre-write guard AND an acceptance test that diffs the registry byte-for-byte after a second run.
- [P2] `test_duplicate_check_wall_clock_under_budget` asserts < 30 s over 19,191 pages as a unit test. Wall-clock asserts in the default test suite flake on slow/loaded CI runners. Gate it behind `@pytest.mark.perf` or an env var (e.g., `RUN_PERF_TESTS=1`) so default CI stays green and the benchmark runs only on demand.
- [P2] Tests at `docs/reports/batch-pack-1-runner-tests.py` must import the runner at `docs/reports/batch-pack-1-runner.py`, but `docs/reports/` is not on `sys.path` by default and contains a hyphenated filename (not a valid Python module name). The plan does not specify the import mechanism (conftest, `importlib.util.spec_from_file_location`, renamed underscore module, or `__init__.py`). This has bitten the repo before — see the memory entry on `llm-wiki` hyphen-path poisoning.
- [P3] Atomicity of the registry patch is not specified. A crash between processing entry 20 and 40 will leave the YAML half-modified. Plan should require temp-file-plus-rename (`os.replace`) with a pre-write schema check.
- [P3] `processed_date: <iso>` format is unspecified (local vs UTC, tz-aware vs naive). This is a reproducibility smell for a report-generator: the same run on two machines will produce different bytes. Pin it to `datetime.now(timezone.utc).isoformat(timespec='seconds')` and make the test assert the regex format.
- [P3] Classifier-precedence tests cover LAW > MARINE only. No test covers LAW > NAVAL_ARCH (e.g., IMO notes on a DNV-hosted URL) or NAVAL_ARCH > MARINE (e.g., hydrodynamic notes on an IACS host). These precedence boundaries are the ones that will fire in ambiguous real cases.
- [P3] The full stub frontmatter schema is not enumerated in the plan. `test_build_stub_frontmatter_matches_wiki_schema` only checks a superset of the four base keys, leaving `target_wiki_domain`, `out-of-scope-for-promotion`, `sources`, `classifier_trace`, `duplicate_candidate` untested for presence/type. Lock the schema in the plan and test each required key.
- [P3] Deliverable and Acceptance Criteria slightly disagree on whether maritime-law stubs count toward 'stubs generated' or only toward the follow-on catalog. Deliverable says they are 'enumerated but not promoted'; AC says `target_wiki_domain ∈ {..., maritime-law}` for generated stubs. Clarify whether a maritime-law stub is counted in `sufficient` or treated as deferred.
- [P3] The pre-push forbidden-path guard in the acceptance criteria uses `git diff --name-only | grep -vE '^(data/document-index/|docs/reports/|docs/plans/)' returning empty`, but a legitimate change to `docs/plans/README.md` (explicitly listed under Files to Change) will pass the guard — fine — while a file added under `docs/` (e.g., `docs/foo.md`) would also pass. Tighten the regex or invert the logic to an allow-list-only assertion.

### Suggestions
- Add a `skip_already_processed: bool = True` guard in `patch_registry_additive` plus an explicit acceptance test: run the runner twice, then assert `registry_after_run_1 == registry_after_run_2` at the byte level.
- Split the 30-s wall-clock test out of the default suite: mark it `@pytest.mark.perf` and add to acceptance criteria that the perf run is executed once at plan-approval time but not on every commit.
- Specify the test-import strategy explicitly in Files-to-Change — either (a) rename the runner to `batch_pack_1_runner.py` (underscore) and add a `conftest.py` under `docs/reports/` that appends the directory to `sys.path`, or (b) use `importlib.util.spec_from_file_location` in the test module. Pick one, write it in the plan, and note the memory-entry about hyphen-path poisoning as prior art.
- Pin `processed_date` to UTC ISO-8601 with seconds precision; add a regex-format assertion in `test_processed_flag_is_additive_only`.
- Add two classifier-precedence tests: LAW > NAVAL_ARCH (IMO-keyword notes on `standards.dnv.com` host) and NAVAL_ARCH > MARINE (class-rules notes on a marine-adjacent host).
- Enumerate the full stub frontmatter schema (keys + types + required-flags) in a small table under Pseudocode, and tighten `test_build_stub_frontmatter_matches_wiki_schema` to assert every required key with its expected type.
- Require atomic write-back: write to `online-resource-registry.yaml.tmp`, fsync, then `os.replace`. Add a test that simulates crash-after-partial-write (monkeypatch `open` to raise mid-loop) and asserts the original file is intact.
- Consider adding a 'Classifier Trace' JSON artifact alongside the MD report so downstream #2039/#2067 can consume classifications programmatically without re-parsing the report.
- Reconcile Deliverable vs. AC on maritime-law counting: state explicitly whether maritime-law entries are in `sufficient`, `insufficient`, or a third `catalog-only` bucket, and update `test_output_report_counts_invariant` to match.

### Questions for Author
- How will the test module import the runner given that `docs/reports/batch-pack-1-runner.py` has a hyphenated filename and `docs/reports/` is not on `sys.path`? (The workspace memory flags hyphen-path poisoning as a recurring P1 smell.)
- Does `test_run_is_idempotent` assert report-level idempotency only, or does it also verify that the registry file is byte-identical after a second run? If the latter, please say so in the test description.
- Are maritime-law stubs counted as 'promoted' (i.e., part of the 25 sufficient) or as deferred? The Deliverable and AC read differently on this point.
- What timezone and precision does `processed_date` use? Without pinning, two machines running the same command produce different bytes.
- Should the perf test (30-s wall-clock over 19,191 pages) run on every commit, or only during plan-approval and release gates? If the former, expect flakes on loaded CI.
- For the acceptance criterion that asserts no writes under forbidden paths, would the author prefer an allow-list enforcement (only `data/document-index/**`, `docs/reports/**`, `docs/plans/README.md`) rather than a deny-list, to avoid silent drift into unintended `docs/` subtrees?
