### Verdict: MAJOR

### Summary
Plan v3 is a substantial improvement over v2 — the overlay-file pivot cleanly resolves Gemini r2's regex-YAML P1 without adding a dep, the underscore filenames eliminate the recurring hyphen-path smell, and the three-bucket partition reconciles the maritime-law double-counting honestly. The TDD list (28 tests) and overlay schema/generator contracts are unusually precise. However, two contradictions inside the plan need resolution before execution: the dry-run partition counts disagree between prose and table, and the AC requires review artifacts in `scripts/review/results/` while the allow-list guard explicitly forbids any `scripts/**` writes.

### Issues Found
- [P1] Internal count contradiction in §Evidence: the 40-entry survey prose says 'Sufficient/insufficient split under 120-char + indicator rule: 25 / 13 (recounted v3 ... minus 2 maritime-law catalog-only)' but the immediately-following three-bucket table reports 23/15/2. Neither 25+13+2=40 nor 23+15+2=40 maps cleanly onto the prose-and-parenthetical (25-2=23 explains sufficient, but the 13 insufficient figure is irreconcilable with the table's 15). One of the two is stale. Resolve before execution since the AC depends on the runner reproducing this split.
- [P1] AC-vs-allow-list contradiction on review artifacts: the final AC bullet requires 'Review artifacts for all three providers posted to scripts/review/results/', but the allow-list-guard regex set (Claude r2 P3 fix) does not include any scripts/** path, and §3.1 explicitly forbids scripts/**. If the allow-list gate is enforced strictly on `git diff --name-only origin/main...HEAD`, posting review artifacts will fail the gate. Either carve out scripts/review/results/ in the allow-list (with rationale tied to §3.1's policy) or move artifacts to an owned path.
- [P2] Atomic-write pseudocode lacks tmp-file cleanup. `tmp.write_bytes(...)` then `os.replace(tmp, OVERLAY_PATH)` — if `os.replace` raises (cross-device link, perm error), the .tmp file is orphaned. test_overlay_atomic_write_no_partial monkeypatches os.replace to raise but the test description doesn't say whether it asserts tmp cleanup; production code should wrap with try/finally + tmp.unlink(missing_ok=True).
- [P2] `processed_date` carry-forward semantics underspecified when source content changes. The generator carries `processed_date` forward whenever a prior overlay matches `source_registry_sha256`, but per-entry `source_checksum` can still change for a given id (notes edited, classification stable). The plan does not document whether `processed_date` means 'first promoted' or 'last successful processing' — consumer code in §Consumer-side fallback logic doesn't distinguish either. Add an explicit semantic note: it is 'first promoted' (record `last_refreshed` separately if last-processing semantics are needed).
- [P2] `@pytest.mark.perf` marker is not registered. Plan introduces the marker but doesn't show registration in pyproject.toml `[tool.pytest.ini_options] markers`. Without registration pytest emits PytestUnknownMarkWarning, and `-m 'not perf'` selection still works but accumulates warnings. Add the marker registration to the Files-to-Change list (or call it out as an existing config that already registers it).
- [P3] test_overlay_byte_identical_across_reruns ordering is not explicit. Per §Generator contract, byte-identity across reruns requires that run 2 finds a prior overlay so `processed_date` carries forward. The test description should say 'arrange: clean state → run 1 (establishes baseline) → run 2 (must match run 1)' or it can be misread as 'two parallel fresh runs match', which is not what the design guarantees.
- [P3] test_check_duplicate_finds_existing_wiki_page does not specify whether it uses the live `knowledge/wikis/` tree (read-only access) or a tmp_path fixture. If it relies on the live wiki it becomes order-dependent on whether the duplicate page survives unrelated wiki edits.
- [P3] Concurrent-runner race not addressed in Risks. atomic os.replace prevents partial-write corruption but not write-write races: two simultaneous runners can both read the same prior overlay, then race on `os.replace`, and the loser silently overwrites the winner with possibly-stale `processed_date` if their inputs differed. Low likelihood in this workflow but worth one risk-line + 'document as out-of-scope: human-driven single invocation' if that is the intent.
- [P3] `docs/reports/conftest.py` placement may surprise. pytest auto-loads conftest.py for any test collected under that directory. If other unrelated test files later land under `docs/reports/`, the sys.path shim adds the directory unconditionally. Consider scoping the shim or moving it next to the test module only.

### Suggestions
- Resolve the 25/13 vs 23/15/2 inconsistency by deleting the prose 'split: 25/13' line (it appears to be a v2 leftover), or by re-running the partition and updating both prose and table to agree. The AC's three-bucket invariant is the authoritative contract — make the survey numbers match it.
- Either expand the allow-list regex set to include `^scripts/review/results/.+\.md$` with a comment ('§3.1 carve-out: review-artifact tooling output, not source code under scripts/'), or move review artifacts under `docs/reports/reviews/` (owned). Be explicit about the resolution since §3.1 forbidden-paths is quoted verbatim earlier.
- Wrap the overlay write in `try: tmp.write_bytes(...); os.replace(tmp, OVERLAY_PATH) finally: tmp.unlink(missing_ok=True)` and assert tmp absence in the atomic-write test.
- Add a one-line note in the overlay schema table that `processed_date` is 'first promoted' semantics; add an optional `last_refreshed` field if downstream consumers (e.g. #2227, #2207) need 'most recent processing' provenance.
- Register the `perf` marker in `pyproject.toml` (or call out the existing registration). Add a Files-to-Change entry if the registration doesn't already exist.
- Reword `test_overlay_byte_identical_across_reruns` description to make the run-1 → run-2 ordering explicit, and consider also asserting `sha256(overlay_run2) == sha256(overlay_run3)` to lock in true steady-state determinism.
- Use `tmp_path` + a synthetic 2-page wiki tree for `test_check_duplicate_finds_existing_wiki_page` to remove dependency on live `knowledge/wikis/` content.

### Questions for Author
- The AC requires posting review artifacts to `scripts/review/results/`, but the allow-list-guard regex set explicitly excludes that path and §3.1 forbids `scripts/**` writes. How should the allow-list gate be expanded (or the artifact location relocated) to keep both gates passing?
- Does the prose '25/13' split or the table '23/15/2' split reflect the live partition on HEAD `12b4be8`? Has the partition been re-verified after introducing the 120-char + indicator rule and the catalog-only third bucket?
- Should `processed_date` mean 'first promoted' or 'last successful processing'? The generator carries it forward unchanged (= first promoted), but the field name is ambiguous. If downstream consumers (#2227, #2207) expect 'last processed', a separate `last_refreshed` field is needed.
- Are concurrent runner invocations a realistic concern in this workflow, or is the runner always invoked from a single human-driven execution? If concurrency is possible, the atomic-write semantics need lock-file or fcntl-style coordination on top of os.replace.
- Is the `perf` pytest marker already registered in `pyproject.toml`, or does v3 implicitly need a registration patch? If the latter, that crosses into config/** which §3.1 forbids — needs the same allow-list reconciliation as the review-artifacts question.
