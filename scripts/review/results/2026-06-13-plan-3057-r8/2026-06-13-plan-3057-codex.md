## Findings
1. `notification-purge` can still be duplicated because the plan allows the live legacy line to classify as preserved while also selecting/rendering the catalog task. Plan pseudocode says to preserve existing external/ignore lines exactly and only assert expanded/unexpanded `notification-purge` legacy lines classify as “cataloged/preserved” (`docs/plans/2026-06-13-issue-3057-cron-hygiene-hardening.md:388-389`, `:456`, `:478`). Existing classification checks fingerprints before catalog keys (`scripts/cron/cron_transaction.py:191-198`), and `notification-purge` has a preserved-local fingerprint matching `find logs/notifications/` plus `-delete` (`config/workstations/harness-state-classes.yaml:120-130`). The same task is also in the catalog (`config/scheduled-tasks/schedule-tasks.yaml:311-320`) and the plan requires its selected command to appear in `plan["new_text"]` (`docs/plans/2026-06-13-issue-3057-cron-hygiene-hardening.md:456`). That combination preserves the old out-of-block line and adds the managed one. The existing state-class comment explicitly says the live duplicate should be deduped, not merely preserved (`config/workstations/harness-state-classes.yaml:126-128`). The plan needs an explicit rule/test that catalog-owned preserved-local lines such as `notification-purge` are not duplicated after cutover.

2. The plan omits `scripts/cron/cron-audit.py`, leaving the pre-cutover classifier inconsistent with the planned raw+rendered full-command catalog matching. The deliverable promises “raw-and-rendered catalog matching for placeholder fallback tasks” (`docs/plans/2026-06-13-issue-3057-cron-hygiene-hardening.md:296`), but Files to Change excludes `scripts/cron/cron-audit.py` (`docs/plans/2026-06-13-issue-3057-cron-hygiene-hardening.md:421-436`). `cron-audit.py` is documented as the fail-closed pre-cutover gate (`scripts/cron/cron-audit.py:6-12`) and builds its own catalog fragments with raw command fallback only (`scripts/cron/cron-audit.py:72-98`). The plan changes `cron_apply.py` catalog keys (`docs/plans/2026-06-13-issue-3057-cron-hygiene-hardening.md:378-381`, `:424`) but leaves the audit path able to report different classifications from the cutover path. Either the shared catalog-key/rendering helper must be used by `cron-audit.py`, or the plan must explicitly scope out the pre-cutover audit and explain why inconsistent audit/apply classification is acceptable.

## Blockers
1. Finding 1: add a concrete dedupe/classification rule and test for live out-of-block `notification-purge` so cutover does not preserve and re-add the same catalog-owned task.
2. Finding 2: include `scripts/cron/cron-audit.py` in the shared raw+rendered catalog-key change, or explicitly justify and test the audit/apply divergence.
