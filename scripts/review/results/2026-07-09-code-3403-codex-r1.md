## Findings
- MAJOR: `tools/voice-dictation/codex-dictate.sh:111` / `stop_and_type` -- the launcher treats any live PID in `${state_dir}/arecord.pid` as its own recorder and then kills it at lines 47-50. I reproduced this by writing an unrelated `sleep` PID into a temp `arecord.pid`; running the launcher killed that unrelated process. This can happen with stale `/tmp/codex-dictate` state, PID reuse, or a malformed/manual pidfile, and it violates the persistent/restart safety expected for a global hotkey. Required fix: record and validate recorder identity before killing, e.g. verify `/proc/$pid/cmdline`/start time matches the `arecord` invocation and expected wav path, otherwise delete stale state and start a new recording. Add a regression test that a stale pidfile pointing at a non-`arecord` process is not killed. Current test `scripts/agents/tests/test_voice_dictation_detection.sh:292-296` encodes the unsafe behavior by passing when a generic `sleep` process is killed.
