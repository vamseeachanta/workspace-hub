Same defect class as the r2 metric-scoping finding: covered only implicitly by the generic locked-decisions test. Add "schema-invalid" to both the assert and the test row.

2. **MINOR — the plan ignores the parent's `gate:completeness` obligation.** `gh issue view 3427` shows the `gate:completeness` label. Per `.claude/rules/completeness-before-close.md`, an opted-in issue reaching `status:plan-approved` requires a computed/persisted/owner-verified completeness record before `gh issue close`, positioned "Cross-review → [completeness gate] → Close". The plan's Acceptance Criteria and lifecycle text never mention computing the completeness score, rendering `docs/reports/<date>-3427-completeness.html`, or the owner-only `status:completeness-verified` label. Not an implementation blocker, but the owner approves this plan as the full lifecycle description; add a closure-gate AC so the gate isn't rediscovered at close time.

3. **MINOR — no defined path if Codex remains unavailable at r3.** Codex failed r1 (stdin/rc=124) and r2 (no artifact within the 700-second bound). The AC requires "Final Claude and Codex artifacts will contain substantive reviews," and the disclosure-and-owner-acceptance mechanism is defined only for the Gemini T3→T2 degradation.
