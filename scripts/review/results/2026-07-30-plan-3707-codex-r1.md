# Adversarial Review: #3707 Cron Upkeep Clockwork Plan

Verdict: MINOR after revision

Reviewer stance: adversarial self-review. The review will assume the plan has defects until each correctness-critical claim will be checked. No praise or restatement will be included.

## Checks Performed

- Checked `scripts/windows/reconcile-ecosystem.ps1` for PowerShell/Git Bash delegation risk.
- Checked `config/workstations/registry.yaml` for path layout assumptions beyond `/mnt/local-analysis`.
- Checked `scripts/cron/daily-cleanup.sh`, `scripts/lib/worktree_guard.py`, and executable `scripts/` stash commands for D1-D5 plan assumptions.
- Checked that #3708 will remain a deployment blocker because `cron-audit.py` will fail closed and `setup-cron.sh --replace` will remain disabled.
- Checked that the planned tests would fail against current code rather than passing vacuously.

## Findings

### F1 — MAJOR — Initial sequencing could have implied YAML-only scheduling would satisfy "clockwork"

Evidence: `scripts/cron/setup-cron.sh:31-35` will reject `--replace`, and `scripts/cron/cron-audit.py:374-375` will return nonzero on uncataloged live lines. A `schedule-tasks.yaml` entry alone would not make system cron execute `daily-cleanup`.

Revision: The plan will require #3708 to land before live system-cron deployment. It will allow code/config staging only as non-live preparation and will make closeout depend on the #3708 safe apply path.

### F2 — MAJOR — Initial path model risk could have broken Windows and non-primary Linux layouts

Evidence: `config/workstations/registry.yaml` will include Linux sibling roots, Windows `D:\` roots, and `gpu-claw` style `/home/.../ws` roots. `scripts/windows/reconcile-ecosystem.ps1:79-98` will convert Windows hub paths to Git Bash POSIX paths and delegate to `scripts/readiness/reconcile-ecosystem.sh`.

Revision: The plan will add registry-driven path tests for dev-primary, dev-secondary, Windows, and gpu-claw style layouts. It will explicitly keep Windows daily-cleanup system cron out of v1 while preserving the PowerShell reconcile wrapper.

### F3 — MAJOR — Initial worktree policy could have weakened deny-by-default into age-only deletion

Evidence: `scripts/lib/worktree_guard.py:59-69` will approve removal only when `.wt-owner` matches. `find . -name .wt-owner` will return no markers in this checkout, so unmarked worktrees would remain protected but cleanup would stay inert unless creators write markers.

Revision: The plan will recommend that worktree-creating automation write `.wt-owner` markers. Daily cleanup will only remove guard-approved owned worktrees; unmarked worktrees will count as blocked backlog and health evidence.

### F4 — MAJOR — Initial stash policy risk could have repeated repo-wide stash sweep incidents

Evidence: executable `scripts/` will contain no `git stash drop` or `git stash clear`, while repo memory will document prior damage from unfiltered stash-drop loops. Stashes will be repo-wide, so broad disposal will be unsafe.

Revision: The plan will forbid `git stash clear` and unfiltered drop loops. Future auto-drop will require a specific `stash@{N}` ref, allowlisted automation-owned message, age threshold, and content-safe classification; unknown stashes will raise a consumed health alert instead.

### F5 — MINOR — Fleet crontab absence will not be locally verifiable without SSH

Evidence: the local `crontab -l` will show no daily-cleanup entry, but the user forbids SSH, so ace-linux fleet crontab absence will remain issue-supplied evidence.

Revision: The plan will state that fleet crontab absence is issue-supplied for planning and will require future on-box read-only audit evidence before live apply.

### F6 — MINOR — No-op health tests could pass vacuously if no backlog exists

Evidence: A disposal job that sees no eligible backlog should not fail merely because it disposes nothing.

Revision: The plan will require paired tests: eligible backlog plus zero disposal for N runs will fail as `CLEANUP_NOOP`; true empty backlog plus zero disposal will remain healthy.

## Residual Risk

- Provider diversity will not be present in this self-review artifact. The user requested self-review specifically, so the plan will not claim multi-provider consensus.
- #3708 will remain the live deployment blocker. This plan will be approval-ready for design, but the implementation closeout will need #3708 evidence.
