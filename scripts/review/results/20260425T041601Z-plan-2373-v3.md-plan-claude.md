### Verdict: APPROVE

### Summary
Plan v3 for #2373 surgically addresses every Claude r2 MAJOR (10) and Gemini r2 MINOR (3) item with deterministic, falsifiable contracts: pinned EXPECTED_SLICE_COUNT=68, sha256 id-checksum, sha256-based collision_group_id, defaultdict grouping, broadened slug regex, explicit alias fixture, audithook for /mnt/ace blocking, and split lane/main owned-path enforcement. The Codex deferral is well-reasoned given the documented #2479 stdin-hang regression and the file-only deterministic nature of the deliverables. Acceptance gates are equality-based and the lane is internally consistent, scoped, and testable.

### Issues Found
- [P3] Minor: §Resource Intelligence Summary states 5 ledger rows are excluded by registry overlap, but the slug-verification table flags DNV-RP-C203, DNV-RP-C205, and DNV-RP-F105 as registry-excluded — three of the five overlapping rows are named, but the other two are not enumerated anywhere in the plan. Listing all 5 ids inline (or in a dedicated cross-tab) would make the equality gate auditable from the plan body without re-running the dry-run.
- [P3] Minor: The audithook reference snippet uses `sys.addaudithook` with `event == "open"`, but Python's audit event for builtin `open()` is actually `open` (correct) — however many YAML/JSON loaders go through `io.open` which raises the same audit event, so the hook will also block legitimate reads to `/mnt/ace/`-prefixed paths the lane *might* legitimately need (none currently, but worth a sentence asserting that no required input paths are under `/mnt/ace/`). Also, `subprocess`-spawned children won't inherit the audithook — if the lane shells out (e.g., `git`, `gh`), child processes are unguarded. Plan does not appear to shell out, but a one-line invariant would harden this.
- [P3] Minor: `pre_run_shard_match_locked` asserts `len(hits) >= 1` for `DNV-OS-E301`, but DNV-OS-E301 is a mooring/cathodic standard and the slice excludes `marine` domain. Confirming the seed id is in-slice (or explicitly noting the seed is for matcher-validation only and need not be in-slice) would prevent confusion when a future reader greps for the seed id and finds it absent from emitted reports.
- [P3] Minor: Risk table caps standards-aliases fixture at ≤5 entries but the dry-run only surfaced 2 alias rows (API 579-1 and API 579-1/ASME FFS-1). The ≤5 ceiling is sensible as a smell-test, but the plan does not specify what action the lane takes between 3-5 (presumably allowed) vs >5 (must surface). A single sentence — e.g., 'lane fails fast if alias count >5' — would make the gate falsifiable.
- [P3] Minor: §Pseudocode Step 5 calls `propose_target_page(entry, aliases)` but the helper's signature in §Slug Normalization Rule takes `(entry, aliases)` where `entry` is a dict — fine — but the alias lookup uses `entry["id"]` while the alias-fixture keys are quoted strings like `"API 579-1"` containing whitespace and a slash. Confirm `entry["id"]` from the ledger preserves whitespace exactly as written in the fixture (no normalization happens to the lookup key on either side). A single test row in the verification table or a `pre_run_alias_lookup_roundtrip` test would lock this.

### Suggestions
- Add an inline 5-row enumeration (or compact list) of the registry-overlap ledger ids in §Pre-Approval Count Pinning so the '-5 rows' line in the exclusion ladder is auditable from the plan body alone.
- Add an invariant statement to the audithook section: 'no subprocess invocations during the lane; helper scripts run in-process via runpy' — this closes the audithook-not-inherited gap.
- Either pick an in-slice seed id (e.g., a cathodic-protection or pipeline ledger row known to have shard hits) for `pre_run_shard_match_locked`, or add a sentence noting the seed is intentionally orthogonal to slice membership.
- Specify the alias-table cardinality gate explicitly: 'lane fails if `len(aliases) > 5`'; today the ≤5 ceiling lives only in the Risks section as prose.
- Add a `pre_run_alias_lookup_roundtrip` test that asserts `aliases[entry['id']]` resolves for at least the two known canonical pinned alias rows, to lock the whitespace/slash key shape.
- Consider making EXPECTED_SLICE_ID_CHECKSUM and EXPECTED_SLICE_COUNT a single committed YAML constant (e.g., `data/document-index/batch-pack-4-slice-pin.yaml`) so the count_slice.py helper reads them rather than the lane re-typing them — reduces drift between plan body and helper.
