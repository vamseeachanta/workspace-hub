### Verdict: MAJOR

### Summary
v2 surgically addresses all 8 Claude r1 MAJOR items and pre-empts the Gemini r1 false-positives via embedded ls-evidence; the plan is well-scoped, falsifiability-forward, and serialization-aware. However, several determinism claims are undermined by concrete pseudocode defects (non-deterministic hash, undefined shard-matching, unsorted groupby, slug regex narrower than the prose) and one core acceptance gate (EXPECTED_SLICE_COUNT) is still a placeholder. Tighten these before moving to status:plan-approved.

### Issues Found
- [P2] EXPECTED_SLICE_COUNT is referenced as the equality acceptance criterion (Pseudocode Step 2 assert; Acceptance Criteria bullet 3) but is described as 'pinned during plan-approval' rather than written into the plan body. Without a concrete integer literal (or a named, committed constant file) the plan's own equality gate is unfalsifiable at the moment of review.
- [P2] `collision_group_id = hash(p)` (Pseudocode Step 5) is non-deterministic across Python invocations because PYTHONHASHSEED randomizes str hashing. Two runs over identical inputs will emit different `collision_group_id` values, defeating the determinism promise in §Topic Clustering Rule and §Slug Normalization Rule.
- [P2] `find_shard_summary_rows(entry['id'], entry.get('title', ''))` (Pseudocode Step 4) is invoked but its matching algorithm is unspecified — exact id, substring, normalized-id, fuzzy on title? The `has_summary_evidence` flag and the `multi-shard` provenance-stratification predicate both depend on this; leaving it undefined leaks non-determinism into provenance sampling.
- [P2] `groupby(slice_entries, key=lambda e: e['domain'])` and the analogous `groupby(... key=... target_page)` (Pseudocode Steps 5–6) appear to be `itertools.groupby`, which requires pre-sorted input and yields one-shot iterators. Without a `sorted()` and without materializing `list(rows)` once, both per-domain emission and collision detection will silently miss groups and the `len(list(rows)) > 1` predicate will exhaust the iterator before the inner `for r in rows` annotation runs.
- [P2] `to_slug()` regex `r'[/. ]+'` (Pseudocode §Slug Normalization Rule) only collapses slash/dot/space, but real ledger ids contain parentheses, ampersands, slashes inside titles, and revision suffixes (e.g., `API 579-1/ASME FFS-1`). The §Evidence table itself shows that case → `api-579-1-asme-ffs-1`, which does NOT match the existing `api-579-ffs.md`. The plan handles this via `manual_alias`, but does not specify where the alias table lives nor who authors it — so the 'deterministic' classification still relies on uncited human judgment.
- [P3] First-matching-cluster-wins (Topic Clustering Rule) is stable but biased: keyword 'design' fires `cp-design`, `pipe-design`, `struct-strength`-adjacent text, etc. No tie-break rule for multi-keyword overlaps means re-ordering the YAML changes assignments without a behavior change.
- [P3] `post_run_no_source_reads_audit` references `python -X importtime -c '...'` and an open()-trapping wrapper, but the actual mechanism (sys.addaudithook? LD_PRELOAD? strace?) is not specified. As written, the test name is concrete but the implementation contract is not.
- [P3] Codex r1 timed out under #2479 and v2 is therefore Claude+Gemini-only. The plan flags this but does not state whether re-review is a hard gate before status:plan-approved or whether Claude+Gemini consensus suffices. Per `feedback_codex_sustained_MAJOR_loop` the precedent is sustained-MAJOR-only, not unavailability — so the gate needs an explicit decision in this plan.
- [P3] §Files to Change lists `Update (separate commit, main-session-only) docs/plans/README.md`, but §Forbidden lists `tests/**` and `config/**` without listing `docs/plans/README.md` under the lane's owned paths. The §Serialization Protocol covers this in prose, but `post_run_only_owned_paths` greps allow `^docs/plans/` — small mismatch between 'main-session-only' and 'lane diff allows it'.
- [P3] §Topic Clustering Rule fixture pre-lands `cp-other`, `pipe-other`, `struct-other` only implicitly (`f'{entry["domain"]}-other'`). The fixture YAML does not declare these `-other` cluster_ids, so a per-domain report rendering 'cluster_id: cp-other' has no row in the printed keyword table — reviewers cannot challenge a blank assignment.

### Suggestions
- Run §Pre-Approval Count Pinning now and write the resulting integer into the plan body as a literal (e.g., `EXPECTED_SLICE_COUNT = 138`) before requesting status:plan-approved. Cite the per-domain × org cross-tab inline.
- Replace `hash(p)` with `hashlib.sha1(p.encode()).hexdigest()[:12]` or use the target path string itself as the `collision_group_id` so reruns produce identical maps.
- Define `find_shard_summary_rows` explicitly: e.g., 'iterate shard records; match if `record.standards_refs` contains exact ledger.id OR `record.title.lower()` contains the normalized id'. Add a `pre_run` test that locks the count of shard hits per a known seed id.
- Replace `itertools.groupby` calls with `collections.defaultdict(list)` accumulation, or wrap each call in `sorted(..., key=...)` and convert to `dict((k, list(v)) for k, v in ...)`. Cleaner and avoids the iterator-exhaustion class of bug.
- Spell out the `manual_alias` source-of-truth as a committed fixture (e.g., `data/document-index/standards-aliases.yaml`) and require entries there to predate the per-domain reports — same pre-land model as the topic-clusters fixture.
- Add a tie-break rule for topic clustering: longest-matching-keyword wins, ties broken by `cluster_id` lexicographic order. Trivially deterministic and reviewable.
- Pick an audit-wrapper implementation explicitly — `sys.addaudithook` filtering on `open` events with a path prefix `/mnt/ace/` is the lightest path. Reference it in the test row so reviewers can re-execute the trap.
- Either commit to a Codex r2 gate post-#2479 (preferred — Codex's GitHub-connector grounding is non-overlapping per `feedback_cross_provider_review_payoff`) or document why Claude+Gemini consensus suffices for this specific plan (no live-state contradiction surface).
- Declare the `<domain>-other` clusters in the fixture YAML with `keywords: []` so the keyword-table render is well-formed for unmatched rows.
- Reword §Files to Change line 7 to clarify that the lane-owned diff MUST NOT include `docs/plans/README.md`, and tighten `post_run_only_owned_paths` to forbid `^docs/plans/` for the lane commit while permitting it for the main-session commit (or split into two tests by phase).
