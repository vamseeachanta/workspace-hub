### Verdict: MAJOR

### Summary
The plan has multiple correctness-critical gaps: key dependency and resource-intelligence claims are unverified, `doc_key` compliance is underspecified against operating-model §3, and the TDD matrix does not cover several acceptance criteria or stated failure modes. The dominant defect class is unverifiable and internally inconsistent operational design around identity, storage tiers, and dependencies.

### Issues Found
- [P1] Resource-intelligence claims are unverified and therefore blocking under the review rules. In `Resource Intelligence Summary`, claims such as `Found: scripts/knowledge/llm_wiki.py`, `Found: scripts/data/document-index/phase-a-index.py`, `Found (closed): #1772`, `Related issue #2360`, `Related issue #2363`, and `Memory project_hermes_codex_quota.md` are all asserted without proof, and `Distinct sources consulted: 9` is likewise unverified.
- [P1] The plan does not affirmatively specify `sha256:`-namespaced identity as required by operating-model §3. In `Documents consulted`, it says `doc_key identity — embeddings keyed on doc_key`, and in `Deliverable` it says `addressable by doc_key`, but nowhere defines the accepted `doc_key` format, rejects path-only identity, or states how non-`sha256:` keys are handled.
- [P1] The storage design is internally inconsistent and potentially violates §7 tier rules. `Artifact Map` defines `Storage (gitignored) | data/document-index/embeddings.parquet → cache mirror at /mnt/ace/.embeddings/`, while `Documents consulted` says `Parquet blob may live on /mnt/ace/, manifest must be git-tracked`. That leaves two durable copies with no stated authority, sync direction, or tier classification.
- [P1] The plan does not verify that its dependency claims are executable against current repo state. In `Documents consulted`, `Related issue #2360 — ... embeddings build is unreliable until #2360 ships OR tool handles missing keys` and `#2363 ... complementary retrieval path` are asserted, but no issue status, sequencing, or compatibility with this issue is proven.
- [P1] Acceptance criteria are not fully covered by tests. `Acceptance Criteria` requires `First real run writes embeddings-manifest.yaml with ≥1000 rows on current corpus`, `Query latency p95 < 2s on local corpus`, `Nightly cron entry merged`, and `Review artifacts posted`, but `TDD Test List` contains no test or benchmark harness for row-count sufficiency, no latency benchmark, no cron-wiring validation, and no review-artifact validation.
- [P1] Stated runtime safeguards are untested. In `Risks and Open Questions`, the mitigation says `cron aborts if nightly cost >$5 without --force`, but no file in `Files to Change` obviously owns that policy, no pseudocode implements it, and no test in `TDD Test List` verifies the abort path.
- [P1] The plan's review-artifact claims are contradictory. The header says `Review artifacts: scripts/review/results/2026-04-20-plan-2393-claude.md | ...-codex.md | ...-gemini.md`, but `Adversarial Review Summary` marks `Codex | PENDING` and `Gemini | PENDING`. A plan cannot simultaneously cite concrete artifact paths and mark those reviews pending without clarifying which artifacts already exist.
- [P2] The frontmatter dependency is acknowledged but not resolved at the plan level. `LLM Wiki pages consulted` says `varying frontmatter shape per §8.1`, and `test_missing_doc_key_skipped` only proves skipping; it does not define whether missing baseline-floor fields (`title`, `last_updated`, `doc_key`) are a blocker, a warning, or an exclusion policy for the indexed corpus.
- [P2] The pseudocode relies on undefined data sources and joins. In `Stage 1 — build`, `load L2 summaries from phase-a-index + registry` is a correctness-critical join path, but no concrete registry file/path/schema is cited in `Artifact Map` or `Files to Change`, so the L2 input contract is underspecified.
- [P2] Query correctness is under-tested for failure modes. `TDD Test List` covers model mismatch and layer filtering, but not empty-index queries, corrupt/missing manifest, corrupt parquet, missing `/mnt/ace/` cache, malformed frontmatter beyond missing `doc_key`, or vector-dimension mismatches after model changes.
- [P2] Scope is broader than a single-purpose deliverable. `Complexity: T3` bundles a model-selection spike, new build pipeline, new query CLI, cron wiring, README update, and review-artifact process into one issue. The `Deliverable` is ostensibly an index, but the plan also introduces architecture selection and operational rollout work that should be dependency-gated or split.
- [P2] Security and operational threat modeling is missing for mount and external-model paths. `Artifact Map` writes to `/mnt/ace/.embeddings/`, and `Pseudocode` evaluates cloud options (`Voyage-3`, `text-embedding-3-large`), but the plan does not define path-safety rules, secret sourcing, access control, cache poisoning/overwrite protections, or what data may be sent off-machine during the spike.

### Suggestions
- Add a verification appendix to `Resource Intelligence Summary` with exact file paths, issue statuses, and the concrete registry entry or schema each claim depends on; remove any claim you cannot prove.
- Amend the plan to state the `doc_key` contract explicitly: only `sha256:` namespace is accepted as canonical identity, path-only identity is forbidden, and legacy/nonconforming keys are either migrated or excluded with a counted manifest field.
- Choose one authoritative storage tier for the vector blob and document it unambiguously. If `/mnt/ace/` is authoritative, make the repo copy a non-authoritative local cache or remove it; if the repo-local parquet is authoritative, do not also describe `/mnt/ace/` as the durable location.
- Convert dependency mentions into an explicit dependency table: issue number, required status, why it matters, whether this plan blocks on it, and what fallback behavior is allowed if it has not shipped.
- Expand the TDD matrix to cover every acceptance criterion and every stated mitigation: row-count sufficiency, p95 latency benchmark, cron config validation, cost-cap abort behavior, empty/corrupt index handling, missing manifest, and cache/mount failures.
- Resolve the review-artifact contradiction by either removing pending artifact paths from the header or changing the review summary to name which artifacts actually exist and which are still required before approval.
- Define the L2 input contract concretely by citing the exact registry file/path and schema used to join phase-A summaries to registry metadata.
- Add a security/ops section covering secret sourcing for cloud models, outbound-data policy during the model spike, mount path validation, atomic writes, and protections against stale or poisoned cache state.
- Trim scope by splitting the model-selection spike or cron rollout into a prerequisite issue if they are not required to land the core index/query functionality safely.
