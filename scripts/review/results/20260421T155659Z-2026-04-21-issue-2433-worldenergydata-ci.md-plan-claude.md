### Verdict: MAJOR

### Summary
Plan is thorough, evidence-rich, and follows the planning template well, with a clear path decision, verified resource-intel, and granular acceptance criteria. However, several execution details create risk of a half-green CI: the test job runs with coverage thresholds and addopts flags that the verification commands deliberately bypass, the `hse/importers` url-test paths appear under two different directories (`tests/unit/hse/importers/` and `tests/modules/hse/importers/`) but only one is in the skip set, and `continue-on-error: true` placement semantics on a multi-step job need tightening. Addressing these and tightening the acceptance criteria to match what CI actually runs will make the plan executable as written.

### Issues Found
- [P1] Verification divergence from CI: acceptance criteria run `pytest tests/ --collect-only --override-ini="addopts="`, which strips pytest.ini's `-x --maxfail=5` AND any `--cov-fail-under` thresholds. CI runs `uv run pytest tests/ -v --tb=short --cov=src ...` without that override, so local 'green' does not prove CI green. Add an acceptance step that runs the exact CI command (or a close proxy including `--cov=src` and any fail-under threshold) against the patched branch before declaring done.
- [P1] Incomplete skip-list coverage for hse url importers. The error list in the Evidence block names `tests/unit/hse/importers/test_bsee_{incidents,penalties,statistics}_importer_url.py` and the 15-file black reformat list additionally names `tests/modules/hse/importers/test_bsee_{incidents,penalties,statistics}_importer_url.py`. The skip set in Pseudocode only contains the `tests/unit/...` copies. If both directories exist and share the broken import chain, three files will still error at collection. Reconcile whether the `tests/modules/hse/importers/` copies exist, are collected by CI, and whether they belong in the skip set or are intentionally different.
- [P1] `continue-on-error: true` placement ambiguity. The plan says 'add continue-on-error: true on type-check job's mypy step' in one place and 'to the type-check step' in another. For a job named `type-check` that runs a single `uv run mypy ...` step, setting it on the step vs the job has the same CI outcome, but since the `build` job depends on `[test, lint]` (not type-check), the current CI is not actually gated on type-check. Verify whether type-check is currently blocking `build`/merge at all — if not, this change is cosmetic and not required to unblock Dependabot PRs.
- [P2] `pytest_ignore_collect` path-matching logic uses `path_str.endswith(rel)` and `dir_pattern in path_str`. Without an explicit repo-root anchor this can produce false positives (e.g., `in path_str` matching any parent path containing 'tests/unit/marine_safety' string). Plan should specify using `collection_path` as a `pathlib.Path` and comparing against a repo-relative path to avoid brittle substring matches, especially given worldenergydata has symlinked/nested module trees.
- [P2] `tests/unit/marine_safety` is listed as a directory-level skip, but the 15-file black list includes `tests/unit/marine_safety/test_validators.py` as a reformat target. Reformatting a file that will then be ignored at collection is wasted churn and can re-introduce lint drift later. Either remove the reformat for files inside skipped directories, or justify reformatting them for when the skip is lifted (acceptable — just make the choice explicit).
- [P2] Acceptance criterion 'At least one Dependabot PR (#329-#333) shows green CI checks after the fix PR merges' requires the Dependabot branches to be rebased on the merge commit. Dependabot does not auto-rebase on every target-branch push; manual `@dependabot rebase` comments or equivalent may be needed. Add that step explicitly to the plan.
- [P2] The `lint` job runs black AND isort per the Resource Intel summary (`run a lint job which runs ... black --check --diff src/ tests/`), but only black is called out in Files to Change. Acceptance criteria include isort, but the pseudocode step list does not include running isort locally before commit. Add an explicit 'run isort' step to pseudocode and Files-to-Change if isort changes are needed.
- [P3] `broken_module_tests` is named for module-level test files but also includes `tests/modules/fdas/integration/test_end_to_end.py` (flagged as 'fdas duplicate basename' not a missing module). The root cause for that file differs — duplicate basename is a pytest collection uniqueness issue, not an ImportError. The comment should reflect this so future re-enablement uses the right remediation (rename, not module restoration).
- [P3] Risk section notes preserved `/tmp/` artifacts may be GC'd, but does not describe how to regenerate the exact skip set from scratch. If GC happens, the 22-path list must be re-derived by running pytest collect on a fresh clone — call that out as a recovery procedure.
- [P3] The plan's Adversarial Review Summary section is empty ('pending'). Per workspace-hub rules, adversarial review must be posted before `status:plan-approved`. Plan should not be merged/approved until that table is filled with actual verdicts.

### Suggestions
- Add an acceptance criterion that reproduces the CI `test` job command verbatim (`uv run pytest tests/ -v --tb=short --cov=src ...`) — not the stripped-addopts variant — and captures exit code 0. This is the only observation that proves CI-green.
- Before implementation, run `ls worldenergydata/tests/modules/hse/importers/` and `uv run pytest tests/modules/hse/importers --collect-only` to confirm whether those files exist and fail. If yes, add them to the skip set explicitly and document in Evidence.
- Switch `pytest_ignore_collect` skip matching to `collection_path.relative_to(rootdir).as_posix() in broken_module_tests` (set membership on normalized relative paths) rather than `endswith`/`in` substring matches. Safer and self-documenting.
- For each skip-set entry, include a one-line comment with the missing symbol and the worldenergydata issue number (once filed) for re-enablement — this matches the acceptance criterion already in the plan and makes the conftest.py patch self-auditing.
- Add an explicit step to either rebase Dependabot PRs (`@dependabot rebase` comments) or document that CI will re-run on next scheduled Dependabot update cycle. Current acceptance criterion can otherwise stall.
- Consider deleting `tests/unit/marine_safety/test_validators.py` from the reformat list if the whole directory is being skipped, or promote the reformat commit to 'reformat + keep-skipped' with a note.
- Add a Verification section distinguishing pre-PR local checks (what the plan currently lists) from post-merge CI checks (which jobs must go green on the merge commit and on each Dependabot PR) — so reviewers and the executor have two clear gates.
