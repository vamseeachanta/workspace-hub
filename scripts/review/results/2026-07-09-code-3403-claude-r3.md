## Findings

- **MINOR: scripts/agents/install-voice-dictation.sh:44-46 (`write_inert_hotkey`) — quoting defect puts a stray `\` in the user-facing message and leaves dead code.** In `command="... \\\"\\${msg}\\\" ..."`, `\\$` collapses to `\` + live expansion, not the intended escaped `\$`. Verified empirically: the stored command inlines the full message at install time with a literal leading backslash, so the notification/logger body reads `\Voice dictation inactive: ...`, and the `msg=\"...\"` assignment inside the inner shell is dead (never referenced). The committed test executes the command and asserts only that notify-send fires, so it can't catch this. Fix: use `\\\$` to defer expansion, or drop the inner `msg=` indirection and pass the single-quoted message directly.

- **MINOR: tools/voice-dictation/codex-dictate.sh:88-104 (`start_arecord`) / bottom dispatch — no mutual exclusion; the 0.15 s grace sleep enlarges a double-press race that orphans an `arecord`.** The pidfile is written only *after* `sleep "${grace}"`. Two hotkey presses within ~150 ms both see no pidfile, both spawn `arecord` writing the same `${wav}`; the second overwrites the pidfile, so the first `arecord` is never killable via the toggle and holds the capture device until logout. A rapid human double-tap is inside this window. Fix: take an `flock` on `${state_dir}/lock` around the pidfile-check/start/stop critical section, or write the pidfile before the grace check and clean up on failure.

- **MINOR: tools/voice-dictation/codex-dictate.sh:18, tools/voice-dictation/dictate-test.sh:16 — predictable world-writable fallback state dir.** When `XDG_RUNTIME_DIR` is unset the state dir is `/tmp/codex-dictate`, created with `mkdir -p` (no ownership/mode check, no `-m 700`). On a multi-user box an attacker can pre-create it and read recorded audio, or symlink `rec.wav` to clobber a victim-writable file via `arecord`. The kill path is protected by `is_owned_recording`, but the wav/pidfile writes are not. Fix: `mkdir -p -m 700` plus an ownership check, or `mktemp -d`-style per-user fallback (`/tmp/codex-dictate-$(id -u)` with mode 700).

- **MINOR: tools/voice-dictation/codex-dictate.sh:48-77 (`stop_and_type`) — hotkey press during transcription truncates the wav being transcribed.** `stop_and_type` removes the pidfile immediately, then transcription can run for several seconds on CPU. A hotkey press in that window sees no pidfile, calls `start_recording`, and `arecord` truncates `${wav}` while `transcribe.py` is still reading it → garbled or empty transcript with no error. Fix: record to a unique temp wav per session (name it in the metafile), or hold the flock from the previous finding across transcription.

- **Nit: tools/voice-dictation/codex-dictate.sh:37-41 (`inject_text`) — `wtype "${text}"` and `ydotool type "${text}"` lack a `--` argument guard** (the `xdotool` branch has one). A transcript beginning with `-` would be parsed as an option. Low likelihood; note `wtype` has no `--` convention, so prepending a space or using `printf | wtype -` is the robust form.

`★ Insight ─────────────────────────────────────`
- Git stores only one permission bit (`100755` vs `100644`), so a mode fix is best locked in with a `git ls-files -s` assertion in the test suite — which this commit did; the review's job then shifts to confirming the test actually runs and the worktree agrees with the index.
- Triple-layer quoting (installer bash → GLib `g_shell_parse_argv` → inner `bash -lc`) is where `\\$` vs `\\\$` bugs hide: inside double quotes, `\\` collapses first, leaving `$` live for expansion one layer too early. Testing "the command runs" isn't enough — assert the argv the leaf tool receives.
