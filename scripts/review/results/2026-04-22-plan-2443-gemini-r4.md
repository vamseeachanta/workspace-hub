### Verdict: MAJOR

### Summary
The v4 draft fails to resolve the requested blocker set. The `uv run` invocation is still present in the script, the README/index drift remains explicitly deferred, and the non-negotiable markdownlint floor has a significant residual bypass via markdownlint aliases and tags. Additionally, there is a code-vs-comment contradiction in the verifier's configuration dictionary handling.

### Issues Found
- **`uv run` policy blocker not closed:** The `scripts/verify-markdownlint-floor.sh` script still hardcodes `uv run python - "$cfg" <<'PY'`, failing to resolve the blocker requiring the removal of the undeclared `uv` tool dependency.
- **Floor-rule bypass (Aliases and Tags):** The markdownlint floor can be trivially bypassed. The Python verifier only checks for exact primary rule keys (e.g., `"MD025"`). A user can leave `"MD025"` unspecified (which defaults to true in the script) but successfully disable the rule by setting its alias (`"single-title": false`) or tag (`"headings": false`) in the JSONC config.
- **Floor-rule code contradiction:** The verifier script claims `# Extra guard: if default is False, floor rules MUST be explicitly True (not absent, not {}-dict without truthy)`. However, the implementation `cfg.get(r, False) is False` uses Python's strict identity check. Providing an empty dict `"MD025": {}` returns `{}`, and `{} is False` evaluates to `False`, thereby bypassing the guard. This contradicts both the inline comment and the TDD step 2 description.
- **README/index drift not closed:** The draft explicitly states in the Risks/Open section: `Open — should this plan also update docs/plans/README.md index... Defer to next session`. The governance drift blocker has not been resolved.
- **Stale Status section:** The document header claims `(v4 revision: 2026-04-22)`, but the status section is still titled `### Status (v3)` and states it is awaiting Wave 3 review, showing incomplete version maturation.

### Suggestions
- Replace `uv run python` with standard `python3` in the verifier script.
- Update the verifier script to explicitly reject the presence of any keys in the JSONC that aren't exact `MD0xx` IDs or standard top-level config keys like `default` to prevent alias/tag bypasses.
- Fix the dictionary truthiness check in the verifier script to properly inspect dictionary contents instead of relying on an `is False` identity check.
- Add the `docs/plans/README.md` index row update to the Artifact Map and Acceptance Criteria to resolve the governance drift.
- Update the `Status` section header and text to accurately reflect the v4 state and Wave 4 review stage.
