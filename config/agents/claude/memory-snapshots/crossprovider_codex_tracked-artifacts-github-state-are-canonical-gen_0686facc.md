When verifying issue readiness, use GitHub issue state (labels, comments) and committed repo files as authoritative. Generated local artifacts (reports, snapshots) are evidence only if explicitly tracked or cited by GitHub. Conflating generated output with approved state bypasses the issue's approval gate.
