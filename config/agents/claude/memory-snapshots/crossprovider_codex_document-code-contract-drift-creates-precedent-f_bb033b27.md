When expanding valid input/outcome ranges (e.g., consensus from `FULL` to `[FULL, MAJORITY, SPLIT]`), update docstrings and public contracts immediately. Drift between code and documentation creates reviewer surprise and establishes a pattern where future inconsistencies pass unnoticed.
