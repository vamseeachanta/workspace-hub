When GitHub issues are revised to narrow scope (e.g., #334: 'foundation-only', no package-root expansion), plan artifacts often still reflect the earlier, broader scope. Plan redrafts must explicitly reconcile issue-revision gaps; a revised issue + unchanged plan blocks approval even if the issue itself is now tighter.
