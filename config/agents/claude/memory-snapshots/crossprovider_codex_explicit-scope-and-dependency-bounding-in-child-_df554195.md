Child issues prevent scope creep by: (1) explicitly listing in-scope and out-of-scope deliverables, (2) naming parent/sibling dependencies, (3) stating what will NOT change (e.g. 'no stored foreign keys'). This protects downstream issues from surprise redesigns.
