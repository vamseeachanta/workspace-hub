Corpus-driven ingestion of the Frontier Deepwater corpus into PRIVATE **llm-wiki-fdas**, epic **#24** — the broad/shallow counterpart to the analysis loop [[project_fdas_wiki_population_loop]] (#1–#7, deep vertical riser-buckling screens). Started 2026-06-08.

**The "corpus" is the TOTAL business-development engagement archive** (`/mnt/ace/frontierdeepwater`, the frontierdeepwater COMPANY repo) — the APS/FrPS dry-tree "Appraisal/Production System" concept pitched to TOTAL ~2016–2018, plus 2025–26 *World Oil* Lower-Tertiary articles. 108 office docs among heavy code/agent/venv noise → content-triage required.

**KEY DECISION: run INLINE on ace-linux-1, NOT the ace-linux-2 skip-perms dispatch.** The corpus is LOCAL on a1 (`/mnt/ace/frontierdeepwater`), so the handover's a2-sshfs+`--dangerously-skip-permissions` dance is unnecessary; inline orchestration + normal interactive PR approval sidesteps the skip-perms classifier gate AND ssh fragility. (The a2 dispatch loop is for sessions NOT on a1.)

**Corpus pages are a DIFFERENT archetype than the analysis pages:** `trust_label: source-extract`, `derivation_status: quoted`, `parse_status: provisional`, `visibility: private` — they record "what the document says" with provenance; they do NOT run engineering screens. Applying the issue-#8 engineering-screen method to a source extract is a category error. `analysis_maturity` is deliberately NOT used on these pages.

**Reusable deterministic extractor: `scripts/extract_office.py`** (committed). Handles docx→txt / xlsx→csv(per-sheet, data_only) / msg→txt(thread header+body, via extract-msg) / pdf→txt(via pymupdf). Per-batch manifests via `--batch A..E|all`. **Corpus root from `FDAS_CORPUS` env, NEVER committed** (keeps host mount paths out of the client wiki — issue-#8 "no raw mount paths" gate). Re-run reproduces extracts byte-for-byte. RAW BINARY NEVER COMMITTED — only derived text/CSV + sha256 pointer in `sources/README.md`.

**STACK THE BATCHES** (each branch off the prior batch's tip; PR base = prior branch). Two shared surfaces — `scripts/extract_office.py` and the auto-generated `pages/README.md` — would conflict/be-missing if batches branched from `main` in parallel. Stacking flows shared infra forward; each PR diff stays batch-scoped; user merges A→B→C→D→E in order (GitHub auto-retargets bases as each merges). `gen_index.py` rebuilds the index from page frontmatter (`name`/`description`/`issue`/`order`) — NEVER hand-edit `pages/README.md`/`reports/README.md`.

**Verify loop = 2-round Codex per batch** (producer never self-certifies). `codex exec -s workspace-write --skip-git-repo-check "<prompt>" < /dev/null > review_batchX.md` from the repo write-root; mv the review file OUT before committing (it stages otherwise). Recurring finding class = **interpretation/provenance overclaims on faithful data**: a quote must match the source EXACTLY (clause order too); a cross-reference ≠ a quote (don't imply Batch-B's cost figure is "quoted from" the article exec summary); a DERIVED number (920×0.2=184) is not "quoted" on a source-extract page; "identical across all N" must be literally checked. Hashes/extract-fidelity passed every time; the prose generalized beyond the extract — that's what Codex catches.

**⚠️ STACKED-PR MERGE-CASCADE HAZARD (hit + recovered 2026-06-09):** when a human merges a stack A←…←F2 in order, each child PR's base must retarget to `main` as its parent merges. If the top PRs are merged while their base still points at an intermediate branch that has *already* merged to main, the top content merges INTO that orphaned intermediate branch and **never reaches main** (silently — PRs show MERGED). Here #36/#38 (F1/F2, the 24 decks + 2 pages) stranded on `corpus/batch-e-prefeed`; main had only 11 pages/0 decks despite all PRs "merged". RECOVERY: the surviving intermediate branch (`batch-e-prefeed`, which F1/F2 had merged into) was a clean ADDITIVE superset of main (`git diff --stat origin/main origin/<branch>` = exactly the stranded files, no conflicts) → one new PR from it to main (#39, MERGEABLE/CLEAN) landed everything. LESSON: after merging a stack, VERIFY main actually has the top batches' files (don't trust "all PRs merged"); if stranded, PR the surviving superset branch → main. **SECOND HIT 2026-06-09: PR #44 (attachment harvest) merged 21s after its base #42 → stranded on `corpus/economics-formula-recapture`; tree-check caught it (main had the #43 matrix claiming Closed but no code).
