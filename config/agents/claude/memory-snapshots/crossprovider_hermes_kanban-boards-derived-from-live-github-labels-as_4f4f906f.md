Kanban boards should be generated from live GitHub issue labels (state, category, domain), not maintained as separate manual queues. Labels are the authoritative source; the board is a computed view over them. Split into execution-ready, approval-drift, plan-review, planning-needed, and working-audit lanes based on label patterns and evidence presence.
